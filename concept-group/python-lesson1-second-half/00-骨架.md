## 1. 组定位

- **这一组在解决什么问题**：把「能存一个值」推进到「能存一组数据、并能按名字准确取出想要的那一份」—— 这是从玩具程序走到处理真实数据的分水岭。
- **目标读者**：已学完上半场（环境搭建 / Notebook / 变量与基本类型 / 报错怎么读）；会写赋值与 `print`，会用 `type()`，能看懂 Traceback 的最后一行。
- **学完之后的收益**：能读写「一张表」级别的数据结构；看到 CSV、接口返回的 JSON、数据库查询结果时认得它们的形状；撞到 `IndexError` / `KeyError` 时知道回头查哪一篇。

## 3. 边界声明（最关键）

### 3.1 运算符（Operators）

- **in-scope**：算术运算符 `+ - * / // % **`（含 `/` 真除法与 `//` 整除的区别）；比较运算符 `== != > < >= <=`（结果永远是 `bool`）；逻辑运算符 `and or not`；`=` 与 `==` 的区别；运算符优先级（够用即可，配"不确定就加括号"的实践建议）；**同一个符号在不同类型上语义不同**（`+` 数字相加 / 文本拼接，`*` 文本重复）。
- **out-of-scope**：
  - 变量是什么、类型有哪些 → 归**组外**「变量与基本类型」（本组直接沿用，不重复讲）
  - 成员运算 `in` / `not in` → 归 **列表**（`x in [...]`）与 **字典**（`键 in {...}`）各自讲
  - `TypeError` 的逐行读法 → 归**组外**「报错怎么读」（本概念只说明"类型不匹配会抛 `TypeError`"这一句）
  - 位运算 `& | ^ ~ << >>`、运算符重载、`is` 身份运算 → 本组不展开
  - 用条件做分支（`if` / `while`）→ 归后续「控制流」课程（本概念只产出"算出一个 True/False"，不负责拿它做分支）

### 3.2 列表（Lists）

- **in-scope**：用 `[]` 创建；索引（从 0 开始、负数从末尾数）；切片 `[a:b]`（取到 b 之前，不含 b）；`len()`；增删改 `append` / `insert` / `remove` / `pop` / `del`；`sort()` 原地排序与 `sorted()` 返回新列表的区别；成员运算 `x in [...]`；**可变（mutable）带来的引用共享**（`b = a` 后 `a.append` 会影响 `b`）；越界抛 `IndexError`。
- **out-of-scope**：
  - `+` 对数字与文本的语义 → 归 **运算符**（本概念只提一句"两个列表也能用 `+` 合并"）
  - 键值对容器、"某个名字是否存在" → 归 **字典**
  - 用列表表示"一条记录" → 归 **列表套字典**
  - 遍历列表的 `for`、列表推导式、`map` / `filter` → 归后续课程（本篇只给写法预览，不展开）
  - 元组 / 集合 / `numpy` 数组 → 本组不展开

### 3.3 字典（Dictionaries）

- **in-scope**：用 `{}` 创建；键值对；按 `d[键]` 取值与 `d.get(键, 默认值)` 的区别；增 / 改 / 删 `d[键] = 值`、`del d[键]`、`d.pop(键, 默认)`；**键必须是不可变类型**且唯一；成员运算 `键 in d` 查的是**键**；`keys()` / `values()` / `items()` 三视图；保持插入顺序（3.7+）。
- **out-of-scope**：
  - `KeyError` 的报错逐行读法 → 归**组外**「报错怎么读」（本概念只说明"取不存在的键会抛 `KeyError`、用 `get()` 可避免"）
  - 列表的增删改与索引切片 → 归 **列表**
  - 多行记录 / 一张表 → 归 **列表套字典**（本概念只讲"一条记录"用单个字典表示）
  - 哈希表实现原理与复杂度细节 → 本篇只给"按键查找很快"的直觉，不讲哈希
  - JSON 序列化、嵌套多层的复杂结构 → 本组只到"一层字典"与"列表套一层字典"

### 3.4 列表套字典 = 一张表（List of Dicts）

- **in-scope**：为什么"每行字段名会重复"要用字典装（列名不丢）；把多行记录放进列表 → 一张表的心智模型；`rows[i]` 取一行、`rows[i]["字段"]` 取一格；`rows.append({...})` 加一行、`rows[i]["字段"] = 新值` 改一格、`del rows[i]` 删一行；**同一张表每行的键应一致**；认清它就是 CSV / JSON / 数据库查询结果的常见形状。
- **out-of-scope**：
  - 列表自身的索引 / 切片 / 增删 → 归 **列表**
  - 字典自身的建 / 取 / 改 / 删 → 归 **字典**
  - 遍历取整列、筛选、排序、分组（含列表推导式）→ 归后续课程（本篇只在代码块里给一行写法预览）
  - pandas / SQL / CSV 文件的读写 → 归后续课程（本概念只建立"用基础容器表示表"的心智模型）
  - 多层嵌套（字典套列表套字典…）→ 本组不展开

## 4. 先修顺序

| 顺序 | 概念 | 为什么排在这里（一句话） |
|---|---|---|
| 1 | 运算符 | 不依赖组内任何概念，且是后面三个"做事"的基础 |
| 2 | 列表 | 只需组外的「变量与基本类型」，是本组第一个也是最基础的容器 |
| 3 | 字典 | 需要先有"容器"这个概念，再理解"按名字而不是按编号找" |
| 4 | 列表套字典 = 一张表 | 需要同时懂列表与字典 —— 它是把前两者拼起来的那根线 |

**学习路径一句话**：会算 → 会装一串 → 会装带名字的 → 会装一张表。

> 顺序说明：这与用户给出的清单顺序一致（运算符 → 列表 → 字典 → 列表套字典），也恰好是教学上的自然顺序。

## 5. 共享术语表

> Phase 2 生成时必须严格使用本表措辞，防止四份材料自造词。组外已定义的「变量」「类型」「报错信息」「异常」沿用上半场骨架，本表不重复。

| 中文 | 英文 | 本组内统一含义 | 不要写成 |
|---|---|---|---|
| 运算符 | operator | 对值进行运算的符号，如 `+` / `==` / `and` | 操作符、算符 |
| 表达式 | expression | 由值和运算符组成、会算出一个结果的一段代码 | 语句 |
| 真除法 / 整除 | true division / floor division | `/` 结果永远是小数；`//` 向下取整 | 除法（不说清是哪种） |
| 列表 | list | 有序、可变的序列，用 `[]` 表示 | 数组、清单 |
| 元素 | element / item | 列表中的一项 | 项、条目 |
| 索引 | index | 元素在列表中的位置编号，从 0 开始 | 下标（首次可用，之后统一"索引"） |
| 切片 | slice | 用 `[a:b]` 取列表中一段（不含结尾位置） | 截取、分割 |
| 字典 | dictionary / dict | 键值对的集合，用 `{}` 表示 | 映射、map |
| 键 / 值 | key / value | 字典里"名字"和它对应的"内容" | 索引（键不是索引） |
| 成员运算 | membership test | 判断某值是否在容器里，用 `in` | 包含判断 |
| 可变 | mutable | 创建后还能原地修改内容 | 可改的 |
| 记录 / 行 | record / row | 一张表里的一个条目 | 条目、对象 |
| 字段 | field | 记录里的一个属性名（相当于表格的列名） | 键、列（首次可用"列名"，之后统一"字段"） |

## 6. 冲突检查

| 可能重叠的点 | 涉及概念 | 裁决 |
|---|---|---|
| 成员运算 `in` 谁来讲 | 运算符 ↔ 列表 ↔ 字典 | **运算符**只讲算术 / 比较 / 逻辑三组，**不含 `in`**；`in` 归 **列表**（`x in [...]`）与 **字典**（`键 in {...}`）各自讲；字典篇必须写明"查的是键不是值" |
| `+` 施加在容器上 | 运算符 ↔ 列表 | **运算符**用数字与文本演示"同一符号两种含义"；**列表**只留一句"两个列表也能用 `+` 合并"，不展开 |
| 索引与切片 | 列表 ↔ 组外「字符串」 | 组外的字符串方法属上半场；本组 **列表** 独占索引 / 切片的完整讲解，不重复字符串部分 |
| `KeyError` | 字典 ↔ 组外「报错怎么读」 | **报错怎么读**讲逐行读法；**字典**只讲"什么时候会抛、如何用 `get()` 避免" |
| `IndexError` | 列表 ↔ 组外「报错怎么读」 | 同上：**列表**只说明"越界会抛 `IndexError`"，逐行读法归报错篇 |
| 可变对象的引用共享 | 列表 ↔ 组外「变量与基本类型」 | 上半场已讲"名字指向值"；本组 **列表** 负责把这条原理**落到可变对象上**（`b = a` 后 `a.append` 影响 `b`）；**字典** 只提一句"字典同样可变" |
| "一条记录"到底用谁表示 | 列表 ↔ 字典 ↔ 列表套字典 | 单条记录用**字典**；多条记录用**列表套字典**；**列表** 不承担"记录"职责 |
| `for` 遍历 | 列表 ↔ 字典 ↔ 列表套字典 ↔ 后续课程 | 三者都**不展开**遍历；只在代码块内以注释形式给"写法预览"，并标注属后续控制流课程 |

**未裁决项**：无。
