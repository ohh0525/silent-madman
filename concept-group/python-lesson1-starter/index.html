1 · 这一组在解决什么问题

让零基础学员第一次接触 Python 时，把「在哪写 → 怎么跑 → 写什么 → 写错怎么办」这四个动作一次打通，而不是被环境问题挡在门外。

学完之后的收益：能自己装好环境、在 Notebook 里跑通代码、独立看懂并修掉自己的报错、写出带变量的简单程序。

这一组不是四个孤立词条。四份材料共享同一份边界声明与术语表，并且每一份的第 5 段都明确写出了「我和隔壁那份的分工在哪」—— 这正是「一组材料」区别于「一堆材料」的地方。

2 · 学习路径（先修关系）

之所以把「报错怎么读」排在最后：它的示例全部基于变量与类型（如 TypeError）。代价是前两份材料里学员撞到报错时手上还没有解读工具 —— 这是刻意的取舍，换取的是示例更贴近学员当时的水平。

4 · 边界速查（谁讲什么）

可能重叠的点归属裁决
TypeError 谁来讲报错怎么读完整讲排查；变量与基本类型只留一句「类型不匹配会抛 TypeError」
「跑通第一个程序」环境搭建的 hello world 只用 print("...")，不引入变量；变量与基本类型才引入赋值
「代码写在 Notebook 里」Notebook 只管「在哪写、怎么跑」；代码内容本身归变量与基本类型
报错输出显示的位置Notebook 只讲「输出显示在单元格下方」；输出内容什么意思归报错怎么读
与既有 Word 讲义的关系既有 docx 定位为课堂讲义（含教学法与练习）；本组 HTML 版定位为自学速查卡，不复刻课堂练习

5 · 共享术语表

四份材料严格使用下表措辞，避免各写各的。

中文英文本组内统一含义
解释器interpreter真正执行 Python 代码的程序
编辑器 / IDEeditor / IDE写代码的工具，如 VS Code、PyCharm
单元格cellNotebook 里一个可独立运行的最小单元
内核kernelNotebook 后台真正执行代码的进程
变量variable一个指向某个值的名字
类型type一个值属于哪一类，如 int / str
报错信息error message / traceback屏幕上一整段错误文本
异常exception程序运行中抛出的错误对象

7 · 一句话回顾

这四个概念合起来是一句话：先让程序跑起来，再让它会算，最后让你看得懂它为什么不听话 —— 顺序不能反，边界不能糊。
