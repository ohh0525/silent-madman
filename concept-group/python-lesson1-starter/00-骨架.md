## 1. 组定位

- **这一组在解决什么问题**：让零基础学员第一次接触 Python 时，把「在哪写 → 怎么跑 → 写错怎么办 → 写什么」这四个动作一次打通，而不是被环境问题挡在门外。
- **目标读者**：完全没写过程序的人；已会基本电脑操作，但没配过开发环境。
- **学完之后的收益**：能自己装好环境、在 Notebook 里跑通代码、独立看懂并修掉自己的报错、写出带变量的简单程序。

## 3. 边界声明（最关键）

### 3.1 环境搭建

- **in-scope**：安装 Python 解释器；选择并安装一个编辑器/IDE；验证装好了（查版本号）；跑通第一个 `print`；PATH 未配置导致的「命令找不到」怎么处理。
- **out-of-scope**：
  - Notebook 界面怎么用、cell 怎么跑 → 归 **Notebook**
  - 报错信息怎么逐段读 → 归 **报错怎么读**（本概念只要求"能照着关键字搜"）
  - pip / 包管理 / 虚拟环境 / 多版本共存 → 归后续课程，本组不展开

### 3.2 Notebook

- **in-scope**：什么是 cell；运行 cell 与运行顺序；代码 cell 与 Markdown cell 的区别；内核 kernel 的状态；保存为 `.ipynb`；重启内核与「全部运行」。
- **out-of-scope**：
  - Notebook 本身怎么安装 → 归 **环境搭建**
  - 变量作用域、类型规则 → 归 **变量与基本类型**
  - Notebook 的服务端架构与远程部署原理 → 本组不展开（只需会用）

### 3.3 变量与基本类型

- **in-scope**：变量 = 名字指向值；赋值与重新赋值；四种基本类型 `int` / `float` / `str` / `bool`；用 `type()` 查看类型；类型转换 `int()` / `float()` / `str()`；变量命名规则。
- **out-of-scope**：
  - 每种类型的完整方法清单（如 `str` 的十几个方法）→ 归后续「字符串专题」，本概念只给最常用的 1–2 个
  - `TypeError` 的排查步骤 → 归 **报错怎么读**（本概念只说明"类型不匹配会抛 `TypeError`"这一句）
  - `list` / `dict` / `tuple` 等容器类型 → 归后续课程

### 3.4 报错怎么读

- **in-scope**：Traceback 的四段结构；"先看最后一行"；五步排查法；五类高频错误（`TypeError` / `NameError` / `ValueError` / `KeyError` / `FileNotFoundError`）的逐行拆解；报错常见英文句式对照。
- **out-of-scope**：
  - 每类错误背后的类型系统原理 → 归 **变量与基本类型**
  - 断点调试器 / `pdb` / IDE 图形调试 → 本组只讲"读"，不讲"调"
  - 安装失败类问题的排查 → 归 **环境搭建**

## 4. 先修顺序

| 顺序 | 概念 | 为什么排在这里（一句话） |
|---|---|---|
| 1 | 环境搭建 | 不依赖组内任何概念，且是其余三个的前提 |
| 2 | Notebook | 需要先装好环境，才能打开它 |
| 3 | 变量与基本类型 | 需要一个能跑代码的地方，且报错篇的示例依赖它 |
| 4 | 报错怎么读 | 需要先会写一点代码（含变量），才有东西可报错 |

**学习路径一句话**：装好 → 会跑 → 会写 → 会查错。

## 5. 共享术语表

> Phase 2 生成时必须严格使用本表措辞，防止四份材料自造词。

| 中文 | 英文 | 本组内统一含义 | 不要写成 |
|---|---|---|---|
| 解释器 | interpreter | 真正执行 Python 代码的程序 | 编译器 |
| 编辑器 / IDE | editor / IDE | 写代码的工具，如 VS Code、PyCharm | 只写"软件" |
| 单元格 | cell | Notebook 里一个可独立运行的最小单元 | 格子、块 |
| 内核 | kernel | Notebook 后台真正执行代码的进程 | 核心、CPU |
| 变量 | variable | 一个指向某个值的名字 | 容器、盒子 |
| 类型 | type | 一个值属于哪一类，如 `int` / `str` | 数据类型（首次出现可用，之后统一"类型"） |
| 报错信息 | error message / traceback | 屏幕上一整段错误文本 | 乱码、bug |
| 异常 | exception | 程序运行中抛出的错误对象 | 与"报错信息"混用 |

## 6. 冲突检查

| 可能重叠的点 | 涉及概念 | 裁决 |
|---|---|---|
| `TypeError` 谁来讲 | 变量与基本类型 vs 报错怎么读 | **报错怎么读**完整讲排查；变量与基本类型只留一句「类型不匹配会抛 `TypeError`，读法见报错篇」 |
| "跑通第一个程序" | 环境搭建 vs 变量与基本类型 | 环境搭建的 hello world **只用** `print("...")`，不引入变量；变量与基本类型才引入赋值 |
| "代码写在 Notebook 里" | Notebook vs 变量与基本类型 | Notebook 只管「在哪写、怎么跑」；**代码内容本身**归变量与基本类型 |
| 报错输出显示的位置 | Notebook vs 报错怎么读 | Notebook 只讲「输出显示在 cell 下方」；**输出内容什么意思**归报错怎么读 |
| 「报错怎么读」已有 Word 讲义版本 | 本组 HTML vs 既有 docx | **裁决**：`Python基础语法课程/Python基础语法讲义（补充·报错怎么读）.docx` 定位为**课堂讲义**（含教学法、练习）；本组 HTML 版定位为**自学速查卡**，不复刻课堂练习，只保留结构+速查表 |

**未裁决项**：无。
