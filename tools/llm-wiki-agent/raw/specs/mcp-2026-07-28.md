## What this is

On **2026-07-28** the Model Context Protocol (MCP) maintainers finalized the next
revision of the specification. It is described as **the largest revision of the
protocol since launch** (and, per Anthropic technical staff member David Soria
Parra, the most substantial change since authorization was added). A release
candidate was published ahead of the final ship date.

## Headline change: MCP is now stateless at the protocol layer

MCP transforms from a **bidirectional stateful protocol** into a **request/response
stateless protocol**. Two Specification Enhancement Proposals drive this:

- **SEP-2575** — removes the `initialize` / `initialized` handshake.
- **SEP-2567** — removes the `Mcp-Session-Id` header and the protocol-level session.

What replaces them: the protocol version, client identity, and client capabilities
that were previously exchanged once at connection time now travel **in a `_meta`
field on every request**. A new **`server/discover`** RPC lets clients fetch server
capabilities up front when they want to; it is **not required**.

Consequence: **any request can land on any server instance behind a plain
round-robin load balancer** with no shared storage. Remote MCP servers effectively
become standard HTTPS endpoints.

### Before (2025-11-25)

```
POST /mcp HTTP/1.1
{"jsonrpc":"2.0","id":1,"method":"initialize",
 "params":{"protocolVersion":"2025-11-25","capabilities":{},
           "clientInfo":{"name":"my-app","version":"1.0"}}}
→ server replies with Mcp-Session-Id; every later request must carry it
```

### After (2026-07-28)

```
POST /mcp HTTP/1.1
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: search
{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"search","arguments":{"q":"otters"},
           "_meta":{"io.modelcontextprotocol/clientInfo":{"name":"my-app","version":"1.0"}}}}
```

A single fully self-contained request, routable to any instance.

## Stateless protocol, stateful applications

Removing the protocol-level session does **not** force applications to be stateless.
Servers needing state across calls mint an **explicit handle** from a tool (e.g.
`basket_id`, `browser_id`, `workflow_run_id`) and have the model pass it back as an
ordinary argument. The maintainers argue this is often **more powerful** than hidden
session state — because the handle becomes a first-class value the model can *see*,
reason about, and thread across multi-agent workflows.

## Other changes in the release

| Area | Change | SEP |
|---|---|---|
| Routing | `Mcp-Method` and `Mcp-Name` headers now **required** on Streamable HTTP requests; gateways/rate limiters/WAFs route on headers without parsing JSON bodies | SEP-2243 |
| Caching | `tools/list`, `prompts/list`, `resources/list`, `resources/read` now carry `ttlMs` + `cacheScope` cache hints (modeled on HTTP Cache-Control), enabling catalog caching and stable upstream prompt caches | SEP-2549 |
| Server→client requests | Replaced held-open SSE streams with **Multi Round-Trip Requests (MRTR)**: server returns `resultType: "input_required"` with its requests + `requestState`; client re-issues the original call with `inputResponses` | SEP-2322 |
| Authorization | Hardening: **RFC 9207** issuer validation; formal shift away from **Dynamic Client Registration (DCR)** toward **Client ID Metadata Documents (CIMD)** | — |
| Extensions | Extensions become **first-class**: **Tasks** (long-running ops, moved out of base protocol) joins **MCP Apps** (server-rendered UIs) and **Enterprise Managed Authorization (EMA)** | — |
| Deprecations | **Sampling**, **Roots**, and **Logging** deprecated (12-month minimum window). New implementations should call LLM provider APIs directly (instead of sampling) and log to stderr / OpenTelemetry (instead of MCP logging) | — |
| Tool schema | Full **JSON Schema 2020-12** for tools | — |
| Notifications | Opt-in via a long-lived `subscriptions/listen` stream naming the notification types wanted | — |
| Tracing | **W3C Trace Context** propagation in `_meta` formally documented (fixed key names), so a tool call can follow one span tree across host → client SDK → server in any OpenTelemetry backend | — |
| Governance | **Formal deprecation policy** with a 12-month minimum window; extensions framework; conformance-suite requirement | — |

## Adoption speed (within days of release)

- **GitHub MCP Server** shipped support *ahead* of the official release. Three changes:
  1. **Removed Redis-backed session storage** — eliminated a DB write on every `initialize` and a DB read on every request.
  2. **Stopped deep packet inspection** — values needed for logging/secret scanning now arrive in spec-guaranteed HTTP headers.
  3. **Reworked elicitation** — each step is now a separate HTTP request, with a Go SDK wrapper keeping old and new clients working.
- **Cloudflare** — each request runs on a fresh stateless server, no protocol session, no protocol-specific Durable Object.
- **Manufact** (hosts thousands of MCP servers) — new SDK cut **package size by ~83%** and is **~25% faster**; went stateless without infrastructure workarounds.
- **Supabase** — previously could never support elicitation (needed a held-open connection); MRTR lets its tools pause mid-call to confirm with the user.
- **AWS** — stateless core available in Amazon Bedrock AgentCore; contributed the Tasks extension. Existing clients keep working; upgrade is opt-in per version.
- **Microsoft Foundry** — can scale from dozens of integrations to thousands while centralizing governance/identity.
- **Simon Willison** (independent) — rebuilt tooling against the new protocol; wrote that stateless MCP had "recaptured my interest".

## Scale signals (from the official blog)

- Close to **half-a-billion downloads a month** across Tier 1 SDKs; TypeScript and Python SDKs each crossed **1 billion total downloads**.
- By mid-2026, **>10,000 MCP servers** reportedly in production; SDKs downloaded **>97 million times per month**.
- Salesforce reported **4.5 million MCP calls** processed since its Headless 360 launch routed interactions via MCP.
- SDK support: TypeScript, Python, Go, C# shipped with the release; Rust in beta; all Tier 1 SDKs preserve backward compatibility.

## Backward compatibility

The release **contains breaking changes**. Major SDKs preserve backward compatibility
with the old spec, so simply continuing to use existing MCP connections requires no
immediate migration. Interop between a new-revision server and an old client may need
a compatibility layer. Old and new versions can coexist: gateways advertise supported
versions; a client selects a version per request.
