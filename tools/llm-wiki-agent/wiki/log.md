Its attack, **"Repeat-After-Me"**, is trivial: knowing the tool-call format the orchestrator recognises, the attacker writes text naming a target tool plus its own arguments and asks the LLM to repeat it verbatim — the model "merely reproduces the supplied text" and the orchestrator dispatches it. Reproduced on **six** frameworks: **LangGraph, Microsoft Agent Framework, AutoGen, Google ADK 2.0, AWS Strands Agents, CrewAI**. The LangGraph 1.2.0 + Llama 3.1 8B transcript is the load-bearing one: first attempt — model refuses but *prints the call as text*, nothing executes; reframed as hypothetical and told to emit only the quoted text — the model returns it in structured form, **LangGraph executes it immediately with the attacker's arguments, and the model's refusal arrives only after the tool returned.** The authors' sentence is the page's title: "**The refusal text and the executed call disagree: the system prompt shaped what the model said, not what the orchestrator did.**" Missing pre-execution check reported to the LangGraph maintainers. Second leg, at ecosystem scale: ToFu derives semantic checks from each tool's own metadata + a CWE-guided sanitizer corpus (74 sanitizers / 21 introspection tracers) and fuzzes **273 MCP servers / 3,405 tools** ⇒ **253 verified bugs in 343 tools across 118 servers** (from 508 candidate flags): reflected output **115** (CWE-116/79) · path traversal **64** (CWE-22) · log injection **58** (CWE-117) · **SSRF 7** (CWE-918) · data exfiltration **5** (CWE-201) · **OS command injection 3** (CWE-78) · leftover temp file 1. Their diagnosis: "**many tools implicitly rely on the LLM to sanitize inputs**". The independent reading (Vibhum Dubey, quoted by CSO): "**Model output is not the permission**" — separate the model's ability to *request* an action from the system's authority to *carry it out*. Why this is a seam: [[ToolHallucination]]'s closed-world rung asks *does the tool exist* — here the tool **exists and is invoked correctly**, so that rung passes by construction; [[HumanInTheLoop]] grades by impact × reversibility but **assumes the gate is synchronous and blocking**, which is precisely what the orchestrator broke; [[AgentSandbox]] bounds *what an action can touch*, not *who treated the call as already authorised* — the wiki's own "**authority is not isolation**" line now has a second, upstream member. It also finally gives [[AgentHarness]] a fifth thing the harness does that nobody had listed: **the harness is itself a trust principal** (it interprets text as an invocation), not a transparent pipe. ⚠️ Grade: **preprint, not yet peer-reviewed** (FSE 2027 acceptance is a venue, not a review); full transcript published **only for LangGraph**, the other five are "reproduced" with no detail; dummy tools (`make_bomb` / `launch_missiles`) with no real effect; servers tested at fixed code versions; **no claim of in-the-wild exploitation**; the 253 bugs are *verified* but their severity in any given deployment is not established. **Not ingested.**

**(2) NEW ⭐ 记忆评测的内禀化 —— 「回答对了」不等于「记住对了」/ Intrinsic vs Extrinsic Evaluation of Agent Memory (FEB-30) (ledger row 10-17B).** Cluster F rests on one unexamined instrument: whether the agent's **answers** look right is used as a proxy for whether its **memory** got it right. **FEB-30** (`arXiv:2610.22209`, submitted **2026-10-15**; Sebastian-Antonio Toma / Jean de Kernier / Mike Ply / Oliviu Matei; 14 pages; code and data released at `github.com/amazon-science/feb-30-benchmark`) names and measures the flaw: the paradigm "**conflates memory correctness with retrieval and generation quality**", producing **false positives where a correct response masks broken memory** and **false negatives where an incorrect response blames correct memory for a retrieval failure**. Construction is instructive on its own — **paradigm inversion**: documents are *generated from known fact trajectories*, so ground truth is deterministic and needs **no human annotation**; each of **30 fact-evolution trajectories** (6 diagnostic categories × 3 difficulty levels) says how a fact *should* evolve across multi-author artifacts (documents, emails, conversations), which allows **direct inspection of the memory store after each ingestion step**. Applying it to a representative memory system: **intrinsic and extrinsic evaluation diverge by an average of 16 percentage points**, with **44% of trajectories exceeding meaningful divergence thresholds**; and diagnostic decomposition finds the system **classifies memory operations (create · update · reinforce · supersede) correctly only 20% of the time** — a failure "**entirely invisible to extrinsic evaluation**", with failure modes differing systematically by category and difficulty. Why this is a seam rather than a new topic: the operation taxonomy is almost the same one [[MemoryGovernance]] already uses (its four measured actions are Capture / Update / Recall / QA, and the learned-policy branch puts **ADD · UPDATE · DELETE · NOOP** into the action space) — so today supplies, for the first time, an instrument that **scores those decisions directly** instead of inferring them from answer quality. It therefore bears on the wiki's own evidence hygiene at three points: [[DyadMem]]'s four-stage gold annotations and its headline *Gold-Memory strong / Full-Pipeline collapses* finding are both measured downstream; `overview.md`'s standing open question that **Cluster F's entire evidence base is author-reported and needs independent reproduction** gets a sharper form — reproduce not only the numbers but **whether the metric can see the failure at all**; and it ports the existing 10-08 thread "**评测的评测**" (`arXiv:2610.07274`: only 22.6% of recorded passes clear four checks) from agent *scores* to **memory operations**, the same move one layer down. **(3) NEW 以协调基质为中心 —— 可引用消息取代直接通信 / Substrate-Centric Coordination (ScaleMAS) (ledger row 10-17C; not ⭐).** Yesterday's `MultiAgent.md` revision supplied CVE-grade evidence **that** cross-contamination happens but no candidate **shape** that prevents it. **ScaleMAS** (`arXiv:2610.16120`, submitted **2026-10-12**; Zhenting Qi (Harvard) with Zhuokai Zhao, Rulin Shao, Kerem Oktar, Zhiyuan Yao, Himabindu Lakkaraju, Wen-tau Yih, Ansong Ni, Bhargavi Paranjape, Yilun Du — **FAIR at Meta + Harvard**) names three problems that grow with group size and diagnoses all three as artifacts of **agent-centric** design: **reading burden** grows with the group (message-passing delivers every sender's output; coordinator systems route every result into one context), **useful information is diluted** by shared work of unknown quality, and **failure becomes routine** (a lost agent can crash the whole run). Its note on the intermediate generation of designs is the useful part for this wiki: recent **blackboard-style** methods move coordination into a shared medium and thereby relieve **only the third** problem. ScaleMAS makes the medium *addressable and citable* instead of merely shared: asynchronous agents operate on a shared datastore of linked messages through three operations — **publish** (with optional *references to earlier messages it builds on*), **search** (top-k, ranked by relevance **and by how often the message is cited**, which the authors find to be an effective proxy for quality), and **visit** (by address).
