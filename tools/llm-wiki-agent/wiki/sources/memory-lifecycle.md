Its core move is to stop treating memory as *a store* and treat it as **four actions that each fail differently** — Capture → Update → Recall → QA — plus one governance question that every design must answer explicitly: **who decides what to write, when to retrieve, and when to delete.**

Its thesis sentence: a memory system with no owner does not stay ownerless — **the decision power flows to whoever wants to exploit it**. The page therefore runs a single spine from *hygiene* (the four actions and their benchmarks) through *decision rights* (human rules → trained policy → attacker) to *four governance bottom lines* (auditable / rollbackable / permissioned / signature-verified), at which point the reliability discipline and the security discipline **merge at the memory layer**.

## Key Claims
- **Memory is four actions, not one repository.** DyadMem splits long-term memory into **Capture** (write new memories from this session) → **Update** (reconcile with the existing bank) → **Recall** (select entries still valid) → **QA** (answer from evidence), and places **gold annotations at every stage** (3,065 episodes / 50,961 sessions / 61,210 QA, spanning 16 open-weight + 4 closed models). Why it matters: an end-to-end QA score **stirs four different qualities together** — a correct answer can come from a broken bank (lucky), and a wrong answer cannot be localised. *Only measuring them separately tells you what to repair.*
- **Every action has a quantified failure mode.** Capture: DyadMem measures **systematically low capture recall** for frontier models, plus incomplete recall and unsafe deletion; it also makes explicit **URAM** (same user, *different agents should remember different things*). Update: **Memora** (ACL 2026 Findings, arXiv:2604.20006, ASU/Genies/U. Arizona) introduces **FAMA**, a forgetting-aware metric that **penalises reliance on deleted or superseded memories** — four LLMs and six memory agents are found to “frequently reuse invalid memories and struggle to reconcile evolving memories”, with the memory module delivering only **marginal** gains; meanwhile **94% / 85%** of questions in pre-existing benchmarks span at most 2 sessions. Supporting evidence: **Memory Is a Derivation** (arXiv:2609.36130) audits compressed memories — restoring the fuller pre-write history recovers support for roughly **60%** of apparently unsupported memories, but **17–21% remain unsupported**, and **composed memories can assert relations history never established**. **MemoryAgentBench** (arXiv:2507.05257) lists **selective forgetting** alongside precise retrieval, test-time learning and long-range understanding as one of four memory capabilities; **PATH-Bench** (arXiv:2608.01149) defines **forward/backward forgetting transfer (FWT/BWT/FGT)** and concludes **“strong transfer does not guarantee retention.”** Net effect: **“failed to forget” becomes a deductible score, not rhetoric** (FAMA = recall score − stale-dependency penalty).
- **The load-bearing variable is *who decides*** — and there are exactly three classes of decider:
  | Decider | What gets written / retrieved / deleted | Representative evidence | Core weakness |
  |---|---|---|---|
  | **Human-written rules** (today's default) | Engineer hard-codes importance thresholds, TTL, extraction counts, similarity top-k | Layered memory (resident core + external retrieval + explicit forgetting policy) is the 2026 production form | Rules have no judgement about *what counts as stale*; every new domain needs re-tuning |
  | **Trained policy** (2026's new answer) | ADD / UPDATE / DELETE / NOOP are placed **in the action space** and trained jointly by RL on task-success reward | **Memory-R1** (arXiv:2508.19828, ACL 2026 main long paper `2026.acl-long.583`): dual-agent architecture, only **152 QA pairs** to train, **LoCoMo F1 +68.9% vs Mem0**; **ATMem** (arXiv:2606.31612): cost-aware memory reward + STR-GRPO, ATMem-UI-8B reaches **76.6% on AndroidWorld** vs UI-TARS-2-230B's **73.3%** at ≈**1/29** the parameters; same family — ICML arXiv:2609.17088, UI-Mem (arXiv:2602.05832), MemChain (arXiv:2607.24097), MMPO (arXiv:2605.30159) | **All six systems remain undeployed in production**; benchmarks exclude distribution shift and adversarial input; no single system yet owns write + retrieval + transformation |
  | **Attacker** (the decider nobody wants) | Write timing and content decided by the injector | **PMPA** (arXiv:2609.13889, Auckland/Fudan, 2026-09-12): malicious instructions embedded in *benign* sources induce harness agents to **write them into durable memory themselves** — OpenClaw ISR/C-ASR **73.7% / 55.5%**, **Claude Code 66.9% / 81.7%**, with **benign-task performance unchanged**; **Darktrace** (Eric Rozon, published 2026-09-24, disclosed 2026-08-18 to Anthropic/OpenAI/AWS): **all four harnesses (Claude Code / Codex / Kiro-CLI / Pi) accept forged conversation history**; under Kiro-CLI the attack reaches **Active Directory domain takeover** | **The fix sits on the vendor side** (message signing + server-side validation) ⇒ the defending operator **cannot deploy it** |
- **Durable state is the difference between a session and a system.** Memory has a property a single-turn conversation does not: **errors compound**. A wrong answer this turn is forgotten next window; a wrong memory becomes a *fixed input to every future plan*. The page's sharpest inversion: the danger is not that the agent forgets — it is that it confidently treats a **three-month-superseded fact as current**.
- **Four governance bottom lines: auditable · rollbackable · permissioned · signature-verified.** Every write / supersede / delete should be as traceable as a git commit (who, when, on what source — the entry discipline of [[Provenance]]); deletion must be a real, recorded, provable operation with a rollback path, not an invisible manual sweep; **who may write to shared memory** must be managed as explicitly as database permissions; and against the Darktrace class the only root fix is **cryptographically signed model replies validated server-side on every turn** — until then the local session-history store must be treated as a **security-sensitive file**, and *any write to it by a non-harness process is an unambiguous attack signal*.
- **Where this page draws its boundaries.** ① **Not “a bigger context window”** — window is capacity, governance is structure and discipline; DyadMem's own numbers are the counter-evidence (Gold-Memory strong ⇒ **Full-Pipeline collapse**) ⇒ *the bottleneck is not whether it fits, but the quality of the four actions.* ② **Not [[Compaction]]** — compaction governs how **this turn's** in-window history is cut; this page governs how the **out-of-window** bank across sessions is written, revised and deleted (adjacent, and anything compaction drops that still matters should land in long-term memory rather than evaporate). ③ **Not a duplicate of [[Provenance]] / [[CitationLock]] / [[Abstention]]** — those govern the **entry and exit discipline** (writes carry origin; cite only what was opened; abstain without sourced evidence); this page governs **the whole lifecycle in between** — update, forgetting, and decision-rights. *A clean entry does not imply a clean lifecycle:* PMPA's payload arrives **inside a benign document that carries legitimate provenance**.
- **Forgetting is a capability, not a failure.** FAMA counts “reusing deleted information” as a deduction; a system that never forgets scores perfectly on old recall-only benchmarks and is a disaster area on governance benchmarks. Symmetrically, **unsafe deletion** (removing a fact still under reference) must also be measured — DyadMem quantifies **both ends**.

## Key Quotes
> “智能体记忆的治理,是把记忆从"一个只会增长的档案库"改造成"一套有人拍板、可审计、可遗忘的决策系统"。”

> “记忆不是一个仓库,而是四个会各自出错的动作(写/改/取/删)加上一个必须有人回答的问题——**这些决定由谁做**;治理就是让每个动作可审计、可回滚、有主人,因为放任不管的时候,决定权不会空缺,它会流向想利用你的人。”

> “前两行是工程选型问题,第三行是安全底线——**如果记忆没有主人,主人位置不会空缺**。”

> “不是模型不会用记忆,是"记忆的四个动作"各自都有洞。”
