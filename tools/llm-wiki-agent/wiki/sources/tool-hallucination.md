## Summary
A concept-learning HTML document (7-section format) generated by the silent-madman concept-explainer skill on 2026-09-22 — the third of three "actor-side" materials. Defines **tool hallucination** as an agent invoking a tool that does not exist in the registry, or passing arguments no schema ever declared — and argues that because such a call is **structurally not a decision any gate ever made**, it must be caught by a closed-world resolution step placed **before** every permission gate. Primary source: arXiv:2609.19425v1 (2026-09-16).

## Key Claims
- **Tool hallucination ≠ tool selection.** Tool selection asks *which of the real tools should I use*; tool hallucination asks *does the tool I just named exist at all*. Selection methods all presuppose "the call targets a real tool", which is precisely the premise hallucination breaks.
- **Permission gates cannot catch it — structurally, not for lack of rigour.** A gate's judgement domain is *the set of tools it exposed*. A hallucinated tool name is by definition outside that set, so the call never becomes a gate decision and the gate never gets the chance to refuse it. **The failure is a structural blind spot, not a tuning problem.**
- **The fix is a dumb, early fact-check: a Resolution Rung.** Before dispatching any call, two training-free checks: ① is the tool name a member of a **closed registry**; ② does its contract signature match the trusted source. Only then do permission gates, least privilege and audit run. The paper's framing is that its value is **in its position, not its algorithm** — it must sit upstream of every causal gate.
- **Measured, not hypothetical: 322 real hallucinations** captured across **10 hosted models** and **two invocation surfaces**; **154** further hallucinations on a real MCP surface after tools were merged.
- **Scale does not buy immunity — the most counter-intuitive finding.** A **675B**-parameter model behaves comparably to a **7–8B** model on this failure. "The next bigger model will grow out of it" is not a viable roadmap; the correct move is an architectural fact-check layer, not another model upgrade.
- **Interface freedom amplifies the hallucination space.** Fabricated tool names concentrate on the most permissive invocation surface (free-form JSON parsed as a tool call) versus a schema-constrained one. Constraining the surface **lowers probability but does not reach zero** — so constraint and the upstream rung are both required.
- **Merging MCP servers *adds* a new hallucination surface.** When several MCP servers are combined into one namespace, new failures appear that no single registry can express: name **collision** and **shadowing**. This is **structural, not linear in tool count** — the act of merging creates it, including for frontier models that were clean on the single-registry surface. Practical consequence: treat a namespace merge as a **review-worthy change**, not a config detail.
- **A residual that cannot be eliminated.** "Borrowed parameters" — arguments that are schema-indistinguishable from legitimate calls — are explicitly described as the irreducible remainder. This is why the rung is necessary even after the surface is tightened.
- **One hallucinated call is not a harmless parse error.** Malformed JSON gets rejected by a parser at the cost of a retry; a *syntactically valid* call to a non-existent tool passes every format check. For an agent that can act, that is an **unbounded action**, not a formatting mistake.
- **Release artifact:** a versioned benchmark, **HTB**, accompanies the paper.

## Key Quotes
> "工具幻觉，是指 agent 调用了注册表里根本不存在的工具，或给真实工具传了任何 schema 都没声明过的参数；而因为这种调用在构造上不是任何门做过的决策，所以必须在所有权限门控之前先做一次「注册表成员资格 + 签名」的封闭世界消解。"

> "门控只能管住「你敢不敢用我放出来的工具」，管不住「你编了一个我从来没放出来的工具」—— 所以在所有门之前，必须先有一道很笨但很靠前的事实核对。"

> "论文把它称作 Resolution Rung（消解阶），并强调它的价值不在算法而在位置：它只能装在最上游，必须早于任何权限门控。"
