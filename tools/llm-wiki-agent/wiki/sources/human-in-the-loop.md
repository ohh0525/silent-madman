## Summary
A concept-learning HTML document (7-section format) generated by the silent-madman concept-explainer skill on 2026-09-22 — the second of three "actor-side" materials. Defines the human-in-the-loop approval gate as the practice of grading an agent's actions by **impact × reversibility** and inserting a code-resident, auditable, timeout-aware checkpoint *before* irreversible or consequential write actions. Names the rule the field is converging on: **"read freely, keep writes human"** (读放开，写留人).

## Key Claims
- **Grade the actions first, or the gate becomes theatre.** Every action is sorted by impact × reversibility and assigned a supervision mode — human-in-the-loop (approve first) / human-on-the-loop (may veto) / fully automatic (sampled afterwards). Forcing human review onto high-frequency low-impact actions produces a **rubber stamp**: latency and cost go up, risk does not go down.
- **"Propose" and "execute the side effect" must be two paths.** The model produces a proposal; a *different* execution path actually invokes the side-effecting tool, and that path must pass through the gate. If the model can still call the side-effecting tool directly, any gate is decoration — it can be bypassed or simply never consulted.
- **The gate's decision must be deterministic and live in code/config, not the prompt.** Action class, amount/quantity thresholds, confidence, input novelty. As the material puts it: a threshold that lives only in a policy document and is not embedded in the execution path **is not a threshold** — a prompt-resident rule can be ignored, overridden, or talked around.
- **A pause must be resumable by another process, and must be measured.** A review may take seconds, hours or days; the process that resumes need not be the one that paused it — so the full workflow state must be **persisted before pausing**, and the post-approval action must be **idempotent** (a retry must not double-pay or double-send). Effectiveness is measured with **automation rate / override rate / escape rate (should have escalated but didn't) / review latency**. Without measurement, gates rot: high false-positive rates make teams stop responding; high escape rates mean you have no gate.
- **"Read freely, keep writes human" is the operating rule.** Let the agent read, search, summarize and draft without friction — a bad summary is cheap and discoverable. Anything that *sends / pays / submits / deletes / mutates a system of record* goes through a checkpoint. The agent still absorbs ~95% of the work; the human spends seconds on the one irreversible move.
- **The gate must carry a decision payload, not a dialog box.** The reviewer needs the inputs the agent saw, the action it intends, and its reasoning, beside three controls — approve / reject / modify-and-execute. If approving requires opening three other systems to check, the gate is in the wrong place and will produce blind "approve" clicks.
- **Explicitly NOT a model self-restraint mechanism.** The material draws a boundary that matters for this wiki: mechanisms like *refuse-when-evidence-is-insufficient* ([[Abstention]]) and *cite-only-what-you-opened* ([[CitationLock]]) have **the model itself** as their subject, and govern **saying**. An approval gate has **the system and the human** as its subject, and governs **writing / paying / deleting**. One is an honesty mechanism, one is a control mechanism — two different layers, both required.
- **Not a sandbox either.** A sandbox constrains *what the agent can reach* (capability boundary, physical isolation); a gate constrains *whether to ask a human before reaching* (decision boundary, process control).
- **Calibration is a loop, not a setting.** Start conservative, run, then split escalations into "the team actually changed something" vs "it was waved through" and raise the threshold on the most-misfiring rule; separately lower the threshold on any class that *should* have escalated but didn't. Repeat. Every escalate-rule needs its own review cadence, because business drift invalidates rules.

## Key Quotes
> "人在环审批闸门，是把 agent 的动作按「影响大小 × 可逆程度」分级，在不可逆或有后果的写动作之前插入一个写在代码里、可审计、可超时的检查点，等人批准之后才允许执行。"

> "一条只写在政策文档、没有嵌进系统实际执行路径的阈值，不算阈值。"

> "审批闸门不是让 agent 变慢，而是把「不可逆的那一下」从模型手里收回来 —— 读让它放开做，写留给人点头，并且这条规则必须写在代码里、能被度量、能被另一个进程接起来。"
