## Summary
A concept-learning HTML document (7-section format) generated by the silent-madman concept-explainer skill on 2026-09-26, from the same day's concept-radar ⭐ first pick. Defines the **agent harness** as the engineering shell that turns "one model call" into "an agent that gets work done": assembling prompts, retrieving and injecting tool definitions, executing tools, deciding what to drop when the window fills, resuming after crashes, scheduling subagents — i.e. `Agent = Model + Harness`. Its news hook: in September 2026 this shell went from "every team writes its own" to a product sold by both head vendors (OpenAI Agents API public beta on the Codex harness, 2026-09-10; Anthropic Opus 5.5 "managed orchestration"; Agent Brief's "Harness Wars" issue, 2026-09-25).

## Key Claims
- **`Agent = Model + Harness`.** The [[Agent]] page describes the loop's *semantics* (reason → choose tool → execute → observe); the harness is that loop's *implementation* — who assembles the prompt, who manages the tool table, who runs compaction, who handles recovery. The wiki's mechanism pages are **parts inside this shell**.
- **Four duties per loop, missing any one degrades "works" to "demo":** ① assemble context (system prompt + tool definitions; modern harnesses use **tool search** — retrieve tool schemas on demand instead of injecting all of them every turn); ② run the loop and judge stopping (no stop condition = an infinitely expensive loop); ③ govern the window (**automatic compaction** near the limit lets a task span multiple windows); ④ resilience & scale (session keep-alive, crash recovery, subagent scheduling via a flag + `max_concurrent_subagents`).
- **OpenAI Agents API (public beta 2026-09-10) rents out the Codex harness:** objects `Agent` (model/instructions/tools/MCP servers) + `Environment` (three-way choice: `openai_hosted` / `self_hosted` / `none`) + persistent `Session`. With no environment there is no sandbox, no Bash, no workspace files — yet the harness still runs the model and calls remote [[MCP]] tools. Hosted sandbox partners: 9 vendors (Blaxel, Cloudflare, Daytona, DigitalOcean, E2B, Modal, Oracle, Runloop, Vercel); `/workspace/outputs` auto-published as artifacts.
- **The three headline features are pre-existing wiki concepts** — automatic compaction ([[Compaction]]), tool search, multi-agent — evidence that the user's library held the *parts* and lacked the *container*.
- **⚠️ Managed defaults are the security boundary, and they are permissive:** egress `network.access` defaults to `enabled`; `restricted` accepts only 1–100 **exact** hostnames (no wildcards, protocols, paths, ports; subdomains and redirect targets must be listed individually); "agent-generated code can access whatever files, credentials and network its environment can reach" — injected secrets remain exposed, use a vault. Same-week Codex sandbox escapes (**Heapjack / Overpatch**, patched in Desktop build 26.818.21641 and CLI 0.149.0) show managed harnesses **centralise patch responsibility rather than remove sandbox risk**.
- **"Harness Wars" framing (Agent Brief 2026-09-25):** "orchestration is becoming managed infrastructure". Anthropic's Opus 5.5 line ($4/$20 per Mtok, cached reads −60% to $0.20) plus builder sentiment ("stop over-engineering, let the model orchestrate itself — Opus orchestrating Opus is cheap and good enough") challenges multi-model routing complexity.
- **Vendor self-reported numbers must be discounted:** latency ~¼, per-task cost −60%, failed responses −86%, one customer's eval 0.71 → 0.85 — all OpenAI/design-partner self-reports, not independent benchmarks. **Documented defaults are citable; self-reported performance is not.**
- **Skills are becoming the harness ecosystem's packaging format** (same issue): Claude Skills public library 372 skills / 20 domains; 216 single-file zero-dependency skills following the Agent Skills open standard (cross Claude Code / Codex CLI / Gemini CLI / Cursor); Azure Agent Skills 193 / 19 categories. Connects directly to [[Skill]].
- **Boundary vs sandbox:** the harness decides **who orchestrates**; the sandbox decides **where it runs and what it can touch**. OpenAI makes the split explicit (Agent vs Environment objects) — the two should be decided separately, and the wiki's action-side chain still lacks its `execute` (sandbox) page.
