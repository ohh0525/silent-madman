## Summary
A concept-learning HTML document (7-section format) generated by the silent-madman concept-explainer skill on 2026-09-26, from the same day's concept-radar third pick — the only genuinely **new** candidate of that batch and the wiki's first coverage of anything *between* agents. Defines multi-agent orchestration as multiple agents with independent context windows working on one goal, exchanging **verified** partial results and failure paths through a shared workspace — beating best-of-k independent sampling at equal-or-less compute, **provided a verifier exists**. The material's teaching spine is the counter-result: *fails without verifier or low compute* — communication needs verifiable progress as its anchor, otherwise the shared workspace degrades into cross-contamination.

## Key Claims
- **team@k vs best@k (the headline result).** k *communicating* agents vs the best of k *independent* samples. **ARC-AGI-3**: team@3 matches best@13, team@5 matches best@33 (≈4.3× / 6.6× equivalent independent compute). **LP85**: 64 independent attempts all failed; team@5 solved 65%. **FT09**: team@3 ≈ 26% → 90%. **polyomino packing**: team@3 set SOTA 0.945 (prev 0.894). **MNIST compression**: a 4-agent team produced a 1,957-byte classifier at 99.4% accuracy — 20% smaller than the human best.
- **The mechanism is verified-progress sharing, not roles.** No preset roles, no central orchestrator; k agents with the same goal and compute budget exchange partial results, failure paths and code through a shared workspace. The gain comes entirely from **building on confirmed breakthroughs** — and from not re-walking confirmed dead ends.
- **⚠️ The counter-result is the point:** the method "**fails without verifier or low compute**". With no cheap way to judge whose progress is real, or when compute is too tight to wait for verification, communication overhead exceeds its gains and **independent agents do better**. "Should I go multi-agent" is therefore an engineering predicate: *first ask whether the task has a verifier.*
- **New failure surface: cross-contamination (互相污染).** An unverified conclusion from one agent can be inherited as a premise by the others — a failure mode that does not exist in the single-agent world and that lands exactly on [[Provenance]]'s extension line: in a team, trust must cover not just fact origin but the **verification status of peers' conclusions**. Shared memory should be treated as inspectable working context, not a source of truth.
- **Productised: Claude Code Projects (beta 2026-09-17).** One coordinator session splits a goal into parallel threads; each thread is a full independent cloud Claude Code session with its own branch and repo copy, able to run tests, open PRs and spawn its own subagents; threads share project memory and a corpus; overlapping edits are handled as **ordinary merge conflicts, not silent merges**. Honest self-declared limits: threads **each consume subscription quota** (parallelism is not free); launch-phase threads run **only on Anthropic's cloud**; shared memory is "inspectable working context, not authoritative source of truth"; **CI / tests / human review remain the integration boundary** even when the coordinator reports all threads complete. Coordinator runs Opus high-effort; <200 threads/day no fixed cap; concurrency preferences are preferences, not enforcement.
- **Decentralised scale: Agensh (Microsoft Research, Furu Wei team).** Removes the central-orchestrator bottleneck via shared workspace + message interface + shared context of reusable discoveries; scaled 1 → **1,024 agents** on pandoc, pass rate 33.89% → 55.06%; ProgramBench hardest five 19.31% → 28.78% (1 → 128 agents). Secondhand figures — direction and magnitude only.
- **Boundaries:** vs subagents (peer team vs threads *inside* one agent — Claude Projects nests both); vs shared memory (space dimension vs time dimension); vs [[ContextEngineering]] (what to exchange *between* windows vs what to place *within* one); multi-agent is a **productised harness capability** (OpenAI: a flag + `max_concurrent_subagents`) but as a concept has its own trade-off logic.

## Key Quotes
> "k 个通气的 agent 能追平几十个单干的——但「通气」只在有验证器时才值钱:先找到便宜的判定对错的方法,再组队;没有它,共享白板就是谣言板。"

> "收益全部来自「建立在别人已确认的进展之上」——这不是分工(没有预设角色),也不是中央调度(没有指挥官),就是一张共享的白板。"

> "一个人的错误结论被其他人当作已验证的前提继承下去。这就是多智能体独有的新失效面:互相污染。"
