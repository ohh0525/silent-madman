## Summary
A digest of the MCP 2026-07-28 specification revision — described as the largest revision of the Model Context Protocol since launch. MCP transforms from a bidirectional stateful protocol into a request/response **stateless** protocol: the `initialize`/`initialized` handshake and the `Mcp-Session-Id` header are removed, and protocol version, client identity, and capabilities travel in `_meta` on every request. Compiled 2026-09-16 from the official spec blog, official architecture docs, AWS, GitHub's changelog, and the Agentic AI Foundation roundup.

## Key Claims
- **SEP-2575** removes the handshake; **SEP-2567** removes the session ID header. Any request can now land on any server instance behind a plain round-robin load balancer — no sticky sessions, no shared session store.
- A new optional **`server/discover`** RPC lets clients fetch server capabilities up front; it is not required, because each request is self-describing.
- **Stateless protocol ≠ stateless application**: servers mint an explicit handle (`basket_id`, `browser_id`, `workflow_run_id`) and the model threads it back as an ordinary argument. Maintainers argue this is often *more powerful* than hidden session state, because the handle becomes a value the model can see and compose.
- **MRTR (Multi Round-Trip Requests, SEP-2322)** replaces held-open SSE streams: server returns `resultType: "input_required"` + `requestState`; the client retries the original call with `inputResponses`.
- **`Mcp-Method` and `Mcp-Name` headers are now required** (SEP-2243) so gateways/rate-limiters/WAFs route and meter without parsing JSON bodies.
- **List results are cacheable** (SEP-2549): `tools/list`, `prompts/list`, `resources/list`, `resources/read` carry `ttlMs` + `cacheScope`.
- **Authorization hardening**: RFC 9207 issuer validation; formal shift from Dynamic Client Registration (DCR) toward Client ID Metadata Documents (CIMD).
- **Extensions become first-class**: Tasks (long-running ops, moved out of the base protocol) joins MCP Apps and Enterprise Managed Authorization (EMA).
- **Sampling, Roots, and Logging are deprecated** (12-month minimum window). New implementations should call LLM provider APIs directly and log to stderr / OpenTelemetry.
- Full **JSON Schema 2020-12** for tools; **W3C Trace Context** propagation in `_meta`.
- **Backward compatibility**: major SDKs (TS, Python, Go, C#; Rust beta) preserve old-spec compatibility, so existing connections need no immediate migration — but new-revision servers may need a compatibility layer for old clients.

## Key Quotes
> "The highlight of this release is a stateless protocol core — MCP is transforming from a bidirectional stateful protocol into a request/response stateless protocol." — official release post
> "The initialize/initialized handshake is removed (SEP-2575)... The Mcp-Session-Id header and the protocol-level session... are also removed (SEP-2567)." — official release candidate post
> "Removing the protocol-level session does not mean your application has to be stateless." — official spec blog
