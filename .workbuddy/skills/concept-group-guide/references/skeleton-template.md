# 概念组骨架模板

> 用法：照抄本模板生成 `concept-group/<group-slug>/00-骨架.md`，逐项填满。
> **6 项内容一项都不能少。** 填完**直接进 Phase 2，不要停下等确认**。
> 默认（`auto`）在文件顶部加一行：`> ⚠️ 未确认骨架（自动模式）：以下为模型假设`。
> 仅当用户显式要求 `skeleton_review` 时，才停在此处交用户确认。

---

```markdown
# <组名> · 概念组骨架

> 本文件是「一组相关概念」的定义文件。它先定关系，再定内容 —— 后续每份学习材料都以本文件的边界声明与术语表为准。
>
> 生成于 <日期> ｜ 概念数 <N> ｜ 目标读者 <audience_level>

---

## 1. 组定位

- **这一组在解决什么问题**：<一句话>
- **目标读者**：<谁，已具备什么基础>
- **学完之后的收益**：<能做什么 / 能回答什么问题>

---

## 2. 概念清单

| # | 概念（中/英） | 一句话定义 | 在本组中的角色 | 先修（本组内） |
|---|---|---|---|---|
| 1 | | | | — |
| 2 | | | | #1 |
| 3 | | | | #1 |

> 「角色」写这个概念在整组里承担什么：是基础概念、还是上层应用、还是把前几个串起来的那根线。

---

## 3. 边界声明（最关键）

> 每个概念都必须有 in-scope / out-of-scope；**每条 out-of-scope 都要点名归到哪个概念**。
> 这是防重复的唯一可靠手段 —— 写得含糊，后面必然出现两份材料讲同一件事。

### 3.1 <概念 1>

- **in-scope**：<本概念负责讲透什么，2–4 条>
- **out-of-scope**：
  - <不讲什么> → 归 **<概念 X>**
  - <不讲什么> → 归 **<概念 Y>**

### 3.2 <概念 2>

- **in-scope**：
- **out-of-scope**：
  - → 归 ___

（依此类推，每个概念一节）

---

## 4. 先修顺序

> 对概念清单做拓扑排序。顺序错了，读者会在第 1 份材料里就撞见还没讲的概念。

| 顺序 | 概念 | 为什么排在这里（一句话） |
|---|---|---|
| 1 | | 不依赖组内任何概念 |
| 2 | | 需要先懂 ___ |
| 3 | | 需要先懂 ___ |

**学习路径一句话**：___ → ___ → ___ → ___

---

## 5. 共享术语表

> 统一措辞，防止各份材料自造词。Phase 2 生成时必须严格使用本表。

| 中文 | 英文 | 本组内统一含义 | 不要写成 |
|---|---|---|---|
| | | | |
| | | | |

---

## 6. 冲突检查

> 显式列出"两两之间可能重叠的点"及归属裁决。宁可写得啰嗦，也不要留模糊地带。

| 可能重叠的点 | 涉及概念 | 裁决 |
|---|---|---|
| | A vs B | 归 A，B 里只留一句指向 A 的引用 |
| | B vs C | 两边都不展开，单独放进 __ C |

**未裁决项**：<若有，明确写出"以下留待人工裁决">；若无，写「无」。
```
