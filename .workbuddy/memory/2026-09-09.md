## GitHub Agentic Workflow 安装

### 用户意图
- 用户问 "github agent" 指什么 → 经过 4 选 1 问询,选定 **B:在 silent-madman 里加一个 GitHub Agentic Workflow(.md + lock.yml + .gitattributes)** 作为学习资料
- 跟上一次装 `tools/llm-wiki-agent` 思路一致:把"概念学习主题"扩展到生产级实例

### 关键调研
- **GitHub Agentic Workflows(gh-aw)** 是 GitHub 官方 2026-02 技术预览、2026-06 公开预览的特性
- 仓库: [`github/gh-aw`](https://github.com/github/gh-aw)(Go 实现的 `gh` CLI 扩展)
- 范式: 在 `.github/workflows/<name>.md` 写 Markdown + YAML frontmatter → `gh aw compile` 生成 `<name>.lock.yml` → GitHub Actions 直接跑
- **lock.yml 是 gh-aw 的编译产物,包含 SHA-pin 的 actions、allowedDomains 网络白名单、cache-memory git 仓库、telemetry OTEL 配置、safe-outputs 校验脚本等**;手写几乎一定出错

### 装了哪些文件
| 文件 | 大小 | 用途 |
|---|---|---|
| `.github/workflows/agent-triage-issue.md` | ~3.8 KB | workflow 源文件: 新 issue 触发 → Copilot 读标题+描述 → 建议 5 个内置标签之一 + 评论解释 |
| `.gitattributes` | ~250 B | 标记 `*.lock.yml linguist-generated=true`(lock.yml 是 gh-aw 编译产物,不计入语言统计、也不该手改) |
| `README.md`(修改) | +10 / -5 行 | 目录结构图加 `.github/workflows/` 节点;最后更新日期同步 |
| `concept-relationship.md`(修改) | +24 行 | 新增 "延伸案例:GitHub Agentic Workflow" 章节,把 Agent/上下文/Skill 三者映射到 gh-aw 的对应物 |

### 没做什么(及原因)
- ❌ **没写 `agent-triage-issue.lock.yml`** —— 因为 lock.yml 涉及 SHA-pin 哈希、cache-memory、telemetry、allowedDomains 网络白名单等 gh-aw 编译期决定的字段,手写会出错;按 create.md 官方推荐,留给用户本地 `gh aw compile` 生成
- ❌ **没在沙盒里跑 gh-aw CLI** —— 沙盒没有 `gh` CLI + UAC 无法响应 + 用户偏好"系统级动作用户本地执行"
- ❌ **没 push 到 GitHub** —— 同上,git push 留给用户

### 用户本地需要做的事(下一步)
1. 在 silent-madman 仓库根目录跑一次:
   ```bash
   gh extension install github/gh-aw
   gh aw compile agent-triage-issue
   ```
   这会生成 `.github/workflows/agent-triage-issue.lock.yml`
2. 检查 lock.yml 是否合规(可选): `gh aw compile --validate agent-triage-issue`
3. 把 `.github/` 和 `.gitattributes` 一起 push 到 GitHub:
   ```bash
   git add .github/ .gitattributes
   git commit -m "Add GitHub Agentic Workflow (compile lock.yml locally)"
   git push origin main
   ```
4. Push 后在 GitHub 上 Settings → Actions → General 确认 Copilot 已启用(否则 agent job 跑不起来)
5. 开一个测试 issue 验证 workflow 触发

### 启示/经验
- **GitHub Agentic Workflows 完美契合 silent-madman 的"Agent 概念学习"主题** —— 它是 Agent/上下文/Skill 三者在生产级平台的实例化
- **"装上 GitHub Agent"** 在 2026 年的最实用路径是 gh-aw(而非 Copilot Coding Agent),因为不需要付费 Copilot 订阅就能用,只需 `gh aw compile` 走标准 GitHub Actions
- **`safe-outputs` 是 gh-aw 最有价值的设计** —— 把 agent 的副作用限定在白名单里(标签、评论),而不是给它 GITHUB_TOKEN 全权限,这个安全模式值得记住
- **手写 lock.yml 不可行** —— 涉及 SHA-pin / 哈希 / 编译期元数据,必须由 gh-aw CLI 生成
