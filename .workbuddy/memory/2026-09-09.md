## LLM Wiki Ingest: 3 份概念学习 HTML 入 wiki(本会话)

### 触发
- 用户要求"将仓库中的概念学习 HTML 加入到 llm wiki 中"
- 沙盒内无 Claude Code CLI(LLM Wiki 的"宿主 agent"),WorkBuddy 自己模拟执行完整 ingest 工作流(基于 `CLAUDE.md` 定义的 10 步流程)

### 工作流(基于 CLAUDE.md § Ingest Workflow)
1. 复制 3 份 HTML 到 `raw/learning-materials/`(保留不可变原始资料)
2. 写 `wiki/sources/{agent,llm-context,skill}.md`(Source Page Format: frontmatter + Summary/Key Claims/Key Quotes/Connections/Contradictions)
3. 更新 `wiki/index.md`(添加 3 个 sources + 4 entities + 9 concepts 条目)
4. 更新 `wiki/overview.md`(新增 synthesis + ASCII 闭环图)
5. 创建 entity 页 4 个(Anthropic / OpenAI / SourceScore / BaiduBaike)
6. 创建 concept 页 9 个(Agent / LLMContext / ContextWindow / Skill / ProgressiveDisclosure / Token / ReAct / MCP / Transformer)
7. 追加 `wiki/log.md` 3 条 ingest 记录

### 产出统计
- 3 份 HTML 原始资料(11.9 KB / 16.1 KB / 17.2 KB)
- 16 个 wiki 文件(3 sources + 9 concepts + 4 entities + index/overview/log)
- 0 矛盾被检测到(三份资料互相一致)

### 关键设计选择
- 概念页用 `[[Wikilink]]` 互相串联,体现 LLM Wiki "互联知识图" 的核心
- `ContextWindow` 作为 `LLMContext` 的英文名 redirect 页(满足搜索/链接的双向可达)
- overview.md 包含 ASCII 闭环图,可视化三核心(Agent / LLMContext / Skill)的反馈循环
- 所有 entity/concept 页 frontmatter 的 `sources` 字段精确列出引用过的源 slug

### 启示/经验
- LLM Wiki Agent 的 CLAUDE.md 设计优秀:10 步流程 + Source Page Format + 前置 frontmatter,即使没有 Claude Code,只要按定义执行也能产出合规 wiki
- 跨源资料消化(silent-madman 三份 HTML → wiki 互联图)的难度低于预期,因为 concept-explainer 的 7 段结构本身就是"摘要友好"的
- 沙盒无 markitdown / Claude Code 时,WorkBuddy 直接读 HTML 内容并按 Source Page Format 重写为 markdown 是可行的替代方案
