## 二、概念雷达（阶段二：发掘当下最有价值的概念）

### 候选 1 ⭐（新行）｜ 观察的时效性与再验证 / **Observation Staleness & Re-validation**（别名：Context Coherence / 观察漂移）

**为什么「当下」最有价值 —— 缝在哪（一句话）**
wiki 的 [[Provenance]] 管「**写进来时有没有来源**」、[[MemoryGovernance]] 管「**谁有权增删它**」、[[ContextRot]] 管「**上下文一多就变糊**」——**但没有任何一页管「这条观察在取用那一刻还是真的吗」**：它写进来时**确实有来源、确实为真**，是**世界在它背后动了**（用户改了文件、别的 agent 改了仓库、外部工具改了数据源）。这是记忆簇的**读侧 / 现在时**那半张图，与 10-09 第五扫描线「**这个东西活多久？谁以为它活多久？**」正面对齐。

**一句话定义**
> **观察的时效性 = 一条曾被正确取用的观察，其有效性相对"活的源头"随时间的衰减；再验证 = 在复用它之前，先拿它与当前源状态对账。**

**边界辨析（与已覆盖概念划清）**
| 对比页 | 它管什么 | 本候选管什么（差异） |
|---|---|---|
| [[Provenance]] | **入口**：事实带来源 + 时间 + 证据 | **当下**：入口干净**不蕴含**取用时仍真（10-09 已立「入口干净 ≠ 生命周期干净」，本条再推进一格：**生命周期干净 ≠ 当下仍真**） |
| [[MemoryGovernance]] | **生命周期**：谁决定 Capture/Update/Delete | **读前对账**：不改变「谁有权写」，而是「**复用前先验一次**」 |
| [[ContextRot]] | **量**效应：token 越多越糊 | **效度**效应：token 不多，但**已经过期**——两者症状像、根因不同 |

**2–4 条真实来源（均经 WebSearch 于 2026-10-10 返回；标 [verified]）**
1. **[verified]** *When Agent Context Goes Stale: Incoherence in Volatile Agent Context*（arXiv:2610.05281，2026-10-04 提交）—— https://arxiv.org/abs/2610.05281
   提出 **Concord** 上下文一致性框架：把每条工具观察**链接回它的源**、检测源变化、按可配置策略在复用前 **更新 / 注记 / 抑制** 过期上下文；自建 **ConcordBench**（先读文件、后续被编辑致其过期），三个前沿模型上答案与恢复后的工作区状态一致，**token 比最强非 oracle 基线少 46.4%**。
2. **[verified]** *MemTrace: State-Consistent Memory for Long-Horizon Coding Agents*（arXiv:2610.04838v1，2026-10-04 提交）—— https://arxiv.org/abs/2610.04838v1
   「provenance-aware memory」把历史存为不可变 **Memory Trace**（锚到文件/符号/测试），**恢复历史证据前先校验其相对当前仓库状态是否仍有效**；在 Codex CLI 下 DeepSWE pass@1 **+21.2**、SWE-EVO Resolved **+4.4**、SWE-Milestone **+17.8**。
3. **[verified]** *Whose Memory Is It? Scope-Aware Commit Rules for Long-Term LLM Memory*（arXiv:2610.09008，NeurIPS 2026 Workshop LP4FM Poster，2026-10-06 提交）—— https://arxiv-vanity.com/papers/2610.09008
   把问题命名为 **discourse ownership（话语权归属）**：一个**被考虑过又被否决**的计划 / **被模拟的工具结果** / **转述的他人信念**，若记忆只留结论句，它会**以事实身份回归**——「记录既不假也不无关，只是被**抽离了它成立时的语境**」。提出 **CASK** 提交规则：只让**共享世界的事实**进持久记忆，临时内容仅在其原作用域内可见。⚠️ 注：本篇同时是候选 2「承诺」与候选 1 的**共用接缝**（作用域 / 有效性边界）。
4. **[verified，二手级别]** *Agent Memory's Real Failure Is Currency, Not Retrieval*（DEV Community，博客）—— https://dev.to/madebyexpert/agent-memorys-real-failure-is-currency-not-retrieval-40h9
   给出可引用的判据句与一组**须标注为二手的**数字：**STALE 基准**上系统 **77%** 时候找回了更新后的事实，但只有 **~3%** 标记为「值得据此行动」；某前沿模型**被直接问**时 **92%** 能识别过期事实，而**当问题隐式依赖它时只剩 30%**。结论句：**「记忆坏，不是因为找不到，而是因为找到的那条已经不再为真」**——这是**状态管理**问题（有效性窗口 / 失效 / 缓存一致性），不是检索问题。
5. **[verified，二手级别]** *Context drift: when a multi-agent crew's shared beliefs about the goal go stale*（World Programming）—— https://www.worldprogramming.org/posts/context-drift-when-a-multi-agent-crews-shared-beliefs-about-the-goal-go-stale-ss7noc
   把同一失效搬到 [[MultiAgent]] 的共享工作区：每个 agent 手上那份目标**在被派发那一刻都完整且正确**，失效发生在**之后**——「别把目标钉成**不可变**，要钉成**可失效的**」；缓存管理需要**第四个动词：invalidate on external change**。⇒ 与候选 1 的 [[MemoryPoisoning]]/cross-contamination 是**同一形状再上一层**。

**建议的下一步**
- **值得生成 `learning-materials/<name>.html`（建议名 `observation-staleness.html`）**，骨架建议：**对象**（工具观察 / 文件内容 / 他人结论 / 被否决的计划）× **失效来源**（用户改 / 同伴改 / 外部工具改 / 计划被否）× **处置四选一**（更新 / 注记 / 抑制 / 拒绝复用）× **验收**（是否与当前源对账、token 代价）。
- 若暂不成文，**低成本替代**：在 [[LongTermMemory]] 增「读前再验证」一节 + 在 [[ContextRot]] 增「效度 vs 量」的边界注记 + 在 [[Provenance]] 增「来源 ≠ 当前有效性」一行。
- ⚠️ **证据等级如实标注**：第 1–3 条为一手 arXiv 摘要级（**PDF 未逐页打开**，与 10-09 的 LAM 条目同等级）；第 4–5 条为**二手博客**，其数字**未经独立复现**，只能作方向与判据句引用，不得当作可复现结论。

### 候选 2（承接强化 · 不新增行）｜ 持久化执行 / **Durable Execution**（= 09-23 行，积压 **17 天**）

**缝（一句话）**：[[AgentHarness]] 说循环**由谁跑**、[[AgentSandbox]] 说**在哪跑**——**但没有一页说「进程死了之后这个 run 还在不在」**；而 [[HumanInTheLoop]] 的验收标准（**pause must be persisted / resume idempotent**）正落在这张**不存在的页**上（命中 10-07 立起的优先级判据：某页验收标准落在另一页身上、而那一页不存在 ⇒ 最高优先级）。

**本日的「变化」是证据类别，不是热度**：首次出现**一手产品**把「持久化」与「外壳」明确拆成两个对象。
1. **[verified]** *What is a durable agent harness? Pi Durable, Pi 1.0 and the slot it takes in an agent stack* —— https://stackness.dev/blog/what-is-a-durable-agent-harness-pi-durable-pi-1-0-and-the-slot-it-takes-in-an-agent-stack
   **Pi Durable**（Earendil，**2026-10-01**，实验性）的判据句：**durable harness = 每一步在"执行/展示"之前先写入存储，于是新进程可以重开存储并从中途续上**；把「harness」定义为「**存储 + 并行跑多个会话所需的机械**」。三属性：**崩溃恢复 / 外壳独立于客户端 / 多客户端同看同管**。并给出与 **Temporal**（2026-08-20）、**Anthropic** Managed Agents（失败外壳可 `wake(sessionId)` 重启）的同族关系，以及一条**边界**：**Claude Code 的会话"持久化的是对话，不是文件系统"**。
2. **[verified]** *Pi 1.0: Codemode, Pi Durable and an open agent harness, explained* —— https://amargupta.tech/blog/pi-1-0-codemode-pi-durable-and-an-open-agent-harness-explained
   同日 **Pi 1.0** 发布：**Codemode**（模型**写脚本调 MCP 工具**，而非把全部 schema 塞进 prompt——官方称 **~40% 更少 prompt token**）、**deferred tool loading**、虚拟模型路由。⚠️ 厂商自报、**无基准底数**，只可作方向引用。
3. **[verified]** *Pi Durable extends a coding harness into long-running agent applications* —— https://reading-list.oddship.net/notes/2026-10-05-pi-durable-agent-harness
   把持久化 agent 工作**明确定义为「运行时 + 存储问题」**：transcripts / task state / execution environments / restart behavior / 多人协同 steer 都是**外壳的显式组成部分**；诚实标注：**实验性，两段演示视频未独立复核**。

**边界辨析**：与 [[Compaction]]（窗口内省 token）不同——**持久化的对象是 run 的状态与副作用，不是窗口**；与 [[MemoryGovernance]]（跨会话的**知识**）不同——**durable execution 管的是进程与副作用的 exactly-once**；与 [[AgentSandbox]]（在哪跑）互补——**沙箱管隔离，持久化管续命**。

**建议的下一步**
- 本行 **仍建议升格为 ⭐ 并优先成文**（该建议已连续挂起 **3 天**，见文末 📌）；`learning-materials/durable-execution.html`，骨架 = **三对象**（会话 / harness / 执行环境）× **四类恢复语义**（Temporal 事件重放 / DBOS 按位点采纳 / 框架超步检查点 / 线程快照）× **验收四问**（谁调度 / 中途崩溃后剩什么 / 存的是什么 / 能否多客户端）。

### 候选 3（承接强化 · 不新增行）｜ 智能体支付与商务层 / **Agentic Payments & Commerce**（= 10-08 行）

**缝（一句话）**：wiki 的行动链 `propose → resolve → authorize → gate → execute` **在 execute 处就断了**，**从没有人管"花多少"**；而 2026-10 出现了**「支付即凭据」**的部署形态——**agent 没有账号、没有 API key，付一次费换一次调用**，这正是 [[AgentIdentity]] 的「消费实例」与 [[HumanInTheLoop]] 闸门之外缺的**预算面**。

**本日新增的一手/准一手证据（均 [verified]）**
1. **[verified]** Pay.sh（**Solana Foundation × Google Cloud，2026-10-03**）—— https://cubed.run/blog/solana-google-cloud-pay-sh-stablecoin-micropayments-ai-agents
   **钱包即身份、支付即凭据**：开发者把 Solana 钱包接到 Gemini / Claude Code / Codex，**约 60 秒**完成接入；agent 按次发现→报价→授权→带付款凭证重试 HTTP；后端为 Google Cloud API（Gemini 推理 / BigQuery / Bigtable / Cloud Run）**按次计价**。判据句：**「用微授权（micro-entitlements）替代订阅授权」**。
2. **[verified]** Sui Agent Payments × Alibaba Cloud（Sui Basecamp，**2026-10-07**）—— https://www.coinlive.com/news/sui-agent-payments-expands-to-alibaba-cloud-allowing-ai-agents
   走 **x402**（HTTP 402）；**支出控制放在 owner 层**：可访问服务 / 总预算 / 单笔上限 / 过期时间，**链上强制执行、随时可撤销**；服务信息通过 **`SKILL.md` + JSON 端点**暴露 ⇒ 与本机环境「Skill 做打包格式」的做法**同形**。
3. **[verified]** x402 / ACP / AP2 三方对位（2026-10-07 更新）—— https://pondero.ai/agents/guides/x402-vs-acp-vs-ap2-agent-payment-protocols-october-2026
   分层清晰：**AP2 = 授权层**（Mandates 为可验证凭证，**不动钱**，2026-04-28 v0.2 捐给 **FIDO Alliance**）、**ACP = 商家结账层**（Stripe Shared Payment Token，**限定单一商家与单笔金额**）、**x402 = 结算层**（Coinbase，**2026-07-14 起由 Linux Foundation 治理，40 家成员**）。**诚实项**：ACP 的旗舰 ChatGPT Instant Checkout **已于 2026-03 下架**。
4. **[verified]** x402 使用量对位（截至 2026-10 初）—— https://cryptocoinshow.com/learn/ai-agents-and-crypto-payments
   **75.4M 笔 / $24.24M（30 天）⇒ 平均约 32¢**；而 **TRM Labs（2026-09）估：$52.7M 的 x402 结算里，真正由 AI agent 完成的只占 0.6%–7.5%** —— 本库「**已上架 ≠ 已使用**」纪律的又一记硬数字。

**边界辨析**：与 [[AgentIdentity]]——**每跳收窄的凭据 vs 密码学凭证化的"花钱权"**（AP2 mandate 是该页的消费实例）；与 [[HumanInTheLoop]]——**闸门决定"要不要"，预算决定"花多少"**；与 09-30「常驻智能体」/10-01「企业上下文层」互补——**支付是常驻 agent 的第四个属性（能花钱）**。

**建议的下一步**：修订成本低于新开页——[[AgentIdentity]] 增「消费授权（mandate）」一节 + [[HumanInTheLoop]] 增「预算闸门」一节；若预算面证据继续累积，再考虑 `concepts/AgentPayments.md`。
