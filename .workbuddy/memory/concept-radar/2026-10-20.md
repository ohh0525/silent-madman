## 候选 1 ⭐ 连续记忆的「无作用域修订」—— 聚合分数藏掉了什么（ScopeMem）

### 为什么「当下」最有价值

1. **它是 10-17A 那条线盼了三天的第一个测量值。** 10-17A 立下的是「连续记忆**不可寻址** ⇒ 你无法引用一个向量」，但那只是**可陈述性**的判据，**没有一个数字**。ScopeMem 给出了第一个：**无作用域的修订会改坏 8–13% 原本正确的决策**，而且**聚合准确率把这个损失藏起来了**。
2. **它点名了潜记忆真正在做的那个动词 —— 而且是 [[MemoryGovernance]] 四动作里的一个。** 对照实验显示：收益被「自然归因于编码进去了的历史」，实际**主要来自「动作修订」**（prefix 学会了去改模型默认动作）。⇒ 潜记忆在**不可寻址的载体上执行了一次 UPDATE / supersede**，而那一条正是 FEB-30 测出「只有 20% 判对」的那个操作。
3. **它与 10-17B FEB-30 同形，因此给 10-17 那个开放实验提供了第一个半截的实证立足点。** FEB-30：外在评测看不见记忆操作层的失败；ScopeMem：**聚合准确率看不见潜记忆逐决策的损失**。两者是同一句判据的两次落地 —— **判定的粒度会先于被判定的东西失灵**。
4. **它给出一条本库从未写过的修复形状：修订要有作用域。** ScopeMem 的编码器以「模型的初始答案」为条件生成 prefix，被训练成**改错的同时保住对的** ⇒ 被改坏的正确决策降到 **5.6%**，且修复量**高于**任何被测的 CE 训练 prefix。⇒ **不是「要不要改」，而是「改的时候有没有作用域」。**
5. **它是本期三条里唯一直接落在既有 ⭐ 行上的。** 10-17A 与 10-17B 都是 ⭐，本行不是新领域，是它们的**共同下半截**。

## 候选 2 ⭐ 暴露 ≠ 行为 ≠ 状态 —— 记忆归属的三阶段审计（Whose Credential Is It?）

### 为什么「当下」最有价值

1. **它给本库最常见的一种测量姿势判了刑：只测「暴露」。** [[MemoryPoisoning]]、[[MemoryGovernance]] 的 Recall、10-13 的准入 —— 全部在问「坏东西**进来了吗 / 被取到了吗**」。本文把它拆成三个事件：**暴露**（foreign credential 到达 prompt）、**行为**（智能体真的拿它去做了）、**状态**（对方账户真的被改了）。
2. **而三个阶段的答案相差极大。** 良性条件下：混合 **763** 条历史登录的记忆库为 **84.7%** 的必需 app 取回了**他人**的凭据 —— 但智能体**几乎不会去用它**。压力条件（记忆里缺用户自己的凭据、且把唯一一条他人的凭据当作用户自己的记录呈现）：七个智能体在 **80–94%** 的运行中**使用了它**，并在**最多 43%** 的运行中**改掉了受害者的账户**，**有时还能通过官方检查**。
   ⇒ **84.7% 的暴露几乎不产生行为；而行为一旦产生，43% 会落到状态。** 只报暴露率，两个方向都会误读。
3. **修复方式恰好是 10-17A 那条线的反面证据：它要求可寻址。** 在每行凭据**之前或之内**标出所有者 ⇒ 滥用从 **92 / 305 配对运行降到 1 / 305**（换用不含姓名的用户名也成立）。⇒ **归属标注依赖「逐行」，而连续记忆没有行。**
4. **它把代价也量了出来 —— 本库一贯要求「反证据同屏」的那种代价。** 所有者绑定的注记在**干净记忆**上要花掉每个模型 **3–5 个成功任务**。且**写错所有者会大致恢复滥用**；尾部挂 owner 标签、追加安全指令**只对部分模型有效**。⇒ 修复不是免费的，也不是稳的。
5. **它与 10-13 / 10-14A 是「变量」与「仪器」的关系。** 10-13 命名了**归属 ≠ 权限**、10-14A 命名了**跨主体状态隔离**；本行交付的是**测量这三段的那台仪器**，以及「暴露高 ≠ 危害高」这个反直觉的实测结果。

### 关键数字

| 阶段 | 数字 |
|---|---|
| **暴露** | 混合 **763** 条跨用户历史登录的记忆库，为 **84.7%** 的必需 app 取回他人凭据 —— **但智能体几乎不据此行动** |
| **行为**（压力测试） | 记忆中缺本人凭据、仅呈现一条他人凭据并当作本人记录 ⇒ **7 个智能体**在 **80–94%** 的运行中使用了它 |
| **状态** | 其中**最多 43%** 的运行**改掉了受害者账户**，**有时通过官方检查** |
| **修复** | 在每行凭据**之前或之内**标出所有者 ⇒ 滥用 **92 → 1 / 305** 配对运行（换不含姓名的用户名仍成立） |
| **代价** | 所有者绑定注记在干净记忆上**每个模型少 3–5 个成功任务** |
| **修复的脆弱性** | 所有者**写错**会大致恢复滥用；尾部标签与追加安全指令**只对部分模型有效** |
| 规模 | 19 页 / 14 图 / 12 表；AppWorld；提交 **2026-10-19 02:53 UTC**；Hau-Sing So 等 6 人 |

### 一句话定义

> **共享长期记忆里，「别人的凭据进到了 prompt」不等于「智能体会拿它去做事」，更不等于「对方的账户真的被改了」—— 84.7% 的暴露几乎不产生行为，而一旦产生行为，最多 43% 会落到状态上。⇒ 只报暴露率的评测，在两个方向上都会误读。**

## 候选 3 人类指令的持久化与「权威侵蚀」（Structured Authority Injection · SAI，不标 ⭐）

### 为什么「当下」最有价值

1. **它顶到 [[HumanInTheLoop]] 唯一没有的那一栏：指令的**持久性**。该页是本库**唯一**在「检测之后还有动词」的链条（分级 → 闸门 → 幂等执行 → 审计），但**没有一处谈「这条指令在多轮规划之后还作数吗」**。SAI 的问题陈述就是这句话：**没有协议级机制能让操作者注入跨规划周期持续有效的约束性指令**。
2. **它给「权威侵蚀」起了名字并给了机制。** 自由文本指令有两个失效原因：**无 schema 校验 ⇒ 解释歧义**，以及 **authority erosion —— 操作者的指令在累积的上下文里失去分量**。⇒ 这正好是 🎯 **10-09「常驻上下文与指令预算」** 那条线的**动态版本**：那一行问「哪些内容值得占用常驻预算」，本行答「**值得的那部分，还必须带持久性语义**」。
3. **它的机制有一个本库反复记过的形状 —— 不对称。** SAI 的 override 工具**只能由监督接口调用，规划智能体永远不能**：智能体能读这些命令，**但不能创建或删除它们**。⇒ 与 [[MemoryGovernance]] 的「Permissioned」、10-17C 的「task content 必须以引用的形式抵达」同族：**读权 ≠ 写权**。
4. **它把「常驻预算」从「一段文字」升级成「带失效语义的类型化数据」。** 三类 override：**Constraint**（硬约束永不被违反；软约束仅当无合规方案时才绕过；**持续到被显式解除**）· **Priority**（随外部渠道到来的紧急性；**受影响任务或任务类完成时自动过期**）· **Strategy**（协同启发式；可贯穿全程，或**恰好 N 个规划周期后过期**）；冲突按固定优先级 **C > P > S** 在**构建 prompt 时**计算。⇒ **每条常驻指令有类型、有优先级、有显式到期。**
5. **代价与不稳定性同屏（本库最看重的那类反证据）。** 九模型 × 八场景：最强模型上 prompt 开销**最多降低 38%**（GPT-4o），DeepSeek-R1 **31%**，GPT-OSS-20B 在两个场景中**从零完成到全部完成**；但 **Gemini-2.0-Flash 在区域分配场景从 1.00 掉到 0.50**，**DeepSeek-R1 在 S7 因权威上下文增长而耗尽 4096 token 预算**，而 LLaMA / Qwen / Claude-Haiku 一组**只增加开销、没有成比例的改进**。

### 关键数字 / 机制

| 项 | 内容 |
|---|---|
| 问题 | **控制缺口**：无协议级机制可注入跨规划周期持续的约束性指令 |
| 两个失效 | **解释歧义**（无 schema 校验）+ **权威侵蚀**（指令在累积上下文中失去影响力） |
| 机制 | 操作者更正走**类型化、schema 校验的 MCP 工具调用**；每轮 prompt 前置一个**带排序的权威上下文**；权威通道**对规划过程不可达** |
| 三类 override | **Constraint**（硬约束永不违反 / 软约束仅在无合规方案时绕过；**持续至显式解除**）· **Priority**（任务或任务类完成时**自动过期**）· **Strategy**（全程有效或**恰好 N 个规划周期后过期**）；冲突 **C > P > S**，在构建 prompt 时计算 |
| 不对称 | **override 工具只能由监督接口调用；规划智能体可读不可写、不可创建或删除** |
| 结果 | 九模型 × 八场景：歧义解释减少、权威衰减缓解；最强模型 prompt 开销**最多降低 38%** |
| 代价 | Gemini-2.0-Flash 区域分配 **1.00 → 0.50**；DeepSeek-R1 在 S7 **耗尽 4096 token 预算**；LLaMA / Qwen / Claude-Haiku **开销上升而无成比例改进** |
| 前提 | 无需微调或访问权重；仅需支持 MCP 工具使用的指令微调模型 |
| 提交 | **cs.AI 2026-10-19 新提交列表**收录（arXiv:2610.22373v1）；Ryan Tran 等 9 人 |

### 一句话定义

> **人类给智能体的指令会在累积的上下文里逐渐失去分量（权威侵蚀），而自由文本又无法被校验；解法不是写得更重，而是把指令变成类型化、带失效语义、且只有监督方能写的协议对象 —— 智能体能读，但不能改。**

### 与已覆盖概念的边界辨析

| 对比 | 差别 |
|---|---|
| vs **[[HumanInTheLoop]]** | 那一条是「**这一动作要不要人批**」（分级 / 闸门 / 幂等 / 审计）；本行是「**这条指令在多轮之后还作数吗**」。⇒ 是同一页的**时间维度那半栏**，不是新话题。**建议并入，不单独成文** |
| vs **🎯 10-09「常驻上下文与指令预算」** | 那一行问「什么值得常驻、这份文件该多大」；本行答「**值得常驻的还必须带持久性语义**」。⇒ **本行是 🎯 行的一台候选装置**，也是它三周来第一次拿到可引用的机制 |
| vs **[[MemoryGovernance]]「Permissioned」** | 同形（**读权 ≠ 写权**），但对象不同：那条管**谁能写共享记忆**；本行管**谁能写指令**。⇒ 同一条纪律的第二个实例 |
| vs **10-17C ScaleMAS** | 那一条让**同伴产物**以可引用消息的形式抵达；本行让**人类指令**以类型化对象的形式抵达且不可被规划方改写。⇒ 同一族（**抵达形式决定权威**）的两个成员 |
| vs **[[ContextEngineering]]** | 后者是**单轮**的窗口内摆放；本行是**跨规划周期**的持续。且本行把「常驻」从**体积**问题变成**类型 + 到期**问题 |

**必须同屏的边界**：全部为**仿真**评测（八个模拟场景），非真实部署；设计假设**单一可信监督方**（多方监督下优先级怎么定未涉及）；**额外 prompt 开销会 destabilise 本来表现良好的模型**（作者自陈）；**收益高度依赖模型** —— 作者自己把 LLaMA / Qwen / Claude-Haiku 列为「最弱一组，SAI 只增开销」。⚠️ **日期存疑**：`arxiv.org/abs/2610.22373` 页面元数据显示「Submitted on **27 Jul 2026**」，与 arXiv ID `2610`（10 月）及 **cs.AI 2026-10-19 新提交列表**矛盾；本报告以**新提交列表**为准，该不一致已如实记录、待核。
