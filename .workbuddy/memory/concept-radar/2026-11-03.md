### 候选 11-03A ⭐⭐⭐ · 记忆的表示本身要被路由 —— 没有一种记忆跨场景最优

| 项 | 内容 |
|---|---|
| **概念名** | 路由式持续学习 / 记忆表示的选择是一个路由问题 · **Routed Continual Learning (Routed CL)** |
| **一句话定义** | 把过往轨迹按问题**聚类**，**每个簇各自**从固定的记忆系统库里挑一种来维护状态；每次运行前由 LLM 路由器决定「复用哪个簇」还是「新建簇」—— 于是**学习机制**与**状态簇**都变成被选择的对象，而不是全局一次性承诺。 |
| **为什么当下最有价值** | 本库 `LongTermMemory` 白纸黑字写的是「**2026 的设计赌注 = 三种并行记忆**（episodic / associative / semantic-HDM）」—— 这恰是**一次性承诺一整套表示**。而 Routed CL 的立论第一句就是「**没有一种保留经验的方式能跨场景都好**」。⇒ **缝不在某一句，而在本库把「选什么表示」当成了已答项**，而这篇证明它是个**待解的路由问题**，并且给出了解法与价格。 |
| **来源（全部 WebSearch 真实返回）** | `arXiv:2610.38796`（Michael Philip, Mahesh Balakrishnan, David Geraghty, David Mao, Vidhya Venkat, Ilya Mironov；**FAIR at Meta**；2026 年 10 月；`cs.LG` + `cs.MA`）`[verified]`<br>https://arxiv.org/abs/2610.38796 · https://arxiv.org/html/2610.38796v1 · https://doi.org/10.48550/arXiv.2610.38796<br>中文报道（36 氪，2026-11-02）https://www.36kr.com/p/4052444548994181 |
| **关键实测数字** | 异构流：**301** 个 CL-Bench 实例 + **97** 个 τ³-Bench 银行实例 = **398** 交错；**4 个语言模型 × 5 组匹配 rollout**；较单一全局 ICL 历史**归一化奖励 +15–30%**（相对最大可获归一化奖励）；高于 ICL-only 聚类；**相对 Global ICL 的估计 API 成本 −65–72%**。 |
| **边界辨析要点** | vs **`LongTermMemory`**（本库）：本库问「跨会话状态**存在哪**」，这篇问「**用哪种表示存**」⇒ 是本库的**上游一格**：三种并行记忆可以是它的记忆系统库里的三个候选，而不是全部。<br>vs **`MemoryGovernance`**（本库）：Governance 的决策者是「人写规则 / 训练策略 / 攻击者」三选一；Routed CL 给出**第四种决策者的雏形 —— 路由器**（按问题挑机制）。但这篇**不管安全**，别把它读成治理方案。<br>vs **`ContextEngineering`**：上下文工程管的是**每一轮窗口里放什么**（窗口内、逐轮）；路由管的是**哪个记忆系统持有这份状态**（窗口外、跨运行）。两者相接但不重叠。<br>⚠️ **附带价值（值得单独记一笔）**：该文以 **OpenAI 网络能力评测中 agent 自建共享留言板、跨运行传播 exploit** 作为动机案例。本库 `MultiAgent` 的 cross-contamination 自 2026-09-26 起一直是**二手转述**；这是本库第一次遇到**正式引用该事件、可当作一级来源**的论文。<br>⚠️ **证据分级**：作者自陈成本为「estimated API cost」；评测为混合任务流，数字不可外推到单一垂直场景。 |

### 候选 11-03C ⭐⭐ · 声明携带证明 —— 谎言拦在声明上，不拦在信道上

| 项 | 内容 |
|---|---|
| **概念名** | 携带证明的消息 / 三值判定与只能收窄的授权链 · **Proof-Carrying Messages (PCM)** |
| **一句话定义** | 每条 agent 间声明都携带证据：来自**该 agent 无权写入**的只追加 Merkle 日志的记录 + 包含性证明 + 由**该 agent 无法控制的**证明签署者签名。接收方离线校验，对每条声明给**三值**结果 —— proven / unproven / failed；**仅靠发送方自述的声明永远不是 proven**；授权以「根植于已记录的人类批准」的授予链传递，且**只能收窄**。 |
| **为什么当下最有价值** | 直接给 `overview.md` 那条开放子问题一个**守方自己就能布**的答案。本库 `MemoryPoisoning` 的结论是「根因修复在**供应商侧**（服务端校验签名回复），**disclosed ≠ mitigable by you**」，overview 于是问「vendor-side 的修复何时落地」。PCM 说明**不必等供应商**：把「证明」做成消息层的协议即可。⇒ 缝的形状很清楚：**本库在「agent 说的话」这一层完全没有机制** —— `Provenance` 的对象是「事实」，而 PCM 的对象是**另一个 agent 的声明**，正是 overview 自 2026-09-26 起反复说的「Provenance 的对象应扩到 verification status」的**协议实现**。 |
| **来源（全部 WebSearch 真实返回）** | `arXiv:2610.39109`（Bravish Ghosh，Cygnux Labs；**2026-10-29**；50 页 / 9 图 / 15 表；`cs.CE` 跨 `cs.AI` / `cs.CR` / `cs.MA`；规格 + 一致性向量 + 验证器 + 基准集**全开源 MIT**）`[verified]`<br>https://arxiv.org/abs/2610.39109 · https://arxiv.org/html/2610.39109v1 · https://doi.org/10.48550/arXiv.2610.39109 |
| **关键实测数字** | 预先指定的基准：**926 条真实运行消息，其中 712 条是谎言（16 类）**。PCM 只接受 **10 条**（**1.4%**，95% CI 0.8–2.6%），且**全部是 stale evidence**；**plain A2A 接受全部 712 条**；六种在役协议（A2A + 签名 Agent Card / uAgents / RFC 9421 / SCITT / AP2 / Verifiable Intent）接受 **504–712** 条；**两个独立验证器在全部 926 条上判定一致**；单条验证约 **1 ms**。 |
| **边界辨析要点** | vs **`MCP`**（本库，Cluster C）：MCP / A2A 解决的是「**谁传的**」（信道认证）；PCM 解决的是「**内容是不是真的**」⇒ 作者原话：**被怀疑的正是发送方本身**，所以信道认证在此处不构成证据。<br>vs **`Provenance`**（本库）：本库字段是 origin + time + evidence，对象是**事实**；PCM 把对象换成**别的 agent 的声明**，并给出**三值**而非二值判定 ⇒ **unproven 这一档是本库现在完全没有的**（本库只有「引了」与「没引」）。<br>vs **`MemoryPoisoning`**（本库）：那边是**内容被写坏了**（诱导自写 / 伪造历史）；这边是**内容可能是对的，也可能不是，但你没有证据**。⇒ **两轴，不是同一问题的两种解法。**<br>vs **`AgentIdentity`** 的 per-hop attenuation：那是在**签发**时收窄；PCM 的授权链是**在使用时**证明其收窄过，且**根植于已记录的人类批准** ⇒ 把 Cluster D 的「只能变窄」从**运行时纪律**升级为**可离线校验的属性**。<br>⚠️ **作者自己划的信任边界必须一起引**：① 不能让一个已被攻陷的 agent 变诚实；② **证明签署者是可信计算基**。另：残留的 10 条谎言**全是陈旧证据** ⇒ 与 `MemoryGovernance` 的「遗忘是一种能力」直接咬合。 |
