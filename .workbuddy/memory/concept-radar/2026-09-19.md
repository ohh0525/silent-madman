### 候选 1 ⭐ 首选:A2A 协议(Agent2Agent)

**一句话定义**:让**一个 Agent 发现、委派任务给另一个 Agent** 的互操作协议;Agent 通过发布结构化的「agent card」声明自己的能力与联系方式,其它独立 Agent 可安全读取并委派任务,无需为每一对新配对写定制集成代码。

**为什么"当下"最有价值(缺口/接缝)**:

### 候选 2:线索锚定的工作记忆(Cue-Anchored Working Memory)

**一句话定义**:让「记忆」由 **harness 在情境触发时确定性注入** 的一类事实——不由 Agent 主动想起,而由运行时在 Agent 打开某文件(path cue)、引用某符号(symbol cue)、或临近压缩(event cue)等时刻,**不经过模型判断地**把对应事实塞进窗口;判定标准是「**递送机制**,而非存了什么」。

**为什么"当下"最有价值(缺口/接缝)**:
这条**直接改写你 [[LongTermMemory]] 页的核心定义**。你现在的写法是「窗口装不下跨会话状态 → 于是存到窗口之外 → 需要时**检索再注入**」——主语是**存储**,动作是 Agent **主动读取**。2026 年 9 月被反复讨论的这篇论文把因果**倒过来**:一个存储到底是「记忆」还是「参考文档」,**由递送机制决定,不由存了什么决定**——「**lookup 的就是文档,injection 的才是记忆**」。实证很硬:*只靠主动存的 store 在 114 轮里零调用;而 harness 注入的事实挺过了 138 次压缩-恢复循环*。这是你知识网里**第二处「新证据直接挑战既有节点核心假设」**的地方(第一处是 09-18 的子智能体隔离),价值高于纯新增——它会迫使你**修订** [[LongTermMemory]] 与 [[Provenance]] 的措辞,并让你看清 [[ContextEngineering]] 之外还有一条「harness 侧确定性注入」的路。

### 候选 3:测试时计算 / 推理预算(Test-Time Compute / Reasoning Effort)

**一句话定义**:把算力从**训练期**挪到**推理期**——模型在给出答案前先「想」一段(内部推理链 / 多路径搜索 / 自校验),用**更多的推理 token 换更高的正确率**;2026 年的可调形式是**推理预算**(OpenAI `reasoning_effort`、Anthropic `budget_tokens` 等)。

**为什么"当下"最有价值(缺口/接缝)**:
你的 Cluster A 主题是「**有界资源**」,但它只算了**一根轴**:[[LLMContext]] / [[Token]] 描述的是「**读进来**的 token」受窗口上限约束。2026 年出现的**第二根轴**是「**想出去**的 token」——而且它**吃的是同一个窗口、同一份账单**。现状是:**推理 token 会把推理成本抬高 3~30×**,且「想得久」与「想过头」之间只有一线之隔(overthinking trap)。所以你的「有界资源」簇缺一个**预算旋钮**:`reasoning_effort` / `budget_tokens` 决定了模型在回答前能烧多少 token,而这个决策**直接改写 [[ContextEngineering]] 的取舍**(留给「读进来的材料」的窗口,会被「想」吃掉)。它也和 [[ReAct]] 形成对照:ReAct 是**外部**「推理-行动」循环的模式,测试时计算是**模型内部**「想多久」的算力分配——一个在窗外循环,一个在窗内燃烧。
