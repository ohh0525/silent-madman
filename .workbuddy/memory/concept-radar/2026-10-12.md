### 候选 1 ⭐｜智能体可观测性与评测 —— 长轨迹的「可见性」与「失败归因」

**Agent Observability & Evaluation / Long-Horizon Transcript Observability**（= 台账 10-08 行，⭐，**🎯 4 天**）

**为什么「当下」最有价值（一句话点明接缝）**
10-11 草稿自己写下的边界句「**一次运行可以可靠地跑完，却给出糟糕的答案**」把**可靠性（跑得完）**与**质量（跑得好）**劈成两个正交轴 —— 而 wiki 现在有前者的草稿（`output/pending-review/durable-execution.html`），**后者连一页都没有**；[[HumanInTheLoop]] 的验收标准明写要测 automation / override / **escape** rate，提供「看得见」的那一页却不存在。

**一句话定义**
在长周期、多智能体的运行里，**评测者能可靠推断出 agent 行为真相的那个范围**（observability envelope）正在收窄；本概念是关于**如何把一次跑了几百万 token 的 run 变成可回溯、可归因、可复核的证据链**。

**与已覆盖概念的边界辨析**

| 对比 | 边界 |
|---|---|
| vs [[AgentHarness]] | harness 答「**谁跑循环**」；本行答「**跑的时候看得见什么**」。是同一层的第四项职责，不是新层 |
| vs [[MemoryGovernance]] | 治理管「**状态怎么变、谁有权改**」；可观测管「**这次运行到底发生了什么**」——前者是策略，后者是证据 |
| vs [[Provenance]] / [[CitationLock]] / [[Abstention]] | 这三条的**对象都是模型说的话**；本行的对象是**系统实际做的事**。wiki 的真实性纪律此前从未覆盖后者 |
| vs [[MultiAgent]] | MultiAgent 说「**验证器是协作的前提**」；本行说「**没有轨迹可见性，连验证器该验哪一步都定不出来**」 |
| ⚠️ 与 09-23 持久化执行 | 已由 10-11 的判据句分栏：**跑得完 ≠ 跑得好**，两者互为替代指标是错的 |

### 候选 2｜RAG —— 争的不再是「用哪个检索器」，而是「检索什么」

**Retrieval-Augmented Generation: from chunks to structured evidence**（= 台账 09-17 行，**素材侧最老 `⏸`，25 天**）

**为什么「当下」最有价值（一句话点明接缝）**
这是一个**证据性质再次变化**的信号，不是重复推荐：09-27/09-28 那轮争的是**检索器**（关键词 vs 向量，已自我修正为「分场景反转」），本周争的是**被检索的对象本身** —— 而 wiki 的 [[Provenance]] / [[CitationLock]] / [[Abstention]] 那套真实性纪律，第一次有了**检索层的实现形态**，可它连一页 RAG 都没有。

**一句话定义**
把检索的对象从「相似的一段文本」换成**带来源、带时间、带证据关系的结构**（Claim / Fact / Event 分层 + 确定性图算子重建），使「查得到」与「说得清出处」变成同一件事。

**与已覆盖概念的边界辨析**

| 对比 | 边界 |
|---|---|
| vs [[LongTermMemory]] | 长期记忆是 **agent 自己的跨会话状态**；RAG 是**外部语料**。二者都「按需加载」，但**所有权与写入权完全不同**（MemoryGovernance 的四个 bottom line 只管后者之外的那一半） |
| vs [[ContextEngineering]] | 上下文工程是**管理窗口的原则**；RAG 是它**可用的一种手段**。overview 已写明 ProgressiveDisclosure 是上下文工程的一个实例 —— RAG 是另一个，且**至今无页** |
| vs [[Provenance]] | Provenance 是**阅读侧的纪律**（每条事实带来源 + 时间 + 证据）；CogMem 是把这套纪律**下沉到存储 schema**（Claim 节点带 source 与 target、冲突更新按时间范围调和）。⇒ 本行是 Provenance 的**下游实现**，不是它的重复 |
| ⚠️ 与 09-28 的自我修正 | 生成材料时**首屏仍须写「分场景反转」**，不得写「向量已死」；本轮的新增量是**对象之争**，不是**检索器之争的翻案** |

### 候选 3｜间接提示注入 —— 「打开文件夹」也算被注入，且它拿不到 CVE

**Indirect Prompt Injection / Artifact-Mediated Propagation**（= 台账 09-23 行，19 天；同时是 overview 2026-10-09 明确列出的开放项「*transient* indirect prompt injection 无页」）

**为什么「当下」最有价值（一句话点明接缝）**
[[MemoryPoisoning]] 只覆盖了「注入**被持久化**之后」那一半（PMPA 诱导自写 / 伪造会话历史）；**从未被写下来的另一半是：一次根本没被存储的注入，照样能改变行为** —— 而这一半在 2026 已经有了生产级证据，且最承重的事实是一条**否定式**事实：**它拿不到 CVE，因为它是受支持的功能**。

**一句话定义**
恶意指令不在用户的直接消息里，而在 agent 被要求**处理的外部内容**中（文档 / 检索块 / 网页 / 配置文件 / 技能说明 / 工具返回）；当这些内容被当成指令而非数据时，行为被劫持 —— 且**不需要进入记忆**。

| 对比 | 边界 |

| vs [[MemoryPoisoning]] | 记忆投毒 = **持久化那一半**（payload 穿上合法 provenance 后长期回灌）；本行 = **瞬态那一半**（一次读取即生效，不留痕）。overview 自 10-09 起就点名要分家，本行是它缺的那一页 |

## 本期方法沉淀（有长期价值）

1. **第七条扫描线：可见性审计** —— 不问「缺什么动词」（10-08）、「什么不免费」（10-09）、「活多久」（10-09E）、「训练与部署是同一个对象吗」（10-11），而问「**这件事发生了之后，谁能在事后把它重建出来？**」。命中结果：[[HumanInTheLoop]] 要求测 escape rate、[[MultiAgent]] 要求「验证器是前提」、10-11 草稿要求「跑得好也要测」—— **三条验收标准同时押在一个不存在的页上**（命中 10-07 立的优先级判据：某页的验收标准落在另一页身上、而那一页不存在 ⇒ 最高优先级）。
2. **「零新行」本身是一个可记录的事件**：台账 22 期以来第一次出现一期之内没有新候选。这不是信号枯竭，而是**接缝已被命名得足够密** —— 新事实先落在既有行上被吸收。⇒ 由此可立一条新判据：**当一期之内全部候选都是承接强化时，说明瓶颈不在「找新概念」而在「把既有行做成材料」**。
3. **否定式事实要单独列为承重证据**：Miasma 蠕虫最有价值的信息不是「它做了什么」，而是「**它拿不到 CVE，因为那是受支持的功能**」。这类事实无法被任何「修复漏洞」的流程捕获，是最容易被漏记的一类。
4. **反证必须与主证据同屏，且要指出它和哪条既有结论相反**：Mind Viruses 的「一句警示即近乎免疫」与 Cluster F 的「投毒之后提示层防御保护很差」方向相反。区别在于**时序**（投毒前 vs 投毒后），因此在页面上必须写时序而不只写结论。
