### 11-06A 详情

- **一句话定义**：当没有参考摘要、没有下游任务结果可跑时，agent 历史的压缩 / 记忆写入质量可以从**轨迹自身**取得监督信号——掩码重建（SUMONE）、用后回溯归因（MEMOIR）、事后笔记自举（MEMENTO）三种互不依赖的取法。
- **边界辨析**：与 `Compaction`（含 11-05B「压缩 vs 过滤」节）的分界在**问题层次**——压缩 vs 过滤是「丢弃时保留什么」的**决定论**，本条是「凭什么知道保留得好不好」的**监督信号来源论**，两者正交；与 `LongTermMemory` 的分界在**写入路径 vs 存储结构**——本条不问记忆装在哪（文本 / 状态 / 权重，那是 11-05B/C 的轴），只问**写入那一刻的信号**；与 11-05A 前瞻记忆的分界在**信号的时间指向**——前瞻记忆的信号指向未来动作，MEMOIR 的归因信号同样**用后才产生**但**修改的是检索优先级**（回溯修订，不是前瞻触发）。
- **来源**（WebSearch 真实返回，[verified]）：
  1. SUMONE：https://arxiv.org/abs/2611.06445v1 [verified]
  2. SUMONE 全文：https://arxiv.org/html/2611.06445v1 [verified]
  3. MEMOIR：https://arxiv.org/abs/2611.07631 [verified]
  4. MEMENTO：https://wpnews.pro/news/memento-learning-context-management-for-long-context-processing-agents [verified]（二手转述，arXiv ID `2611.00244`；一级链接未直接打开，摄取前须按规矩核一级）
- **值得注意的点**：① SUMONE 的「同一 checkpoint 跨模型跨 harness 迁移」直接回应了 `AgentHarness` 页「harness 职责 ④」的压缩工序**可插拔**问题——压缩器可以是独立小模型而非 agent 本体；② MEMOIR 把「重要性分数」从**写入时一次性静态打分**改成**使用后持续修订**，这是 11-05「时间方向轴」在**写入侧**的镜像（读取侧的前瞻 ↔ 写入侧的回溯修订）；③ MEMENTO 论文正面断言「off-the-shelf 模型（含 GPT-5.5 / GLM-5.3）写的笔记是无效笔记」——即**压缩质量不是涌现的，是训出来的**。
- **建议下一步**：值得生成 `learning-materials/self-supervised-write-signal.html`（受人工核查承诺约束，先经核查）；或先在 `Compaction` 页加「监督信号从哪来」一节（SUMONE / MEMOIR / MEMENTO 三取法对照），并在 `LongTermMemory` 页标注「写入时静态重要性打分」这个既有默认。

### 11-06B 详情

- **一句话定义**：任务级能力不简单组合成项目交付——把 agent 放进「brief → 多轮反馈 → 终交付」的专业项目链条里量，最好的系统也只拿 65/100，且失败集中在「把前面的工作带着走」（错误继承、traceability 丢失）。
- **边界辨析**：与 `MultiAgent` 的分界在**单系统跨任务 vs 多 agent 协作**——DeliverBench 是一个 model-harness 系统串 150 个子任务，不是编排问题；与 `AgentHarness` 的分界在**任务内 vs 任务间**——harness 职责清单（状态保活、恢复）都在一个任务内，本条问的是**子任务之间的工作连贯性**；与 `AgentObservability` 的分界在**测量单位**——五层评测以任务为单位，本条以**项目**为单位；与 `Provenance` 的关系是**同域两面**——Provenance 问「这条事实从哪来」，DeliverBench 量的是「交付时这条链还在不在」。

### 11-06C 详情

- **一句话定义**：把「当队友」单独量——只在「模型有全信息时能独立做对」的任务上测协作行为（拒绝捷径、核查他人、顶住压力、接手污染任务），把协作能力从个体能力里剥离出来的基准。
- **边界辨析**：与 `MultiAgent` 的分界在**被测对象**——MultiAgent 测编排结构（通信 / 共享内存 / 角色分工），CIB 测**单个 agent 的队友行为面**；与 `HumanInTheLoop` 的分界在**压力方向**——闸门模型是「agent 提请、人批准」的单向问责，CIB 测的是**双向动态**（agent 会被谈判对手的人际压力压弯，也会被弱队友的遗留工作拖坏）；与 10-31A（弃权 / 过度拒绝）的分界在**主动性**——弃权是「知道不该动」，CIB 的接手污染任务是「动了之后自己也被带坏」，两者正好是接手链的两端。
- **来源**（[verified]）：
  1. https://arxiv.org/abs/2611.02633 [verified]
  2. https://arxiv-vanity.com/papers/2611.02633 [verified]
  3. https://arxivlens.com/PaperView/ViewPdf/measuring-ai-agents-as-teammates-with-collaborative-intelligence-7717-66cd5f18 [verified]
- **值得注意的点**：① **隔离设计本身是仪器贡献**：「只考能独立做对的题」把「不会做」与「不会配合」分开——与 11-05B「把阈值漂移与判别力丧失分开测量」同一仪器谱系（控制变量先于数字）；② 「顶得住捷径、顶不住人际压力」给 `MemoryPoisoning` / 注入轴补了一个**非技术通道**的攻击面（压力不是注入文本，是对话动态）；③ 160 公开 + 80 held-out 的防污染切分合本库证据等级写法。
- **建议下一步**：暂不立专页；在 `HumanInTheLoop` 页加「人际压力通道」草稿批注、在 `MultiAgent` 页标注「agent-as-teammate 是编排之外的另一测量面」即可。
