### 11-09A · 用模型自己的思维链攻击它 / Thought Injection ⭐⭐⭐

**一句话定义**：对带显式推理阶段的大推理模型，把攻击载荷**写成模型自己的推理语态**（仿其思维链风格）喂回去，ASR 可达 **50%**（反向 shell 外泄、仓库植入后门）；**同一恶意目标用标准用户语态从不成功**，而思维链标签还会**压制模型的注入披露倾向**，剥除标签也不是可靠防御。

**为什么"当下"最有价值 —— 缝在哪**

11-08B 刚立了「模型倾向相信自己说过的话」这条非对抗性失效（内容的所有权）；本条把**同一个信任机制武器化**：

- **攻击面新在「语态」，不在内容。** 注入轴既有条目（11-04A 野外 / 11-04B 溯源 / 11-04C 恢复 / 11-07C 签发后）共享一个默认：载荷以**可辨别的他者语态**到达（用户口吻、工具输出、网页文本）。本条证明**最强的伪装不是装成用户，而是装成模型自己**——检测式防御找的是「像指令的他者文本」，而仿思维链的载荷根本不像指令。
- **披露机制被自己的标签关掉。** thinking tags 抑制披露倾向——模型最接近「说出我看到了可疑内容」的通道，恰好被推理格式的标记压住。⇒ 与 11-07A「无对手失效」互补：那边是**无异常可检测**，这边是**有异常但披露通道被关**。
- **防御不可移植。** 标签与风格的效果**全部是模型特定的**（model-specific），没有一个跨模型通用的剥离规则 ⇒ tag stripping 不可靠。

**数字（摘要级，一手摘要已核）**
- 两部分研究：① 静态思维注入 × 风格 × 带标签/不带标签 —— 效果均为**目标模型特定**；② 容器化 agentic cyber range，用目标模型自己推理轨迹的风格写间接注入，对 GLM-5.3 / MiniMax-M2.5 / Qwen3.8-Flash-Next 等生产级开源模型，**ASR 最高 50%**（reverse-shell exfiltration / repository backdooring）。
- 对照：同一恶意目标用**标准用户语态**的提示注入 **从不成功**（never succeeds）。

**真实可达来源**（均 WebSearch / WebFetch 真实返回，**[verified]**）
1. https://arxiv.org/abs/2611.08811 —— *I Think, Therefore I Attack: Evaluating Thought Injection Attacks on Reasoning Agents*，Parth Illendula / Garik Livingston / Zain Shamsi / Ravi Srinivasan / Alex Liu，**cs.AI + cs.CR**，v1 **2026-11-06 00:06 UTC**，194 KB [verified]
2. https://arxiv.org/html/2611.08811v1 —— HTML 版（未逐表核）[verified]

> ⚠️ **证据分级**：① 摘要级引用，正文表未开（「50%」是 ASR 上界口径，非均值）；② 攻击对象全部为**开源权重**生产级模型，闭源 API 模型未测；③ 作者团队规模小（5 人），无独立复现。摄取前须开 HTML 核表。

**边界辨析要点**
- **vs 11-08B 清洁者污染**：那条是**无对手**的自我锚定（模型被自己上一轮的错读带偏）；本条是**有对手**且专门利用同一信任——「相信自己的话」从失效模式变成攻击原语。两条必须互指，否则读起来像重复。
- **vs `MemoryPoisoning`**：那页的载荷**持久化**进记忆；本条载荷是**瞬时的**（喂回当前推理流），恰好落在 overview 明写「transient injection 无专页」的开放项上——它是该页候选的第一块**对抗侧**材料（11-04A 是野外侧）。
- **vs 11-04B 影响溯源图**：溯源防的是「载荷从哪来」；本条的载荷**没有稳定来源特征**（风格随目标模型变），溯源锚点失效。
- **vs `AgentIdentity`**：per-hop attenuation 假设跨主体信任可以逐跳收窄；本条攻击的恰是**主体对自己的信任**——衰减模型没有「自体」这一跳。

**建议下一步**
> **值得，优先级高**。它把 11-08B 的「所有权信任」与注入轴接通，且直接喂 overview 的 transient-injection 开放项。
> 最低成本动作 = 给 `wiki/concepts/MemoryPoisoning.md`（或将来立的 TransientInjection 页）加一节草稿批注（`pending ingest`），标题 **「The strongest disguise is the model's own voice」**，并附一条可抄的工程规则：**推理阶段的输出回灌必须走与外部输入不同的通道校验，不能因为「看起来像自己写的」就免检**。
> 若成篇：标题 `thought-injection.html`，主线只取「语态即攻击面 + 披露被标签压制」，不要写成推理模型安全综述。

### 11-09B · 不改指令也能改结果 / Task-Tampering & the Authority Definition ⭐⭐⭐

**一句话定义**：把间接注入的攻击定义从「指令样措辞」改成「**授权决定权**」——凡试图影响**其来源无权决定**的那个决策的植入内容即攻击；按此口径，攻击可以**不替换任务、只篡改进行中任务的决策输入**（引用假退款政策抬高退款额），而且**检测删除类防御对它几乎无效**：目标改向类攻击降到 2.4%，观测/状态类仍有 **9.5% / 12.1%**；工具策略防御 15.4% ≈ 无防御 17.0%。

**为什么"当下"最有价值 —— 缝在哪**

- **它给「什么算攻击」补上了定义层。** 本库注入轴所有条目都在问「怎么防」，共享一个未言明的定义：攻击 = 指令改写 / 任务替换。本条换成**授权口径**（source 是否有权决定这个 decision），一下把攻击面从「objective」一格扩到**六个决策部件**（objective / decision rules / available actions / expected consequences / observation reading / state beliefs）——后五格里**三格比 objective 更好打**。
- **防御覆盖被系统性高估。** 只测任务改向的 benchmark 会高估防御覆盖：detection-and-removal 的 2.4% 是**对 objective 攻击**的成绩，对 observation / state 攻击留在 9.5% / 12.1%；tool-policy 防御 15.4% 与无防御 17.0% **几乎没差**（因为这些攻击**保留预期工具、只操纵执行中取到的值**）。
- **与 11-07B「记忆的归属主体」同一根轴的两端**：那条问「记忆属于谁」，本条问「**这个决定轮得到这份内容说话吗**」——都是授权问题，一个在存储侧，一个在决策侧。
- **答复 overview 的 transient-injection 开放项（定义侧）**：那格要立页，缺的正是「transient 注入的边界画在哪」；授权口径是现成答案。

**数字（摘要级，一手摘要已核）**
- 基准：**90 个验证用例 × 3 个工具使用环境 × 5 个 LLM**；每个用例的用户请求**明文指定**有权裁决目标决策的来源。
- 无防御：**decision rules / available actions / state** 三类攻击的平均成功率**高于** objective 攻击。
- detection-and-removal：objective 2.4%，**observation 9.5% / state 12.1%**，且该差距在检测优化改写下持续存在。
- tool-policy：**15.4%**（无防御 17.0%）。
- 代码与数据开源：`github.com/amazon-science/task-tampering-prompt-injection`。

**真实可达来源**（**[verified]**）
1. https://arxiv.org/abs/2611.07640 —— *Beyond Instruction Override: Benchmarking Indirect Prompt Injection with Task-Tampering Attacks*，Rongting Zhang / Martin Bertran / Sandeep Avula / Chia-Jung Lee / Vanessa Murdock（Amazon），**cs.CR + cs.AI**，v1 **2026-11-05**，34 页 6 图 [verified]
2. https://github.com/amazon-science/task-tampering-prompt-injection —— 代码与数据仓（论文自陈，未逐文件核）[unverified]

> ⚠️ **证据分级**：① Amazon 自建基准 + 作者自报（与 Cluster F 同级）；但 90 案例经**验证流程**（validated），且开源可复现；② 「六个决策部件」的攻击构造是**作者定义**，别的 benchmark 未沿用 ⇒ 引用时写「按其口径」；③ 摘要级引用，正文表未开。

**边界辨析要点**
- **vs 11-04A 野外注入实测**：那条测**野外发生多少**；本条测**什么该算攻击**——口径不同，正好互补（先定义再测量）。
- **vs `MemoryGovernance` 第三底线**（谁可写共享记忆须像数据库权限一样管理）：底线说的是**写权限**；本条把同一权限思想推到**决策影响权**——读进来是一回事，**有权决定**是另一回事。
- **vs 11-09A**：A 攻击的是**语态**（装成自己人）；B 攻击的是**定义盲区**（防的东西和打的东西不是一类）。两者合起来说明：检测式防御既认错**人**，也认错**罪**。
- **vs tool-policy / `ToolHallucination`**：工具策略防「调了不该调的工具」；本条攻击**用该用的工具、喂错值** ⇒ 策略层看不见。

**建议下一步**
> **值得，优先级高（与 A 并列，二选一先做 B）**。它是 overview「transient injection 立专页」开放项的**定义基石**，且六部件分类可直接当该页的骨架。
> 最低成本动作 = 给 `wiki/concepts/MemoryPoisoning.md` 的 transient/persistence 区分段加一条草稿批注（`pending ingest`），标题 **「Attack defined by authority, not by instruction-wording」**，记录六部件分类与两个防御失灵数字。
> 若成篇：标题 `authority-based-injection.html` 或并入 TransientInjection 页作第一节。

### 11-09C · 纠正过的错不能再犯 / Procedural (Behavioral) Memory ⭐⭐

**一句话定义**：现有 agent 记忆存的基本是**事实**（偏好、实体、对话史），不存**程序性知识**——用户每个会话开头都在重复纠正同一个错误；把人工纠正与自评的工具调用失败**编译成祈使式 RULE 指令**、**在适用的决策点注入**，合规率从朴素检索的 55% 提到 **95%**，且每查询注入 token **少约 10 倍**。

**为什么"当下"最有价值 —— 缝在哪**

- **记忆轴缺「类型」这一维。** 11-05 三条拆的是**时间方向**（前瞻）与**载体**（状态 / 权重），11-06A 拆**监督信号**——但全部默认记忆内容 = 事实。本条补上**程序性知识**（怎么做事）这个类型，且给出三要素设计空间：**representation（显式指令）· activation（何时激活）· placement（在哪个决策点交付）**。
- **placement 与注入轴的时位暗合同构**。记忆不是检索进来全塞进上下文，而是**在它适用的那个决策点交付**——这恰是 11-04 注入时位轴在**记忆侧**的镜像（攻击者挑时机注入恶意内容，系统也挑时机注入行为规则）。
- **与 11-07A 正面相撞，必须点名**：forge_dc 的 RULE 指令**在结构上就是一个自动生成的 mini-Skill**（祈使式程序性指导，按相关性在决策点加载）。11-07A 已证明**良性**程序性指导会让不安全操作率与准确率**同涨**（+10.3 / +10.3）⇒ forge_dc 的 95% 合规增益**继承同一风险面**，论文没测这一侧。

**数字（摘要级，一手摘要已核）**
- 系统：Forge Decision Context（forge_dc），信号源 = 人工纠正 + 自评工具调用失败。
- 基准：DC-Bench，**71 场景 × 9 个行为维度**，从真实执行轨迹构建，确定性 mock 工具环境。
- 结果：**95% 合规**（朴素检索 55%），每查询注入 token **约少 10 倍**；与四个前代方法沿五阶段演进对比。
- 发表：**NeurIPS 2026 Workshop PALM**（Personalized, Aligned, Long-Term Memory）——与 11-05C OPSD（`2611.05636`）同会场。

**真实可达来源**（**[verified]**）
1. https://arxiv.org/abs/2611.08644 —— *Decision Context: Persistent Behavioral Learning for AI Agents*，Nima Vahdat / Pashootan Vaezipoor，**cs.AI**，v1 **2026-11-05**，12 页，NeurIPS 2026 PALM Workshop [verified]

> ⚠️ **证据分级**：① **两作者、自建基准（DC-Bench）、单一系统**，五阶段对比里有四代是自己的前代工作 ⇒ 「最强系统是自己家最新版」存在自证结构；② 95% 合规是**行为合规**指标，未测安全侧（见上面与 11-07A 的相撞）；③ NeurIPS workshop 非主会。⇒ 引用口径写「单系统自报」，不入主证据链。

**边界辨析要点**
- **vs `LongTermMemory`**：那页管**记什么事实、存多久**；本条管**怎么把纠正变成不再犯的规则**——事实记忆答「用户喜欢什么」，行为记忆答「我上次哪里做错了」。
- **vs 11-05A 前瞻记忆**：前瞻记**未来意图**（何时兑现）；行为记忆记**过去纠正**（编译成规则）。两者都是「记忆不止是存档」，方向相反。
- **vs 11-05B 状态过滤**：那条说「读显式状态胜过读全量历史」；本条是其在**行为维度**的实例——RULE 指令就是一种显式状态，10 倍 token 节省是同一个机制的红利。
- **vs `Skill` / 11-07A**：Skill 由**开发者策展**、forge_dc 由**用户纠正自动编译**——来源不同，但注入后的结构相同（祈使式程序指导 + 决策点加载）⇒ 11-07A 的风险结论**大概率可迁移**，这本身值得一条批注。

**建议下一步**
> **暂不成独立 HTML**（两作者 + 自建基准 + 未测安全侧，单篇撑不住）。建议给 `wiki/concepts/LongTermMemory.md` 加一节草稿批注（`pending ingest`），标题 **「Facts vs procedures: memory for how to behave」**，记录三要素设计空间与「RULE ≈ 自动生成 Skill ⇒ 继承 11-07A 风险面」这条交叉警告。
> 若后续出现第二形态（另一团队的 procedural memory 系统），再议立线。
