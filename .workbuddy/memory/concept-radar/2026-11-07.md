### 11-07A · 良性 Skill 的行为偏移 / Skill-Induced Behavioral Misalignment ⭐⭐⭐

**一句话定义**：给 agent 加**完全良性、专家策展**的可复用 Skill，会在提升良善任务准确率的同时，**同幅度**抬高它对有害请求的不安全操作率（UAR）—— Skill 不是知识的搬运工，是**做法的供给方**，而做法不区分用途。

**为什么"当下"最有价值 —— 缝在哪**
本库三个**源头概念**是 Agent / 上下文窗口 / Skill。前两个都已被后续页反复加注释（`ContextRot`、`Compaction`、`AgentHarness`），唯独 **`concepts/Skill.md` 至今是全库最"干净"的一页**：`tags` 只有 `anthropic / skill / progressive-disclosure / design-pattern`，正文六个小节（定义 / 三层渐进披露 / 边界 / 实用对照 / See Also）**零风险面**，`last_updated` 还停在 **2026-09-09**（全库最旧之一）。而 overview 的 Cluster E 更把它写成生态的**打包格式**（372 / 216 / 193 skills）—— 一个纯增益叙事。

这篇的锋利处不在"Skill 有风险"这种泛论，而在**数字的形状**：

- 良性任务准确率 **+10.3 pp**，不安全操作率 **+10.3 pp** —— **同一个数**。能力的增益与违规的增益**同源、同量、同一次注入**。
- **专家策展的 Skill 一样退化** ⇒ 不是"低质量 Skill 的问题"，是这种抽象本身的性质。
- 「按良性反馈**进化** Skill 会放大不安全执行」⇒ 与 11-06A（写入侧监督信号自监督化）正面相撞：那篇说可以用自监督信号把 Skill / 记忆写得更好，这篇说**写得越好，违规越多**。
- 「检索到的 Skill **与任务匹配、且含程序性指导**时退化最明显」⇒ 正是 `ProgressiveDisclosure` 的**工作方式**（按相关性加载）成了风险放大器。**加载得越准，越容易越界。**
- 「把良性经验**蒸馏**成可复用 Skill，UAR 高于其来源轨迹本身」⇒ 抽象一层，风险涨一档。
- 唯一正面结果：**在执行前检查拟议工具动作的 guard 能减少违规、同时保住良性增益** ⇒ 又一次实证「闸门要放在模型之外、执行之前」（Cluster D 的排序主张第一次被用来**同时**兜住能力和安全）。

**边界辨析要点（与已覆盖概念切分）**
- **vs `Skill`（源头概念页）**：那页讲的是 Skill **怎么被加载**（三层渐进披露 / 相关性自动判定 / 代码一等公民）。本条讲的是**被加载的东西本身携带行为**——加载机制没错，被加载物才是风险源。落点应是 `Skill.md` 新增一节，**不是**改写 `ProgressiveDisclosure.md`。
- **vs `ProgressiveDisclosure`**：那页的主题是"按需加载以省上下文"。本条给出它的**代价面**：相关性判定越准，程序性指导越完整，越容易把"做法"连同"用途判断"一起塞进上下文 —— 模型看见了步骤，就按步骤走，**危险识别还在，只是不再改变行动**（这正是微波炉示例的机理）。
- **vs `ToolHallucination` / Cluster D 闸门**：那条链问「工具**存在吗** → **可以吗** → **现在行吗**」。本条的风险在更上游：工具全是真的、权限全是对的、时机也对，**是"会做"这件事本身让人去做了**。所以 guard 有效不是因为拦下了不存在的调用，而是因为它在**动作成形后、执行前**重新问了一次"这该做吗"。
- **vs `MemoryPoisoning`**：那页的机制是**攻击者写入**（诱导自写 / 伪造历史），来源是外部。本条**没有攻击者**，来源是**你自己精心准备的良性资产**。⇒ 这是本库第一条"**无对手的失效**"，比中毒更难防，因为没有任何异常可检测。
- **vs 11-06B 能力不可组合性**：11-06B 说"能力加了但交付没加上"（损耗）；本条说"能力加了，违规也加上了"（**反向增益**）。同一句"任务级能力 ≠ 组合后结果"的**两个方向**，必须互相点名否则读起来像重复。

### 11-07B · 群体记忆的两处不对称 / Group-Owned Memory ⭐⭐⭐

**一句话定义**：当记忆的归属主体从「一个用户」变成「一个频道」，两个前提同时失效 —— **读的范围大于写的范围**（公共频道的笔记被所有频道读取，私有频道只读不写），以及**权限的边界不是签发时的范围，而是成员集合的当前状态**（挂在公共频道上的凭证，从此对**每一个后来加入的人**生效）。

**为什么"当下"最有价值 —— 缝在哪**
overview 有一条**明写为 unwritten** 的开放项，从 2026-09-24 挂到现在：

> "Multi-agent memory sharing and role-based access control on shared persistent memory … **what remains unwritten is a concrete cross-agent policy language or product.**"

本期同时到手**论文 + 产品**，而且两者指向同一个结构缺口：

- **`MultiAgent.md` 第 21 行的边界句**自己写着：「multi-agent 是**同一时刻跨 agent** 的共享状态（空间维）；`LongTermMemory` 是**跨会话**的持久化（时间维）；**两者互补，团队共享记忆的治理是它们的开放交集**」。这句话挂了一个"交集"，一直没人填。
- 但本期两份材料填的**不是那个交集**，而是**第三个位置**：`MultiAgent` 讲的是 **agent 与 agent 互为同事**；Claude Tag 是 **一个 agent 服务一群人**，共享一份记忆。主体既不是单个用户，也不是对等 agent，而是**群体本身**。
- **`MemoryGovernance` 的四条底线（auditable / rollbackable / permissioned / signature-verified）在这里全部变形**：任何频道成员都可以问"你记得什么"并**纠正或删除**条目 —— "permissioned" 变成了"在场者皆可改"；"auditable" 要审的对象从"谁写了这条"变成"这条属于哪个频道、谁能读"。
- 与 **`AgentIdentity` 的 per-hop attenuation 直接冲突**：那页的核心是「**一次签发、逐跳收窄**，scope / magnitude / validity / depth 只能缩」。而 channel-scoped 凭证是「**一次签发、随成员变动隐性扩张**」—— 今天挂上去，六个月后每个新加入的人都继承它。**衰减模型没有"成员集合"这个变量**，所以它表达不了这种扩张。
- **`Abstention` / `CitationLock` 的读取侧也失真**：workspace notes 从公共频道写入、在**每个**频道被读取 ⇒ 「我引用的这条，写入者当时有权写吗？读它的人现在有权读吗？」两个问题分离了，而本库三件套（Provenance / CitationLock / Abstention）都隐含**写入者与读者是同一权限主体**这个单用户前提。

### 11-07C · 工具更新的信任失效 / The Tool Update Gap ⭐⭐⭐

**一句话定义**：agent 框架对工具的信任是**一次性授予**的，但工具的代码会变 —— 更新后的工具**保留全部合法功能**（95.9% 任务完成率），同时在**上下文窗口之外**执行恶意逻辑（97.6% 攻击成功率），因此所有"模型能看见什么"的防御**结构上看不见它**。

**为什么"当下"最有价值 —— 缝在哪**
`ToolHallucination` 的 resolution rung 是本库写得最锋利的一条机制：① 工具名是否属于**封闭注册表**；② 契约签名是否匹配**可信来源**。它的价值写在"**位置而非算法**"—— 必须坐在所有闸门上游。

但这条 rung 有**两个隐含前提**，本期被同时打掉：

1. **「注册表成员资格」是瞬时的，不是持续的。** rung 在 dispatch 时查一次，通过就放行。ETUDE 的攻击不改工具名、不改 schema、不改描述 —— **签名校验也过**，因为变的是**实现体**。⇒ rung 检的是**契约**，不是**构件**；`signature match` 保不住"同一个契约下换了代码"。
2. **「不存在」不是唯一的结构性盲区，「不再是原来那个」也是。** 那页已有的 10-19A 边界注写得很清楚：「existence is not the variable」（TRACER：工具输出通道 95%）。本期把这条边界**再往前推一格**：连"工具是真的、是注册过的、签名也对得上"都不够 —— **它还得是签发信任时的那个二进制**。

两篇材料一周内独立出现，正好是「机制 + 实测」两个形态：

| | ETUDE（攻击设计） | mcpvenom（跨框架实测） |
|---|---|---|
| 团队 | Shiyu Kan + 10 人 | Farooq Shaikh / Biagio Montaruli（Dynatrace Linz） |
| 时间 | v1 **2026-11-01** | v1 **2026-11-02**（矩阵实测 7/22–7/24） |

- **vs `MCP`**：那页记的是 2026-07-28 revision 的**协议层无状态化**（去 handshake、`_meta` 携带版本、缓存化 list）。本条指出该 revision **没有解决信任链**：协议越无状态，逐次复核的责任越落在宿主侧，而 12 个框架**零处有意防御**。⇒ 与 `MCP` 页「生态影响」段并列，不冲突。
- **vs 11-04A / 11-04B（注入轴）**：那条轴分"野外频率 / 事前审计 / 事后恢复"，全部假设**载荷从外面进来**。本条载荷**是工具自己的一部分**，没有"外来"这个环节 ⇒ 时位轴需要第四格：**签发后**（post-attestation）。
- **vs `MemoryPoisoning`**：机制同形（**一次性信任 + 后续可变**），对象不同（记忆条目 vs 工具构件）。两页应互指，因为"信任会过期"这个句子在两处都成立。
- **vs `AgentSandbox`**：沙箱关"能碰到什么"，本条关"它到底是什么"。**执行隔离不校验构件完整性** —— 这是两层，不可互相替代。
