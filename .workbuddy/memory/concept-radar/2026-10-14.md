### 候选 1 ⭐（新行 10-14A）｜**跨主体状态隔离 —— 这条推理状态是谁的** / Cross-Principal State Isolation（Context Bleed / Tenant Isolation）

| 项 | 内容 |
|---|---|
| **为什么「当下」最有价值** | [[AgentIdentity]] 把「**on whose behalf**」做成了凭据链（RFC 8693 + 逐跳收窄），[[MemoryGovernance]] 把「**谁有权增删**」做成了决策权三分（人 / 策略 / 攻击者），10-13「检索准入」把「**这条记忆该不该进这次回答**」做成了入口闸门 —— **唯独没有一页问「这条推理状态归哪个主体」**。而今天三路证据同时指认这一格，且**承重事实是一个已编号、已修补的真实漏洞**：🔴 **CVE-2026-105752**（vLLM prefix cache 租户隔离失效）。更关键的是这条缝的**形状**：**入口闸门解决不了它** —— 泄漏发生在**已被准入的共享状态内部**（prefix cache / 共享会话记忆），不是「该不该放进来」能拦住的。 |
| **一句话定义** | 当同一个 agent（或同一个推理运行时）服务**多个目标可能冲突的主体**时，若它维持**共享推理状态**，则一个主体的目标会**因果地**影响另一个主体的决策；因此需要**按关系/主体切分状态（relationship-specific state isolation）**，而不是只按条目做准入判定。 |
| **边界辨析** | vs **[[AgentIdentity]]**（**凭据侧**：who acts、on whose behalf、逐跳收窄 —— 本行是**状态侧**那一半，身份页至今只写了凭据，没写「上下文归谁」）· vs **[[MemoryGovernance]]**（**决策权：谁有权增删改** vs **归属：这条状态属于谁** —— 「有权改」≠「归他所有」）· vs **10-13「检索准入」**（**逐条记忆的入口闸门** vs **闸门之下的结构问题**；且 10-13 的准入类别里已含 *belongs to another user* ⇒ 本行给它补的是「**即使建了这道闸门，泄漏仍在发生**」的实测证据 + 一个**非策略层的干预位置**）· vs **[[MemoryPoisoning]]**（**外部攻击者写入** vs **两个都是合法主体、无攻击者**）· vs **[[MultiAgent]]**（wiki 的正面主张是「**共享工作区交换已验证进展**」；本行给出它的**边界条件**：共享在**同一主体内部**是收益，**跨主体时是泄漏通道**）· vs **[[AgentSandbox]]**（**容器边界：能碰到什么** vs **推理状态边界：这次推理里混进了谁**）· vs **10-09「由内而外监控」**（**读内部激活做观察** vs **在 KV cache 定位并消融做干预**）。 |
| **建议下一步** | **低成本三处页修订优先**：① `concepts/AgentIdentity.md` 增「**状态侧身份：推理状态按主体切分**」一节；② `concepts/MemoryGovernance.md` 增「**归属 ≠ 权限**」一行；③ `concepts/AgentSandbox.md` 增「**容器边界 ≠ 推理状态边界**」一句。若做材料 → `output/pending-review/cross-principal-isolation.html`，骨架 =「**三种泄漏通道对照（prefix cache / 共享会话记忆 / 检索缓冲）× 两栏（发生在哪一层 · 闸门能不能挡住）**」+「**主体切分审计自查清单**」。⚠️ 受 README「人工核查承诺」约束，**未写入 `learning-materials/`**。 |

**2026-10 三路证据（全部 [verified]）**

1. 🔴 **CVE-2026-105752 — vLLM Prefix Cache Information Disclosure**（NVD **2026-10-05** 发布 / 2026-10-06 更新；SentinelOne 漏洞库）。**vLLM < 0.30.0** 的 `POST /v1/responses` Harmony 工具续接路径在**重建下一轮引擎输入时未传播 `cache_salt`**，使续接前缀落入**全局未加盐的 prefix cache 命名空间**——即使调用方启用了 salting。prefix caching **默认开启**；已认证租户可对受害者的低熵工具后历史做重放，通过 `cached_tokens_per_turn` 计数做**存在性预言**，判断该前缀是否被其他租户处理过。CWE-200（信息泄露），**0.30.0 修复**。⇒ 这是「跨主体状态隔离」在真实推理引擎里**已被编号、已被修补**的实例。
2. **arXiv:2610.17365v1《When Goals Leak Across Relationships》**（Saloni Gupta / Sébastien Krier / Glenn Matlin，**2026-10-12**）。agent 同时服务多个**目标冲突**的客户时若维持**共享推理状态**，一个关系的信息会影响另一个关系的决策。**OLMo-3-7B-Instruct**、**两客户受控环境**、**20 个市场场景**（每客户被赋予相反目标）⇒ **共享会话记忆下 22% 的可判定决策偏离当前客户目标**。随后追到 **KV cache**：线性探针显示 **client-goal ownership 在中层高度可恢复、且集中于特定注意力头**；**在这些位置消融对手方的缓存目标表征会把模型拉回当前客户**，且**探针定位的头优于随机头**、**消融目标 token 优于同客户的非目标 token** ⇒ **因果而非相关**。原文结句：**relationship-specific state isolation in persistent LLM agents**。
3. **Lineage-Aware Memory Governance**（**2026-10-05**，摘要级）。面向**企业** AI agent 的**推导门控（derivation-gated）列级访问控制**：防护的是「**一个合法算出的结果，请求方本无法自行推导出来**」这类泄漏，以及**同名 KPI 在不同部门逻辑冲突**；明确定位为与 MemGPT / Zep / A-MEM 对照。⇒ 与上面两条合起来是「**协议/内存层 + 企业语义层**」两侧同时缺这一格。

**核心「但是」（须进第一屏）**

- 🔴 **CVE 的严重性要按它的实际范围读**：它是**时序预言**（推断某前缀是否被处理过），**不是**直接读出对方内容；且作用域是 **vLLM < 0.30.0 + 已认证租户 + prefix caching 默认开启**。它证明的是「**隔离机制存在且已被绕过的实例**」，**不是**「所有框架都在泄」。
- ⚠️ **2610.17365v1 是预印本、单模型（OLMo-3-7B-Instruct）、单一受控环境（20 场景）**；**22% 不能读作线上发生率**。它的价值在**因果链**（探针定位 → 消融 → 行为改变），不在数字的外推。
- ⚠️ 与 10-13「检索准入」的**接缝要说清，不要重复计数**：10-13 已把 *belongs to another user* 列为准入类别。本行的增量是**两层**——(a) 实测证明**光有这道闸门不够**；(b) 干预位置**不在检索策略层，而在 KV cache / 命名空间层**。若你认为这属于同族，**应并入 10-13 行而非另起一行**（本期未擅自合并）。

**2026-10-13 两篇一手论文（[verified]）**

1. **《Beyond Memory: Harnessing Long-Horizon Agents with Explicit Belief States》（PoS）** — 南开大学 + 阿里云 + 清华大学；arXiv **2610.01415**；项目页 `luoyu100.github.io/projects/progression-of-states/`；代码 `github.com/luoyu100/PoS`。
   - 长程任务里信息会过时：杯子刚才在微波炉里、现在可能已被拿走；一次工具调用只表达「要做什么」，**返回的观察才说明实际发生了什么**；前几轮看似合理的判断会被新证据推翻。完整轨迹保留顺序、记忆与压缩负责筛选整理 —— 但**每次选动作时，智能体仍要把分散的信息重新拼成对当前任务的理解**。PoS 把这一步**显式化**。
   - **信念 = 智能体基于已有证据形成的当前理解**（既有直接观察，也有仍待检验的推断），**可被更新、被检查，也可能出错**。
   - 第一步「现在是什么情况」：用**实体 / 状态 / 关系**组织世界（杯子、微波炉、柜子 = 实体；杯子是否热、微波炉是否关闭 = 状态；杯子在哪、由谁拿着 = 关系），**状态和关系保留来源、置信度与可用支持证据**；只保留会影响行动、结果判断与目标完成的信息（记「温度与位置」，不记「曾经操作过微波炉」）。
   - 第二步「还差什么」：**信息缺口 Epistemic Gap**（还需弄清楚的事）／**达成缺口 Achievement Gap**（还需通过行动改变的事）。
   - 闭环 = **从识别「已经卡住」（Belief Trapping）到决定「怎样恢复进展」**。**4 个基准 × 3 个基础模型 = 12 组设置**，PoS 整体指标均高于论文纳入比较的其他方法。
2. **《Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents》** — Yuchen Lu / Julian McAuley / Lei Zhang；arXiv **2610.18784**；**2026-10-13 提交**。
   - 问题句：长程 agent 把进度累积在**持久任务状态**里，却反复处理**描述该进度如何取得的交互历史** ⇒ 能否把长程上下文**围绕可复用的进度**而不是产生它的历史来组织？
   - CarryOn = **面向对象的上下文运行时**：由 **continuation carriers**（延续载体）+ 补充执行上下文 + 近期交互的活动尾部构成上下文视图；**明确不以「压缩后的历史」或「重建出的进度叙述」为延续的主要依据**。
