## 候选 1 ⭐ LLM — 编排层 — 工具 的信任边界
### The LLM–Orchestrator–Tool Trust Boundary

### 为什么「当下」最有价值

**一句话**:wiki 的 Cluster D 链条里**没有「编排层」这个参与者** —— 它默认「模型输出 = 意图」,也默认「工具会执行它自己声明的语义」;ToFu 用一次**平凡到可笑**的攻击证明这两条默认**同时不成立**,而且**模型说「不」与编排层做「是」可以同一个回合里发生**。

这一格之所以是「当下」而不是「一直存在」:

1. **它直接否定了一条 wiki 已经写进 overview 的横断主题**。「顺序是一等设计对象」自 2026-09-24 起是承重主题,而拒答**在工具返回之后才到达**意味着 —— **顺序是框架实现的属性,不是你设计的属性**。你画的那条链,执行时不是那条链。
2. **它给了「封闭世界消解那一档」一个规模数字**。`[[ToolHallucination]]` 要求在任何闸门之前加一档「工具在不在注册表里 + 签名对不对」。ToFu 的攻击里**工具真的存在、参数格式完全合法**,那一档**照放不误**;而同一篇论文顺手测了 **273 个 MCP server / 3,405 个工具,118 个 server 上的 343 个工具有已验证缺陷** —— 这是 wiki 第一次拿到「那一档**实际上没装**」的生态级证据(43% 的 server 中招)。
3. **它给 `Agent = Model + Harness` 补了第五件没人列过的事**。`[[AgentHarness]]` 列了四条职责(组上下文 / 跑循环判停 / 管窗口 / 保活恢复),**没有一条说「编排层本身是一个信任主体」** —— 它把文本解释成调用,这个解释动作**就是一次授权**。

### 一句话定义

> **在「模型 → 编排层 → 工具」这条链上,编排层把模型输出文本解释成结构化调用并直接派发;这个解释动作本身就是一次授权,而工具又常常不执行它自己声明的输入语义 —— 于是「模型说了不」与「工具已经做了」可以同时为真。**

机制要点(可落成骨架):

- **攻击面 = Repeat-After-Me**:攻击者知道编排层识别的调用格式 ⇒ 写出「目标工具 + 自己的参数」的文本 ⇒ 让模型逐字复述 ⇒ 模型只是在复述,编排层当成调用派发。
- **六个框架复现**:LangGraph · Microsoft Agent Framework · AutoGen · Google ADK 2.0 · AWS Strands Agents · CrewAI。
- **承重 transcript**(LangGraph 1.2.0 + Llama 3.1 8B,两个 dummy 工具 `make_bomb` / `launch_missiles`,唯一防线是 system prompt):
  1. 第一次要求复述 → 模型**拒答但把调用当文本打印出来** → 编排层什么都没跑;
  2. 改 framing 为「假设性」并要求只输出被引用的文本 → 模型以结构化形式返回 → **LangGraph 立即用攻击者的参数执行**;
  3. **模型的拒答在工具返回之后才到达。**
- **ToFu 第二腿(生态级)**:74 个语义感知 sanitizer / 21 个内省 tracer,从工具自己的 metadata + CWE 语料自动生成检查与模糊测试 harness。273 server / 3,405 工具,508 个候选 flag 人工复核后 **253 个已验证缺陷**,落在 **343 个工具 / 118 个 server**:

## 候选 2 ⭐ 协议枢转 —— 跨智能体的授权继承
### Protocol Pivoting & Cross-Agent Authorization Inheritance

### 为什么「当下」最有价值

**一句话**:`[[AgentIdentity]]` 逐跳收窄的是**凭据**,`[[MultiAgent]]` 记录的 cross-contamination **自 2026-09-26 起一句证据都没有**(整页标 secondhand);而今天这一格拿到了 **CVE 级、跨五家互不相关机构**的实证 —— 漏洞不在凭据,而在**「这个任务凭什么带着权威走」**。

三条「当下」的理由:

1. **它填的是 `[[MultiAgent]]` 的空洞,不是新增一格**。wiki 从 2026-09-26 起写着「共享工作区会退化成 cross-contamination」—— 但那是**推论**。现在 Google / JPMorgan / Weaviate / 法国 DINUM / 印尼 Tangerang 五家机构在同一类缺陷上确认并修复,**美国联邦五个 MCP server 截至报道仍在分流**。这是推论第一次变成事实。
2. **它给出了「授权被继承」的判据句**。[[AgentIdentity]] 的 RFC 8693 收窄覆盖「**谁可以行动**」,本行指出**空的是「批准了什么」**这一半 —— 修复规则应当写成:**每一次协议转换都触发一次新的授权,而不是继承上游的决定**。
3. **CVE-2026-14540 的修复方式本身就是教学材料**:Google 不是「修了 SSRF」,而是**在启动时拒绝不安全的 base URL,而不是在首次请求时**,再加连接时解析地址检查 + IP 黑白名单。研究者的原话:「*That is what a real SSRF guard looks like. It is also more work than most MCP servers have done.*」—— **控制的位置又是答案**,和候选 1 同一条横断主题。

### 一句话定义

> **攻击者把指令种进某个 agent 会读的内容;该 agent 把它当作一条正常的委派任务转给它信任的同伴;同伴因「信任上游」而执行 —— 毒指令经 MCP 进来、跨进 A2A 或 Agent Network Protocol,中间的授权边界就丢了。研究者称之为「协议枢转」。**

机制要点:

- **为什么 LLM 拦不住**:MCP server **为每个 agent 存凭据**,且**内网 agent 被预设互相信任** ⇒ 一个本会被 LLM 拒绝的利用,在这里成功。
- **落点多为 SSRF**:Google 的 MCP Toolbox for Databases 用 Go HTTP client 初始化时**没设 `CheckRedirect` 策略、没验证目标 IP** ⇒ 构造路径参数可让它跟随重定向到内部端点,甚至云 metadata 地址 **169.254.169.254**(吐 IAM 凭据)。
- **根因句(Rapid7 · Douglas McKee)**:「*Each protocol was built assuming it lived on its own, so each one checks its own front door while nobody watches the hallway in between.*」—— 操作化版本:**依赖扫描器看不见「以委派文本形式到达的工具参数」**。
- **反驳必须与结论同屏**(X41 D-Sec · Markus Vervier):更准确的说法仍是**间接提示注入**,跨协议 hop「*is not strictly required for such attacks to work*」⇒ **不是新品类,是老品类有了新的可达范围**。
- 时间线:研究者 Syed Anas Mohiuddin 用约五个月推进;将于 **MCPCon North America 2026-10-23** 演讲。

| `[[MultiAgent]]`(共享工作区 / verifier 前置条件) | 本页把 cross-contamination 记为失败面但**无证据**。本行是它的 **CVE 级实证**;且把前置条件从「要有 verifier」精确到「**要有跨协议的新授权**」。 |

## 候选 3 厂商托管的记忆层 —— 第四个决定者
### Vendor-Operated Memory: The Fourth Decider

> **不标 ⭐** —— 它是既有 [[MemoryGovernance]] 的**增补一格**,不是新簇;且本期一手性最弱(模型卡经二手转述)。

### 为什么「当下」最有价值

**一句话**:`[[MemoryGovernance]]` 明确列了**三个决定者**(人工规则 / 可训练策略 / **攻击者**),并写下「**空着的控制位不会一直空着**」—— 但**记忆层一旦住进你不运营的模型 API 里,决定者就是第四个:厂商**。这一格 wiki 里是空的。

三条理由:

1. **它把三条治理底线移出了部署方可达范围**。[[MemoryGovernance]] 的四条底线是 可审计 · 可回滚 · 有权限 · 信签名。当记忆在厂商侧:**谁定保留期?删除请求到底删了什么?哪条被记住的细节影响了这一次输出?** —— 三问**没有一页回答**,而第三问是 [[Provenance]] 从未被问过的形式。
2. **一手评论者自己点出了这个缺口**:「Meta 的公告没有描述记忆上限,也没有说明你会如何查看和清除它存了什么」—— 这不是我的推断,是评测方的原话。
3. **顺带拿到一个可以迁移一辈子的教学件**:Meta 自己的模型卡里,**ExploitGym 拿到 92 个 flag,验证后只有 21 个走了预期漏洞路径,71 个走非预期路径;因为公开排名只统计预期漏洞利用,可比的数字是 21**。⇒ **厂商在自己的模型卡里披露了自己的数字经不起路径核验**。这是 wiki 既有「厂商自报 ≠ 已独立复现」分栏纪律**最干净的一个实例**,且可推广成一句判据:**验证路径,而不是验证头条数字。**

### 一句话定义

> **当「跨会话记忆」由模型厂商而不是部署方运营时,记忆的决定者从三个变成四个 —— 保留期、删除语义、以及「哪条被记住的细节影响了这次输出」这三项治理权,随记忆一起交给了你不运营的一方。**
