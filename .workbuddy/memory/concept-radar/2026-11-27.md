### 11-27A 压缩的行为保真 / Behavior-Preserving Compaction（RECAP） ⭐⭐

**一句话**：长任务里把历史换成摘要，训练和评判摘要时该用什么信号？RECAP 的回答不是「摘要像不像原文」，而是「**摘要诱导出的后续行为，和原历史诱导出的行为差多少**」。它把这个「行为失真」写成目标函数，梯度分解成两路互补信号——给摘要生成的 distortion-based reward，和给压缩后动作的 self-distillation。在 Qwen3.5-4B 上两个环境都稳定超过只给任务奖励的 RL 基线，BrowseComp-plus 绝对提升 **4.6%**、SWE-bench Verified 绝对提升 **4.3%**；消融确认「同时监督摘要生成与压缩后行为」是收益来源。3 作者（Yulun Jiang / Maria Brbic / Michael Moor），**v1 2026-10-19**，cs.CL+AI。

- **概念名（中英）**：压缩的行为保真 / Behavior-Preserving Compaction（RECAP，behavior distortion objective）
- **为什么"当下"最有价值**：[[Compaction]] 页与扩展十一把压缩写成「有损摘要 + 读手可能被污染」，但从未把「**摘要该保住什么**」设成可优化、可评判的目标；A 把保真锚点从文本移到行为，正好补上这一格，并与 11-26A（压缩触发权归 harness 还是模型）凑成一对——一个问「谁来触发」，一个问「保什么」。同时它是台账第 6 条训练—部署一致性审计（扩展八）在压缩这一格的实例：压缩器与被压缩后的策略必须联合训练、共同评判，否则「训得好、上线崩」。
- **来源链接（均 [verified]，一手 abs 已 WebFetch 直开核验）**：
  - https://arxiv.org/abs/2611.31258 [verified] —— 一手 abs（直开）：标题、3 作者、v1 2026-10-19、cs.CL+AI、行为失真目标与两路学习信号、Qwen3.5-4B 与 4.6%/4.3% 全部出自此页摘要
  - https://arxiv.org/pdf/2611.31258 [verified] —— 一手 PDF（abs 页 View PDF 链接）
  - https://arxiv.org/html/2611.31258v1 [verified] —— 一手 HTML 全文（abs 页 HTML 链接）
- **一句话定义 + 边界辨析**：定义——把上下文压缩的目标从「摘要保住原文的语义/文本」改成「摘要保住原历史所诱导的后续行为」，据此把梯度拆成摘要生成的失真奖励与后续动作的自蒸馏两路联合训练。边界：① vs 11-26A（模型经 context API 自控压缩）——那条争「**谁来触发**压缩」，本条争「**压缩该保什么、怎么训**」，一个在控制主体、一个在保真判据；② vs [[Compaction]] 有损压缩——本条不改压缩在窗口中的机制位置，改的是评判压缩好坏的那把尺子；③ vs 11-25B（逐条折叠 > 滚动摘要，保留单位）——那条在「**留什么单位**」，本条在「**用什么信号判断留得对**」；④ vs 扩展八训练—部署一致性——那条问「训练时与部署时是不是同一个 harness」，本条把该一致性下沉到「摘要前后是不是同一段行为」，不是同一层。
- **⚠️ 证据边界**：预印本、单团队自报、单一骨干（Qwen3.5-4B，未跨模型/跨规模）；v1 实为 **2026-10-19**，是 11 月下旬 digest 重新回到视野的 10 月作品，**不是本周新论文**，推荐理由是与本期接缝的契合度而非时效；4.6%/4.3% 为两个环境上的绝对提升，摘要未给基线绝对值与方差；行为失真的具体度量（KL / 动作分布差异？）与 RL 配方须开 PDF；未测长上下文与多模态（接 11-08 零视觉盲区）。成篇前须开 PDF 核目标函数形式与消融分表。

### 11-27B 记忆量的模型归属 / Model-Relative Memory Budget（IBM 自蒸馏记忆） ⭐⭐⭐

**一句话**：一个已真正上线的 agent 记忆流水线——先从自身轨迹挖每回合 1–3 条简短教训（lesson），再合并成更小的指南集（guideline，每条记录自己合并了多少条教训），推理时要么全量注入、要么给精选子集；随开源库 `altk-evolve` 发布，已部署在 IBM 的 **CUGA agent 与 watsonx Orchestrate 平台**。以 AppWorld 为仪器、覆盖基线完成率 40–92% 的多个模型，核心发现是一句反直觉的话：**该记多少，是模型的属性，不是记忆的属性**。强模型 DeepSeek-V3.2 带着全部 191 条指南还在涨（任务完成 **+9.5 分**、场景完成 **+16.1 分**）；弱模型 gpt-oss-120b 从 39.9% 起步，全量 199 条只到 51.2%，而**精选约 29 条反而到 55.4%**（两次运行均值）。围绕这个结果，作者如实写了四件搞砸的事：一条高支持度指南反而帮倒忙、合并时 provenance 被静默丢掉、一个被吞掉的 API error 让所有任务失败却留下看似正常的日志、以及一个差点造成与既有方法错误对比的 baseline confound。9 作者（K. R. Jayaram 等，IBM），**v1 2026-11-19**，cs.AI，**IAAI 2027 Oral 录用**。

- **概念名（中英）**：记忆量的模型归属 / Model-Relative Memory Budget（self-distilled lessons → guidelines，IBM）
- **为什么"当下"最有价值**：台账第 21 条「边际价值审计」的四例都把边际价值锚在对象侧（协作 / 单条记忆 / 加法伴生结构 / 记忆累积），本条第一次把**读者模型能力**设为自变量——同一批自蒸馏指南，换读者后「多记」的符号翻转（强模型全量增益 vs 弱模型精选反胜），这是审计线迄今最干净的主体侧反例，也与 11-23B MemCredit「效用依赖状态」成「状态侧→读者侧」对偶。同时 `overview.md` 反复记着「记忆治理没有生产证据、六个可训练策略全部未投产」——本条是 IBM 真实部署的产品复盘，且把「合并时 provenance 静默丢失」这类只有产品化才暴露的失败写进一手摘要，正面给 [[Provenance]] 与 [[MemoryGovernance]] 补生产侧反面证据。
- **来源链接（均 [verified]，一手 abs 已 WebFetch 直开核验）**：
  - https://arxiv.org/abs/2611.26361 [verified] —— 一手 abs（直开）：标题、9 作者（IBM）、v1 2026-11-19、cs.AI、IAAI 2027 Oral 标注、altk-evolve / CUGA / watsonx Orchestrate 部署信息、+9.5/+16.1 与 39.9/51.2/55.4 全部量化结论出自此页摘要
  - https://arxiv.org/pdf/2611.26361 [verified] —— 一手 PDF（abs 页 View PDF 链接）
  - https://arxiv.org/html/2611.26361v1 [verified] —— 一手 HTML 全文（abs 页 HTML 链接）
- **一句话定义 + 边界辨析**：定义——把 agent 轨迹挖成教训、合并成带合并计数与出处的指南集，并按读者模型能力决定全量注入还是精选子集；核心结论是「合适的记忆量是模型的函数」。边界：① vs 11-26B AdMem（逐动作信用 + utility 淘汰）——那条给每条记忆算信用与生命周期，本条不改条目算法、只改「注入多少由谁决定」，一个在条目级、一个在读者级；② vs 11-23B MemCredit（反事实边际贡献估计）——那条估「这条记忆对决策有多大用」，本条指出这个「多大用」随读者模型翻转，是它的上位变量；③ vs 扩展六记忆治理（四条底线）——本条用「合并时 provenance 静默丢失」给出审计底线在生产中被破坏的真实例子，是治理页的反面证据而非重复；④ vs 11-22B GrepMem（append-only 纯文本日志）——那条争「不抽取、全留、靠 grep」，本条争「抽取合并后留多少、看读者」，两条在同一「写入侧取舍」轴两端，可互证。
- **⚠️ 证据边界**：IAAI 2027 Oral（同行评审强于普通预印本），但作者全为 IBM、单一产品（CUGA / watsonx）自报；仪器为 AppWorld 单一基准，40–92% 基线跨度靠多个模型而非多任务域；gpt-oss-120b 的 55.4% 是**两次运行均值**（摘要明写），+9.5/+16.1 是 DeepSeek-V3.2 特定配置；「29 条精选」的选取规则与成本摘要未披露；四个失败案例是作者自陈，未给发生频率。成篇须开 PDF 核选取算法、合并计数是否真的承载 provenance、以及 baseline confound 的处置。

### 11-27C 恢复机制的真实证据 / Evidence-Based Recovery Auditing（Exercised, Rarely Recovered） ⭐⭐⭐

**一句话**：当编码 agent 删错文件、长任务跑崩，用户靠 checkpoint 续跑、undo、请求审批、读日志来恢复；研究型 runtime 还承诺 saga 补偿与事务回滚。这些机制在真实使用中到底成不成？作者在数据收集前冻结评级协议，对 **12 个持久化 agent runtime、26 个编码 agent harness、12 个研究 runtime**（共 50 个）在八类恢复机制上逐条评级（从「没找到」到「在真实运行中被用过」），两轮盲编码、仲裁、并对照归档来源复核。结论：**恢复几乎处处被用到**（11/12 runtime、25/26 harness 至少有一份真实使用报告），但 128 份这样的报告里只有 **19 份完整恢复**、54 份部分恢复、45 份失败；checkpoint/resume 在 27 份报告里只成功 **1 次**，rollback 在 15 份里只成功 **1 次**。研究 runtime 呈相反画像——保证在基准上被评估、运行中没有一份报告，而其**核心保证「外部效应补偿」没有任何一个 harness 提供**。单作者（Kaviru Hapuarachchi），v1 2026-11-20，cs.SE+AI+MA，5 页 2 图，附复现数据集（Zenodo DOI）。

- **概念名（中英）**：恢复机制的真实证据 / Evidence-Based Recovery Auditing（Exercised, Rarely Recovered）
- **为什么"当下"最有价值**：`overview.md` 把「persistent execution 的跨运行时语义比较」列为开放项，`concept-relationship.md` 扩展七只落到「none of them holds by default」这句断言；C 第一次用统一协议把 50 个运行时拉到同一把尺子上，把那句断言升级为**可引用的分表证据**，也正面接上台账**第 8 条「已安装性审计」**（有人实测过它在起作用吗、测的是哪一层）——此前 [[AgentHarness]] 的「保活/恢复」职责与 [[HumanInTheLoop]] 的「暂停可持久化、恢复可幂等」要求都停在规格层，没有一份「实际恢复成功率」的证据。它还与 11-24B（快照缺本地 OAuth scope 检查）成一对：一条从单个产品里扒出缺口，一条从 50 个产品的公开报告里扒出系统性缺口。
- **来源链接（均 [verified]，一手 abs 已 WebFetch 直开核验）**：
  - https://arxiv.org/abs/2611.27090 [verified] —— 一手 abs（直开）：标题、单作者、v1 2026-11-20、cs.SE+AI+MA、5 页 2 图、Zenodo 复现数据集 DOI、50 个运行时与 128/19/54/45、27 份 1 次、15 份 1 次、「补偿无任何 harness 提供」全部出自此页摘要
  - https://arxiv.org/pdf/2611.27090 [verified] —— 一手 PDF（abs 页 View PDF 链接）
  - https://arxiv.org/html/2611.27090v1 [verified] —— 一手 HTML 全文（abs 页 HTML 链接）
- **一句话定义 + 边界辨析**：定义——用预先冻结的评级协议与双盲编码，对公开报告中 agent 恢复机制「是否真在真实运行里成功过」逐条评级，以证据而非承诺衡量恢复能力。边界：① vs 扩展七持久化执行（durable runs / lifecycle controls）——那层讲的是「有哪些机制、语义有何不同」（设计空间），本条讲「这些机制在真实使用里成不成」（证据空间）；② vs [[HumanInTheLoop]] 闸门——闸门要求「暂停持久、恢复幂等」，本条测的是这条要求在 50 个实现里究竟兑现了几次，是它的验收侧；③ vs 11-24B Safe Personal RSI（快照缺 scope 检查）——那条是单产品深度审计，本条是跨产品广度评级，两者一深一广；④ vs 第 21 条边际价值审计——那条问「机制值不值成本」，本条问「机制有没有真的生效」，是它前置一步的「动词实效」（台账第 13 条动词实效审计，见 `SCAN-LINES.md`）。
