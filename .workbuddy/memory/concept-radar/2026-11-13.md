### 11-13A · 经验要写成能被推翻的样子才准入库 / Falsification-Gated Self-Evolution(FGSE)⭐⭐⭐

**一句话定义**:自演化 agent 默认把「这一段情节成功了」直接当成「这条经验可用」写进长期记忆,于是局部成功被误当成可复用知识;FGSE 把每条候选经验改写成**结构化假设**(显式前置条件 + 行为改变 + 预期效果 + 验证器),只在**临时态**里跑三道探针——**目标迁移 / 证伪 / 归档回归**——再按实测增益与风险决定 commit / refine / reject。

**为什么"当下"最有价值 —— 缝在哪**

- **直接答复 11-10A 留下的公开问题**。11-10 的原话判据是:「验证门槛是良性资产风险面的唯一治理答案——而**当前没有任何自演化系统测它**」。FGSE 第一次把门槛本身量化了:证伪失败 5.0%、回归损伤 1.3%、有害提交 3.6%。这不是又一篇自演化论文,而是把「入库要反复验证」这句口径**变成了可测的三道探针**。
- **补上 11-11A 的下半句**。11-11A(CLR-Bench)查明「库只增不减」的成因是**例外记账**;FGSE 给的是同一格的另一面:该记的是**可证伪形式**,而不是把例外删干净。两篇合起来才完整——一个说「为什么越堆越多」,一个说「什么才配进来」。
- **给 11-07A 的「无对手失效」配上治理手段**。11-07A 发现良性 Skill 会同时抬升准确率与不安全操作率(+10.3 pp / +10.3 pp 同一个数),当时结论是「检测式防御结构上无效」。FGSE 不检测,它在**入库前**就把候选经验按「能不能被推翻」筛一遍——属位置型防御,正好落在 11-07A 指出的唯一有效类别里。
- **时位新格**:此前本库的「事前」都在**执行前**;FGSE 的事前在**入库前**——比执行更早一个环节。

### 11-13B · 记不住来源的记忆不该被信任 / Evidence-Linked Memory(WikiTrace)⭐⭐⭐

**一句话定义**:外部记忆通常只保留蒸馏后的经验条目,丢掉产生它的那次运行,于是 agent 拿着结论却没有证据,无法核实;WikiTrace 把每条经验存成一句简短洞见,并**层层挂链**(洞见 → 成因摘要 → 原始轨迹):每条洞见记下它来自哪一次运行、那次运行是成是败,原始轨迹则原样保留;当洞见缺细节、彼此冲突、或来自失败运行时,agent 沿链**下钻**到源轨迹补齐或纠正后再动手。

**为什么"当下"最有价值 —— 缝在哪**

- **把本库记忆线的归因方向掰了回来**。`MemoryPoisoning` 系列一直假设毒是**对手写进去的**;WikiTrace 指出另一条更常见的路径:毒是**自己蒸馏出来的**——只用「成功/失败」一个标签去反推「哪个动作导致了这个结果」,必然靠猜。这是 11-07A「无对手的失效」在记忆线上的第一份实测。
- **给 `Provenance` 添一种「引用时」的用法**。本库的溯源概念此前都在**观测/审计**侧(11-04B 溯源图、11-12A 拿它当落刀坐标);这里溯源变成**读者手里的一把尺**——不是给审计员看的,是给正在用这条记忆的 agent 自己查的。
- **一个反直觉的操作结论**:证据链最值钱的时刻是**已经出错之后**。二手报道的拆解是:出错后下钻比「只有洞见」高 17.3 分,而例行前置检查只高 3.4 分。⇒ 「检查该在怀疑时触发,不该在每次任务前触发」——这条与 11-08C(审查预算:被问到的子决策更易失守)同域:审查资源有限,触发点选错就白花。
- **一条可直接迁移的度量纪律**:代码库同时报 **Gain**(无记忆会失败、本方法救回的占比)与 **Regression**(把本该成功的变成失败的占比)。只报前者,沉默退化就不可见——这正是 10-29A「记忆税」在**指标设计**层的落地。

**数字(一手摘要无数字;以下为二手转述,单列)**

- 二手(automater.ai / clauday):八套件均分 **90.2** vs 无记忆 **79.5**;同洞见无链接基线 +3.2;regression **4.5%**,同洞见无链接 **6.5%**,单纯重跑无记忆 **9.7%**;唯一在每个套件都不低于无记忆的方法。
- 二手(llms.blog):无记忆也能成功的任务里,**52%** 的失败可归因到某条具体记忆条目,其中 **20%** 是条目本身错。
- Hugging Face Daily Papers(Nov 11)当日 **#1**,41 upvotes(二手转述)。

### 11-13C · 一条经验能见谁,是写入时定的 / Memory Scope at Write Time(MixUA)⭐⭐

**一句话定义**:多用户、多 agent 共享经验时,既有系统默认「共享即有益」,把蒸馏出的经验丢进一个全局池;MixUA 按「**谁受益 + 可披露什么**」把每条经验派到四个作用域之一——**用户-主体对 / 单用户 / 单 agent / 全局**——使可见范围成为写入时的一次显式判定,而不是读取时的临时推断。

**为什么"当下"最有价值 —— 缝在哪**

- **半答复悬了 31 天的最老 🎯**。10-13「检索准入 × 跨主体状态隔离」合并总纲的判据是两句:「记忆能不能用在这里」×「这条推理状态是谁的」。MixUA 答的是前一句,而且是本库 remedy plan 里点名的那个方向——把「准入」做成**记忆条目的一等属性**。但**后一句没答**:它管的是长期记忆条目的可见域,不是并发推理状态(context / KV / cache)的隔离。⇒ **不构成完整答复,🎯 不降级**,但在台账里标注「准入侧已获机制原型」。
- **把 11-07B 的诊断推进到机制**。11-07B 发现「读范围 > 写范围,权限随成员集合隐性扩张」,当时结论是 `AgentIdentity` 的 attenuation **缺一个输入变量:成员集合**。MixUA 的四个作用域就是把这个变量显式化——作用域由「受益面」决定,不由「来源」决定。这条区分很关键:按来源分类是**归档**,按受益面分类才是**授权**。
- **给出可测的越界读数**:隐私探针里「被种下的私密事实出现在禁止作用域」的比例 **0.02%**。这是本库第一次见到跨主体记忆泄漏有具体分母。
- **与 11-12C 互补成一对**:11-12C 管**委派链上**授权是否衰减(传播保真);这边管**共享池里**记忆是否越界(作用域保真)。一个是纵向链路,一个是横向池子。

**数字(摘要级,一手 abs 已核)**

- 5 用户 × 7 agent;**pass rate** 较无记忆最高 **+16 pp**,较单一全局记忆 **+5 pp**;**偏好保留** 最高 **90%**;**隐私探针越界** 最多 **0.02%**。
- 有意思的一条:任务即使此前**只被别的用户、在别的 agent 上**试过,MixUA 仍给出增益——说明跨主体共享的收益是真的,不是只靠本主体历史。

- **vs 11-12C(授权传播保真)**:那边管授权**沿委派链**是否衰减,这边管记忆**沿共享池**是否越界。纵向 vs 横向。
- **vs 10-14A(跨主体状态隔离)**:那条要问的是「这条**推理状态**是谁的」——上下文、KV、会话缓存的并发隔离;MixUA **不涉及**,只到长期记忆条目层。**不要把两者混成一条**。

**建议下一步**
> **值得,但排在 A、B 之后**。最低成本动作 = 待 `MemoryGovernance.md` 下次回引更新时,按 10-13 的 remedy plan 增一节「**Recall 的第二维度:准入**」+「归属 ≠ 权限」一行——这一节现在有实例可写了。若成篇:`memory-scope.html`,主线 = 「可见范围是写入时定的,不是读取时猜的」。⚠️ 成篇时**必须**写清它不覆盖推理状态隔离,否则等于替 10-14A 假结案。
