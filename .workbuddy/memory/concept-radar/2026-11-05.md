本期三条全部指向**记忆的两个默认假设**：① 记忆的载体默认是**文本**（提取要点 → 检索回注）；② 记忆的时间方向默认是**向过去看**（回溯式，为当下决策取回过往信息）。三条各拆掉一个默认：

- **11-05A · 时间方向** —— 记忆不仅要记过去，还要**记未来**（前瞻记忆）

- **11-05C · 载体** —— 记忆可以装进**模型权重**，查询时零上下文

### 11-05A 详情

- **一句话定义**：让 agent 记住**未来指向的意图**（pending objectives + 激活条件 + 支撑证据），并在合适机会出现时——无需用户显式请求——决定是否、何时兑现的记忆框架。
- **边界辨析**：与 `LongTermMemory` / `MemoryGovernance` 的分界在**时间方向**（回溯取回 vs 前瞻兑现，四动作全部是对「过去」的操作）；与 `HumanInTheLoop` 的分界在**动作来源**（闸门审「模型现在提出的动作」，前瞻记忆管「存着的意图何时变为可行动」——意图兑现那一刻仍应过闸门，两概念相接不互替）。
- **来源**（WebSearch 真实返回，[verified]）：
  1. https://arxiv.org/abs/2611.05731 [verified]
  2. https://arxiv-vanity.com/papers/2611.05731 [verified]
  3. https://theagenttimes.com/agents/article/pro-memory-preprint-separates-stored-agent-intentions-from-a-03ce6b4d [verified]
  4. （第二形态实例）ProMemAgent：https://arxiv.org/pdf/2610.27400 [verified]
- **值得注意的点**：两个独立团队（UIUC 系 / ProMemAgent 系）在两周内各出一篇 + 各带一个基准 ⇒ 满足本库「两个不同形态实例才立线」的门槛，「前瞻记忆」是**正在成形的簇**而非孤例。
- **建议下一步**：值得生成 `learning-materials/prospective-memory.html`（受人工核查承诺约束，先经核查）；或先在 `LongTermMemory` 页加「回溯式之外」一节 + 在 `HumanInTheLoop` 页标注「意图兑现也要过闸」的接缝。

### 11-05B 详情

- **一句话定义**：把 agent 记忆当作信号处理意义上的**递归过滤**——历史只通过一个由被跟踪键数决定大小的**状态**起作用；决策不依赖读全量日志，依赖维护好这个状态，且「显式状态反超长上下文」的门槛随读者模型增强而外推。
- **边界辨析**：与 `Compaction` 的分界在**压缩对象**（压缩是「保留最有信息量的文本」，过滤是「只保留决策所依赖的状态」——论文明确批评前者）；与 `LongTermMemory` 的分界在**跨会话 vs 会话内**（过滤是运行时纪律，治理是跨会话生命周期）；与 `AgentIdentity` 的关系是**同一问题两种仪器**（授权状态判定：一边是凭证链，一边是状态机读日志）。
- **来源**（[verified]）：
  1. https://arxiv.org/abs/2611.02361v1 [verified]
  2. https://arxiv.org/html/2611.02361v1 [verified]（含成对设计：两段历史仅差决定性事件的**次序或一个字段**，正确答案互换）
- **方法上的硬点**：① 成对样本设计把「阈值漂移」与「判别力丧失」**分开测量**（256 事件时 7B/14B 已完全不判别）；② 预注册测试里**读者模型可预测过滤器精度**（平均误差 0.02）；③ 第二域冻结复刻 + 换措辞，horizon 复现 —— 这是本库偏好的「仪器级」证据结构（与 11-03B 的 plateau 型证据同档）。
- **建议下一步**：`Compaction` 页值得加「压缩 vs 过滤」一节（本库至今只有压缩叙事）；overview 开放项「ContextEngineering 独立测量」可引用此基准（是否算正面答复待拍板，见第四部分）。

### 11-05C 详情

- **一句话定义**：把长期事实记忆从「文本 + 检索回注」搬到「模型参数」——用 on-policy 自蒸馏训练一个无上下文学生模型内化用户记忆，再用 verify-then-regenerate 路由器按查询分派给权重或文本记忆。
- **边界辨析**：与 `LongTermMemory` 的分界在**载体**（文本回注 vs 参数内化，后者查询时零上下文）；与 11-03A（RoutedCL）的分界在**路由对象**（表示 vs 载体）；与 `Skill` 的分界在**知识类型**（Skill 装程序性知识按需加载，权重记忆装陈述性用户事实常驻参数——方向恰好相反：一个往上下文外搬，一个往参数里搬）。
- **来源**（[verified]）：
  1. https://arxiv.org/abs/2611.05636 [verified]
  2. https://arxivlens.com/PaperView/Details/route-to-remember-adaptive-memory-selection-for-llm-agents-b0f6e132691a48b0 [verified]
  3. （所引基准一手）HaluMem：https://arxiv.org/html/2511.03506v3 [verified]
- **值得注意的点**：作者明写动因是「生产 agent 的记忆成为瓶颈，且**几乎全由文本构成**——每次查询的额外成本随累积历史增长」——正是对文本默认的正面点名。
- **建议下一步**：暂不立专页（证据仍为 workshop 级、单团队）；登记为「路由轴」第二实例，待第三个载体形态（如图记忆的检索复杂度主张，见备查 GraphMemory 线）出现再议。
