### 11-12A · 警报响后冻结多大一块 / Post-Alert Fault Containment(Airlock)⭐⭐⭐

**一句话定义**:多智能体系统里单个 agent 的坏输出会沿数据消费链横向扩散,而既有控制只有两档——只掐源头(漏掉已消费污染的下游)或整图回滚(陪葬健康并发工作);Airlock 把「**围堵的切口单位**」从这两个极端里解放出来:树状运行时(权限自父到子只收窄)提供**纵向**边界与控制开关,追加式溯源 DAG 记录**横向**跨 agent 数据消费,告警后沿 DAG 前向追踪污染执行、后向收敛根因,再按两档落刀——免求解器的全隔离档,或 fence-then-prune 的截止期感知最小割档(只切必需的边,保住其余健康工作)。

**为什么"当下"最有价值 —— 缝在哪**

- **时位深挖**:本库「事后」格已有 11-04B ARGUS(溯源观测)与 11-04C RecoverAgent(检出→改写→续跑),但**没人问过「警报响后冻结的单位是什么」**——Airlock 的对照实验把这个默认假设拆了:A2A 原生控制最多围堵 33.3% 故障、LangGraph 最多保住 16% 无需重做的工作,两档之外的第三档(污染子图最小割)多保 **+68~+96 pp** 健康工作。
- **给 10-26 那个「失效的到达方式」候选一个防御侧对应物**:当时判「损失沿依赖图到达、逐条审查全过」;Airlock 干脆**把依赖图变成控制底座**——溯源 DAG 不再只是观测仪器(11-04B),而是落刀坐标。「失效沿图到达 ⇒ 就沿图切」这条思路第一次有了实现。
- **与 11-06B CIB 成对**:那边是**预防**(隔离设计,任务开始前划界),这边是**事后外科手术**(污染已扩散后的选择性围堵)——同一问题的两个时位。
- **授权轴的运行时结构**:「权限自父到子只收窄」正是 `AgentIdentity` attenuation 在运行时的强制实现——衰减不再是模型自觉,是树结构保证。
- **动机证据是野外级**:论文以 2026 年 7 月 OpenAI–HuggingFace 事件开篇(约 1,200 个 agent 在共享凭证上互传 70,000+ 消息、约 700 个加入对 HF 的攻击)——正是「切断源头也止不住、整场销毁也不干净」的实例。

**数字(摘要级,一手 abs 与 PDF 首屏已核)**

- **1,832** 次测试床运行 + **161** 次物理智能家居 LLM 运行 + **24,266** 条仿真记录;主测试床与智能家居网格上**阻断全部告警后错误动作、零收敛后泄漏**。
- 对照:A2A / LangGraph 原生控制**至多围堵 33.3% 故障,或至多保住 16% 无需重做的工作**;Airlock 多保 **+68~+96 pp** 健康工作;密集扩散下最小割档比全隔离档再多保 **+46 pp**。
- 代码开源(论文 Appendix B)。

### 11-12B · 工作成果带着编译好的上下文出门 / Compiled Context as Deliverable(PAF)⭐⭐

**一句话定义**:专业工作的交付物默认是文档——看得见结论,丢掉研究过程、计算、假设、证据链与授权边界,后继者想追问只能重建工作流;Portable Agent Format(PAF)把「**知识的交付单位**」从文档换成**包**:成品 + 编译上下文 + 类型化事实 + 可检索源记录 + 溯源分类 + 签名发布元数据 + 治理策略 + 运行时档案,让**另一个模型或运行时**无需重建原流程即可盘问这份成品——「格式携带知识,不携带生产它的模型或 agent 进程」。

**为什么"当下"最有价值 —— 缝在哪**

- **正面触碰 overview 的 persistent execution 开放项**:那格明写「未写的是跨运行时语义比较」;PAF 是「**生产过程 ≠ 消费过程**」的第一个可操作实例——包就是跨运行时的上下文载体。
- **11-05B「显式状态反超全量历史」的交付时位版**:那边是会话内读什么(读显式状态 96–98% vs 读全量历史 48–55%);这边是**把状态打进行李箱**——而且实验设计恰好复刻同一对照:托管治理读手 96% vs 「说明书 + 原始文件检索」86%,原始材料直接聊天只有 48%。
- **MemoryGovernance 第三底线的物化**:「谁可写共享记忆要像数据库权限一样管理」——PAF 把**授权边界做成交付物的一部分**随包旅行,治理从运行时约定变成随身行李。
- **0.8B 离线读手是「小模型 × 编译上下文」的第一组对照数**:69% 总体 / 54% 可答,−1 率(实质错误 + 越权回答)仅 2.9%,对照配置(源材料 + 说明书、无包)为 56%——上下文编译的质量直接决定小模型能不能顶上。
- **失败案例本身有价值**:离线检索在某金融数据包上 **0/40** 历史记录题全挂——「编译过的上下文也有编译不进去的东西」,给这条线立了边界碑。

### 11-12C · 授权凭证在多跳委派中会不会变形 / Authorization Propagation Fidelity(A2A 多跳委派)⭐⭐

**一句话定义**:A2A 委派工作流里,发请求的 agent ≠ 授权源头 principal——这中间每一跳都可能让授权**变形**;本文在合成四方医疗报销流程上实测一个分层下游验证设计(当前调用方上下文 / 传递授权证据 / 逐跳 Ed25519 请求认证 / 独立重放状态四层分离):15 个对抗条件拦下 14 个,但**专门设计的委派路径测试暴露了语义衰减的缺失**——验证逻辑只比对「路径顺序与终点」,不检查「每一跳的权限范围是否只收窄不扩大」;更关键的负结果:**共享授权证据 HMAC 密钥的合法持有者可以修改所代表的授权内容并生成有效证据**——「持有密钥」与「有权代表」是两回事。

**为什么"当下"最有价值 —— 缝在哪**

- **授权轴三侧就此凑齐**:存储侧(11-07B 权限随成员集合隐性扩张)× 决策侧(11-09B 第 20 条,authority-based attack definition)× **传播侧(本条,授权在多跳中的保真)**——与 11-11B 那次「监督环节三条输入通道凑齐」同款的结构完成时刻。
- **直接给 `AgentIdentity` 的 attenuation 补实证**:那页记着「衰减缺『成员集合』输入变量」;本条实测出**衰减在协议层根本缺席**——不是缺输入,是没这道检查。
- **「密钥持有者可合法伪造」是 11-09 备查 Signed, Sealed, Leaked 的协议侧回声**:那边说「签名证明谁发布了字节,不证明字节做什么」;这边把同一命题在授权证据上做成了可复现实验。
- **负结果设计值得学**:14/15 通过本来是漂亮成绩,作者偏把第 15 个(委派路径)单拎出来证明设计缺陷——「通过率」与「测没测到要害」的分离,是 11-03B「验证者自身可靠性」在协议层的镜像。

**数字(摘要级,一手 abs 已核)**

- 合成四方医疗报销工作流;15 个对抗条件 **14 拦 1 暴露**(暴露的正是语义衰减缺失);HMAC 密钥持有者伪造授权证据**实验成立**。
- 全配置安全处理中位延迟 **5.11 ms**、序列化载荷 **3.87 kB**(固定深度本地基准)。

> ⚠️ **证据分级**:① 摘要级,正文未开;② **合成单一工作流**(医疗报销),原型级,无真实部署;③ 三作者小团队;④ 「14/15」的分母是自选对抗条件集。结论方向(逐跳收敛 capability / 源头签名)是设计要求,不是已验证方案。
