### 11-22A 多智能体的边际价值审计 / Marginal Value of Multi-Agent Coordination(PACE) ⭐⭐⭐

**一句话**:把多智能体系统相对「匹配样本数 / 匹配算力预算」的基线做元分析——综合 9 项原始评估、516 个多智能体配置,多智能体相对匹配基线平均 **-0.042** 准确率,**74%** 的可比对照中不优于或等于基线;正收益只在**证据分区(partitioned evidence)、外部验证(external verification)、模型间错误多样性(error diversity)**三类条件下出现。

- **概念名(中英)**:多智能体协作的边际价值审计 / Marginal-Value Audit of Multi-Agent Coordination(PACE = 该文附带的审稿清单 + 核算工具名)
- **为什么"当下"最有价值**:overview 的 [[MultiAgent]] 是本项目多智能体线的正面招牌(team@5 ≈ best@33,≈6.6× 等效算力),其自带「无验证者则失败」边界。PACE 从元分析层把另一半补齐并收紧:所谓收益很可能来自「多采样 + 多算力」而非「协作」本身——一旦用匹配预算的基线重算,协作平均为负。这正是本库第 21 条扫描线要问的「这套设计假设了它补的洞还空着吗」的直接实例,且主落点比 11-20B 更纯粹(落在边际价值本身,而非评测对象错位)。与 11-15C Unprompted Coordination 成张力对:那条说「共享本身能创造无人设计的协调收益」,这条说「协作本身平均不值成本,除非满足三条件」。
- **来源链接(均 [verified],一手 abs 已直开核验)**:
  - https://arxiv.org/abs/2611.17610 [verified] —— 一手 abs(WebFetch 直开):标题、单作者 Seyed Mahmoud Sajjadi Mohammadabadi、v1 2026-11-13、43 页 / 11 图 / 13 表、cs.AI+CL+LG+MA、全部量化结论均出自此页摘要
  - https://arxiv.org/html/2611.17610v1 [verified] —— 一手 HTML 全文(搜索结果直接返回摘要与正文片段,含资源向量 R 六维、四档基线阶梯、GitHub 工具链接)
  - https://github.com/mahmoudsajjadi/pace [verified] —— 作者随论文发布的 PACE Reviewer Checklist + pace CLI 核算工具 + 复现数据(abs 页 comments 明列)
  - https://www.theagenttimes.com/articles/multi-agent-systems-average-0-042-lower-accuracy-on-matched--73fb03c7 —— 二手报道(WebSearch 返回),仅作交叉核对;数字以一手 abs 为准
- **一句话定义 + 边界辨析**:定义——把「协作」与「多采样、多推理算力」解耦后,衡量多智能体架构相对等成本单智能体基线的净收益,并给出收益成立的必要条件。边界:① vs [[MultiAgent]]——那条记的是「team@k 有收益 + 无验证者失败」的实测结论;本条是元分析层,质疑的正是「那个收益是否被算力混淆」,两者是主张 vs 审计,不是同一层。② vs 11-20B BRIDGE——同属「最小机制够不够」,但 BRIDGE 在记忆检索层,本条在多智能体协作层。③ vs 第 21 条扫描线(见 `SCAN-LINES.md`)——本条是该扫描线的直接实例(问「多智能体设计假设协作本身有价值,真的吗」),不新增扫描线。
- **⚠️ 证据边界**:单作者、预印本、元分析(自身不产生新实验,结论依赖所纳入的 9 项原始研究);「正收益三条件」是相关性归纳非因果证明。成篇前须开 PDF 核纳入研究的筛选口径与随机效应模型细节。

### 11-22B 无损无索引记忆 / Lossless, Index-Free Memory(GrepMem) ⭐⭐⭐

**一句话**:用两个部件——完整历史的 append-only 纯文本日志 + 正则搜索工具——替代摘要、掩码、结构化记忆;不需要 embeddings、检索索引、记忆抽取或额外模型,在 ContextBench 上达 **95–97%** 准确率(有损基线最多 21%),BCP-Multi 上超 SUPO 摘要 **8.8 个百分点**,在五个评测任务上均位于 accuracy-token-cost Pareto 前沿。

- **概念名(中英)**:无损无索引记忆 / Lossless, Index-Free Memory(GrepMem)
- **为什么"当下"最有价值**:正面顶到 overview 里 [[ContextEngineering]] 用 [[Compaction]] 做长任务裁剪的默认假设——Compaction 是有损压缩,GrepMem 证明「根本不压缩、全留、召回时正则定位」在多个基准大幅胜出。这是 11-20B BRIDGE「最小 RAG 够不够」的同一条线的极端形态(BRIDGE 的最小 RAG 仍用 hybrid BM25/cosine 索引,GrepMem 连索引都不建),也给 overview 最老开放项 RAG case study 一个最朴素的对照组:如果纯文本 grep 就够,RAG 的复杂度需要重新论证。与 11-13 备查 Folio「压缩的可逆性」(折叠时打印句柄、可回读原件)成一族——两者都反对「压缩必须丢信息」,但 Folio 是结构化折叠、GrepMem 是根本不折叠。
- **来源链接(均 [verified],一手 abs 已直开核验)**:
  - https://arxiv.org/abs/2611.25123 [verified] —— 一手 abs(WebFetch 直开):标题、三作者 Ziyan Yang / Taiwei Shi(共同一作)/ Jieyu Zhao、v1 2026-11-18、17 页 / 6 图 / 6 表、cs.CL+cs.AI、全部量化结论出自此页摘要
  - https://arxiv.org/pdf/2611.25123 [verified] —— 一手 PDF(abs 页 View PDF 链接)
  - https://arxiv.org/html/2611.25123v1 [verified] —— 一手 HTML 全文(abs 页 HTML 链接)
- **一句话定义 + 边界辨析**:定义——把「记什么/怎么索引」的决策从写入时推迟到召回时,以全量无损日志换取召回精度,用正则工具替代检索系统。边界:① vs [[Compaction]]——那条是有损压缩、作用在窗口内;本条是零压缩、全量外置日志 + 召回时检索,作用位置相反。② vs [[ContextEngineering]]——那是「谁决定放什么进窗口」的总原则;本条是该原则的一个极端实例(什么都不淘汰,只靠召回时定位)。③ vs 11-20B BRIDGE——BRIDGE 仍有索引,GrepMem 无索引。
- **⚠️ 证据边界**:单模型(Qwen3.5-9B)+ RL 训练 + 自建五策略对比;「grep 反超」是否在更大模型 / 生产级历史长度上成立未验证;正则召回依赖 agent 知道要搜什么(查询构造能力是隐含前提);一手 abs 未提代码开源。
- **建议下一步**:作为 `context-engineering.html` / `llm-context.html` 的一节批注「压缩的反面:不压缩 + 按需 grep」,或生成草稿级 `learning-materials/lossless-index-free-memory.html`。受「人工核查承诺」约束,**只写草稿,不写 `learning-materials/`**。

### 11-22C 信念记忆 / Belief Memory(HabitusMem) ⭐⭐

**一句话**:把记忆从「存交互内容」改成「存助手对用户的信念」——借 Bourdieu 的 habitus(持久但可修正的性情),把用户建模为潜在偏好状态,每次交互(含当前请求)既揭示又更新它;每条信念自带 **evidence / scope / status**,两个 agent family 上 PersonaMem-v2 与 VitaBench 2.0 均取记忆系统最佳。

- **概念名(中英)**:信念记忆 / Belief Memory(HabitusMem)
- **为什么"当下"最有价值**:顶到 [[LongTermMemory]] / [[MemoryGovernance]] 的「记忆 = 存内容 + 溯源」默认表示单位——HabitusMem 主张表示单位应是「带 status / scope 的信念」,除「记得准不准」再多一维「这条偏好现在还成立吗、适用在哪」。它把 11-13C MixUA 的「作用域写入时指派」(scope)+ 11-16A DISCERN 的「读时消解/该不该答」(status)统一进一个三元组,并给 11-14A Memory Trap「良性记忆把『这一次』泛化成『以后都不用问』」一个写时解药:每条信念显式带 status。与用户当下主线(AI Agent 记忆系统)接缝最紧。
- **来源链接(一手 abs 已直开核验 [verified];其余为搜索返回的可达页)**:
  - https://arxiv.org/abs/2611.25855 [verified] —— 一手 abs(WebFetch 直开):标题、七作者、v1 2026-11-19、cs.AI+cs.NE、完整摘要(含 evidence/scope/status 三元组与两个基准名)
  - https://arxiv.org/pdf/2611.25855 —— 一手 PDF(abs 页 View PDF 链接)
  - https://arxiv.org/html/2611.25855v1 —— 一手 HTML 全文(abs 页 HTML 链接)
  - https://lacuna.tiptreesystems.com/work/habitusmem-belief-memory-over-evolving-user-preferences —— 二手解读(搜索返回),含 VitaBench 2.0 Pass⁴ 与 PersonaMem-v2 表格描述;**一手 abs 零具体数字,分值须开 PDF 核**
- **一句话定义 + 边界辨析**:定义——记忆的表示单位是「对用户的信念」而非原始内容,每条信念带证据、作用域与状态(是否仍当前有效),由 trained writer 写成文本记录供冻结的 agent 使用。边界:① vs [[LongTermMemory]]——那条存「事实 + 溯源」(情景/联想/语义);本条存「信念 + status/scope/evidence」,表示单位不同。② vs 11-16A DISCERN——那条读时消解既有记忆(含弃答);本条写时就把记忆组织成信念。③ vs 11-13C MixUA——那条按受益者派作用域;本条作用域是信念的内置字段。
- **⚠️ 证据边界**:**一手 abs 零具体数字**("best results" 无分值),二手表格数字不可直接当锚点(11-08 教训);trained writer + frozen agent 是特定架构, generality 未证;单团队预印本。
- **建议下一步**:先作为 `memory-lifecycle.html` 的一节批注「表示单位:内容 vs 信念」;成篇前须开 PDF 核分表数字。受「人工核查承诺」约束,**只写草稿,不写 `learning-materials/`**。
