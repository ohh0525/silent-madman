### 候选 1 ⭐ 记忆策略的学习化:从"规则"到"可训练策略"
**Memory as a Learned Policy / Memory Policy Learning**

**为什么"当下"最有价值(缝在哪,一句话):**
wiki 的**记忆四页**([[LongTermMemory]] / [[Provenance]] / [[CitationLock]] / [[Abstention]])回答的是"**记忆该满足什么条件**"(必须带来源、只引打开过的、没证据就拒答),以及(09-24 待摄取的注记)「**它何时该被删**」;但它们**全部默认"记什么 / 何时取 / 何时删"是人工写死的规则**。2025–2026 年,**六个独立团队把这三个决定各自改造成一个带独立奖励目标的"可训练策略"**——记忆从"一个被查询的档案库"变成"**一个被优化的决策子系统**"。这正是记忆簇里**从未有过的那一格:决定者**。

**一句话定义:**
企业上下文层 = 位于**数据基础设施**与**agent 基础设施**之间的一个**持久、版本化、可移植的平面**,把企业的语义(业务含义)、运行态(当前现实)与溯源(来龙去脉)组织成 agent 在**运行时**可查询的形式——而不是把企业知识预先塞进提示词。

**与已覆盖概念的边界辨析:**
- vs [[ContextEngineering]]:**窗口内的取舍手艺 vs 窗口之外的数据平面**。CE 决定"桌上摆哪几份材料";上下文层是"**材料架的来源与维护制度**"。两者是"消费者 / 供给方",不是同一层。
- vs [[MCP]]:**传输协议 vs 语义内容**。MCP(已无状态化)回答"**怎么把工具与资源接进来**";上下文层回答"**接进来的东西是什么意思、是不是最新的、谁有权看**"。原文判据句正好点破:"**Connectivity without meaning is a very efficient way to distribute confusion**"。
- vs [[Provenance]]:**记忆级 vs 企业级**。[[Provenance]] 管"**这条记忆哪来**(origin + time + evidence)";上下文层的 Provenance 组成管"**数据血缘 + 决策与行动的可审计链**"——是同一纪律在更大对象上的实例化,粒度与范围都不同。
- **核心"但是"(须进第一屏)**:🔴 **它是"要工程建造",不是"可整包购买"**。Gartner 原话口径:"a context layer **can't be bought in its entirety**; the layer must be engineered"——责任归属被重新划到**架构与数据团队**(而非 AI 团队)。而 Orbital 的打分显示**目前没有任何厂商在全部六条属性上得 YES**,多数在"实时 / 跨系统"上只是 PARTIAL。**因此本条更像"一块待建平面 + 一套验收判据",而非一个已成熟的产品品类。**
