### 候选 1 ⭐（承接强化 09-23 台账行，**第二次**；建议升格为 ⭐）

**概念名**：智能体的持久化执行与 Session 作为一等公民 / Durable Agent Execution & Session as a First-Class Object（台账 09-23「持久化执行 / 智能体运行时 / Durable Execution」行，积压 **14 天**）

**为什么「当下」最有价值（缝在哪）**：这是 `overview.md` **自己点名「尚未成文」的那条缝**——「persistent execution … what remains unwritten is the cross-runtime semantics comparison — event replay vs checkpoint adoption vs snapshot」。同时它是**两条既有教义的共同未完成项**：[[HumanInTheLoop]] 明文要求「the pause must be **persisted** and the resume **idempotent**」，但库里**没有任何一页回答「谁来持久化、resume 的语义在运行时之间如何不同」**；[[AgentHarness]] 的职责④（keep alive / recover）只是**一笔带过**，并无「持久」的定义。本周这条缝第一次被**三种独立物证同时填上**：

1. **【开源 · 一手】** **Pi 1.0 + Pi Durable**（Earendil，**2026-10-01** 发布，MIT，实验性）：把每一步做成 task，**步进前先落 checkpoint**；新进程打开同一存储后调 `resume()`，逐个从未完成的 checkpoint 继续；被截断的模型请求**重发并保留部分答案（标记 aborted）**；工具调用**只在声明 `replay: safe` 时才重跑**，否则模型收到「该工具已中断、可能部分执行」的结果；`requestId` 让提交在重试间**恰好一次**。
2. **【产品 · 一手默认值】** **DigitalOcean Managed Agents** 公开预览（**2026-10-01**）：Harness Runtime 给每个会话一台独立 Firecracker microVM，**跨会话保留工作区与对话**，会话可 **pause / resume / checkpoint / fork**，按计划或 webhook 运行，**只在真正干活时计费**（auto-pause）。
3. **【判据 · 中立综述】** 一份中立对照文把决定性的那句话说出来：**「session ≠ durable execution」**——`session` 只是「记住对话」，`durable execution` 是「一个**不同的进程**能在数天后从事件历史重放出同一个 run」。文中还并列了四类恢复语义差异：Temporal / Step Functions / Azure Durable Functions 走**事件历史重放 + 确定性编排代码**（编排代码不得有网络调用、系统时钟、随机数）；**DBOS** 把 checkpoint 写进 PostgreSQL 且**无需独立编排服务器**；**LangGraph** 的 checkpointer 从**被中断节点的开头**恢复（不是中断那一行），故节点必须幂等。同一批来源给出结论句：**持久化不是 checkpoint 一个动作，而是「确定性编排 + 幂等活动 + 幂等键 + 信号/定时器」的合成**。
4. **【架构 · 一手媒体转述】** 一篇架构分析指出，[[Anthropic]] 的 Managed Agents 把 Agent 拆成**三件可分别失败、分别重启、分别替换的东西**：`Brain = Model + Harness` / `Hands = Sandbox + Tools` / **`Session = Durable Event Log`**——并给出一个可复用的趋势判据：**「Harness thinning, Infrastructure thickening」**（模型越强，Harness 越薄；但 Sandbox / Permission / **Durable State** / Budget / Evaluation / Observability / Identity / Audit / Side-effect Control **不会消失**，只会更重要）。

**一句话定义 + 边界辨析**：durable execution 是**循环之下那一层**——它把「run 的状态」从进程内存搬到**事件日志 / checkpoint**，使一个 run 可以**跨进程、跨天数、跨部署**继续；「暂停」不再是阻塞一个线程，而是把一个 `await` 条件写进持久存储。边界：
- vs **[[AgentHarness]]**：harness 决定「**谁跑这个循环**」，durability 决定「**状态存在哪里、谁能接着跑**」——Anthropic 干脆把它们拆成两个对象（Harness / **Session**）。这与 09-26 既有分工「harness 管编排、sandbox 管在哪跑」构成**第三条腿**。
- vs **[[HumanInTheLoop]]**：闸门决定「**何时该暂停**」，durability 保证「**暂停这件事活得过重启、且 resume 不重复副作用**」——「human as an async API」正是这条边界的实现形态。**注记：这是本库第一次出现「闸门的验收标准需要一个不曾拥有的页面来满足」的情况。**
- vs **[[AgentSandbox]]**：隔离 ≠ 持久。沙箱被销毁时 run 也一并消失（Manus 旧模型即「任务结束、机器连同里面的东西一起销毁」）；durability 才是让沙箱可以**被回收后再拉起**的前提。
- vs **[[Compaction]]**：压缩在**窗口之内**做有损摘要；durability 在**进程之外**存无损事件。两者解决的不是同一个「记不住」。
- vs **[[MultiAgent]]**：协作的前提是「验证器 + 已验证的中间结果」——durability 正是让一个 peer 的**已验证进度**活过一次崩溃的载体。

### 候选 2（承接强化 10-06 候选 2，**合并**；建议**修订**既有页，不新开两个节点）

**概念名**：写入时蒸馏 vs 读取时选择 / Write-Time Distillation vs Read-Time Selection（非破坏性记忆 · Non-Destructive Memory）

**为什么「当下」最有价值（缝在哪）**：记忆四页（[[Provenance]] / [[CitationLock]] / [[Abstention]] / [[LongTermMemory]]）治理的是「**这条事实写进来时有没有来源**」，**从不问「这条记录在写入的那一刻是否已经被销毁」**；而 [[Compaction]] 把「**写入/摘要时蒸馏**」变成了默认动作。10-06 候选 2（VISTA：无损外部记忆 + 主动回看）第一次点出「第三条路」，但**只在视觉域**。本周它拿到了**文本域的孪生证据 + 两个把「状态演化」量成主要难点的基准**，缝从「一个观察」变成「一条有名字的架构轴」：

1. **【一手 · 文本域孪生】** **Mem++**（arXiv **2610.02002**，**2026-10-01** 提交；UT Austin + AIDAChip）：明确把架构轴命名为 **「shifting from write-time distillation to read-time selection」**——**完整存下每份文档 + 日期 + 作者，写入时不调用任何生成式模型**；读取时只取「日期不晚于问题所询问时间」的文档，融合词法与语义排序；**与「覆盖旧版本」的系统相反，它保留旧版本、把选择权交给回答模型**。结果：OrgMemBench 上**超过最强记忆基线 8.0–13.1 分**；LoCoMo 上**最佳 LLM-judge 平均分**；LongMemEval-S 上第二（仅次于其自身实体图变体）。
2. **【一手 · 状态演化才是难点】** **DSV-Mem**（arXiv **2610.08102**，**2026-10-06** 提交）：面向专业工作流的多模态记忆基准，**最强基线得分低于 45%**；关键结论——难度主因**不是**原始对话长度、不是 OCR、不是算术，而是 **state evolution，尤其是「governing updates 的条数」**；且**模型常在回答前不核对用户前提与先前的状态更新**；增加推理预算与常规记忆管理方法**收益有限**，**「state-aware 设计」更有效**。
3. **【一手 · 历史必须变成约束】** **EMBER-Bench**（arXiv **2610.05013**，**2026-10-04** 提交）：长程具身任务的跨事件因果记忆；**16 个模型中最高 61.2%，人类评测者均值 98.3%**；且**「能正确回溯原因」与「能正确预测下一步」并不相关**；加入因果-后果标注带来 **+13.0 分**，说明模型**无法把历史转成对当前动作的约束**。

**一句话定义 + 边界辨析**：记忆的关键决策点是**「在写入时就把记录压成事实，还是原样保存、把取舍推迟到提问那一刻」**；Mem++ 证明「推迟」在组织型长周期场景更强，DSV-Mem / EMBER-Bench 则证明**难点恰恰在于记录会不断被修订**——而这正是「写入时蒸馏」最容易提前销毁掉的信息。边界：
- vs **[[Compaction]]**：有损 vs **无损**；而且 Mem++ 提供了本库**第一个关于 memo 的可引用判据**——「写入时蒸馏**在问题被提出之前就固定了可回答的内容**」。

- vs **[[ContextWindow]]**：物理上限 vs **时间维度**（「截至某日」是一个**面向时间的查询**，不是面向容量的查询）。
- vs **[[LongTermMemory]]**：跨会话的**持久状态** vs 「**某一时刻生效的是哪一版**」——后者是前者的一个正交维度。
- vs **10-06 候选 2（VISTA）**：**同族**——视觉版（帧无损存外面 + 主动回看）与文本版（文档无损存 + 读取时选择）。**建议合并成一篇**，用「**可再生的环境观测存原始 / 不可再生的推理状态才压缩 / 会被修订的组织记录必须留版本**」三分法收口。

### 候选 3（**新行**；把「模型之外的控制」交付为基础设施）

**概念名**：智能体执行平面与治理中介层 / Agent Execution Plane & the Governed Mediation Layer

**为什么「当下」最有价值（缝在哪）**：09-26 的 Cluster E 讲的是**「谁租这个 harness」**（Harness Wars，厂商托管）；本周它进一步变成**一层中立的、有名字的原语集合**，而且这些原语把本库 Cluster D 的四条教义**从「设计原则」变成了「已出货的默认值」**。缝在于：本库有 [[AgentHarness]]（跑循环）、[[AgentSandbox]]（在哪跑）、[[ToolHallucination]]（工具存不存在）、[[AgentIdentity]]（谁在动）、[[HumanInTheLoop]]（该不该动），**但没有一页写「这五者被收束成一条唯一的、模型无法绕过的通路」这件事**——而本周至少有四家把它做成了产品：

1. **【产品 · 一手默认值】** **DigitalOcean Managed Agents**（**2026-10-01** 公开预览）：`Harness Runtime` 之外另有 **`Action Gateway`** —— **一个托管 MCP 端点挡在 16,000+ 工具之前**（GitHub / Jira / Stripe / PagerDuty / Notion / Postgres … 及自有 MCP server）；**凭证存于 Secrets Manager、只在执行时附加，因此「agent 永不会持有它们」**；工具发现、权限、审批、重试、追踪**全部集中在这一层**。（厂商自报数字须降级：意图-工具匹配 **99.3%**、就绪 886 ms、命令执行 189 ms「落后于自家 Sprites 的 79 ms」——均为**自测、且对比对象为自家产品的词法检索**。）
2. **【产品 · 一手默认值】** **Retool centralized agent harness**（early access）：把「**共享策略层 + 执行层**」放在 agent 与公司系统之间，**工具调用经由唯一网关**；关键升级是**策略可以检查工具的参数**，所以「**有权用某工具 ≠ 有权以任何方式用该工具**」；作者给出本库同款判据的产业化表述——「**These limits are enforced outside the model** … You don't have to rely on the agent remembering a rule in its prompt」；并明确**否定的选择**：无个人笔记本访问、无浏览器自动化、无桌面控制。
3. **【生态 · 一手事实】** **OpenClaw Enterprise 1.0（OCE 1.0）**：OpenAI + Red Hat + Nvidia 等多方联合推进，社区定位「**面向 agent 的 Kubernetes**」，已捐赠 OpenClaw 基金会；引入**企业级控制平面**、多租户隔离、安全边界、标准化 agent 原语、生命周期治理与可审计性，允许替换底层框架/模型/沙箱。背景是该工具此前因默认安全薄弱被 Gartner 定性为「不可接受的网络安全风险」并遭企业普遍封禁——**治理平面是它重新获得部署许可的前提**。
4. **【判据 · 治理对象变化】** **Alterion Helix**（实时自主智能体治理）：把治理对象从「单个事件」改为「**跨决策序列中涌现的行为**」，判据句为「**风险不在任何一个单一事件里，它在一系列决策、交互与行动的序列中涌现**」；引用的动机事件是「自主智能体超出预期任务范围、以群体方式集体动员、跨越基础设施边界」。
5. **【旁证 · 一周四连】** **Strands** 开源 harness（把大工具结果卸载到文件、复用请求组件，**token 消耗 −28%**，所有操作经沙箱路由）；**GKE Agent Sandbox** 面向 agentic RL 的 GA（沙箱就绪从 45–85 秒降到 **1–9 秒**，尾延迟从 7.5 分钟降到 10 秒内）；**DeepSeek harness 0.2** + 桌面端（把「定时提醒」等拆成**可选包**、Windows 沙箱权限诊断后可**回滚式修复**、**异步提问模式**——agent 等用户回答时**可以继续干活**）；**Manus 2.0** 换自研 harness `Cascade`（自报 token −23.2%、完成时间 −28.2%、成本 −32%）。
6. **【同族 · 身份侧】** 六国网络安全机构（ACSC / CISA / NSA / 加拿大 / 新西兰 / 英国 NCSC）联合指引把风险列名为**权限滥用、scope creep、身份仿冒、confused-deputy、问责缺口**，并给出「每个 agent 一个**密码学锚定的独立身份**、最小权限、**运行时认证**、**短时（JIT）凭证**、持续监控、高危动作人工审批」；IAPP 于 **2026-10-05** 撰文主张「**把有系统访问权的 agent 当作特权身份来治理，而不是当软件**」。

**一句话定义 + 边界辨析**：Agent Execution Plane 是**agent 与外部世界之间的那条唯一通路**——它把「工具发现、参数级策略、凭证经纪、人工审批、重试、审计」收束到一点，使**修复只需施加一次**，且**约束不在模型里**（所以模型说不动它）。边界：
- vs **[[AgentHarness]]**：harness 是**循环的宿主**（组装上下文、调用模型、判断停止）；execution plane 是**循环对外发言时必须经过的关口**。前者可被模型影响，后者**按设计不可**。
- vs **[[AgentSandbox]]**：沙箱管**能被碰到什么**（containment）；中介层管**允许发生什么**（policy，且**检查参数**）。Retool 那句「有权用某工具 ≠ 有权以任何方式用该工具」正是两者的分界。
- vs **[[MCP]]**：MCP 定义「**怎么调一个工具**」；mediation layer 是「**调之前先经过一个可治理的网关**」——它**用** MCP 作为工具面（DigitalOcean Action Gateway 即一个托管 MCP 端点），但治理语义在协议之外。
- vs **[[AgentIdentity]]**：身份回答「**你是谁、代表谁**」；中介层是**执行授权决策的那台机器**（六国指引因此要求「运行时认证」而非「配给时授权」）。
- vs **[[ToolHallucination]]**：封闭世界消解保证「**工具存在**」；中介层保证「这次调用**被策略审过、被审批过、被记账过**」——是 09-24 那条固定顺序 `resolve → authorize → gate → execute` 的**物理容器**。
- vs **09-30 候选 3（企业上下文层）**：那是**数据平面**（上下文从哪来、什么意思、谁有权看）；本条是**执行/控制平面**（谁被允许做什么、怎么记账）。
- ⚠️ **纪律应用（本库自订第 09-26 条）**：**厂商默认值可引，厂商基准不可引**。本条的**可引事实** = 凭证在执行时附加、策略可检查参数、「无笔记本/无浏览器/无桌面」这类**明示的否定式默认值**；**不可引** = 99.3% 匹配率、886 ms 就绪、−28% / −32% token 等**自报数字**。写材料时须**分栏**。
