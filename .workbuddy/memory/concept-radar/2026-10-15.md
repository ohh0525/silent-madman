## 候选 1 ⭐ 委派链的可验证性 —— 路径上没有授权服务器的那一跳
### Verifiable Delegation Without an Authorization Server

### 为什么「当下」最有价值

**一句话**:`[[AgentIdentity]]` 的「逐跳收窄」默认**每一跳都有一个授权服务器在场替它签发更窄的新凭据** —— 而真实的多智能体世界里,**子 agent 二度委派、跨组织协作这些跳上没有这样的服务器**,收窄只能由持有者自己做,末端的依赖方还必须**在不回源的前提下**验出「没有任何一跳把收到的东西放宽了」。这一格在 wiki 里是空的。

这一格之所以是「当下」而不是「一直存在」:**它正在被写成标准**。三个证据全部集中在 2026-10-06 → 10-10 这四天内,IETF 127(2026-11-14 至 11-20)已批准 SEC Area 的 BOF「Agent Use of Delegation and Interaction Traceability (audit)」。再晚两个月,这一格就不是「正在形成」而是「已经定案」,学习的价值反而下降。

### 一句话定义

> **委派凭据在缺签发方的跳上,由持有者自行收窄;末端的依赖方仅凭令牌与签发者公钥、不回调源站,即可验出「谁授权的、经过哪些 agent、且无一跳放宽了所收之物」。**

机制要点(可落成骨架):链模型 = 授权链 **L0**(签发者根密钥签名)+ 委派链 **L1..LN**(N = 委派深度);**单一收窄不变式** + **规范化验证算法**(Step V1 起);两种编码 = **JWT 链**(每环指名下一持有者密钥)**与 Biscuit + Datalog 策略**;绑定 **MCP / A2A / 通用 HTTP**。身份两套:`aip:web:example.com/agents/research-analyst`(DNS 型)、`aip:key:ed25519:...`(自证型,面向临时 agent)。

### 与已覆盖概念的边界辨析

| 对照 | 边界句 |
|---|---|
| `[[AgentIdentity]]` | **有授权服务器在场时的重签发式收窄** vs **无服务器、持有者自收窄后的离线可验证** —— 同一条收窄纪律被拆成两半,现有页只写了前半。AIP 原文点破前提:「*The holder does not narrow its own token.*」 |
| `[[MCP]]` | AIP 给了它显式 binding;现有 MCP 页只写「HTTP server 作为 OAuth 2.1 resource server」,**未写没有 authorization server 时委派怎么办** |
| `[[HumanInTheLoop]]` | **闸门决定「现在放不放行」** vs **收据承载「当初被授权到哪为止」** —— 闸门需要一份可出示的授权上界,Receipts 正是那个对象 |
| 09-30「常驻智能体」 | 那条问「**没有代表时谁来管它**」;本行问「**代表关系本身怎么被验出来**」 |
| `[[AgentSandbox]]` | 容器边界限制「**能碰到什么**」,验证不出「**有没有越权意图**」 |

**必须与结论同屏的反向证据**:Poppy draft 0.1 把密码学强度全压在**连接层**(发现文档 / client id + 公钥 / issuer 匹配 / **DPoP 绑定令牌**),授权层只剩 `poppy:read` + `poppy:write` 两个 scope 加各公司自造的 `custom_scopes` —— **「token 证明了 agent,没有证明差事」**。⇒ 连接层的收窄有人在认真做,**权限词的可移植语义这一层几乎没人做**。

### 建议下一步

- **低成本优先(推荐)**:修订 `concepts/AgentIdentity.md`,增一节「**当路径上没有授权服务器时**」,把「收窄由谁执行」从隐含前提写成显式变量;`concepts/AgentSandbox.md` 增一行「检验证明不了你没有意图」。
- 值得生成 `learning-materials/delegation-verifiability.html`;骨架建议 = **「三种委派位置对照表(有签发方 / 无签发方-自收窄 / 无签发方-无法验证)× 三栏(谁能收窄 · 依赖方能验什么 · 验不了什么)」** + 「**看懂一份规范的状态行**」(individual draft / WG draft / RFC)。

## 候选 2 ⭐ 写入侧的弃权 —— 一条门槛管不住所有类别
### Write-Side Abstention (Category-Conditioned Retention)

### 为什么「当下」最有价值

**一句话**:`[[Abstention]]` 在 wiki 里一直是**出口端**纪律(没来源 ⇒ 拒绝**回答**),而从来没人问它是否也有一条**入口端**(有来源但支持不足 ⇒ 拒绝**存下**)—— 更没人承认「**一条全局门槛同时管所有类别**」在原理上就分不开某些差别。

最硬的那个数:**4,715** 条候选断言中,**value / belief 类只有 77.9% 被其来源支持,而其他所有类别为 96.2%**。这个不对称是 2026-10 才被测出来的;而它与既有知识网的接缝极其精准 —— `[[MemoryGovernance]]` 的第三个决策者(攻击者)利用的正是这个缺口:**一条来源合法但支持不足的 value 断言,被当成既成事实反复复用**。

### 来源(3 条,WebSearch 真实返回)

| # | 来源 | 性质 / 证据等级 |
|---|---|---|
| 1 | https://www.arxiv.org/abs/2610.07100 —— 《When to Remember, When to Abstain: Category-Conditioned Retention for Reliable Agent Memory》,Owolabi / Gupta / Fei Wang,**2026-10-05** 提交 | **[verified]** 一手摘要;🔴 单一预印本 |
| 2 | https://export.arxiv.org/abs/2610.11573v1 —— **MemoType / TriMEM**,2026-10-08;证明任何**单一检索策略**在多类语料上有期望精度**上界** | **[verified]** 摘要级,PDF 未逐页开 |
| 3 | https://arxiv.org/abs/2610.08048v1 —— **DAEDALUS**,2026-10-06;无任务无 oracle verifier 时,启发式**经反复成功后才入库** | **[verified]** 摘要级 |

### 一句话定义

> **存留决策不应是一条全局置信度门槛,而应是按断言语义类别取值的门槛 —— 在一些类别激进弃权、在另一些类别宽松放行,因为不同类别「有来源」到「被来源支持」的基线本来就不一样。**

关键读数:**已部署的**冷启动记忆管线 + 100 个合成 persona、**4,715** 条候选断言,**value/belief 类 77.9% 被来源支持 vs 其他类别 96.2%**;全局门槛**在原理上分不开这个差别**;按类别收紧后,不支持存留 **6.2% → 4.0%**(相对下降约 36%,跨折一致),且在可比存留量下**多保留约 13 个百分点覆盖**(95% CI 9.8–16.0)。作者把它定性为**写入边界上的一种 selective prediction**。

> **读侧孪生**:MemoType/TriMEM 在同一周证明 —— **任何单一检索策略在多类语料上存在期望检索精度的基本上界**。⇒ **写侧一条门槛管不住所有类别,读侧一种策略也管不住所有类别 —— 同一条判据的两端。**

### 与已覆盖概念的边界辨析

| 对照 | 边界句 |
|---|---|
| `[[Abstention]]` | **出口端:没有来源证据 ⇒ 不答** vs **入口端:有来源但支持不足 ⇒ 不存** —— 同名的两种弃权,方向相反;现有页从未被问过它面向哪一端 |
| `[[MemoryGovernance]]` | 那条问 **谁有权决定**;本行问 **决定的依据是否应随内容类别而变**。且它的第三个 decider(**攻击者**)利用的正是本行测量的缺口 —— 这就是 PMPA「payload 穿着合法 provenance 进场」的**量化版本** |
| `[[Provenance]]` | provenance 记录**出处**,不裁定**支持得够不够**;77.9% vs 96.2% 正是「**有来源 ≠ 充分支持**」的测量 |
| 10-13「检索准入」合并行 | **召回侧:这条能不能进这一次回答**(逐条判定) vs **写入侧:它能不能进记忆库**(类别是判定依据)—— 准入再严,救不回一条本不该被存下的东西 |
| `[[ContextRot]]` | **量变导致精度下降** vs **不同内容类别本身的可靠性基线就不同** |
| 09-29「记忆完整性」 | **写进来的是假的** vs **写进来的是真的、只是支持不足而被当成确定的** |

**核心「但是」(须进第一屏)**:单预印本、合成 persona、**效应量 modest**(6.2%→4.0%)。它给的是「**按类别取值**」这个方向和一个方向一致的结果,**不是一个可以照抄的阈值**。

### 建议下一步

- **低成本优先(推荐)**:修订 `concepts/Abstention.md` 增「**弃权有两端:不答 / 不存**」;`concepts/MemoryGovernance.md` 增「**Capture 的门槛按类别取值**」;`concepts/Provenance.md` 增一行「有来源 ≠ 支持得足够」。
- 值得生成 `learning-materials/memory-write-abstention.html`;骨架建议 = **「写入侧 × 读取侧」两行对照**(一行 = 本候选的类别化门槛,一行 = MemoType 的路由),中间共用一句判据:**「一条策略管不住多类语料」**。
- 与候选 3 呼应:GemForge 那条把单次失败硬化成永久规则的案例,是本候选「入口端缺闸门」的**具体失效形状**,两篇可互为案例。

# 方法备注 · 第十条扫描线
