### 11-18A 编排框架的授权与信任边界 —— 把框架当被测主体,同一 LLM 下表现不同 ⭐⭐⭐

**一句话**:Agentic 系统的安全风险发生在**编排边界**(身份怎么表示、操作怎么授权、指令与信息怎么在组件间传播);以往多在单一框架内讨论,本文用**同一 LLM(gpt-4o-mini)** 横向实测 LangChain / LangGraph / AutoGen / OpenClaw 四个框架,把"框架能力/模型级指令"与"真正强制执行的授权边界"分开。

**为什么当下最有价值**:它正面顶到 🎯 **10-13「检索准入 × 跨主体状态隔离」**——本库连续多期标注"跨主体机制证据仍缺";本文给出**跨框架的可复现机制原型**:工具链组合(E3)、TOCTOU 符号链接(E6)、委派/审计伪装成合法任务的权限提升(Variant D)在多数框架中都能突破授权,而显式授权、受控能力分配、文件系统隔离与执行防护在受保护配置下能挡住特定越权。它同时是第 20 条(授权口径)在**存储/决策两侧之外补上的编排侧证据**,与 11-15A 授权漂移、11-15B 权限合取构成"漂移—合取—边界实测"三段。

**数字与机制(一手 abs 已核,2026-11-18 WebFetch arxiv abs 页)**

- 12 个实验映射到 **OWASP Top 10 for Agentic Applications**,统一用 gpt-4o-mini,覆盖提示注入 / 未授权资源访问与命令执行 / 记忆投毒 / 跨主体信任与身份攻击。
- 提示注入(E1/E2):A–C 变体(直接覆盖 / HOUYI 分隔符 / 权威声称)四框架全抵抗;**Variant D 委派/审计伪装**在 LangChain / LangGraph / OpenClaw 三个框架诱出未授权工具调用(虽均未外泄 canary),AutoGen 完全抵抗。

### 11-18B 自改进 harness —— harness 从固定脚手架升为可自改写的演化对象 ⭐⭐⭐

**一句话**:基础模型能否当自主 agent,同样取决于运行时软件(harness);静态 harness 为一个模型/任务调好后,换模型就卡壳、烧 token、性能回退。本文给出统一框架:把 harness 拆成**四个可编辑运行时组件**(上下文与状态 / agent 控制 / 动作接口 / 验证与恢复),配一条**四阶段循环**(诊断失败 → 提议代码补丁 → 验证候选 → 部署更新)。

**为什么当下最有价值**:本库 `AgentHarness` 页此前只讲 harness 的**四个职责是什么**,B 把问题推进到"**这四个职责能不能被 agent 自己改写**",并给出排序证据:门控的模块化演化 > 提示词反思 > 全量 harness 重写。它同时回应 11-16 反复出现的"验证器/门"母题——self-modification 的安全护栏(防提示词膨胀、benchmark gaming、评测器篡改)本身就是新一轮的"谁来验证验证者"。

**数字与机制(一手 abs 已核,2026-11-18 WebFetch arxiv abs 页)**

- 四可编辑运行时组件:context and state / agent control / action interfaces / verification and recovery。
- 四阶段循环:diagnose failures → propose code patches → validate candidates → deploy updates。
- 优化器沿长轨迹追错,自动发现可复用运行时机制:**pre-stop verifiers / loop breakers / persistent memory**。
- 全量重写会过拟合或跨模块崩坏;**带验证门(modular updates with validation gates)的模块化更新**跨模型泛化且约束 token 成本。
- 实验:SWE-bench Lite 上,门控模块化演化在**跨模型、跨仓库**上优于提示词反思与全量重写,token 成本只是其一小部分。
- 明确反对的失效模式:prompt bloat / benchmark gaming / evaluator tampering。

### 11-18C MAPE 程序演化发现记忆设计 —— 别再手调记忆系统,让程序自己搜设计空间 ⭐⭐

**一句话**:记忆系统的人工设计众说纷纭,MAPE 用**程序演化**从最小种子出发、经标准化生命周期接口与"诊断—提议"循环自动演化整个记忆程序;在 LoCoMo / LongMemEval 上比人工设计基线**最高 +12 个百分点准确率,只要 35% 的服务成本**,且跨服务骨干与基准可迁移。消融收敛出两条真正管用的设计模式:**保留原始对话作为可检索证据** + **按查询意图组合证据**(把组合模块移植进 5 套既有记忆系统全部提升)。

**为什么当下最有价值**:它与 11-16A DISCERN 构成一组**张力对**——DISCERN 从**判定端**说"召回已饱和、瓶颈是消解";MAPE 从**设计端**说"真正拉开差距的不是更花哨的检索,而是保留原始证据 + 按意图组织"。两条独立工作同时把矛头指向"卷检索算法本身"的边际收益。它还是 overview 最老开放项(RAG 案例研究)与"记忆设计选型"的实证回答:给"该往哪投资"一个可迁移的答案,而非又造一个系统。

**数字与机制(一手 abs 已核,2026-11-18 WebFetch arxiv abs 页)**

- LoCoMo / LongMemEval:比人工设计基线**最高 +12pp 绝对准确率,35% 服务成本**,跨服务骨干与基准可迁移。
