## 二、概念雷达（阶段二 · 3 条候选）

**本期母题**：三条都是「**加法而不是替换**」——保留原机制，在旁边挂一个廉价的伴生结构，让它只在关键时刻补位。A 不替换文本记忆，旁边加一条参数化通道（低秩 adapter），逐字情节缓冲继续供货；B 不替换当前 prompt，旁边加一道评测门 + 可撤销修复，全不过就保留原样；C 不替换同步摘要，旁边加一条旁路摘要队列，趁主队列的队头阻塞闲置算力做事。共同反对一个默认假设：**要改进一个机制就得替换它**。判别式轴 +3（**伴生结构挂在哪一层 / 变更的采纳判据 / 动作的执行时机**）；时位补三格：**固化时**（A）、**采纳时**（B）、**排队时**（C）。

### 11-24A 即时权重空间固化 / Instant Weight-Space Consolidation（CLAM） ⭐⭐⭐

**一句话**：用一个循环超网络把一整串会话激活在**单次前向**里编译成一个低秩 adapter，**零梯度步、零语言模型生成调用**；门控隐状态以固定大小跨会话携带知识，参数化记忆累积但不膨胀；再配一个逐字情节缓冲在推理时补足细节。LoCoMo / LongMemEval-S 三个开源模型（2–7B）上领先所有 agentic 基线 **1–45 分**、领先所有梯度参数法 **10–45 分**，构建记忆快 **3–151×**；两通道互补——情节缓冲漏掉 gold evidence 时参数通道补 **12–15 分**，即使用 oracle 缓冲仍补 **4–5 分**。

- **概念名（中英）**：即时权重空间固化 / Instant Weight-Space Consolidation（CLAM, Carried Latent Adapter Memory）
- **为什么"当下"最有价值**：overview 记忆三条出路（删掉 / 索引 / 编译进权重）里的第三条此前只有**需训练**的形态（10-17A 连续记忆要编码器、11-05C OPSD 要蒸馏）；CLAM 把固化成本压到单次前向，且给出一条从未被测的判据——**参数化记忆与逐字缓冲不是替代关系而是互补关系**（oracle buffer 下仍 +4–5）。这正面给 10-22B「MemoryTax：原始历史两次胜过压缩记忆」的张力一个答案：不是"原始 vs 编译"二选一，而是两条通道各补对方的盲区。
- **来源链接（均 [verified]，一手 abs 已 WebFetch 直开核验）**：
  - https://arxiv.org/abs/2611.20759 [verified] —— 一手 abs（直开）：标题、两作者（Manan Suri / Dinesh Manocha）、v1 2026-11-16、cs.CL、全部量化结论出自此页摘要
  - https://arxiv.org/pdf/2611.20759 [verified] —— 一手 PDF（abs 页 View PDF 链接）
  - https://arxiv.org/html/2611.20759v1 [verified] —— 一手 HTML 全文（abs 页 HTML 链接）
- **一句话定义 + 边界辨析**：定义——用循环超网络无梯度地把会话流编译成固定大小低秩 adapter，与逐字情节缓冲并行供货。边界：① vs 10-17A 连续记忆 / 11-05C 权重记忆——那些要训练/蒸馏，本条**零梯度即时**；② vs [[LongTermMemory]] 的"you cannot cite a vector"——那条说向量不可逐条引用，本条承认这点并**另设情节缓冲供逐字取证**，两条通道分工而非合并；③ vs [[Compaction]]——压缩改文本、丢细节，本条不改任何文本，把知识放到权重侧。
- **⚠️ 证据边界**：预印本、两作者单团队、自报；只在三个 2–7B 开源模型上测，前沿闭源模型未证；"3–151×"是构建记忆的墙钟对比，跨度大说明基线差异极大，不可当稳定增益；"oracle 缓冲仍 +4–5"是作者自己的 oracle 设定；一手 abs 未提代码开源。成篇前须开 PDF 核超网络训练方式与 oracle 缓冲定义。
- **建议下一步**：作为 `agent-memory-provenance.html` / `memory-lifecycle.html` 的一节批注「第三载体：即时编译进权重 + 逐字缓冲互补」，或生成草稿级 `learning-materials/instant-weight-consolidation.html`。受「人工核查承诺」约束，**只写 `output/pending-review/`，不写 `learning-materials/`**。

### 11-24B 个人智能体更新安全 / Safe Personal RSI（递归自我改进的评测—修复门） ⭐⭐⭐

**一句话**：把递归自我改进（RSI）**限定在 prompt 更新**（权重与运行时代码固定），adoption 前跑一套评测程序：同时测 proposed 与 current 指令、重复失败用例、**临时撤销变更以引导修复**、通过安全与任务双检查才采纳，全不过则保留当前指令。可执行基准含 29 个邮件 / 日历 / 健康 / 购物案例，另有授权复用、记忆、工具输出注入三类独立探针。三模型 × 两处故意危险编辑下 **21 次更新拒绝 20 次**；一次被采纳的修复把攻击违规 **10.7% → 0%**、安全任务完成 **89.7% → 100%**，一条宽泛手写 authority rule 效果相当；更强攻击下跨模型迁移的修复（Qwen2.5-7B → Qwen3-14B）把违规 **69.0% → 17.9%**、安全完成 **19.5% → 64.4%**。运行时探针还查出被评测快照**缺失本地 OAuth scope 检查**。12 作者，v1 2026-11-18 / v2 11-20，cs.SE+AI+CL。

- **概念名（中英）**：个人智能体更新安全 / Safe Personal Recursive Self-Improvement（Safe Personal RSI）
- **为什么"当下"最有价值**：这是台账 11-10A 挂了 14 天的那条开放项——「**验证门槛是唯一治理答案、但没有任何自演化系统测它**」（`Skill.md` 批注仍写着）——的**正面结清**，而且测的是 Skill / prompt 自身的更新，与 11-13A FGSE 的"经验入库门"是不同形态。三个承重发现各接一格：①「临时撤销引导修复 + 全不过保留当前」是 [[MemoryGovernance]] 四底线里 *rollbackable* 的第一次可执行化；②「手写 authority rule 与学出来的修复同效」直接接**第 20 条授权口径审计（见 `SCAN-LINES.md`）**——朴素的来源判据就能顶掉复杂修复；③「缺失本地 OAuth scope 检查」接 [[AgentIdentity]] 的 per-hop attenuation 在真实个人助手里的落地缺口。

### 11-24C 队头阻塞期 KV 压缩 / Head-of-Line-Stall KV Compression（Aggron） ⭐⭐

**一句话**：一个服务系统，不等 KV cache 越过阈值才一次性压缩大段历史，而是**每轮都摘要、只摘要部分 KV**；更关键的是把摘要请求放到独立的 Summarization Queue，趁对应的 agentic 请求因**队头阻塞**卡在主队列时，用那份本就闲置的算力与内存做摘要，且只在预测摘要能在该请求真正执行前完成时才发起。高负载下 P99 程序延迟降 **27–31%**、吞吐提升 **1.34–1.40×**。8 作者，v1 2026-11-19，cs.DC+AR。

- **概念名（中英）**：队头阻塞期 KV 压缩 / Head-of-Line-Stall KV Compression（Aggron）
- **为什么"当下"最有价值**：这是 11-23C Contexture 的**同层对偶**——Contexture 在 serving 层做**驱逐**（按工具操作溯源移走 token），Aggron 在 serving 层做**摘要**（把历史压成更短的表示），两条路正好是第 16 条（改写 vs 拦截，见 `SCAN-LINES.md`）在服务层的两个形态。更锋利的是它挖出一个从没被定价的免费资源：**队头阻塞期间主队列已经付了等待成本，算力/内存是闲置的**——把摘要塞进这个窗口，就把原本占关键路径的压缩变成近乎免费。这是第 4 条资源定价盘点（见 `SCAN-LINES.md`）的又一个实例，且指向一个具体可迁移的判据：**"这个动作能不能挪到别人正在等待的时间里做"**。
- **来源链接（均 [verified]，一手 abs 已 WebFetch 直开核验）**：
  - https://arxiv.org/abs/2611.26435 [verified] —— 一手 abs（直开）：标题、8 作者（Rishabh Ravi / Tony Hong / Chen Wang / Yue Zhu / Mengmei Ye / Hubertus Franke / Fan Lai / Josep Torrellas）、v1 2026-11-19、cs.DC+AR、全部量化结论出自此页摘要
  - https://arxiv.org/pdf/2611.26435 [verified] —— 一手 PDF（abs 页 View PDF 链接）
  - https://arxiv.org/html/2611.26435v1 [verified] —— 一手 HTML 全文（abs 页 HTML 链接）
- **一句话定义 + 边界辨析**：定义——每轮选择性摘要部分 KV，并把摘要调度到主队列队头阻塞的闲置窗口，配一道"能做完才发"的预测门。边界：① vs 11-23C Contexture——驱逐改的是"哪些 token 参与注意力"，摘要改的是"历史被压成什么"，两者不互斥、可叠加；② vs [[Compaction]]——压缩在 harness 层改模型看到的文本，本条在 serving 层管 KV 缓存，宿主不同；③ vs 10-21B AKV 缓存工程——AKV 用 drop / repos 不改一个字，本条**要生成摘要**，是改写侧而非拦截侧。
