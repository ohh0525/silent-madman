### 候选 1 ⭐⭐ 记忆税 / Memory Tax —— 记忆相对于「朴素 RAG」的净值是负的

**一句话定义**：把**朴素 RAG**（分块检索原始历史，不做任何记忆处理）当作基线，把一个记忆系统的得分拆成 **memory benefit**（RAG 答错、它答对的题）与 **memory tax**（RAG 答对、它答**错**的题）—— 净值 = benefit − tax。当 tax 更大时，记忆系统整体上**输给**它本该取代的那个基线。

**为什么「当下」最有价值（缝隙在哪）**：本库**没有 RAG 页**——`RAG` 在全 `wiki/` 只出现 **5 次**、分散在 5 个页面各 1 次，`concepts/` 下**根本没有 `RAG.md`**；而 overview 的**最老开放项**（「A concrete RAG system case study」）与台账**最老 `⏸` 行**（09-17 RAG，**42 天**）**两条独立计数持续指向同一件事**。本行把这件事从「**缺一个 RAG 案例**」变成「**有一个基准答案：朴素 RAG 是记忆系统必须打赢的基线，而多数打不赢**」⇒ 它同时是**最老开放项的结清仪器**和 [[MemoryGovernance]] 承重结论（「瓶颈是四个动作的质量」）的**替代解释**。

**关键数字（[verified]）**
- **11 个记忆系统**（扁平 A-Mem / SimpleMem / MemOS；层级-生命周期 MemoryOS / LightMem / OpenViking；图 HippoRAG2 / PlugMem / MAGMA；训练策略 Mem-T / Memory-R2）× **3 基准**（LongMemEval-s / PersonaMem-v2 / MINT-Eval）× **3 骨干**（Qwen3.5-4B / Qwen3.6-27B / GPT-5.6-luna），统一 embedding、LLM judge 评分、**对齐 retrieval scope**（防「记忆系统只是拿到的更少」这一反驳）。
- LongMemEval-s / 27B：**two-round RAG 81.4**，最接近的 A-Mem **79.4**，MemOS **76.6**；LightMem 在 4B 上落后 **14.6 分**，OpenViking 落后 **40.4 分**。
- **成本侧更刺眼**：A-Mem 离线建库 **117 小时** vs RAG **0.11 小时**（**三个数量级**），**98.4K** 次 LLM 调用 vs **200** 次。
- **税的三个来源**：**Faithfulness**（OpenViking 对 **38%** 事实根本没有记忆单元、另 **13%** 重大损失；对照 MAGMA **93.6%** 无损 ⇒ *loss is a design choice, not fate*）· **Accessibility**（活下来的证据也可能检索不到：第一轮取回的 query 数少于 RAG，证据被埋得更深）· **Robustness**（记忆固定、换 QA 骨干时，记忆系统比原始 RAG 抖得更厉害）。
- **基准也有份责**：一批长期记忆基准上，**无向量的 IDF 关键词匹配也能过 50%**、混合检索约 **70%** ⇒ 任务本身对检索友好、天花板低，于是税才显形。

**边界辨析（与已覆盖概念）**
- vs **10-22B `MemoryTax: The Bitter Lesson`（`arXiv:2610.29823`，Zedong Peng）—— 同名不同文，必须分清**：那篇是**单作者 · 1 段 LoCoMo 对话（419 轮 / 152 问）· 每格 1 次运行 ⇒ n=1**，结论「记忆是弱模型的昂贵补丁」；本篇是 **11 作者 · 3 基准 · 3 骨干**。**前者是信号，后者才是可引用的仪器**。⇒ **建议并入 10-22B（作为其实证升级），并用它结清 09-17 RAG 行**（沿用 10-24 备查项给 Raw-RAG 的同一惯例）。
- vs [[MemoryGovernance]]：那条说「瓶颈是四个动作的质量」；本行说「瓶颈也可能是**写记忆的那个模型** + **压缩扔掉了什么**」，且给出可记账的**净值框架**。⇒ **替代解释，不是推翻**。
- vs [[Compaction]] / 10-26B：那条是「压缩按内容类别有偏」；本行是「**任何对原始历史的偏离都是双刃的**」⇒ 压缩是税的**一个来源**，不是全部。
- ⚠️ **必须同屏**：预印本未同行评议；benchmark 天花板低这一点**作者自己也在责备**；Memory-R2 在 PersonaMem-v2 上**赢 RAG 2.0**、PlugMem 在 MINT-Eval 上**赢 3.3** ⇒ **不是全歼**，诚实引法是「**记忆的边际收益需要重新记账**」，**不可读作「记忆无用」**。

### 候选 2 ⭐⭐ 常驻上下文的衰变 / Knowledge Decay（OSTEON）—— agent 上下文文件里指到的东西，已经不在了

**一句话定义**：`AGENTS.md` / `CLAUDE.md` 这类**常驻**上下文文件不是资产而是**会过期的内容**；OSTEON 提出的学科是：每个项目维护一个受治理的「**决策与契约**」知识库，每次改动机械核对它，并且**在每次会话开始时检查知识本身是否衰变**。

**为什么「当下」最有价值（缝隙在哪）**：本库 🎯 **10-09「常驻上下文与指令预算」**那一行在 10-26 已落地为「常驻 vs 按需 100% vs 53% 的分配规则」与「常驻文件越老越少删」—— 但它回答的是「**留不留**」。本行补的是另一半：**留着的这份，内容已经失效了**——不是「删不删」的问题，而是「它指向的东西已经不在了」。⇒ [[ProgressiveDisclosure]] 的既有告诫是「按需加载的前提是它会加载」，本行给出**反向的那一半**：**常驻的那份一直在，但它已经不真了**。

**关键数字（[verified]）**
- 对 **452 个最高 star 的公开 GitHub 仓库**的探索性快照：**48.67%**（95% CI **44.1–53.3**）存在 root 级或 `.github/` 下的 agent 上下文文件。
- 在**命名了仓库路径**的中位文件里，**9.5%–22%** 的路径**解析不了**（取决于如何解读一处引用）。
- 模型部分：审查能力固定时，**逃逸的改动随吞吐线性增长**，而「读」能抓住的比例**趋于零** ⇒ *governance can lower the slope, capability alone cannot*。
- OSTEON 四条：受治理的决策/契约知识库 · **每次改动机械核对** · **每次会话开始检查知识衰变** · 规划被闸门、**会话记录所学但不写成规则**。

### 候选 3 ⭐ 判官偏向「更多记忆」 / Memory-Aware Reward Modeling —— 连评分函数本身都在夸记忆

**一句话定义**：用**真人偏好**去测「带记忆的回答是否更受欢迎」时发现——带记忆的回答**并不一致更受偏好**，某些情况下用户**强烈偏好**无记忆版本；而**自动判官与用户的一致性有限，且远比用户更频繁地选择带记忆的回答** ⇒ **记忆的价值被评分侧系统性高估**。

**为什么「当下」最有价值（缝隙在哪）**：[[AgentObservability]] 页（10-26 新建、仍 pending ingest）把评测分成 trace / semantic / **judge** / meta / cost 五层，但**「判官层」本身从未被当作一个会偏的对象**——五层都在问「**测得准不准**」，**没有一层问「**评分函数自己有没有系统性偏向**」**。同时它是 10-21「第三载体只按聚合准确率评分」的**第二次独立实证**：第一次是**聚合分数**藏掉分布，这次是**判官偏好**直接偏向「用了记忆」这件事 ⇒ **两次独立测量指向同一方向：更多记忆在评分侧被系统性高估**。

**关键数字（[verified]）**
- **约 1,000** 组成对判断 / **87 位**参与者，**每位用自己的真实 ChatGPT 查询与自己导出的记忆**做判断（关键设计：判的是**关于自己的**记忆，不是泛指「哪个回答更好听」）。
- 结论一：**记忆条件下的回复并不一致优于无记忆版本**，**某些情况下用户强烈偏好无记忆版本**。
- 结论二（**本行最硬的一句**）：**自动评估者与用户一致性有限（预测准确率接近多数基线），且选择记忆条件回复的频率远高于用户**。
- 他们据此训练的 memory-aware reward model 达 **72.8%** 偏好预测准确率，超过既有基线。
- 作者点名三类失败：**over-personalization**（先前的偏好被套用到当前不该套用的请求上）等——**这些不能归为记忆准确性或检索的失败，而是「该怎么用」的失败**。

**边界辨析（与已覆盖概念）**
- vs **10-25C**（AUROC 0.741 天花板）：那条是**检测器精度上限**；本条是**评分函数的偏向** ⇒ 一个是「测不出来」，一个是「**测出来也是歪的**」。
- vs **10-27C SciValidityBench**：那条说「**记住对了 ≠ 有资格用它做决定**」（**对象层面**）；本条说「**连判官都判不出这件事**」（**测量层面**）⇒ **同一段的两半，须分栏互指**。
- vs **10-26C**（披露自我强化）：那条是**记忆改变了它自己的输入流**（系统侧回路）；本条是**评测奖励了记忆的使用**（测量侧回路）⇒ 因果方向不同。
- ⚠️ **必须同屏**：预印本未同行评议；**87 人的自建记忆画像**样本；72.8% 是**偏好预测准确率**、不是任务准确率；**不可读作「记忆没用」**——作者的主张是**换优化目标**（从检索准确率换到用户偏好），不是删掉记忆。
