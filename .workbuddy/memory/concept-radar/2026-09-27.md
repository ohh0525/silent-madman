### 候选 1 ⭐ **持久化执行 / Durable Execution(运行时层 Runtime Layer)**

**为什么当下最有价值(缝在哪)**

`overview.md` 的 Open Question 里**自己写下了这句话**:「persistent execution ... **what remains unwritten is the cross-runtime semantics comparison**」——而 **2026-09-19 首次出现一份中立的四运行时恢复语义对比**(证据截止 09-17),正好就是那句「尚未写」的东西。更关键的是它是 **Cluster E(harness)的下一层**:LangChain 原话「*To build a good agent, you need a good harness. To deploy that agent, you need a good runtime.*」——09-26 刚建成的 [[AgentHarness]] 页,今天就能凭「**壳下面那层是什么**」直接推出缺口。

**一句话定义**

让长时运行的 agent 工作流在**进程崩溃 / 部署重启 / 人工暂停**之后,从**已持久化的执行边界**继续(而非重跑),核心四原语 = 日志化步骤 + 带幂等的自动重试 + 持久化定时器/信号 + 可恢复性。

**与已覆盖概念的边界辨析**

| 对照页 | 边界 |
|---|---|
| [[AgentHarness]] | **实现 vs 运营持续性**。harness 决定「谁跑这个循环」(给 prompt / tools / skills);runtime 决定「这个循环怎么在崩溃、部署、暂停中不死」(给 durable execution / 多租户 / 可观测性)。 |
| [[LongTermMemory]] | 记忆记的是「**事实**」;持久化执行记的是「**已完成的执行边界**」。**会话记忆 ≠ 持久化执行**——记忆能记住 agent 在做什么,但无法证明「哪条 shell 命令真的跑过、哪封邮件真的发出去了、哪次审批真的被授予」。 |
| [[HumanInTheLoop]] | 闸门要求「暂停**可持久化**、恢复者**未必是原进程**」——持久化执行正是这条要求的**兑现层**(否则「人在环」只能在同一个活进程里等)。 |
| [[Compaction]] | 压缩管「窗口内**看多少**」;持久化执行管「窗口外**活多久**」。一个裁上下文,一个保进程。 |
| [[MultiAgent]] | 协作的**空间**维度(多 agent 同时);持久化执行的**时间**维度(同一 agent 跨崩溃/跨天)。 |

**⚠️ 本候选最值得写进材料的「但是」(边界条件即内容)**

- **checkpoint ≠ durable execution**:检查点保留的是**控制状态**,**不是**下游副作用的 exactly-once。「resume」这个词在四个运行时里**指的不是同一件事**:

| 运行时 | 恢复机制(durable reconstruction unit) | 复用什么 |
|---|---|---|
| **Temporal** | 事件历史**重放**(Event History replay)重建 Workflow 状态 | 确定性工作流决策由历史重建;Activity 重试按记录状态与重试策略 |
| **DBOS** | 工作流函数**从头重入**,持久化操作按 `(workflow_uuid, function_id)` 寻址 | 位点与函数身份匹配时**采纳**已完成操作的结果,而非重跑 |
| **Microsoft Agent Framework** | 每个 superstep 完成后的**检查点**(executor 状态 + 待处理请求/响应 + 共享状态) | 恢复到最新持久化 superstep;挂起的 HITL 请求可重新发出 |
| **LangGraph** | **线程级快照**(super-step 边界)+ pending writes | 检查点之前的节点不执行;pending writes 可避免已完成的兄弟节点重跑 |

> **没有任何一个能凭自身让任意的外部副作用 exactly-once。** 且报告明确指出:四者的对比是**语义对比,不是性能排名**(不存在同一负载跑遍四家的证据)。

- **两个可直接引用的「事故式」判据**:①Nirvana Labs 的追问句——「问厂商的问题不是它**是否**持久化,而是**一次没人安排的 kill 之后还剩什么**」(它举例:E2B 终止沙箱后 0/5000 检查点存活,因为本地盘随之消失;Quirq 被杀进程后重建 pod,5,501 个已提交检查点全部回来);②运行时对**短程/未 PMF/单租户** agent 是**净开销**——它固定了契约(事件 schema、响应版本),在 agent 形态还能变时,这个契约本身就是迁移成本。

### 候选 2 **智能体记忆治理 / Agent Memory Governance(多智能体共享记忆的权限、冲突与审计)**

**为什么当下最有价值(缝在哪)**

`overview.md` 的 Open Question 明写:「(... orchestration side covered 2026-09-26 by [[MultiAgent]] ... **the governance side — RBAC on shared memory, who may write what — remains open**)」。[[MultiAgent]] 页刚刚(09-26)点出「互相污染」这一新失效面——**今天正好有产业证据回应它**,且现有记忆簇四页(Provenance / CitationLock / Abstention / LongTermMemory)**只治理「单 agent 跨会话的事实来源」,对「谁能往共享记忆里写、冲突谁裁决、写错了怎么撤」零覆盖**。

**一句话定义**

把「智能体记忆」当作**受治理的组织资产**(而非每个 agent 的私有草稿),以 **作用域 × 角色 × 读写** 三维权限 + 版本化 + 冲突裁决 + 审计留痕来规定「谁可写、写什么、写错了怎么办」。

**与已覆盖概念的边界辨析**

| 对照页 | 边界 |
|---|---|
| [[LongTermMemory]] | 前者是**单 agent** 的外存机制(窗口外持久状态);治理是**多 agent / 多用户**的权限与一致性**制度**。 |
| [[MultiAgent]] | 多智能体页给出的失效面是「**互相污染**」;治理是它的**制度性回应**——用权限 + 版本 + 裁决把「谁能写」变成**结构性约束**,而不是寄望于 agent 自律(与 Cluster D「控制不该放在 prompt 里」同一条原则)。 |
| [[Provenance]] | provenance 让**每条事实**带来源/时间/证据;治理让**每个写入者**带权限与审计。**事实可信 ≠ 写入者可问责**——与 [[AgentIdentity]] 那句「事实可信 ≠ 行动者可问责」**同构**,只是对象从「手」换成了「笔」。 |
| [[HumanInTheLoop]] | 闸门按「影响 × 可逆性」拦**动作**;记忆治理拦的是**事实的写入**。一个不可逆的错误写入会像记忆错误一样**复利**(overview 早已记:「memory errors compound」)。 |

**你可直接引用的关键事实**

- **三种共享记忆架构(各换一致性 vs 吞吐)**:① 分层知识图谱(强一致,冲突靠版本,图查询加延迟);② **事件驱动 append-only 日志**(无人覆盖 → 无写冲突,最终一致;HydraDB Hive Memory 即此型);③ 监督者 + 私有记忆(single-writer,无冲突,但 50+ agent 时监督者成瓶颈)。
- **冲突四策略**:last-write-wins(快,但对金融/安全场景危险) / supervisor decides(慢但可控) / **versioning(保留多个真相,各自引用自己信任的版本)** / temporal ordering(时间戳裁决,公平可复现)。
- **「Git-like 五原则」**(企业记忆应有的样子):**Scoped / Versioned / Reviewable / Auditable / Portable**(可审计、可复核、可导出,避免厂商锁定)。
- **治理四层**:身份与授权 → 编排控制 → **数据与记忆治理** → 运行时观测;**记忆治理层要回答**:什么可被记住、谁能取回、保留多久、以及「**该记忆是可信指令还是不可信参考**」。
- **组织级记忆三层内容架构**:宪法 / 典籍 / 战报(中文源,含「组织失忆的重复学费」量化:50 人组织年重复学费≈4–6 工程师年产能)——与 [[Provenance]] 的「事实 vs 参考」区分天然衔接。

### 候选 3 **智能体化检索 / Agentic RAG(向量库的范式反转)**

**为什么当下最有价值(缝在哪)**

它填的是 `overview.md` **最老的开放项**(RAG,since **2026-09-09**,原文标注「now the **oldest** open item」,也是 Next Ingest Suggestions 第一条)——但**不是把 09-17 推荐过的「RAG 基础」再推一次**,而是因为**这一项本身在 2026 年发生了范式反转**:AAAI 2026 的 Amazon Science 论文实证「**无向量库的 agentic 关键词检索达到 RAG 级表现**」。默认起点被推翻,这是一个**新事实**,不是旧话题。

**一句话定义**

把检索从「**预先建索引 + 一次性 top-k**」变成「**agent 在循环中自己决定查什么、查几次、何时停**」——检索器就是 agent 当下选择调用的那个工具(shell / grep / BM25 / 语义库皆可)。

**与已覆盖概念的边界辨析**

| 对照页 | 边界 |
|---|---|
| [[ContextEngineering]] | 上下文工程讲「每步往窗口**放什么**」;agentic RAG 讲那些内容「**从哪里、用什么工具、查几轮**来」——它是 JIT 检索的**供给侧**,是 ContextEngineering 已命名原则的一个**新实例**(与 [[ProgressiveDisclosure]] 同构:都是「按需加载」)。 |
| [[Skill]] | Skill 按需加载的是**知识 / 流程**;agentic RAG 按需加载的是**证据**。 |
| [[LongTermMemory]] / [[Provenance]] | 检索到的证据**用完即弃**;记忆持久化且规定「**未打开的证据不得引用**」。反转**放大**了 provenance 需求——agent 自己选检索路径,更必须锁定「它**实际打开过**什么」(否则 citation lock 无从校验)。 |
| [[MultiAgent]] | Anthropic 的研究系统(lead agent 分解 → 3–5 个子 agent 各跑自己的检索循环 → 只回蒸馏结论)就是 09-26 那张图在**检索上的实例化**;同一个教训:**子 agent 只回结论,谁来验证?** |

**你可直接引用的关键事实**

- **Amazon Science / AAAI 2026《Keyword Search Is All You Need》**(Subramanian 等):**完全相同的 LLM**(Claude 3 Sonnet / 200K / temperature 0.001)、**相同 6 个数据集**、**相同评测框架**,唯一变量是检索器(向量 RAG vs. 调 `pdfmetadata`/`rga`/`pdfgrep` 的 ReAct agent)。汇总达成率:**Faithfulness 94.5%**(0.81 vs 0.86)、**Context Recall 88.0%**、**Answer Correctness 91.5%**。**异常点反而更说明问题**:FinanceBench(长表格密集的金融申报)**发生反转**,agent 30.40% > RAG 24.24%;BlockchainSolana(精确术语文档)达成率 99.97%。
- **Search-R1**(arXiv 2503.09516):用 RL **训练检索策略本身**(检索文档被 mask 出 policy loss),7 个 QA 数据集平均 EM **0.431 vs RAG 0.304**(相对 **+24%**,7B 模型)。→ 架构含义:一旦检索变成工具调用,它就成了**可学习的策略**,而**冻结的 embedding 模型做不到**。
- **已放弃 embedding 的编码类产品**:Windsurf / Cline / Devin / Sourcegraph Amp——代码库充满精确锚点(标识符、导入、路径、类型名),语义相似度问题本就少,真正的需求是**精确导航**。
- **Anthropic 研究系统**:多智能体比单个 Opus 4 高 **90.2%**,复杂查询研究时间最多 **−90%**,代价约 **15× tokens**;Anthropic 自述 **token 用量本身解释 ~80% 的性能方差**;**但**多智能体利于**广度优先**任务(研究),不利于**深度串行**任务(编码)。
- ⚠️ **「但是」必须写进标题**:向量检索在**改述重 / 跨语言**查询、**语料无词法结构**、**延迟预算不允许迭代**时仍然胜出(单次 ANN 亚毫秒 vs 3–5 轮搜索 2–5 秒)。**新增失效面**=**不受控的 agentic 检索循环**:没有迭代次数上限或训练过的停止策略,平均质量上升的同时 **p99 延迟与单位查询成本方差会飙升**;必须把 **search-iteration count 当一等指标**(迭代次数持续上升 = 检索机制没找对内容,而非该调高上限)。

### 经验 / 坑(有长期价值,写入 daily log)

1. **「向下问一层」与 09-26 的「向里问一层」是同一族方法。** 09-26 记的是「这个机制跑在什么东西**里面**?那东西有页吗?」;今天由它**直接导出**:harness 的**下面**还有 runtime。可固化为——**对每个已建页面同时问「它的下一层是什么、上一层是什么」**。横向穷举概念名找不出结构性空洞,沿「层」追问可以。
2. **「昨天刚建的页,今天就能看到它的下一层」证明缺口是可推导的,而非靠灵感。** harness 页 09-26 建成,09-27 即可凭「壳下面那层」定位持久化执行;而 overview 早在 **09-23** 就把这个问题写进了 Open Questions。**synthesis 的 Open Questions 第三次被验证为最高价值的雷达输入**(09-25 首次记录)。
3. **同一个词,四个运行时里指的不是同一件事。** 「resume」在 Temporal / DBOS / MS Agent Framework / LangGraph 分别是**事件历史重放 / 按位点采纳已完成操作 / superstep 检查点 / 线程快照 + pending writes**。可迁移方法:**凡遇「行业共识术语」,先问「这个术语在各家实现里是不是同一个操作」**——比问「谁更强」更能暴露真实差异,也更容易写出有教学价值的材料。
4. **「checkpoint ≠ durable execution」是本日最值得写进材料的那个「但」。** 检查点保留的是**控制状态**,不是下游副作用的 exactly-once。与 09-26 的「团队收益的前提是验证器」**同构**——**边界条件才是内容**。
5. **「反转型」证据最适合当概念页的骨架。** 候选 3 的教学价值不在「RAG 好」,而在「一个流行三年、几乎所有教程都以此开头的默认起点(先选向量库),在 2026 年被实证推翻到 94.5%」。**写材料时应把反转写进第一屏**——这与 09-26「把『但』字放进标题」是同一条经验的两个变体。
