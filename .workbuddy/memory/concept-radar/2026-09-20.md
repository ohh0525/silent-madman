### 候选 1 ⭐ 首选:提示缓存 / KV 缓存(Prompt Caching / KV Cache)

**一句话定义**:把 Transformer 推理时算出的 **KV(Key/Value)缓存**跨请求复用——当新请求的开头与近期某请求**逐 token 完全一致**时,服务方跳过这段前缀的预填充(prefill),只处理新增 token;**缓存命中的 token 按 0.1~0.5 倍计价、且首 token 延迟显著下降**。

**为什么"当下"最有价值(缺口/接缝)**:
你的「有界资源」簇(**[[LLMContext]]** / **[[Token]]**)**只算了「量」这一根轴**——而且 `Token.md` 白纸黑字写着「Pricing is per-token (input + output)」,即**默认每一枚 token 价格相同**。2026 年这个前提被彻底打破:**同一枚 token 因缓存状态不同,价格差 2~10 倍**(命中读到 0.1 倍,写入反而 1.25~2 倍)。更关键的是它**改写你 [[ContextEngineering]] 的既有建议**:你现在的原则是「按信息寿命分层、稳定的放前面」——而缓存把「放前面」从**风格偏好**升级成**硬约束**(前缀必须字节级稳定,否则整段缓存作废;实测有团队靠把动态内容从 system prompt 挪到末尾,命中率从 **7% → 84%**、总成本降 59%)。物理底座也对得上:你 [[Transformer]] 页写的是「attention 是 n² 成本」——**KV 缓存正是把「重复前缀」从 O(n²) 降到 O(n) 的那个机制**。补上它,「有界资源」簇才从「一根量轴」变成「量 × 价」两维,而 [[Compaction]] 也会多一个**同方向的成本杠杆**(省 token vs 省单价)。

### 候选 2:工具调用 / 结构化输出(Tool Use / Function Calling · Structured Output)

**一句话定义**:让 LLM **不输出自由文本、而输出一个经 JSON Schema 校验的「调用规约」**(函数名 + 参数),由**宿主应用**(而非模型)负责校验与执行,再把结构化结果回填进上下文——这是「模型表达意图」到「系统确定性执行」之间的**契约层**。

**为什么"当下"最有价值(缺口/接缝)**:
你的 [[Agent]] 页把工具调用一笔带过——核心机制第 3 步写「**Execute tool + collect observation**」,伪代码里直接一句 `tool_call = model.choose_tool()`。**这个「choose_tool()」在你整个知识网里是个零成本黑箱**:[[ReAct]] 讲的是「**怎么想**」的推理模式,[[MCP]] 讲的是「**怎么连**」的传输协议,[[Skill]] 讲的是「**装什么**」的知识打包——**没有任何一页讲「模型到底怎么把意图变成一个可执行、可校验的调用」**。而这恰恰是 2026 年生产事故的头号来源:结构化输出之前的 agent,主要失败模式不是「想错」,而是「**想对了、格式写错**」(金额返回 `"$45.00"` 而非 `45.00`,下游直接崩)。补上这一层,你的 [[Agent]] 页才算把「行动」这一步落到实处,而且它会**同时给 [[MCP]] 补上被传输的那个「payload」**、给 [[Skill]] 补上「Skill 里的脚本是怎么被调起来的」。

### 候选 3:提示词自动优化 / GEPA(Prompt Optimization / Reflective Prompt Evolution)

**一句话定义**:把「**提示词**」从人手写的静态文本,变成**可被算法搜索优化的变量**——优化器跑一批带标签样例、把模型的**完整执行轨迹**(推理 + 工具调用 + 工具返回)**交给一个反思模型用自然语言诊断失败原因**,再据此改写指令,并在 Pareto 前沿上保留多个候选。

**为什么"当下"最有价值(缺口/接缝)**:
你的知识网里,**提示词是「作者」——人**。[[Skill]] 是「人写的文件夹」,[[ProgressiveDisclosure]] 是「人定的三层结构」,[[ContextEngineering]] 是「人做的取舍」,**整个体系默认「指令由人编写、由人打磨」**。2026 年这件事出现了一个**新的作者**:优化器。GEPA 在 **ICLR 2026 拿到 Oral**(作者名单含 DSPy 作者 Omar Khattab、Databricks 的 Matei Zaharia / Ion Stoica、Stanford 的 Christopher Potts 等),核心主张是「**语言的天然可解释性,比稀疏标量奖励更适合作为 LLM 的学习介质**」——RL 只告诉你「你得了 0.3 分」,反思告诉你「**你在没拿到用户 account ID 之前就调了搜索工具**」。它把你的「提示词/指令」变成**可度量、可优化、可回归测试的 ML 工件**,这条轴在 [[Skill]] 与 [[ContextEngineering]] 之外,是全新的。**注意边界**:它带来的不是「新机制」,而是「**产生机制的方式变了**」。
