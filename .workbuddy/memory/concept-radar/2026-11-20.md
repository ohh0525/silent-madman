## 二、概念雷达(阶段二 · 3 条候选)

**本期母题**:三条各自把一条「**评测信号本身**」升为一等被测对象——A 质疑「性能基准」能否代表记忆系统的全部责任(只看 performance/efficiency,漏掉 privacy / user sovereignty / security),B 质疑「recall 基准」能否代表记忆系统的价值(测的是「检索到了什么」,不是「让 agent 做成了什么」),C 质疑「高 ASR」能否代表红队的实际收获(mode collapse 下新增成功不带来鲁棒性)。共同反对一个默认假设:**「基准分数 = 真实能力/真实价值」**——这正是 11-16C ReA-Bench「抓到了≠抓对了」在三个新战场(记忆系统评测 / 记忆价值评测 / 红队收益)的继续展开。判别式轴 +3(**记忆评测的责任维度 / 评测测量的对象 / 攻击生成信号的保真度**);时位补两格:**评测时**(benchmark 设计)、**红队时**(攻击生成)。

### 11-20A HEAMS 记忆系统的责任式整体评测 —— 强性能可以与差隐私/差主权共存 ⭐⭐⭐

**一句话**:把记忆系统从「帮 agent 完成任务的工具」升格为「用户持久信息的保管者(custodian)」,用一组显式行为 desiderata 横跨 **performance / efficiency / security / privacy / user sovereignty** 五个维度整体评测;核心发现是**没有任何记忆系统在所有性能基准上领先,强性能分数可以与差的隐私、用户主权、安全分数并存**,而治理层(governance layer)能显著改变结果——召回策略以牺牲有用性换取更少的不当披露,召回 + 保留策略同时提升抗投毒。

**为什么当下最有价值**:正面顶到 overview 的「Cluster F memory governance has no production evidence」开放项——HEAMS 第一次把「用户主权」(能否被纠正 / 删除 / 不被超期保留)变成**可测的一等维度**,并给出可包裹任意记忆系统的 governance layer,把 11-13B「记忆的举证责任」、11-14C「经验退役的验证门」这些分散的治理机制放进同一张责任表实测。它也是 11-16C ReA-Bench「总体召回掩盖分维度盲区」在**记忆系统本体**上的翻版:此前本库评记忆只看「记得准不准」,HEAMS 证明这个口径会系统性漏掉用户实际在意的责任。

**数字与机制(一手 abs 已核,2026-11-20 WebFetch arxiv abs 页)**

- 五维责任 desiderata:performance / efficiency / security / privacy / **user sovereignty**;可包裹任意记忆系统的 governance layer,做「设计选择的可控研究」。
- 关键发现:**no memory system leads every performance benchmark**;strong performance 可与 poor privacy / user-sovereignty / security 分数**共存**。
- 治理效果:recall policies 降低不当披露(代价是 helpfulness 下降);**recall + retention 两种政策都提升投毒抗性**。
- 结论:performance + efficiency 基准**无法揭示**记忆系统是否满足其责任。
- 规模:69 页(正文 26)/ 6 图 / 29 表;代码开源 `github.com/milatechtransfer/heams`。

### 11-20B 最小 RAG 够不够 / RAG in a Trenchcoat —— 基准测的是「检索到了什么」,不是「让 agent 做成了什么」 ⭐⭐⭐

**一句话**:刻意最小的 RAG(BRIDGE:链式观察笔记 + BM25/余弦混合检索 + 时序渲染)在 LongMemEval-S / BEAM 上与先前 SOTA **统计打平(bootstrap CI 内)**、在 EverMemBench 上以同 reader 领先最佳记忆基线 **5.7–6.3 分**,每查询仅 ~5–7K reader-prompt token、每次摄取/查询仅一次 LLM 调用;据此论证「这些记忆原语几乎都不值它们的成本」,并提出五个对抗探针(每个查询只能靠应用一条从未明说的记住规则/模式才能解)——5 探针 × 20 场景**没有架构通用胜出**:原子事实提取器(LangMem)赢规则应用,BRIDGE 的块摘要赢模式归纳,而 recall 基准看不见这种差异。

**为什么当下最有价值**:与 11-18C MAPE 构成一组**直接张力对**——MAPE 说「演化整个记忆程序 +12pp @35% 成本」,BRIDGE 说「抽取/推翻/反思/图合成这些原语几乎都不值成本,最小 RAG 就打平」。两条独立工作从设计端给出相反答案,但**共同结论是评测对象错了**:MAPE 的 +12pp 与 BRIDGE 的 parity 测的都是「标准基准的 retrieval」,而真正该测的是「记忆让 agent 做成了什么」。这正是 11-16A DISCERN「召回已饱和、瓶颈在消解」的下一步:连「消解/检索」这个测法本身都被质疑了。它也回应 overview 最老开放项(RAG 案例研究)——用最朴素配置给出「值不值得堆复杂记忆」的零点。

**数字与机制(一手 abs 已核,2026-11-20 WebFetch arxiv abs 页)**

- BRIDGE:链式观察笔记 + hybrid BM25-with-cosine + chronological rendering;LongMemEval-S / BEAM 与先前 SOTA 在 bootstrap CI 内打平;EverMemBench 同 reader 下 **+5.7–6.3 分**。
- 成本:~5–7K reader-prompt tokens/query,每次摄取或查询**仅一次 LLM 调用**。
- 五个对抗探针:Rule Application +/−、Pattern Induction Style / Procedural、Dynamic Multiturn;由跨厂商验证链在生成时判分,每个查询只能靠应用一条**从未明说**的记住规则/模式来解。
- 5 探针 × 20 场景,四领域 / 三个 grader / 三个 reader family 上结论稳定:**没有架构通用胜出**——原子事实提取器丢掉了模式的「形」,块摘要检索到了规则但 reader 不执行(把规则更醒目地呈现基本补上这个 gap)。
- 收录:**NeurIPS 2026 Main Conference**。

### 11-20C 注入紫队的高分陷阱 —— 高 ASR 不等于鲁棒性,红队会 mode collapse ⭐⭐

**一句话**:证明「红队拿到高攻击成功率(ASR)」**不保证**后续对抗训练带来鲁棒性提升——两个 SOTA 的 RL 红队方法(RL-Hammer / PISmith)会 **mode collapse**,反复发现相似攻击策略,其新增成功不给对抗训练带来任何鲁棒性增益;PIPETTE 用字典学习奖励鼓励更广的攻击策略覆盖,配 on-policy 对抗训练 pipeline,AgentDojo / ASB 上静态攻击 ASR 近零、能扛强自适应攻击,同时良性任务效用接近无防御基线。

**为什么当下最有价值**:接上 11-03B「验证者自身可靠性 plateau」+ 10-10C MetaPI「自适应载荷」——把「谁来验验证者」从**防御侧**推到**攻击侧**:此前本库默认「红队找到的攻击 = 真实弱点清单」,PIPETTE 证明这个信号本身会失真(mode collapse 下 ASR 虚高),所以「红队分数」与「基准分数」一样是需要被审计的信号,正好落在本期母题上。它也给 11-18B「自改进 harness 的验证器」提供反面警示:如果喂给对抗训练的是塌缩的攻击集,harness 越自改越只防得住一类攻击。

**数字与机制(一手 abs 已核,2026-11-20 WebFetch arxiv abs 页)**

- 问题:SOTA RL 红队 RL-Hammer / PISmith 出现 **mode collapse**——反复发现相似攻击,额外成功**零鲁棒性增益**。
- 方法:PIPETTE 用**字典学习奖励**鼓励攻击策略覆盖广度 + **on-policy 对抗训练** pipeline(专为 IPI 防御定制,边抗攻击边完成合法任务)。
- 结果:AgentDojo / ASB 上静态攻击 ASR **近零**,扛得住强自适应攻击,良性任务效用**接近无防御基线**。
- 规模:18 页 / 6 图;cs.CR + cs.AI。
