### 候选 1 ⭐ 智能体记忆的生命周期治理:遗忘 · 更新 · 时序
**Memory Lifecycle Governance: Forgetting · Knowledge Update · Time-Awareness**

**为什么"当下"最有价值(缝在哪,一句话):**
这是 overview 上**最早提出却始终未落地**的 ⭐ 候选(09-24),而今日其证据等级发生了**从"判断"到"一手基准"的质变**——wiki 现有的记忆四页([[Provenance]] / [[CitationLock]] / [[Abstention]] / [[LongTermMemory]])全部在治理"**这条事实有没有来源**",却**零覆盖"这条事实什么时候不再成立"**;而 `LongTermMemory.md` 至今挂着的 `pending ingest` 注记,写的就是这个缺口。

**真实可达来源(均 WebSearch 返回):**

- [verified] LongMemEval-V2 实测梯度:基础检索 **38.1%** → 加笔记 **45.9%** → 主动检索代理 **57.0%** → 最强的**基于文件**的编码代理记忆控制器 **70.1%**(即最强设置仍有约 **3/10** 错) —— 同上 ★F
- [verified] PATH-Bench(华东师大 + 蚂蚁 + 交大等,arXiv **2608.01149**)——显式定义 **FWT / BWT / FGT(前向迁移 / 后向迁移 / 遗忘)**;"**强迁移不保证留存**";并给出 Selective Experience Use(SEU)harness 降低遗忘 —— https://za.arxiv.org/pdf/2608.01149 ★F
- [verified] MemoryAgentBench(arXiv **2507.05257** v4)——把"**选择性遗忘**"与检索、测试时学习、长程理解并列为四个能力 —— https://seed.hyper.media/hm/z6Mkpb42xebXipqcSxAbfta5ADFyU99FF9NdCQcAcrfKtT1z/research/context-engineering/qualifying-multi-turn-state ★F

**一句话定义:**
记忆生命周期治理 = 对已写入的记忆规定**写入 → 衰减 → 更新(取代旧值)→ 删除**的策略层,其核心量是"**一条仍有效的事实能不被丢掉、一条已失效的事实能不继续影响决策**"。

**与已覆盖概念的边界辨析:**
- vs [[Provenance]]:Provenance 记"**它从哪来**"(来源 / 时间 / 证据);生命周期管"**它现在还成不成立**"。二者正交——一条 provenance 完美的旧事实,仍然应当被取代。
- vs [[Compaction]]:Compaction 是**窗口内**的摘要重启;生命周期是**窗口外持久层**的策略,对象是"跨会话的事实"而非"当前对话的token"。
- vs 09-27 候选「记忆治理(RBAC)」:**治理管"谁能写"**(权限/冲突/审计),生命周期管"**何时删**"。二者是同一"记忆卫生"的两端,不可互相替代。
- vs 09-25 候选「记忆时效性」:那是本条的**评测侧**;本条是**策略侧**。建议**合并成一篇**(策略 + 评测),而非两篇。

**值得注意的边界证据(写材料时应原样保留):**
- 90 天对照实验(记忆层 vs 直接塞全部历史):token 少 **23–62×**,但在**标识符/选项类事实**上**记忆反而输给全历史**(客服 30 天召回 **0.25** vs 全历史 **0.62**)——即"记忆不是普遍更优,它在**具名实体**上最弱"。 —— https://bittide.aicompass.dev/article/43d46c1e-fb80-4734-964a-6c176b324173 [verified]
- Anthropic 已警告:**长生命周期状态会把敌意/误导性指令保留下来并回灌到后续会话**。[verified,二手转述于同一 newmarketpitch 页]

## 方法 / 经验(有长期价值才记)

1. **今天两条候选都不来自"新概念名",而来自"把已有纪律换一个作用对象"。** 候选 1:把"来源可核查"从**事实**换成**时效**;候选 3:把"数字要独立验证"从**厂商**换成**基准**。⇒ **可固化方法:每有一条已内化的纪律,就问"它还能作用在什么对象上"**——与 09-26「向里问一层」、09-27「向下问一层」构成第三种追问方向:**换对象**。
2. **"积压最久的 ⭐"应当获得优先级,而不是被新信号持续挤下去。** 09-24 的记忆生命周期已积压 4 天,期间被 09-25/26/27 的新候选反复挤后。今日其**证据等级恰好完成质变**,是"该动手了"的信号。⇒ **雷达应显式维护一个"最老未落地 ⭐"字段**。
3. **昨日结论需要主动纠正**:昨日把 RAG 描述为"默认起点被推翻",今日双源显示那是**编码场景**的局部结论,通用检索研究甚至给出相反的均值结果。⇒ **凡自己写下的"范式反转",次日应主动找反证**;已在本报告"承接强化"栏显式降级为"分场景反转"。**这是本雷达第一次自我修正,应保留为惯例。**
4. **一手复核能发现摘要遗漏的关键限定句。** 今日三次 WebFetch 各捡到一句搜索摘要里没有、但**决定材料骨架**的话:ChangeGamer 的"session ≠ durable execution"、ai2.work 的"92.5 分坐在人造天花板上"、以及"**该领域目前没有中立裁判**"。⇒ **[verified] 与 ★F 应分层标注**,后者优先进入材料首屏。
