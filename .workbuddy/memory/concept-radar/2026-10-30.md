### 🎯 候选 1 · 记忆评测的内在 / 外在分裂（Intrinsic vs. Extrinsic Memory Evaluation）⭐⭐⭐

**为什么「当下」最有价值**

本库 **2026-10-17 自己在 `concepts/MemoryGovernance.md` 写下**：「intrinsic vs extrinsic evaluation and the **open experiment it defines**」—— 即这一格**早被点名，但一直是没有仪器的开放实验**。`FEB-30`（arXiv:2610.22209，**2026-10-15 提交**，本期三条中最新）就是那台仪器：

- 内在 / 外在评测平均背离 **16 个百分点**，**44%** 的轨迹超过显著背离阈值；
- 记忆操作分类（create / update / reinforce / supersede）**只有 20% 判对** —— 而这个失败对**外在评测完全不可见**。

**接缝在哪（一句话）**：`MemoryGovernance` 的「四个动作各自失败方式不同」一直只是**主张**，FEB-30 把它变成**可测量的量**；且与 10-29 新落地的 `concepts/RAG.md` 互补 —— RAG 页算的是「取用值不值」（benefit / tax / 净值），FEB-30 算的是「评测测得准不准」。

**一句话定义 + 边界辨析**

- **定义**：内在评测直接检查**记忆库里那条记录对不对**；外在评测只看**下游问答答得对不对**。两者背离的部分，就是「答案对了但记忆是坏的」和「答案错了但记忆是好的」这两类。
- **vs `[[AgentObservability]]`**：那五层（record / semantic / judge / meta / cost）问的是「**这条 trace 怎么评**」；FEB-30 问的是「**被评的对象该是谁**」—— 记忆库本身，还是最终回答。前者是评分协议，后者是评分标的。
- **vs `[[MemoryGovernance]]`**：**被测量者与测量仪器**的关系，不是两个并列话题。本库那条草稿批注已经把实验定义好了，FEB-30 只是提供了跑它的场地。
- **vs 10-29C「判官偏向」（arXiv:2610.31272）**：同一层的**两个方向** —— 那个问「评分函数自己有没有偏向」，这个问「评分对象是不是错的」。可互为对照组。

1. 建议在 `concepts/MemoryGovernance.md` 增一节，把「开放实验」落成**可跑的判据**（背离阈值 / 操作分类准确率）。

### 🎯 候选 2 · 上下文工程质量的可测量化（Context Quality as a Measurable Preflight Signal）⭐⭐

**为什么「当下」最有价值**

`wiki/overview.md` 的 **Open Questions 第 3 条原文**就是它：「How `[[ContextEngineering]]` techniques are **measured end-to-end**（beyond single-provider claims）— **needs an independent evaluation**」，自 **2026-09-16** 起挂着未动 —— 是 overview 里**除已结清项外最老的开放问题**。arXiv:2607.14275 正面回答它：

- 把上下文质量做成 **七项可打分构造**：role clarity / guardrail coverage / instruction consistency / tool schema quality / grounding sufficiency / injection hardening / token efficiency；
- **刻意把上下文分数与行为分数、发布决策隔离** ⇒ 做到**非循环验证**（这是它区别于绝大多数自评框架的关键设计）；
- 固定模型、只变上下文（poor / structured / hardened）：grounding sufficiency 预测幻觉抵抗、guardrail coverage 预测操纵抵抗、instruction consistency 预测指令遵循、tool-schema quality 预测工具使用。

**接缝在哪（一句话）**：本库 `ContextEngineering` 页一直在讲**怎么做**（分层、即时检索、压缩），**没有一项说做得好不好该怎么量**；2026-10-26 的草稿批注「重发上下文约占推理账单 62%」只有**成本侧**，七项构造补的正是**质量侧**。

**缝得更准的一点（值得单独标出）**

七项里含 **injection hardening（可信 / 不可信内容分离）** 与 **guardrail coverage** —— 这两项正是 **Cluster D**（`[[ToolHallucination]]` 的封闭世界消解、`[[HumanInTheLoop]]` 的闸门）的地盘。⇒ 等于把行动侧两个机制变成了上下文侧的**可打分字段**，本库 A–D 四个 cluster **第一次有共同的量纲**。

而它还不踩本库 2026-09-26 立的那条规矩（「vendor defaults 可引用、vendor benchmarks 不可」）—— 自变量是上下文而非模型（backbone 固定），是**少数可引用的效应量**。

### 🎯 候选 3 · 记忆的依赖推理：Cascade / Absence / Deletion（Dependency Reasoning in Agent Memory）⭐⭐

**为什么「当下」最有价值**

本库**两条独立的草稿批注都指向「依赖」这一格，却都没量**：

- `Provenance`（2026-10-26）：「**失效是非局部的，而依赖是局部的** —— 一条记录的真值在它元数据看不见的地方过期」；
- `MemoryGovernance`（2026-10-25）：「**DELETE 在记录层没有闭合语义**」。

MEME（arXiv:2605.12477，KAIST AI + Tübingen AI Center + NAVER AI Lab）把这两句**同时仪器化**了：

- **Cascade 平均 3%**、**Absence 1%**、Deletion **默认配置下无系统通过** —— 而静态检索表现**是够用的**；
- 提示优化 / 更深检索 / 减少填充噪声 / **大多数更强 LLM 都补不上**；
- 唯一部分补上的是「文件型智能体 + Claude Opus 4.7」：总体 0.55（Cascade 0.32 / Absence 0.59），代价约 **70×** 基线成本。

**接缝在哪（一句话）**：`Provenance` 那句「依赖是局部的」是**结构判断**，MEME 给出的是这个结构的**失效幅度** —— 依赖推理不是慢一点，是**整体塌陷**；而且它直接给 `MemoryGovernance` 的「DELETE 需要闭合语义」一个现成口径：Deletion 任务问的就是「删掉之后还会不会被引用」。

| # | 来源 | 链接 |
|---|---|---|
| 1 | Jung, Rubinstein, Uselis, Yun, Oh — *MEME: Multi-entity & Evolving Memory Evaluation*, arXiv:2605.12477（2026-05-12；6 系统 × 3 范式 × 100 episodes） | https://arxiv.org/abs/2605.12477 |
| 2 | 项目页（含 FIG.02 任务表现） | https://seokwonjung-jay.github.io/meme-eval/ |
| 3 | 代码 | https://github.com/SeokwonJung-Jay/MEME-public |
| 4 | 影响解读：ai|expert，*MEME benchmark finds 97% failure on agent memory dependency tasks*（含企业风险映射：账单地址 vs 收货地址漂移、GDPR 删除未清） | https://aiexpert.news/en/article/meme-benchmark-evaluates-multi-entity-agent-memory-across-sessions |

**一句话定义 + 边界辨析**

- **定义**：依赖推理 = 记忆系统能否在上游事实变更后，把变更**传播到依赖它的记录**（Cascade）、把「**没有更新**」当成有信息的信号（Absence）、以及在**删除后不再引用**（Deletion）。
- **vs `[[MemoryPoisoning]]`（关键区别）**：**完全不同轴** —— 投毒是**内容被写坏**（坏内容戴着合法来源进来）；依赖推理失败是**内容没错但关系没跟上**（一条正确记录的真值随上游更新而过期，且**没有任何坏消息到达**）。⇒ 这正是 `Provenance`「失效非局部」的**另一半**：PMPA 讲前者，MEME 讲后者。
- **vs `[[MemoryGovernance]]` 的四个动作**：MEME 不是第五个动作，而是**四个动作之上的关系层** —— Capture / Update / Recall / QA 每个都可以在单条记录上做对，而 Cascade / Absence / Deletion 问的是**记录与记录之间**是否跟着动。
- **vs `[[LongTermMemory]]`**：LongTermMemory 管**存得住**、跨会话；依赖推理管**跟着变**。FAMA（该忘没忘要扣分）只罚「陈旧」，MEME 补的是「**上游动了而下游没动**」这一格。

**下一步**

1. 建议在 `concepts/Provenance.md` 落一节「依赖是局部的，失效是非局部的 —— 幅度是多少」。
2. 把 MEME 的 **Deletion 口径**接进 `MemoryGovernance` 的 DELETE 闭合语义（该页 2026-10-25 的草稿批注正好缺一个可跑的定义）。
3. 值得生成 `learning-materials/agent-memory-dependency-reasoning.html` —— ⚠️ 草稿级，本期未写入。
