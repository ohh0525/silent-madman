## 二、概念雷达（3 条）

三条的共同形态：**都不是新格子，而是给既有机制补上一栏它此前没有的东西** —— A 补「判据的第二侧」、B 补「失效的第四栏」、C 补「那个属性的提供者」。

### 候选 1 ⭐⭐ 记忆的行动条件化核验 / Action-Conditioned Memory Verification（AMV-Guard）

**一句话定义**：一条记忆在被用于行动之前是否必须重验，**不是这条记忆的属性，而是「你下一步要拿它做什么」的属性** —— 核验力度应由即将发生的动作决定，而不是由这条记忆看起来有多可靠决定。

**为什么「当下」最有价值（缺口在哪）**
本库全部核验 / 弃权机制的判据**都锚在对象上**：[[Provenance]] 看出处、[[CitationLock]] 看有没有打开过、[[Abstention]] 看有没有来源、[[MemoryGovernance]] 四动作操作内容、[[ToolHallucination]] 看工具是否在册。**唯一锚在动作上的是 [[HumanInTheLoop]]（impact × reversibility），而它只锚在最后那道闸门，不锚在前提层** —— 没人问过「这条记忆作为前提，要不要为这个动作重验一次」。本行把那条分级尺第一次装进记忆读取那一侧。

**承重数字**（`arXiv:2610.31446`，2026-10-22 15:43:50 UTC，Yiqi Wang 等 7 人，cs.MA）
- 判据句：*"whether an entry must be re-checked before acting is not a property of the entry: the same remembered address can be used unchecked for a routine shipment but should be re-confirmed before a valuable one."*
- 建模为**序贯停止问题**：一次核验只在**它能改变 agent 下一步做什么**时才值它的成本；提高动作后果的量级会把同一条记忆依次推过 **proceed → verify → direct-abstention** 三个区间。
- AMV-Guard 在 ToolSandbox 上相对**同等输入的静态策略**：核验成本 **−33.9%**，保持 **100% safe-proceed recall** 与 **0% Gate harmful**，Proceed coverage **38.83% → 44.17%**。
- AppWorld 的 **gate-core transfer**（只带停止 / VOI 核心）成本 **−21.3%**，代价是 safe-proceed recall 与任务成功率小幅下降。

**边界辨析**
- vs **[[Abstention]]**：本库现有弃权是**阅读侧的二值判断**（有没有来源）；本行把它变成**按动作后果定价的预算决策**。是扩展，不是替换。
- vs **[[MemoryGovernance]]**：四动作的 Recall 侧**此前没有成本模型**，本行给出第一台。
- vs **候选 2（10-24B）**：**从相反两头抵达同一处** —— A 说门限该挂到动作上，B 说失效可能根本不在取出来的内容里。**必须并列互指，勿合并。**

**必须同屏**：预印本未同行评议；主结果在 ToolSandbox；AppWorld 一栏为 gate-core transfer、作者自陈不带完整结构化管线；100% / 0% 是**相对同等输入的静态策略**，不是绝对安全。

**来源（全部 `[verified]`）**
1. https://arxiv.org/abs/2610.31446
2. https://arxiv.org/abs/2610.31446（Submission history 页内，v1 = 2026-10-22 15:43:50 UTC）

**建议下一步**：**不新建页**。三处修订 —— `concepts/Abstention.md`（增「弃权不是二值，是按动作后果定价」）、`concepts/MemoryGovernance.md`（Recall 侧补成本模型）、`concepts/HumanInTheLoop.md`（把 impact × reversibility 装进前提层）。

### 候选 2 ⭐⭐ 治理态损坏 / Governance-State Corruption

**一句话定义**：一类此前无人命名的故障 —— **改变「哪些留存记录进入模型可见上下文」**，而**存储内容与任务都保持不变**。即：**检索对了，用错的那一条**。

**为什么「当下」最有价值（缺口在哪）**
本库的记忆失效列此前有三栏：**内容**（[[Provenance]] / [[CitationLock]] 看出处）、**动作**（[[MemoryGovernance]] 四动作）、**归属**（10-20B「暴露 ≠ 行为 ≠ 状态」逐行标 owner）。本行加**第四栏 = 选择层 / 控制面**：**哪些记录生效**。三栏都检查「被取出来的那条对不对」，**没有一栏检查「被选中生效的那批是不是该生效的那批」**。
更关键的是：**它用的正是本库自己已经引过的仪器**（Memora FAMA 见 [[MemoryGovernance]]、LongMemEval 见 [[LongMemEval]]）⇒ **本库第一次被自己的尺子测出一个四动作看不见的失效**。

**承重数字**（`arXiv:2610.30698`，2026-10-22 04:13:09 UTC，Bowen Liu 等 4 人，cs.AI + cs.SE，13 页 / 1 图 / 10 表）
- 规模：**6 家 provider** · **731** 个 grounded base · **2,080** 组 matched fault pair。
- 离线控制面：损坏在 **96.25%** 的 pair 中改变了 operative projection；**oracle-backed enforcement 恢复到 100%**。
- 下游：确定性选取的**非概率**面板解析 **298/300** triplet（**238** distinct base）；clean − corrupted = **LongMemEval 二值正确率 40.54 pp**（95% CI **[30.32, 50.71]**）、**rescaled Memora FAMA 30.60 点**（**[23.31, 37.69]**）；两者**均显示可恢复**。

**边界辨析**
- vs **10-20B（归属列）**：那条问「这条内容属于谁」，本行问「哪一批被选中生效」⇒ **分栏，勿合并**。
- vs **[[Compaction]]**：压缩是**改写内容**；本行**内容一字未动**，动的是生效集合 ⇒ 第十六条（改写 vs 拦截）之后又一个「不是同一件事」的实例。
- vs **候选 1**：见上，必须并列互指。

**必须同屏**：13 页预印本未同行评议；下游面板为**确定性选取的非概率样本**；fault 由作者注入、非自然发生；恢复靠 **oracle-backed enforcement** ⇒ **「能修」不等于「你的系统里有那个 oracle」**；作者自陈全队列 frozen-scorer 数字（−27.55 / +27.51）**只是描述性代理**。

### 候选 3 ⭐ 可逆性是假设，不是实现 / RegretBench + BackUpper

**一句话定义**：agent 能完成 **86.1%** 的任务，却只在 **15.2%** 的「会后悔」时刻之前做了备份 —— **完成任务的能力不蕴含备份意识**；而分级表赖以运转的那个属性（可逆性），实际上没人提供。

**为什么「当下」最有价值（缺口在哪）**
[[HumanInTheLoop]] 要求**按 impact × reversibility 分级**，[[MemoryGovernance]] 四底线第二条是 **rollbackable**，overview 写「幂等执行」—— **但没有一页问过「可逆性是谁提供的」**。这是**第十三条扫描线（动词实效审计）第一次咬住本库自己最承重的那个动词**，且比 10-18 的 DELETE 更靠前：那条测「治理动作生效吗」，本条测「**整个闸门赖以分级的那个属性存在吗**」。
它同时是 **10-19B「Finding ≠ Fixing」修复缺口的第二个答案**：本库几乎全是检测器，本行是少数**带便宜修复**的一行，且修复落在外壳职责内、无需改模型。

**承重数字**（`arXiv:2610.28934`，2026-10-20 21:13:31 UTC，Xu Li 等 7 人，cs.AI）
- **RegretBench**：**205** 个可执行任务，全部来自 X / GitHub / Stack Overflow 上**用户自陈「后悔没先保存」**的真实时刻。跨 **6 个前沿模型**：完成率 **86.1%**，事前备份率 **15.2%**。
- **BackUpper**（外壳插件式备份层，每次工具调用前保存受影响状态）：覆盖**全部**后悔时刻动作，恢复相似度 **92.2%**，**$0.014/任务**，比主 agent 自备份**省 7× token**；用户给定偏好后收窄范围，与人类标注吻合 **84.5% F1**。

**边界辨析**
- vs **[[MemoryGovernance]] 的 *rollbackable***：那是**记忆**的回滚底线，本行是**工具副作用**的回滚 ⇒ 对象不同，**分栏**。
- vs **[[AgentSandbox]]**：沙箱**限制能碰到什么**，备份**保证碰坏了能还原** ⇒ 同一条 `execute` 腿的**两半**，须并列互指。
- vs **09-23「持久化执行」**：那条管**进程死了还能续**，本行管**改坏了还能还原** ⇒ 分栏。

**必须同屏**：205 个任务来自**自报后悔时刻**（选择偏差：能被发帖抱怨的那类损失）；单一评测协议；**92.2% 相似度 ≠ 100% 恢复**；84.5% F1 是在**用户已给出偏好**的条件下。

2. https://wpnews.pro/news/back-up-before-you-regret-measuring-backup-awareness-and-automating-backup-in

**建议下一步**：**不新建页**。三处修订 —— `concepts/HumanInTheLoop.md`（reversibility 由谁提供）、`concepts/AgentHarness.md`（备份层作为外壳职责）、`concepts/AgentSandbox.md`（限制能碰什么 vs 保证碰坏能还原）。
