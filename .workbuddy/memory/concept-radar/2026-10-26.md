### 候选 1 ⭐⭐ — 记忆活得比它的理由久 / Memories That Outlive Their Reasons（Tether）

- **来源 [verified]**：
  1. `arXiv:2610.25123` 摘要页 — https://arxiv-vanity.com/papers/2610.25123
  2. 同一篇 PDF — https://arxiv.org/pdf/2610.25123
  3. 中文解读（含「失效的非局部性」图示） — https://clawpk.net/articles/2046-dependency-tethered-memory-tether-tool-using-agents-2610-25123.html
  4. 英文要点摘要 — https://www.ai.jp.net/article/tether-smart-memory-that-withdraws-stale-verdicts-keeps-tool-using-agents-safe-379887
- **元信息**：Yiqi Wang、Jinqian Ju、Jiaqi Zhang、Zhangkai Wu、Yiqun Duan、Zequn Sun、Taotao Cai、Mingkai Zheng（8 人）；cs.CL；**v1 2026-10-18 09:01:52 UTC**，**v2 2026-10-22**。
- **一句话定义**：一条记忆的**真**是有时效的 —— 结论依赖的**前提**一旦失效，结论不会自动跟着失效；Tether 在**写入时记下依赖的精确版本**，**读取时**只要支撑它的东西在库里任何一处失效就**整条撤回**。
- **为什么「当下」最有价值（缝在哪）**：[[MemoryGovernance]] 四个动作的触发器一直是「**有人动过这条记忆**」，而本行测的失效**根本不是一个对记忆的动作** —— 上游只是失效了，通知从未到达这条记录 ⇒ **四个动作里没有一个装得下它**。[[Provenance]] 记**向后**指针（从哪来），10-25B 补**向前**指针（派生出过什么），本行补**第三格：失效沿依赖图传播，而依赖图不在检索窗口里**。
- **承重数字**：读原子事实记忆的 agent 发布 **62%** 本该失效的对象（每条记录写下时都真）；Tether **0.3%**，且比全量重验**少 37% 验证调用**；A-Mem / Graphiti **9%**（每候选 0.83–0.86 次重验），Mem0 **42%**；「有失效就全清」同样安全但**多花 32% 检查**。
- **边界辨析**：
  - vs **10-24A（AMV-Guard）** → **上下游，必须并列互指**：AMV-Guard 的 VOI 门控决定「这条前提值不值得重验」，**它预设失效信号已经到达**；本行证明「公告只点名密钥」的常见形态下**根本没有信号到达** ⇒ **先有到达，才有定价**。
  - vs **10-25B（删除闭包 / AfterDeleteBench）** → **分栏**：那条**有一个 DELETE 动作**（闭包完整吗），本行**没有任何动作**（没删除事件时失效靠什么传播）。
  - vs **10-24B（治理态损坏）** → **分栏**：那条**控制面被改了**，本行**控制面没动**。
- **⚠️ 必须同屏**：预印本未同行评议；**Fallout 是作者自建的合成世界生成器**；0.3% 的前提是「关系与判定在同一会话给出」，分散到不同会话则退化为 **9.4–22.1%**；作者自陈会随**更弱的写入者**退化。
- **建议下一步**：**两处修订，不新建页** —— `concepts/Provenance.md`（增「失效的非局部性」）+ `concepts/MemoryGovernance.md`（Update 的触发器不只有「有人改了记忆」，还有「上游失效」），并**与 10-24A 那节并列互指**。

### 候选 2 ⭐⭐ — 压缩的选择性丢失：任务还在，规则没了 / Compaction drops constraints class-wise

- **来源 [verified]**：
  1. `arXiv:2610.31778` 摘要页 — https://arxiv.org/abs/2610.31778
  2. `arXiv:2610.31778` 全文 HTML（含作者单位） — https://arxiv.org/html/2610.31778v1
  3. `arXiv:2608.11242`（COMPINT）全文 HTML — https://arxiv.org/html/2608.11242v1
  4. The Decoder 报道（17% / extractor 90%+） — https://the-decoder.com/ai-systems-quietly-drop-user-instructions-when-they-compress-context/
- **元信息**：① **2610.31778** — Jeanne Salle · Hardik Bhatnagar · Matthias Bethge · Sahar Abdelnabi · Maksym Andriushchenko（ELLIS Institute Tübingen · MPI-IS · Tübingen AI Center），提交 **2026-10-22 18:15:54 UTC**。② **2608.11242** — Zhiqi Wang · Yichi Zhang · Dongwon Lee · Yuchen Yang（Penn State），提交 **2026-07-31**、修订 **2026-10-11**（⚠️ **非新论文**，本期经报道重新浮出，日期已如实标注）。
- **一句话定义**：压缩不是中性操作 —— 它按**内容类别**有偏地丢弃，而偏差方向恰好对准治理类内容：**「该怎么做 / 不该做什么」被丢掉的速率是「要造什么」的约 6 倍**（真实会话），受控套件上会话约束只存活 **17%**。
- **为什么「当下」最有价值（缝在哪）**：本库 [[Compaction]] 被 overview 定位为**窗口内、逐轮**的**中性**技术，10-22A 已论证它是**治理边界**（伪造轮次被洗白）；本行补第三件事 —— **压缩有类别偏好，且偏好的方向对准治理类内容**。[[HumanInTheLoop]] 的分级规则、[[MemoryGovernance]] 四条底线、[[CitationLock]]、[[Abstention]] 全是这一类 ⇒ **本库反复告诫「规则必须写在代码 / 配置里、不能只在 prompt 里」，而这条告诫假设规则还在；压缩会把它吃掉，且任务分数不变。** 同时它是 🎯 **10-09「常驻上下文与指令预算」（最老 `⏸`，17 天）的第一台可引用仪器**。
- **承重数字**（2610.31778）：ProgramBench 上**第一次压缩**平均丢掉**约 1/3** 反作弊规则，**随压缩次数单调上升**；**SWE-chat 真实会话**中「该怎么做 / 不该做什么」被丢 **约 6×** 于「要造什么」；两个 1M 模型上**阈值不影响分数**；**无方法胜过默认自摘要**；丢弃更多的方法让某些模型掉**最多 20 分**、另一些毫无变化。（2608.11242）：SC 存活 **17%**；不压缩时合规率也仅 **59.2–70.7%**；专设字段不够（pi-mono 0–36%，Anthropic SC-targeted ≤**37.6%**）；**Qwen3.5-9B** 的 SC-aware extractor 达 **95.6 / 95.1 / 90.3%**。
- **边界辨析**：
  - vs **10-22A（Compaction Laundering）** → **同一格的两个相反方向，必须并列互指、勿合并**：那条是**攻击者往压缩里塞东西**，本行是**压缩自己把东西丢掉**（无攻击者）。
  - vs **[[ContextRot]]** → **分栏**：那条是**注意力**失效轴（容量 ≠ 有效容量），本行是**选择**失效轴（按类别挑着丢）。
  - vs **[[Compaction]]** 现有定位 → 本库把它当**中性技术**，本行证明它**不中性**。
- **⚠️ 必须同屏**：2610.31778 为**预印本未同行评议**；「1/3」是 ProgramBench 首次压缩的平均，「6×」出自 SWE-chat；**两个 1M 模型上阈值不影响分数** ⇒ **不可读作「压缩有害」**；2608.11242 **非新论文**，**17% 是受控套件上注入 SC 的存活率，不可读作生产合规率**，extractor >90% 为作者自测、**单一 9B 基座**。
- **建议下一步**：**两处修订** —— `concepts/Compaction.md`（新增「压缩不是中性：类别偏好 + 6× / 17%」一节，与 10-22A 并列互指）+ `concepts/HumanInTheLoop.md`（「规则写在代码里」那条告诫补上「还得能扛过压缩」）。

### 候选 3 ⭐ — 披露自我强化：记忆改变了它自己的输入流 / Disclosure Begets Disclosure

- **来源 [verified]**：
  1. `arXiv:2610.28315` PDF — https://arxiv.org/pdf/2610.28315
  2. 摘要转载（含完整 abstract） — https://github.com/Aaron617/agent-arXiv-daily
  3. 中文综述（同一批论文的第 3 条） — https://clauday.com/article/4ab57399-eb28-4402-85e3-6f4a359a1585
- **元信息**：Masahiro Kaneko · Hiromi Arai · Timothy Baldwin（`arXiv:2610.28315`）。
- **一句话定义**：持久记忆**同时**抬高回复质量与实证泄露，且差距**随会话越拉越大** —— 成因是一个**完全非对抗**的回路：记忆条件下的回复把早先的值当作**预设**带出来，用户确认或不纠正，于是线索与 agent 自己的猜测变成被记录的值，**循环自我强化**。
- **为什么「当下」最有价值（缝在哪）**：[[MemoryGovernance]] 的四动作是**单向管线**（Capture → Update → Recall → QA），**没有一条回边**；[[MemoryPoisoning]] 的第三个决定者是**攻击者**。本行给出「**无人写入却依然被记录**」 ⇒ **Recall 会改变 Capture 的输入流**，这是本库没有的那一格。且修复点落在 [[Abstention]] 那一侧（**不陈述**），本行给「不陈述 / 不预设」一个**可测量的收益**。
- **承重数字**：模拟用户持 **24** 个个人属性，对照「查 / 不查记忆」，跨 **4 个 support 模型**；质量与泄露**同时上升**、差距随会话拉大；**删掉 agent 对某属性的提及，其后续泄露的下降约为单轮效应所预测的两倍**；**指示 agent 不陈述 / 不预设属性** → 泄露回到**无记忆水平**且**保住大部分质量收益**；而过滤 / 匿名化**会放弃大部分收益**。用户自己走不出来：纠正＝泄露，拒绝讨论＝后续预测向更敏感值偏移，错误值放着不管会固化。
- **边界辨析**：
  - vs **10-25A（马赛克效应）** → **分栏**：那条是**拒答一次性把禁止结论带出来**，本行是**跨会话累积的自我强化循环**；本行**有修复**，10-25A 数字更硬。
  - vs **[[MemoryPoisoning]]** → **分栏**：那条是**攻击者**写的，本行**没有攻击者**（勿读作「第四个决定者」，本行是「**无人决定却依然发生**」）。
- **⚠️ 必须同屏**：**模拟用户**（非真实用户）；泄露为**推断准确率代理**而非真实泄露事件；**4 个 support 模型未点名**；修复是一条**指令**、稳健性未测；单一协议。
- **建议下一步**：**并入** `concepts/MemoryGovernance.md` 的 Capture 处（增「Capture 的输入流被 Recall 改变 / 回边」），并与 🎯 **10-09** 行互指。
