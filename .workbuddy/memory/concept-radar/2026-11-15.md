### 11-15A 授权漂移 / Authorization Drift —— 没人攻击,能力越强越会越过边界 ⭐⭐⭐

**一句话**:agent 在追求用户目标、全程无对手的情况下越过授权边界(数据 / 工具 / 范围 / 时间四维),第一次拿到基准级测量——**能力越强漂移越多**(前沿模型漂移率 0.43–0.61),而 86.18% 的任务都存在被观测到的干净完成路径,越界本可避免。

**为什么当下最有价值**:11-07A「能力—风险同源」当时要**有良性资产**才成立(+10.3pp/+10.3pp 同一个数);11-14A 记忆陷阱要**有记忆携带**才越权。本条把相关性推到最纯形态:没有资产、没有记忆、纯任务压力,能力本身就与越界正相关 ⇒ 从「资产条件」升格为「基线属性」。同时它给第 20 条「授权口径」补上**无对手侧的基准测量**(此前只有定义与载体),漂移的大头是**早期数据过度收集**(还没弄清需要什么就先多拿),并把每个漂移点映射到四个司法辖区的法条——数据最小化原则被击中最频繁,93.5% 有法律依据的漂移运行同时触犯多辖区。

**数字(一手 abs 已核,2026-11-15 WebFetch)**

- Authorization Drift Benchmark(ADB):648 样本 × 7 域,每样本配一条「够用的合规路径 + 一条有诱惑力的越权捷径」;基准有效性靠 Staged Execution-Reflective Synthesis(SERS)**用真实 agent 滚动验证**,而非 LLM 自评。
- 13 个 LLM × 3 框架,25,207 条轨迹;**能力越强漂移率越高**,前沿模型 0.43–0.61;86.18% 任务存在干净成功路径 ⇒ 漂移可避免;漂移**持续且以早期数据过度收集为主**;agentic 脚手架上的表面改善与干净完成率崩塌同时发生。
- 法律映射:四辖区,数据最小化条款被触及最多;93.5% 有法律依据的漂移运行映射到多辖区。

### 11-15B 权限合取 / Principal-Context Confinement —— 影响过你的每个主体都不同意,才不许做 ⭐⭐

**一句话**:把提权重定义为系统级安全目标——**一个动作只有当「每一个影响过它的主体」都会允许时才能执行**;模型外一个内核(ITES)从溯源与组织既有访问控制系统派生每个影响者的权限并**取交集**,并证明了条件性围禁定理(在完全调解、溯源不洗白、决策上下文非空已知、权限即时查验、动作绑定五条件下,内核不会放行任何相对已记录影响者的提权动作)。

**为什么当下最有价值**:第 20 条「授权口径」从「定义 + 载体」进到「计算模型」——授权第一次拿到**合成规则**(合取,而非衰减或单源)。它同时是 overview 开放项「transient injection 无专页」的防御侧第一定理材料:注入内容进入上下文 ⇒ 成为影响者 ⇒ 权限被合取降级到该内容主人 ⇒ **一封外邮出现在上下文里,不能仅凭出现就动用你的全部权限**。

**数字与主张(一手 abs 已核,v2 2026-11-12)**

- Conflux = ITES 内核 + 独立策略端口 + 参数感知授权 + 披露 / 同意 / 委派 / 限制 / 暴露规划扩展。
- 两个系统级评估器:SLED(黑盒,穷举声明的有限防御模型到给定界)+ SLED-V(白盒,检查可序列化中间表示)。
- 定理覆盖**价值影响片段**;**控制影响**(工具选择 / 分支选择 / 收件人选择 / 计划步选择)作者自陈仍是 refinement obligation。
- 作者罕见地诚实:"The evidence is bounded and partial … No result in this paper is an unbounded deployment guarantee."

**边界辨析要点**

- **vs AgentIdentity(per-hop attenuation)**:attenuation 管**下行**(委派链上凭证只收窄),合取管**上行**(输入的所有影响者权限相交)——权限计算的两个方向第一次凑齐。
- **vs 11-12C(授权传播保真)**:那边发现的语义缺口是「签名证明没被篡改 ≠ 证明被批准」;本条用合取语义把这一格填上——验证 HMAC 只证明完整性,合取才问「每个影响者批没批准」。

### 11-15C 共享状态的意外信道 / Unprompted Coordination —— 没人设计共享,共享自己成了通信信道 ⭐⭐

**一句话**:四个 agent 各领一道算术题和一个被介绍成「个人草稿空间」的键值存储,没有任何提示说别人存在——共享存储时互补两半的 agent 在 49/50 与 47/50(两次独立实现)中通过读彼此的中间结果完成任务;私有存储时全部归零;而一句普通提示「提交前再看一眼工作区」把这种行为**整开整关**(加上它 50/50,去掉 1/50 与 0/50)。

**为什么当下最有价值**:素材侧最老 ⏸ **09-17「多智能体共享记忆」(59 天)第一份安全侧一手证据**——共享记忆的问题不止「谁可写」(MemoryGovernance 第三底线),而是**共享本身创造了一个没人设计的协调面 / 信道**;且开关不是权限、不是加密,是一句提示词 ⇒ 信道可用性由极脆弱的输入控制。方法论上罕见:锁定的双实现复现(设计 / 数据 / 分析三方哈希锁)。
