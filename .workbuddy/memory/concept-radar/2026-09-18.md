### 候选 1 ⭐ 首选:Agent Harness / 智能体外壳(运行时)

**一句话定义**:Agent 里**除模型之外的全部确定性管理代码**——上下文预算与落盘、压缩与状态复述、沙箱执行、权限裁决;2026 年的行业共识把它写成一条公式:**Agent = Model + Harness**,并明确「**Model proposes, Harness executes**(模型提议,外壳执行)」。

**为什么"当下"最有价值(缺口/接缝)**:
你的 wiki 把 [[Agent]] 定义为「自主的执行循环」、把 [[ContextEngineering]] 定义为「决定往窗口里放什么的**纪律/手艺**」——**但没有任何一页说清「谁在物理上执行这些纪律」**。2026 年的答案是把这层独立出来叫 harness,并且明确 `ContextEngineering` 只是它的**职责之一**。这条接缝之所以关键:它同时是你 Cluster A([[Agent]]/[[LLMContext]]/[[Skill]])与 Cluster B([[ContextEngineering]])的**共同底座**,而你的 `context-relationship.md` 图上**恰好缺这一层**。补上它,你现有的五个概念会从「并列的五件事」变成「有承载结构的一栋楼」。

### 候选 2:子智能体上下文隔离(Subagent Context Isolation)

**一句话定义**:把「加载一份 Skill」从「**写进当前上下文**」改成「**派生一个全新上下文窗口的子智能体去干**」——子智能体在自己的干净环境里跑完,只把**结论**交回主控,而非把过程留在主上下文里。

**为什么"当下"最有价值(缺口/接缝)**:
你的 wiki 里 **[[Skill]] + [[ProgressiveDisclosure]] 这条线是建立在「把内容加载进 agent 自己的上下文」这个前提上的**——一级元数据常驻、正文按需加载,全程都在**同一个窗口**里。2026 年 Cornell + 微软研究院的实证结论正好**从反面**推翻了它:**当任务变长时,把 Skill 当作独立子智能体调用,系统性地优于把它塞进主上下文**。这是你知识网里**第一处「新证据直接挑战既有节点核心假设」**的地方——比「加一个新节点」价值高得多,因为它会迫使你**修订** [[Skill]] 那一段的措辞。它同时给 `overview.md` 的 Cross-Cutting Theme「on-demand loading 是主导解法」补上了**第二个维度**:不仅有「按需加载」,还有「**隔离加载**」。

### 候选 3:智能体记忆投毒(Agent Memory Poisoning)

**一句话定义**:攻击者用**普通对话**(无需任何后端/凭证访问)把恶意内容写进 agent 的**持久记忆**,使其在**之后的每一次会话**里被当作可信上下文召回——是「**带持久化的 prompt injection**」,也是 OWASP 2026 正式编号的 **ASI06**。

**为什么"当下"最有价值(缺口/接缝)**:
你的记忆簇([[LongTermMemory]] / [[Provenance]] / [[CitationLock]] / [[Abstention]])整套设计**默认记忆是诚实的**——它防的是「记错」「记旧」,没防「**被投毒**」。而现实是:**持久记忆本身就是一个长期存活的攻击面**。这条与你的知识网有**两重接缝**:①它给 [[Provenance]] 补上**反面用例**——溯源解决的是「知道来源」,投毒给出的教训是「**来源可信 ≠ 内容可信**,来源标注本身会被『权威洗白』(authority laundering)」;②它与你的**现实处境高度重合**——报告明确指出 `AGENTS.md` / `MEMORY.md` / `SOUL.md` **这类记忆文件正在被当成攻击载体**,而你的仓库恰好有 `SOUL.md` / `IDENTITY.md` / `MEMORY.md` / `CLAUDE.md`,且你刚新建了 Skill——**35%+ 的社区 Skill 至少存在一处安全缺陷**这个数字,与你直接相关。
