### 候选 1 ⭐⭐ —— 压缩即治理边界：伪造的轮次如何被摘要洗成真正的用户指令
**Compaction Laundering / Provenance Destruction in Context-Compacting Coding Agents**

**来源（[verified]）**
1. https://arxiv.org/abs/2610.29869 —— 一手 abs 页（提交 **2026-10-21 15:24:23 UTC**）[verified]
2. https://arxiv.org/html/2610.29869v1 —— 全文 HTML（Introduction 原句已核对）[verified]
3. https://www.arxiv.org/list/cs.CR/recent —— cs.CR 最新列表，确认 **29 页 / 5 图 / 源码+原始数据+实机录屏已公开** [verified]

**一句话定义**
长跑的编码智能体必须压缩上下文：把对话摘要成一段话、**丢弃原文**、此后**以摘要为记忆**；而在一类外壳里，这一步**确定性地销毁了每条消息的来源类型**，使攻击者伪造的一行 `[User]:` 在摘要后**洗白成真正的用户指令**。

**为什么是「当下」最有价值 —— 缺口在哪（一句话）**
本库把 [[Compaction]] 划在「窗口内、逐轮」的上下文工程一侧、把 [[Provenance]] / [[MemoryPoisoning]] 划在「窗口外、跨会话」的治理一侧（overview 甚至原句写着 *"governance runs outside the window ... where Compaction runs inside and per-turn"*）——**本行指出这一刀切错了位置：压缩本身就是治理边界**，而本库没有一页把这两件事连起来。

**核心机制与数字**
- **压平即销毁**：为喂给摘要器，外壳把**带类型的对话**压平成一个纯字符串，用 `[User]:` / `[Tool result]:` 这类**行内文本标签**标注来源，且**不转义**不受信内容里的同名标签 ⇒ 出处在**模型看到文本之前**就没了。
- **五个压平型外壳**（pi / opencode / Cline / Aider / OpenHands）：伪造批准**洗进记忆的成功率 87–100%**，最高到 **~908,000 token** 窗口。
- **四个角色类型化外壳**（Codex / Gemini CLI / Qwen Code / Continue）：同一攻击成功率 **0%**。
- **端到端后果**：洗白的常驻批准驱动真实工具执行型 agent 执行攻击者控制的 `curl | sh` —— **实机 pi TUI 端到端 ~50%**，配对干净对照组 **0%**；同一通道还能稳定把 agent 的规划从指定文件引开 ⇒ **可让代码审查对植入的后门失明**。
- **修复两头**：因出处**在代码里被确定性销毁**，**任何 prompt 层防御都无法恢复**；作者实测**代码级出处检查**拦住 **77%** 洗白、只降级 **2%** 合法摘要内容；序列化器侧修法是**压平前转义角色标签**。

**🔴 本行最关键的一句 —— 它对既有文献（和本库）的更正**
作者原话：既有工作把这个失败描述成**模型能力的局限**（模型无法可靠判断内容从哪来），但在压平型外壳里，**出处在模型看到文本之前就已被外壳销毁**（*the origin is unrecoverable because the harness reduces the typed roles to plain-text labels before the model sees the text*）⇒ **"Susceptibility is therefore a property of the serialization strategy, not of the model."**
⇒ 这直接细化了 [[Provenance]] 页**昨天（10-21）刚写下**的那条边界：本库记的是「模型侧纪律 vs 外壳侧执行点」两种**执行主体**，本行补的是「**而且此前常被归错主体**」。

**边界辨析（与已覆盖概念）**
| 对象 | 位置 | 本行的增量 |
|---|---|---|
| [[Compaction]] | 窗口内、逐轮的省 token 手段 | 它同时是**信任边界**；代价不止丢信息，还有**丢出处** |
| [[Provenance]] / [[CitationLock]] / [[Abstention]] | 窗口外的**阅读纪律** | 纪律管不到**摘要之前的序列化步骤** |
| [[MemoryPoisoning]] | 写侧攻击面（PMPA / Darktrace） | 本行补上 overview 那条明写的开放项：**瞬态注入如何变成持久记忆** —— 洗白就是那一步 |
| [[AgentHarness]] | 容器 | 原文立条：**"Derivative agents inherit it"** —— 建在别人压缩之上的一切都继承其序列化 |

**🔴 必须同屏（引用时不得省略）**
- 单一机构（**Pixee，一家做代码安全的厂商**）· **预印本、未同行评议**；
- 攻击面**仅存在于压平型外壳**（角色类型化外壳天然免疫）⇒ **不可推广为「所有外壳都中」**；
- **77% 检出 / 2% 降级**为作者自测；
- **~50% 端到端**发生在**特定 TUI** 且需攻击者可控内容；
- **前提依赖**：整条链要求「摘要后原文被丢弃」——若保留原文（见候选 2 的另一头）则无处洗白。

### 候选 2 ⭐ —— 记忆是弱模型的昂贵补丁：原始历史两次胜过压缩记忆
**MemoryTax / The Bitter Lesson of Agent Memory　＋　MemDev-Bench**
（**同周、独立、方向一致**的两条证据，作为一行登记）

**来源（[verified]）**
1. https://arxiv.org/abs/2610.29823 —— MemoryTax，一手 abs 页（提交 **2026-10-21 14:46:27 UTC**）[verified]
2. https://arxiv.org/abs/2610.27524 —— MemDev-Bench，一手 abs 页（提交 **2026-10-20 02:39:26 UTC**）[verified]
3. https://arxiv.org/html/2610.27524v1 —— MemDev-Bench 全文（Introduction + 构建统计已核对）[verified]

**一句话定义**
设计型记忆在问题到来前就决定留什么；而**保留原始历史、让模型用自己的工具去搜**，在模型足够强之后**更准也更便宜** —— 因为压缩扔掉的正是 agent 实际在复用的**过程信息**。

**为什么是「当下」最有价值 —— 缺口在哪（一句话）**
[[MemoryGovernance]] 的承重结论是「瓶颈是四个动作（Capture→Update→Recall→QA）的**质量**」，本行给出同一现象的**替代解释**：**瓶颈是「写记忆的那个模型」，以及「压缩这个动作扔掉了什么」——而「被丢弃的东西」这一栏，本库的四个动作里没人测过。**

**两条证据**
- **MemoryTax**（Zedong Peng；cs.CL + cs.AI）：**1** 段 LoCoMo 对话（**419 轮 / 152 问**）× 四种记忆法（full context / BM25 / Mem0 / Zep）× 三个编码 agent（Pi / Codex / Claude Code）× 三个模型（GPT-4o-mini · GPT-6 Luna · Claude Opus 5.5），逐条记账。
  - ⇒ **"Agent memory is a costly patch for a weak model"**：Mem0 **只在 GPT-4o-mini 上**胜过 full context，且**光建库就比一整轮 full-context 还贵**；
  - ⇒ **"a ceiling, set by the model that writes it: a stronger reader does not recover what a weaker writer left out"**；
  - ⇒ Opus 5.5 上 **Pi 站在成本—准确率前沿顶点：99%，成本不到 full context 一半**（唯一一错是答案键本身错）。
- **MemDev-Bench**（Guorui Chen 等 12 人；cs.AI）：**4,869** 条可执行历史任务 / **555** 个基础任务 / **22** 仓库 / **4** 语言，**且标注了相关性**（相对既有基准的关键增量）。
  - **(i)** 记忆确实帮到「没记忆就失败」的任务，收益主要来自**更细粒度的定位与编辑**；
  - **(ii)** 记忆**也让本来能解的任务失败**，**即使历史相关**，且**无关历史会放大这类失败** ⇒ 成因是 **agent 复用记忆而不重新评估它是否适用**；
  - **(iii)** **直接给原始历史轨迹，比给记忆系统显著减少步数** ⇒ 因为**压缩记忆倾向丢掉 agent 实际在复用的过程信息**。

**边界辨析（与已覆盖概念）**
- vs [[MemoryGovernance]] 的四动作：**第 (ii) 条给出一个四动作模型里不存在的失效模式** —— 不是「记忆错了」，而是「**记忆对了、上下文不对**」（Recall 侧）；
- vs [[LongTermMemory]] 第三种载体（连续 / 潜记忆）：本行是**另一个方向**的证据 —— 那条问「不可寻址怎么办」，本行问「**可寻址的压缩本身值不值**」；
- vs 10-21B（缓存工程）：**从相反两头抵达同一个结论** —— 那条说「改文本会作废 cache ⇒ 上下文工程自反地制造成本」，本行说「**压缩扔掉过程信息 ⇒ 保留原始历史反而更省**」。两条互补，**必须并列互指、勿合并**；
- 它是本库**第 4 条（资源定价盘点）自 2026-10-09 以来第一台能记账的仪器**（Mem0 建库成本 > 一整轮 full context）。

**🔴 必须同屏（本行证据最薄，务必原样保留）**
- MemoryTax：**单作者 · 1 段对话 · 每格 1 次运行**（作者自陈 *a short empirical study, with one conversation and one run per cell*）⇒ **99% 是 n=1 的数字**；
- 作者自己指出领先部分来自**只有 agent 能读到的图片说明** —— 去掉含图证据的 **88** 个问题后，Pi 与 full context **只差一个答案**；
- ⇒ **绝不可引为「记忆无用」**；诚实的引法是「**在模型能自搜的条件下，设计型记忆的边际收益需要重新记账**」；
- MemDev-Bench 限于 **SWE-bench 系代码仓库任务**与单一「先跑历史任务再跑基础任务」协议；**两者均无独立复现**。

**建议下一步**
`concepts/MemoryGovernance.md` 增「**被丢弃的那一栏 / The Discarded Column**」一节（两条证据并列 + 第 4 条定价视角），`concepts/LongTermMemory.md` 补一句「原始历史 vs 压缩记忆」的对照。**不建议新建页**。

### 候选 3 ⭐ —— 多智能体在「服务人」的场景下符号翻转
**Does Multi-Agent Collaboration Pay When Agents Serve Users? / Agent Scaling in Dual-Control Settings**

**来源（[verified]）**
1. https://arxiv.org/abs/2610.27655 —— 一手 abs 页（提交 **2026-10-20 05:13:13 UTC**）[verified]
2. https://arxiv.org/html/2610.27655v1 —— 全文 HTML（Introduction + 预注册说明已核对）[verified]
3. https://atlas360.news/en/news/multi-agent-ai-loses-in-12-of-13-user-service-tests —— 二手汇编，**仅用于交叉核对数字**；⚠️ 其「published Oct. 21」为**播报日**，与 abs 页提交日不符 [verified]

**一句话定义**
在**有用户在环**的双控制基准上，与**同一模型**搭出的中心化多智能体系统**在 12/13 个格子里落后于单智能体**，加权均值 **−28 点**，且要打平需 **5.5 倍** token。

**为什么是「当下」最有价值 —— 缺口在哪（一句话）**
[[MultiAgent]] 整页只建立在**一个**边界条件上（「verifier 是前提」），证据全部来自**自主基准**（无用户参与）；本行证明**「自主 vs 服务人」是第二个独立前提，且会让符号翻转** —— 本库此前没有任何一处记录过这条轴。

**核心数字**
- τ²-bench 双控制基准（用户逐轮供信息；电信域用户还会自己动共享环境），airline / retail / telecom 三域；**6 个模型 / 3 个模型族**（主分析 4 个 / 2 族）；约 **7,950** 段模拟对话；**每 episode 一份 completion-token 账本**；**预注册 + 公开变更日志**；轨迹 / 账本 / prompt / 代码全公开。
- **没有一个格子显示 MAS 有收益**：12 个主拟合格子加权均值 **−28 点**（95% CI **[−44, −12]**）；满足机械有效性门槛的 **13** 格中 **MAS 在 12 格落后、1 格打平**。
- 在能力饱和规则**预测 MAS 应有收益的那 2 个格子**上，MAS **分别输 13 点与 22 点**。
- 去掉预算上限后，MAS **最多打平，代价 5.5 倍**中位 token。
- **MAS 没有可测地减少错误的数据库写入**，只是把别的失败换成**预算耗尽与不作为**。
- 结论原句：**"For agents that serve people, the SAS is the default; a multi-agent design must show compute-matched evidence from the setting itself."**

**边界辨析（与已覆盖概念）**
- vs [[MultiAgent]] 的「verifier 是前提」：**不是推翻，是加第二个前提**（自主 ↔ 服务人）⇒ 该页的「边界条件即内容」主题第一次有了**两条轴**；
- vs 本库「vendor benchmarks are not citable」：本行是**符合**本库取证标准的那类证据（预注册 + 公开账本 + 公开材料），故应记为该页**最硬的一条反面证据**；
- 第 4 条（资源定价盘点）：**5.5×** 是一个可以直接引用的硬数字。

**🔴 必须同屏**
- 预印本、**未同行评议**；
- **有一条预注册的有效性门槛未达成并已被作者标注为偏离** —— **MAS 的 planner 从未看到 tool schema**。这是攻击该结果最明显的入口，而作者公开全部材料使这种攻击很廉价（**引用时必须写这一条**）；
- **斜率问题未解**：slope **−0.41**，95% CI **[−1.51, +0.68]**，**跨 0**，model-by-domain 效应主导；
- **只测了一种架构**（中心化 MAS），不可推广到去中心化；
- **唯一那一格收益**出现在最接近 45% 的格子上、且用的是**第二个 simulator**。

**建议下一步**
`concepts/MultiAgent.md` 增「**第二个前提：自主 vs 服务人 / The Second Precondition: Autonomous vs User-Serving**」一节，**并把「planner 未看到 tool schema」写在第一屏**。**不建议新建页**。
