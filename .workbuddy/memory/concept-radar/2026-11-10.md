### 11-10A · Skill 库自演化 / Self-Evolving Skill Library ⭐⭐⭐

**一句话定义**：把「Skill 由开发者策展」的默认假设换成「由运行经验自动生成与修订」——从文档推断操作轨迹生成可复用 Skill（ScienceCUA）、把探索轨迹沉淀为结构化 Gene 资产再反馈进化（Evolver）、跑完任务后由 Curator 把脚本与指导归并进技能库（EvoML）；**一周内三个互不引用的团队各出一版**，且共同设计答案是同一个：**只在真实环境反复验证通过后才入库**。

**为什么"当下"最有价值 —— 缝在哪**

- **`Skill.md` 是全库三个源头概念页之一，`last_updated` 停在 2026-09-09（62 天）**，且是 11-07A 点名的「零风险面」页。三条新证据把这个页面的**默认前提**（开发者策展）拆掉了。

- **验证门槛是共同治理答案**：ScienceCUA「updating the skill library only after repeated validation in real environments」、Evolver feedback-guided evolution、EvoML validation-gated harness——这恰是对 11-07A「良性资产无异常可检 ⇒ 检测式防御结构上无效」的治理回应（位置型防御：入库前再验一次）。

### 11-10B · 危害记在谁头上 / Victim-Centric Harm ⭐⭐⭐

**一句话定义**：攻击成功 ≠ 危害发生——既有指标（ASR / 任务完成率）既不记**谁受了影响**、也不记攻击**如何翻译成下游危害**；MemHarmBench 以受害者为中心：三类受害者（用户 / 工作区·项目所有者 / 外部利益相关方），流程 = 暴露恶意指令 → 测是否留存 → **删掉攻击内容** → 带着记忆开新会话做合法任务，联合评估「跟随攻击者意图 + 完成合法任务 + 可观测异常」；发现跨会话攻击可**行为隐身**：任务照常完成、无异常，但关键决策已偏向攻击者意图。

**为什么"当下"最有价值 —— 缝在哪**

- **`MemoryPoisoning` 页有模型、没仪器**：该页已建立 write-authority 与 persistence step 模型，但危害侧一直只有 ASR 一个代理指标。本条补上**受害侧度量仪器**。
- **与 11-07B「记忆的归属主体」构成同一根轴的两端**：归属问「记忆属于谁」（存储侧治理），受害问「危害记在谁头上」（危害侧度量）——三类受害者分类正是归属分类的受害侧镜像。
- **「有攻击、无异常」是 11-07A「无对手、无异常」的镜像**：检测式防御在两边都结构失效（一边无异常可检，一边异常不暴露）；与 11-09A「披露被标签压制」成对——那边有披露通道但被关，这边**根本没有可观测通道**。
- **删除攻击内容后仍生效**，直接测的正是 `MemoryPoisoning` 页 transient vs persistence 区分的**持久化步骤本身**——overview 的 transient-injection 开放项在危害侧又添一块材料。

**数字（摘要级，一手摘要已核）**

- 三类受害者分类 + 联合评估三问（攻击者意图 / 合法任务完成 / 可观测异常）。
- 核心定性结论：跨多个 agent 系统，跨会话攻击**行为隐身**——正常完成任务、无可检测异常、关键决策仍随攻击者意图。
- 24 页含附录；基准公开：`github.com/Kirito14IT/MemHarmBench`。

**边界辨析要点**

### 11-10C · 元基准 / Meta-Benchmarking for Injection ⭐⭐

**一句话定义**：安全基准不必从零造——把现成 utility 基准（AppWorld / VitaBench / Terminal-Bench）自动改装成端到端间接注入评测套件：自动找注入点、生成现实攻击目标、**优化自适应载荷**、在真实环境里验证攻击成立；在现实自适应 IPI 设定下，**被测防御没有一个同时做到强效用与强安全**。

**为什么"当下"最有价值 —— 缝在哪**

- **新轴「仪器的来源」**：本库注入评测条目（11-04A 野外 / 11-09B 定义）都是自建场景；本条提供「从 utility 基准**量产** security 基准」的工厂——与 11-09B（定义侧）、11-04A（野外侧）拼成 **定义 → 构造 → 测量** 的完整链，正好是 transient-injection 立页的三块测量侧材料。
- **载荷自适应直接呼应 11-09B**：那边「检测优化改写下防御缺口持续存在」是防御视角；这边「optimizes adaptive payloads」是攻击视角——攻守两侧在**自适应维度**对上，静态载荷基准的结论不能外推。
- **「无防御同时强效用 + 强安全」= 效用—安全 Pareto 墙**：10-31A（弃权的代价）是墙上一个点；本条声明**整面墙上无支配点**——10-31A 从单例升格为通则的第一步。
- **基准滞后问题是本库老病**：11-03B（4B→GPT-5.4 全 plateau 68–70%）就是「评测仪器跟不上」的证据侧版本；本条是同一病的**测量构造侧**药方。

**数字（摘要级）**

- 三环境（AppWorld / VitaBench / Terminal-Bench）× 多 backbone × 代表性 agent 与防御。
- 核心结论：**no evaluated defense simultaneously achieves strong utility and strong security**。
- 摘要级无具体百分比；PDF 326 KB，比同类注入基准（24–34 页）篇幅短。

**真实可达来源**（**[verified]**）

1. https://arxiv.org/abs/2611.10026 —— *MetaPI: Constructing Prompt Injection Benchmarks from LLM Agent Benchmark*，Peiran Wang / Chong Xiang / Wenjie Qu / Ying Li / Jiaheng Zhang / G. Edward Suh / Yuan Tian（7 人），**cs.CR + cs.AI**，v1 **2026-11-05 06:33 UTC** [verified]

> ⚠️ **证据分级**：① 摘要级，「墙」结论涉及哪些防御、各自数字**正文未开**；② 7 人团队、无独立复现；③ 「元基准」方法自陈可扩展（heterogeneous environments），实际只落三个环境。

**边界辨析要点**

- **vs 11-09B**：定义口径 vs 基准构造——先定义「什么算攻击」，再量产「测它的仪器」；六部件分类可直接当 MetaPI 生成攻击目标的骨架。
- **vs 11-04A**：野外**发生率**测量 vs 实验室**构造性**测量——互补，不是竞争。
- **vs 10-31A**：弃权代价是效用—安全权衡的**一个点**（过度拒绝侧）；本条测**整条前沿**且说无支配点。
- **vs Trace2Eval（本期备查）**：同是「从真实轨迹造基准」，那边是 **utility 侧**、这边是 **security 侧**——证据轴的一体两面。

**建议下一步**
