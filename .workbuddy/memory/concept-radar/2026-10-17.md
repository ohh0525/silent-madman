## 候选 1 ⭐ 记忆的第三种载体 —— 连续记忆

### Latent & Soft-Token Memory

### 为什么「当下」最有价值

1. **它改变了被治理对象的形态,而不是新增一个格子。** 前 26 期找的都是新概念、新主体、新接缝;这条既不新增参与者也不新开一页论题——它把记忆本身从「文本」换成「连续向量」。而 wiki 里所有关于记忆的规则,都是**为可读文本写的**。
2. **它一次性让四页的存在前提失效。** [[Provenance]] 要挂在**一条记录**上;[[CitationLock]] 要求「只能引用实际打开过的东西」;[[Abstention]] 要求「没有打开过的证据就弃权」;[[MemoryGovernance]] 的四条底线是**可审计 · 可回滚 · 有权限 · 信签名**,四条全都默认「这份东西可以被逐条列举」。连续记忆**没有地址**:没有东西可挂、没有东西可引、没有东西可删、没有东西可签名。⇒ **你无法引用一个向量。**
3. **它落在最大的缺口上。** [[LongTermMemory]] 的整篇张力是「窗口装不下,所以要外置」。今天这批论文说的是:甚至可以**不用文本**——**用 16 个 token 反而赢过全上下文**(FactKG 84.33% 对 80.43%,且文档 token 少 **108 倍**)。这也是 [[ContextEngineering]] 名句「最小高信号 token 集」被字面改写的一刻:**送进模型的「信号」可以根本不是 token**。
4. **与你最近的关注直接相邻。** 最近一份入库材料是 `memory-lifecycle.html`(记忆四动作 + 决定者);这条是它**唯一没覆盖的一种载体**——10-13 的「两种载体 × 四条路」合并总纲里,两种载体(历史 / 任务对象)**都是文本**。

### 来源(4 条,WebSearch 真实返回)

1. **[verified]** Memorilla 论文主页(arXiv:2610.21375,**2026-10-15** 提交;Fallahpour / Idehpour / Kothapalli / Mounier / Wu / Pardis / **Jure Leskovec**;Stanford · Toronto · UPenn · MIT · Vector · Arc)—— https://arxiv.org/abs/2610.21375
2. **[verified]** Memorilla 官方项目页(架构图 + 实测服务成本):**16** 个 memory tokens · 平均 **394 倍**少于全上下文的文档 token(NarrativeQA 上 **>4,000 倍**)· 512 篇文档 **0.74 秒 vs 19.9 秒**(单卡 H100-80GB / batch 1 / Qwen3-8B)—— https://memory.stanford.edu/?ref=fluentrebel.com
3. **[verified]** REMORY 摘要(arXiv:2610.11287,**2026-10-08**;Xia / Chen / Ge / Deng / Yang / Dong / Yuan / Zhu):SummHay 上用 **5.2%** 输入位置逼近全上下文联合分数,**溯源得分上升而洞察覆盖几乎不变**;BrowseComp 与 Terminal-Bench 2.1 上重复工具输出与工具错误显著减少 —— https://papers.cool/arxiv/2610.11287

### 一句话定义

> **用一个被训练出来的小网络,把整份文档集合读完后压缩成固定数量的连续向量(memory tokens),直接放入冻结大模型的输入嵌入空间,从而让模型「记住」远超上下文容量的东西——但返回来的不再是任何可以被逐条检查的文本。**

## 候选 2 ⭐ 记忆评测的内禀化 —— 「回答对了」不等于「记住对了」

### Intrinsic vs Extrinsic Evaluation of Agent Memory (FEB-30)

### 为什么「当下」最有价值

1. **它直接瞄准 Cluster F 承重结论所用的那把尺。** [[MemoryGovernance]] 的头条发现是「前沿模型**给它金标记忆**时很强、**走完整流水线**就崩」——而这个「崩」是**用下游问答准确率量出来的**。FEB-30 说:这把尺本身会把「记忆坏了」读成「记忆没事」。⇒ **我用来下结论的仪器,可能看不见我要找的东西。**
2. **它给既有框架提供了一件缺失的工具。** [[MemoryGovernance]] 把记忆拆成四个动作(Capture → Update → Recall → QA),可训练策略分支把 **ADD · UPDATE · DELETE · NOOP** 放进动作空间——但 wiki 从来没有**直接给这些决策打分**的仪器,只能从答案反推。FEB-30 的四个操作(create / update / reinforce / **supersede**)几乎一一对应 ⇒ 第一次出现**直评操作层**的工具。
3. **数字足够硬,且论文自己划了适用边界。** 内禀与外在评测平均分歧 **16 个百分点**;**44%** 的轨迹超过有意义分歧阈值;四种记忆操作**只有 20% 被判对**,而这一失败「对外在评测**完全不可见**」。限定:14 页、单图、单一「代表性记忆系统」上演示。
4. **它是既有「评测的评测」线的一层下移。** 10-13 已入库的 arXiv:2610.07274 显示只有 **22.6%** 的通过记录能穿过四项查核——那条管的是**智能体的分数**;本条管的是**记忆的操作**。同一个计量学问题,对象下移一层。
5. **它是 `overview.md` 那条开放问题的升级形式。** 该页写着「Cluster F 全部证据为作者自报、需独立复现」。今天的升级是:**不但要复现数字,还要先看这把尺能不能看见失败。**

### 一句话定义

> **现有记忆基准用「下游问答答对了没」代理「记忆对没对」,而这两件事会系统性分家:答对了可能掩盖坏掉的记忆,答错了也可能冤枉好记忆。FEB-30 用「范式反转」生成带确定真值的事实演化轨迹,从而能在每一次写入之后直接打开记忆库本体检查。**

## 候选 3 以协调基质为中心 —— 可引用消息取代直接通信(不标 ⭐)

### Substrate-Centric Coordination (ScaleMAS)

### 为什么「当下」最有价值

1. **它补的是昨天刚打开的那一格的下半部分。** 昨天刚给 `concepts/MultiAgent.md` 加了「协议枢转」一节,用 CVE 级证据证明**跨智能体的污染真的会发生**;但那一节**没有任何形态建议**。今天这条给了形态。
2. **它把一条旧预言变成了可运行的机制。** overview 自 2026-09-26 写着「[[Provenance]] 的对象要从『事实』扩展到『你当事实来用的那个结论的验证状态』」。ScaleMAS 的做法是:消息必须被发布、可被引用、按相关性与被引用次数排序、按地址取回——即**引用计数直接充当质量信号** ⇒ 溯源不再是事后审计,而是**协调机制本身**。
3. **它的诊断里含有 wiki 缺的那半句。** 论文点名:既有的「黑板式」共享中间层**只解决了第三个问题**(抗 agent 失效),没解决前两个(**读负担随群体规模增长**、**有用信息被未知质量的共享工作稀释**)。这正是 [[MultiAgent]] 的 cross-contamination 的严格表述。
4. **它有可对照的反面数据。** 协调者式的 AOrchestra 在 **20% 掉线时就丢掉一半以上分数**;ScaleMAS 在 **128 个 agent** 规模仍继续提升,且**推理开销更低**。
5. **它也给 [[Abstention]] 一个新读法**:top-k 限读是一种**强制性弃权**——不是模型判断后弃权,而是架构让它读不到。⇒ 「没有打开过」从判断变成了设计。
