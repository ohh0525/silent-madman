**一句话定义 + 边界辨析**
- **定义**：若训练回路里的 agent 与部署时的 agent 不是同一个 harness，那么模型学到的最优解对应的是一个**被移除约束后的环境** —— 这类偏差不是 reward hacking，而是**环境错配**；修法不是调奖励，而是**让部署用的那个 harness 原样参加训练**（代理层记录 prompt / response / logprob 即可，harness 无需感知自己在被训练）。
- **vs [[AgentHarness]]**：**机制清单 vs 策略的一部分** —— 现有页说 harness 决定「给模型看什么、允许它调什么、何时判停」，本条补上「**因此它也决定了动作空间与观测空间**」。
- **vs 09-23「自进化智能体」行**：**本条即该行的第一份硬证据**（该行 18 天 ⏸ 且始终无证据）⇒ **建议合并，不并列两行**。
- **vs 10-08「可观测与评测」**：代理记录的 prompt / response / logprob **正是 trace** ⇒ **遥测即训练 substrate**，两条共用同一份数据，是同一件事的两个消费者。
- **vs [[Compaction]]**：重写版随手砍掉的「历史消息压缩到什么长度、工具返回脏数据怎么清洗」**正是被抽掉的约束本身** —— 这把上下文治理从「工程细节」升级为「训练正确性前提」。

**🔴 必须同屏的「但是」**

It can also give an excellent answer once and fail to survive the next deploy. Both problems need measuring.**」
- `[verified]` https://clawpk.net/articles/1606-earendil-pi-durable-checkpoint-long-running-agent-runtime.html —— Pi Durable 中文长文补上**社区热度**（Hacker News 逾 1,500 点）与非幂等后果（**重复发邮件 / 重复下单**）。

## 五、经验 / 坑（有长期价值的记法）

- **可靠性与质量是两个正交轴，此前一直被混记**：「一次运行可以可靠地跑完却给出糟糕答案，也可以给出一次精彩答案却活不过下一次部署——两者都要测。」⇒ 新增判据：**持久化执行（跑得完）与 evals（跑得好）必须分栏**，不能互为替代指标。
