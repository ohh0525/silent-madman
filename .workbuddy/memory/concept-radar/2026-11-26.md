### 11-26A 模型自主管理上下文 / Model-Driven Context Management（context API） ⭐⭐⭐

**一句话**：agent harness 今天替模型管上下文——窗口一满就触发压缩、把历史摘要掉；本文研究相反的做法：**模型自己通过 context API 决定何时、把什么压缩**。作者在 NVIDIA 开源 harness \nooa 里把上下文控制权交给模型，在文档研究与机器学习工程两类任务、8K–512K 全预算区间对比两种策略：会用 context API 的模型达到更高准确率且往往用更少输入 token，紧预算下尤甚——**GPT 6.1 在 32K 预算的 OfficeQA Pro v2 上分数 21% → 56%（近三倍）**，**Kimi 最多少用 41% 输入 token**。但模型之间差异极大（用 API 多寡、压缩激进度、何时开始压缩都不同），改 prompt 还会挪动这个时点。最后证明**推理引擎能让模型驱动的编辑更便宜**：编辑后复用未变后缀的 KV cache，**每次请求 prefill 计算最多省 15% 且准确率无可测变化**，指向「模型学着管自己的上下文 + 推理引擎支持 KV cache 编辑」的协同设计前沿。7 作者（Alessio Devoto 等，含 NVIDIA），v1 2026-11-25，cs.AI。

- **概念名（中英）**：模型自主管理上下文 / Model-Driven Context Management（context API）
- **为什么"当下"最有价值**：[[Compaction]] 与 [[AgentHarness]] 至今把压缩写成 harness 的第①职责「窗口满了自动摘要」，[[ContextEngineering]] 也默认「对窗口的主动管理」由外部机制执行；A 第一次把**压缩的触发权本身**设为实验变量，证明「谁来触发」和「压缩什么」同样决定成败，且省 token 与提准确率可以兼得——给 overview 那条「上下文工程如何端到端评测（非单厂商自报）」补上缺了的控制权维度。

  - https://arxiv.org/pdf/2611.34147 [verified] —— 一手 PDF（abs 页 View PDF 链接）

- **一句话定义 + 边界辨析**：定义——把上下文压缩的触发与对象选择从 harness 的固定策略改成模型经 context API 自主决定，并由推理引擎复用后缀 KV cache 降低编辑成本。边界：① vs 11-25B Autoresearch Harness（context folding > 滚动摘要）——那条争「**保留什么单位**」，本条争「**谁来决定何时压**」，一个在留存策略、一个在控制主体；② vs [[Compaction]]——压缩本身是该页的机制，本条不变压缩算法、只换触发权归属；③ vs [[ContextEngineering]]——那是「对窗口主动管理」的原则层，本条是该原则里「管理权归谁」的一个被测实例；④ vs 11-24C Aggron / 11-23C Contexture（serving 层压缩）——那两条是服务系统在算力/队列层做 KV 压缩，本条是模型在 agent 层调用 API，宿主层不同。

### 11-26B 记忆条目的信用与生命周期 / Per-Action Credit & Memory Lifecycle（AdMem） ⭐⭐⭐

**一句话**：一个能跨任务带记忆的 agent，好坏只取决于它留下的条目——而一个「反直觉、易复现、令领域不适」的观察是：**朴素累积跨任务经验会让 agent 比完全没有记忆还差**。在 AgentBoard 上，workflow-induction 记忆在 **8 个域里有 7 个域解的任务少于无记忆的 ReAct**；一个没有外围结构的逐步程序性 store 在 Jericho 上丢掉 ReAct 一半的完成数。作者认为缺的是两样东西：**逐动作信用分配**（per-action credit）与**条目的显式生命周期**，于是给出 AdMem：每个动作前 actor 承诺一个预期结果，并行运行的 critic 把实际结果对照该预期打分，写出一条带二元 reward 与反思的程序性条目——信用因此落在挣到它的那个动作上，且不需要环境奖励。每条再带一个标量 utility，在 noisy-OR 奖励模型下在线更新，与语境相似度共同排序检索、并驱动淘汰与合并，让 store 有遗忘与整合策略而非无界增长。在 8 个 AgentBoard 域的 707 个任务上 AdMem 解出 **441**，对比 ReAct 的 **388** 与 workflow-induction 基线的 **312**（双侧 Fisher 精确检验显著），增益集中在能跨任务迁移结构的域。所有记忆保持人类可读文本——这既让上述失败可诊断，也（作者自陈）让 store 成为一个可审计但可攻击的表面。5 作者（Runzhe Wang / Huilin Lu / Shengjie Liu / Li Dong / Zhihuai Zhu，Princeton + Amazon + Arm），v1 2026-11-16，cs.AI，NeurIPS 2026 Workshop「Agents in the Wild」。

- **概念名（中英）**：记忆条目的信用与生命周期 / Per-Action Credit & Explicit Memory Lifecycle（AdMem）
- **为什么"当下"最有价值**：台账第 21 条「边际价值审计」攒了三例——11-22A PACE（协作的边际价值可能为负）、11-23B MemCredit（把单条记忆的价值锚到决策效用）、11-24A CLAM（加法伴生结构的边际价值）——但缺一例「**记忆累积本身边际价值为负**」的干净证据；B 用 7/8 域「攒经验不如不攒」把这个负号摆到台面上，并把它机械化成 utility + noisy-OR + 淘汰/合并，正好把「边际价值」从一句审计口号落成条目的生命周期算法，也与 11-22B GrepMem、11-24A CLAM 形成「要不要存、存了怎么退」的对偶。

- **一句话定义 + 边界辨析**：定义——用「动作前承诺期望、critic 对照打分」把信用落到单个动作，再给每条记忆一个在线更新的 utility 驱动检索排序、淘汰与合并，使跨任务记忆 store 有生命周期而非无界累积。边界：① vs 11-23B MemCredit（反事实边际贡献蒸馏成轻量估计器）——那条估的是「**这条记忆对决策有多大用**」，本条把信用归到「**哪个动作挣来的**」并追加淘汰/合并，一个在价值估计、一个在归因与生命周期；② vs 11-13C ENGRAM / 11-14C 退役验证门——那条给经验「出库」设一道验证闸，本条用 utility 在线驱动 eviction，一个在出库门、一个在持续淘汰；③ vs 11-08A 边际价值/世界模型——那条审「教程是否让世界模型增益归零」，本条审「记忆本身是否为负」，同属第 21 条审计线但对象不同；④ vs [[LongTermMemory]] 的三记忆路线——本条不争「存哪类记忆」，争「每条怎么增值与退役」。

### 11-26C 相关性即防御 / Relevance-as-Defense（MINE） ⭐⭐⭐

**一句话**：RAG 里对间接注入的现有防御本质上都是**反应式**的——prompt 工程加的元指令会被注入指令盖过，监督式检测器每来一种新攻击样式就得重训。本文换了个范式：**不检测攻击，而是最大化相关性**。方法 MINE 训练无关、攻击无关，同时充当查询条件的重排器：把每个检索片段按「与查询的互信息最大、同时惩罚 embedding 方差」优化后取 top-k 喂给模型。为在真实条件下评测，作者引入长上下文基准 **LC-Inj-SQuAD（平均每上下文 4,032 词）**，在四个数据集（短上下文 Inj-SQuAD / Inj-TriviaQA、长上下文 LC-Inj-SQuAD、agent 工具调用注入 InjecAgent）上：MINE 在训练无关防御里拿到最佳 accuracy–security 权衡，是**唯一在 fully adaptive attacker 下仍可用**的防御，还能泛化到 agent 工具调用注入，并在长上下文上延迟最低。3 作者（Truong Phan / Ngoc-Quan Pham / Dat Quoc Nguyen，Qualcomm AI Research），v1 2026-11-25，cs.CL+AI，**EACL 2027 主会录用**。

- **概念名（中英）**：相关性即防御 / Relevance-as-Defense（Mutual Information + Embedding Variance，MINE）
- **为什么"当下"最有价值**：`overview.md` 明写 wiki 缺 transient 间接注入专页，注入轴此前由 11-04A（野外实测）、11-08B（清洁者被污染）、11-09A（语态模仿）、11-09B（授权口径）、11-25C（压缩边界授权）铺满，但它们共享一个默认前提「**先检测/先归因，再放行**」；C 把判据整个换成「让查询与内容的相关性最大化，攻击片段自然掉出 top-k」，且是唯一在自适应攻击者下不崩的形态——给注入轴补出一个不属于检测家族的新分支，同时正面接上台账最老开放项「🎯 10-13 检索准入」的 defense 侧（不是管谁能检索，而是让检索本身把注入筛掉）。
- **来源链接（均 [verified]，一手 abs 已 WebFetch 直开核验）**：
  - https://arxiv.org/abs/2611.34188v1 [verified] —— 一手 abs（直开）：标题、3 作者（Qualcomm AI Research）、v1 2026-11-25、cs.CL+AI、EACL 2027 Main 录用标注、全部量化与基准结论出自此页摘要
  - https://arxiv.org/pdf/2611.34188 [verified] —— 一手 PDF（abs 页 View PDF 链接）
  - https://arxiv.org/html/2611.34188v1 [verified] —— 一手 HTML 全文（直开核验）
- **一句话定义 + 边界辨析**：定义——不做攻击检测，转而在检索阶段以「查询-片段互信息最大化 + embedding 方差惩罚」做查询条件重排，使注入片段因不相关被过滤，达成训练无关、攻击无关的防御。边界：① vs 11-09B 授权口径审计 / 11-25C 压缩边界授权——那两条在**动作放行前**判「谁有权决定」，本条在**内容进模型前**判「哪些片段该留下」，一个在授权层、一个在检索层；② vs 11-08B 清洁者洁净度（读手被读到的东西污染）——那条警告「判断哪些该洗的读手也会被污染」，本条用无监督的相关性目标绕开「学一个会过时的检测器」，是对该风险的另一条解法；③ vs 11-24B Safe Personal RSI（prompt 更新的验证门）——那条管「变更要不要采纳」，本条管「内容要不要进上下文」，阶段不同；④ vs RAG 分块/检索准入（🎯 10-13）——那是检索的准入规则，本条把防御直接嵌进相关度排序函数。
- **⚠️ 证据边界**：预印本（已录用 EACL 2027 Main，同行评审强于普通预印本）、单团队自报、含 Qualcomm AI Research 商业方；「唯一对 fully adaptive attacker 仍可用」是作者在其自建 LC-Inj-SQuAD 与 InjecAgent 上的结论，非对所有攻击家族；互信息/方差目标的计算开销与长上下文延迟数字须开 PDF 核；防御面向 RAG 短/长 QA 与工具调用注入，未覆盖多模态（接 11-08 零视觉盲区）。成篇前须开 PDF 核自适应攻击设置与四个数据集的分表。
