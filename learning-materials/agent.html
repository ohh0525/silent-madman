Agent（智能体）

一项能自己决定「下一步做什么」的系统化能力 · 生成时间 2026-09-05

1 · 一句话定义

AI Agent 是一个由大模型驱动、能围绕一个目标自主决定调用哪些工具、观察结果并循环往复，直至任务完成或主动交还控制权的软件系统。

2 · 个人解释

想象你雇了一位助理：你不是给他一份逐步指令，而是只说「帮我订一家明天晚上六点适合带小孩吃的本帮菜餐厅」。普通的聊天机器人只能告诉你「怎么选餐厅」；一个真正的 Agent 会自己上网搜、查点评、比位置、看是否需要订位、看是否有儿童餐，最后真的把订单建好。

关键在于「自主」二字：模型不再是每一步都被人类牵着走，而是一个有目标、有工具、能根据反馈调整下一步的执行者。它内部有一个非常朴素的循环——观察 → 思考 → 行动 → 再观察——一遍遍地跑，直到它觉得目标达成了，或者主动说「这件事我做不了」。

所以 Agent 最反直觉的地方是：它并不是某种新算法，而是一种把已有的大模型、工具调用、记忆、循环结构拼起来的组织方式。模型本身很会推理，但默认并不知道有什么工具可用、能去做什么；Agent 框架负责把这些选项摆到桌上，并设计出循环让模型不断尝试和纠正。

假设一个虚拟场景：你问 Agent「这张报表里哪个产品的毛利率最高」。它会先读文件 → 理解列名 → 用 Python 跑一段计算 → 找出结果 → 用自然语言回报给你。中间任何一步报错，它会自动换思路（比如换一段代码、再读一段示例数据）而不是停下来等你。这是 Agent 最直观的体验。

3 · 核心机制

  1. 接收目标与上下文：用户给出任务 + 当前状态（历史、可用工具列表）。这一步把模糊意图翻译成可执行目标。
    为什么重要：没有清晰目标，模型就会漫无目的地调用工具，浪费 token 和算力。
  2. 推理下一步动作：大模型基于 ReAct / Chain-of-Thought 等范式，输出「我应该调用哪个工具、传入什么参数」。这是模型的「决策中枢」。
    为什么重要：这一步决定了 Agent 的自主性上限——能不能选对工具，是 Agent 聪明与否的核心。
  3. 执行工具并收集观察：外部执行器（搜索引擎、Python、API）真正完成动作，把结构化结果回传。
    为什么重要：模型如果不能落地真实操作，就只是「会说话的搜索框」，谈不上 Agent。
  4. 更新状态并判断是否结束：把观察合并进上下文，判断目标完成或陷入循环；未完成则回到第 2 步重新规划。
    为什么重要：缺了停止条件，Agent 会无限循环烧钱；存在停止条件，它才能成为一种可靠的工程对象。

4 · 应用场景

场景 1 · 自动化代码工程（Claude Code / Devin）

背景：中型代码库中需要把登录页从 React class 组件迁移到 hooks。

如何应用：Agent 接到目标后，先扫描文件依赖 → 写改造方案 → 分批修改 → 自动跑测试 → 失败就重试，直到 CI 通过。

结果：工程师从「逐个文件手工改」变成「审 PR、提反馈」，改造时间从天级压缩到小时级。

场景 2 · 浏览器自动化办公（OpenAI Operator / Computer Use）

背景：需要在 5 个 SaaS 后台里登记同一批客户信息。

如何应用：Agent 启动浏览器、识别表单字段、上传文件、处理验证码，按顺序在每个系统完成表单。

结果：批量后台录入从全职工时降到一键触发，错误率在 1% 以下。

场景 3 · 深度研究助理（Deep Research / Perplexity）

背景：投资经理想了解某新兴赛道的竞争格局。

如何应用：Agent 多轮检索行业报告、招股书、新闻，把信息聚拢后写出结构化对比，并附上每条结论的来源链接。

结果：一份原本要研究员花一周整理的市场扫描，30 分钟内产出可讨论的初稿。

5 · 边界辨析

5.1 不是什么

  • 不是聊天机器人：聊天机器人用大模型回答问题即可；Agent 必须用模型来控制执行路径。把 LLM 接两个工具调用并不自动成为 Agent —— 关键是模型自己决定何时用、用哪个。
  • 不是传统自动化脚本：自动化执行固定的 A→B→C 流程；Agent 自己决定步骤。代价是更低可预测性、更高成本、更多失败模式。
  • 不是 AGI：Agent 在受限领域很强，但仍然是软件，受权限、token 预算、停止条件约束。所谓「自主」是字面意义上的「被允许自主」，并非全能。

5.2 常见误解

  • 「挂了工具就是 Agent」——不对。Anthropic 与 OpenAI 都明确强调：模型必须动态掌控执行流程才算，固定工具调用只是函数增强。
  • 「Agent 越智能越好」——并不。Anthropic 建议从最简单的方案做起，只有当任务真的收益时才升级到 Agent，因为成本和失败面都在涨。
  • 「Agent 不会出错」——会出错，且会「自信地编造」工具结果。生产上必须有 token 预算、最大步数、参数校验和外部验证层兜底。

5.3 适用与不适用

用 Agent用脚本
步骤无法预先穷举（数据清洗、研究综述）步骤明确、每次相同的批处理
需要根据结果灵活变招（改 bug、跨工具工作）毫秒级 SLA 的高频路径
对单次失败可接受重试任何失败都不可逆的强一致性场景
