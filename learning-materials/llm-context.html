大模型的上下文（Context Window）

一项把模型的「短期记忆」量化的工程概念 · 生成时间 2026-09-05

1 · 一句话定义

上下文窗口是 Transformer 大模型在一次推理中能同时读入并参考的全部 token 数量上限，它决定了模型这一轮能看到的所有信息。

2 · 个人解释

把大模型想象成一张固定大小的办公桌。所有要让它「同时看见」的东西——系统提示、整段历史对话、上传的文档、检索回来的片段、它接下来要写的回答——都必须摆在桌面上。桌子就这么大，你摆不下时，最早摆上来的东西会被挤掉。

这张桌子有个奇怪特性：它不是按「汉字」或「单词」计数的，而是按 token 计数的。英文里一个单词大概一个 token，中文因为最小单位是字，每个汉字平均要 1.5–2 个 token。所以同样一段话，中文比英文「占桌子」。

为什么会有这张桌子？因为大模型读东西用的是自注意力机制——每个字都要和所有其他字两两比对一下「关系有多重要」。1000 个字要算 100 万次关系，10000 个字要算 1 亿次。桌面越大，背后的算力开销按平方级上涨，超出训练长度甚至会让推理质量骤降。这种硬件与数学的双重成本，迫使模型必须有一张「有限桌面」。

假设一个虚拟场景：你用 8K 窗口的模型做客服问答。系统提示占 1K、历史对话已经堆到 4K、保留回答给 1K，剩下的 2K 才能塞知识库。一旦用户连发几轮，对话就会被悄悄截断到开头，模型突然「忘了」五分钟前的约定——这就是你日常看到的「AI 失忆」。

3 · 核心机制

  1. Token 化输入：所有文本先用 BPE 等子词分词算法切成 token 序列，让模型用统一的「数字筹码」处理多语言和生词。
    为什么重要：没有这步，模型无法跨语言工作，也无法处理词典外的新词。
  2. 位置编码 + 自注意力叠加：每个 token 生成位置向量，再与所有其他 token 计算注意力分数，得到当前轮的「全图印象」。
    为什么重要：这是模型能「读懂上下文」的物理基础，序列越长计算量按 n² 增长。
  3. 总长度判断与截断：当 prompt + 历史 + 工具结果 + 预留输出 > 窗口上限，要么报错，要么按策略丢弃最早内容（静默截断）。
    为什么重要：这一步决定模型实际「看得见什么」，工程上所有「AI 失忆」问题都从这里来。
  4. 注意力权重偏移：哪怕内容没超限，模型对开头系统提示和末尾当前提问的注意力最强，夹在中间的长文档容易「Lost in the Middle」。
    为什么重要：解释为什么「关键信息不要丢在中间」是一条普适工程经验。
窗口包含 = 系统提示 + 历史对话 + 参考材料 + 预留输出 ≤ N tokens

4 · 应用场景

场景 1 · 多轮代码助手（32K~128K）

背景：工程师让 Claude Code 维护一个中型项目，反复多次编辑同一组文件。

如何应用：把系统提示、项目 README、最近几轮修改过的文件、最新报错统一塞进上下文，保证模型每次回复都能看到「同一张地图」。

结果：模型改 5 号文件时还记得 1 号文件里定义过的接口约定，避免反复问人类。

场景 2 · RAG 检索增强问答（8K~32K）

背景：企业知识库有 10 万份 PDF，用户每次只问一个问题。

如何应用：先把用户问题做向量检索，从库里捞出最相关的 5 个片段（约 2K token），连同问题、回答模板一并送进窗口。

结果：在不大窗口的前提下获得「整库知识」，单次成本下降一个数量级。

场景 3 · 长篇视频/书全本解读（200K~1M+）

背景：要把一本 30 万字的小说或一段 2 小时会议录像转写稿一次性喂给模型，要求跨章节回答。

如何应用：用 Gemini 1.5 Pro 等具备百万级窗口的模型，整本输入后直接问「第 12 章埋的伏笔是什么」。

结果：免去切片+拼接的复杂工程范式，仅靠一次超长输入即可完成跨段关联回答。

5 · 边界辨析

5.1 不是什么

  • 不是模型的全部知识：模型的预训练知识是参数里固化下来的「长期记忆」，跨会话可用；上下文是「本次桌子上的便签」，会话结束就清空。
  • 不是越大越好：窗口从 4K 涨到 200K，单次推理成本按平方级上升，响应延迟也显著放大，需要业务场景上算账。
  • 不是简单的字符数：同一个 PDF 用不同 tokenizer 切出来的 token 数差很大，估算时一定要按目标模型的 tokenizer 算。

5.2 常见误解

  • 「窗口大 = 模型变聪明」——并不。模型对窗口中间的内容注意力天然偏弱，「Lost in the Middle」是普遍现象。
  • 「超出会报错」——大多数商用 API 默认静默截断，先丢弃最早内容让请求成功，所以「失忆」经常表现为莫名其妙的前后矛盾。
  • 「上下文 = 上下文长度」——后者是模型架构的理论上限，前者是实际推理时考虑的输入，二者通常不等。

5.3 适用与不适用

用大窗口用 RAG 或摘要
同一文档内的跨段关联推理（全书 QA）信息分布稀疏、只要局部片段
长链路 Agent（多步工具调用保留全状态）高频、低延迟、低成本场景
对截断敏感（合同全文审查）可接受分块、合并的总结型任务
