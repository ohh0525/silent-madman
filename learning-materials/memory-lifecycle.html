记忆的治理:从档案库到策略

Agent Memory: From Archive to Policy —— 记什么、何时取、何时删,以及这三个决定由谁做 · 生成时间 2026-10-06

1 · 一句话定义

智能体记忆的治理,是把记忆从"一个只会增长的档案库"改造成"一套有人拍板、可审计、可遗忘的决策系统"——写什么(捕获)、怎么改(更新)、何时取(召回)、何时删(遗忘)是四个各自会坏的动作,每个动作都要回答"由谁、按什么目标来做决定",而 2026 年的答案正在从人工写死的规则,变成带独立奖励目标的可训练策略。

2 · 个人解释

想象一个从不整理的档案室。管理员把每一份进门的文件都编目上架——包括后来被推翻的旧决定、已经被取消的偏好、甚至被人偷偷塞进来的伪造公文。半年后你问他"我们现在的供应商是谁",他从架上抽出语义最相似的五份文件摊在你面前,里面新旧混杂、真假并存。多数 agent 的记忆系统就是这个档案室:一个向量库,只管"存"和"按相似度取",不管"哪个已经作废"、"哪份是伪造的",更不管"今天该不该还记得这件事"。

为什么这是个严重问题?因为记忆有一个单轮对话没有的特性:错误会复利。模型这一轮说错话,下个窗口就忘了;但一条写错的记忆,会变成它未来每一轮规划的固定输入。更隐蔽的是四种"静悄悄的坏":该捕获的没捕获(你上周改了地址,它没记);该更新的没更新(两版发布日期并存,它自己打架);召回不完整(只召回三条相关记忆里的一条);删除不安全(把还被引用着的事实删了)。DyadMem 基准第一次给这四种病各配了体检指标——它发现前沿模型拿着金标准记忆答题时表现很强,一旦要走完整流水线(自己捕获、自己更新、自己召回)分数就骤降。换句话说:不是模型不会用记忆,是"记忆的四个动作"各自都有洞。

那谁来补这些洞?此前业界默认的答案是"工程师写规则":重要性打分到多少就删、时间过了 TTL 就过期、每次对话结束抽取三条写入。2026 年出现了两条新的回答。一条是把决定训成策略:六个独立团队用强化学习训练"记什么/何时取/何时删"——Memory-R1 只用 152 条 QA 对训练,就在 LoCoMo 上把 F1 相对 Mem0 拉高 68.9%,因为"删掉一条过期记忆"本身就在它的动作空间里。另一条来自攻击者,是没人想要的回答:如果没人治理记忆,决定权会自动流向想利用它的人——PMPA 攻击把恶意指令藏进良性文档诱导 agent 自己写进持久记忆;Darktrace 证明四家主流编码工具全都接受伪造的会话历史,78 条假对话就把 agent 从"拒绝渗透"推到"主动接管域控"。

所以这份材料把四个此前分立的议题(生命周期/遗忘、调用时机、完整性/投毒、学习化策略)合成一张图:记忆是一个由四个动作组成的系统,每个动作都有失效模式、都有决定权归属问题;治理就是让四个动作都可审计、可回滚、有主人。档案库只解决"存";策略解决"存什么、何时用、何时忘";而安全解决"别让别人的策略跑在你的记忆上"。

3 · 核心机制

  1. 把"记忆"拆成四个动作,而不是一个仓库。DyadMem 把长期记忆显式拆成 Capture(捕获本会话新记忆)→ Update(与既有记忆库调和)→ Recall(选出仍有效的条目)→ QA(用证据作答)四段,并在每一段都放置金标注(3,065 个情节、50,961 个会话、61,210 个问答,覆盖 16 个开源 + 4 个闭源模型)。
    为什么重要:端到端 QA 分数会把四个动作的好坏搅在一起——答对了可能记忆库是坏的(碰巧蒙对),答错了也定位不到坏在哪一段。只有拆开量,才知道该修哪里。
  2. 每个动作都有可量化的失效模式。这是 2026 年几份基准合起来给出的"体检表":捕获端,DyadMem 测出前沿模型的 Capture 召回率系统性偏低;更新端,Memora(ACL 2026 Findings)的 FAMA 指标显式惩罚"依赖已删除/已被取代的记忆",发现现有记忆 agent"频繁复用无效记忆、难以调和不断演化的记忆";作证端,Memory Is a Derivation 审计发现压缩后的记忆即便放回更完整的写入前历史,仍有 17–21% 得不到支撑;遗忘端,MemoryAgentBench 把"选择性遗忘"列为与检索、测试时学习并列的四大能力之一,PATH-Bench 进一步定义了前向/后向遗忘迁移指标并给出"强迁移不保证留存"。
    为什么重要:"该忘的没忘"从此不是修辞,而是一个可扣分的指标(FAMA = 召回分 − 陈旧依赖罚项)。
  3. 关键变量是决定权的归属:谁在拍板三个决定。同一套失效模式,有三种截然不同的"决定者":
    决定者记什么 / 何时取 / 何时删代表证据核心短板
    人工规则(现状默认)工程师写死:重要性阈值、TTL、抽取条数、相似度 top-k分层记忆已成 2026 生产系统主流形态(常驻核心 + 外部检索 + 显式遗忘策略)规则对"什么算陈旧"没有判断力;每换一个任务域要重调
    可训练策略(2026 新答案)把 ADD / UPDATE / DELETE / NOOP 放进动作空间,用任务成功奖励联合 RL 训练Memory-R1(ACL 2026 主会,152 条 QA 对,LoCoMo 相对 Mem0 F1 +68.9%)、ATMem(AndroidWorld 76.6%,参数约 1/29 于对照闭源模型)等六个独立团队六系统全部尚未生产部署;基准不覆盖分布漂移与对抗输入;写/取/变换尚无单一系统同时拥有
    攻击者(没人想要的决定者)写入时机与内容由注入者决定PMPA(arXiv:2609.13889):Claude Code 中毒率 66.9%/81.7% 且良性任务表现不变;Darktrace:四家 harness 全部接受伪造会话历史修复在厂商侧(消息签名 + 服务端校验),防守方自己部署不了
    为什么重要:前两行是工程选型问题,第三行是安全底线——如果记忆没有主人,主人位置不会空缺。
  4. 治理的四条底线:可审计、可回滚、有权限、信签名。写什么、何时忘,必须像 git 提交一样可追溯(谁写的、何时、依据哪条来源——这正是"带溯源记忆"那一页的入口纪律);删除必须是真实、可记录、可证明的操作,而不是"从不可见存储里手动翻找";谁有权写入共享记忆要像数据库权限一样显式管理;而对 Darktrace 类攻击,唯一根治是模型回复带密码学签名、服务端逐轮校验——在那之前,本地会话历史库要被当作"安全敏感文件"对待:任何非 harness 进程写入它都是明确的攻击信号。
    为什么重要:前三条管"自己出错",第四条管"别人使坏"——可靠性纪律与安全纪律在记忆这一层合流。
记忆治理的最小骨架(伪代码:四个动作 + 决定者 + 治理底线) # —— 三个决定,三种决定者 —— DECIDER := RULES | TRAINED_POLICY | ATTACKER # 若缺席,默认流向 ATTACKER def capture(session): # 动作①:捕获 for m in DECIDER.what_to_write(session): write(m, origin=m.source, evidence=m.ptr, ts=now()) # 溯源是入场券 def update(bank, new): # 动作②:调和(取代,不是并存) old = bank.conflicts_with(new) if old: bank.supersede(old, by=new) # 新事实显式取代旧事实 if DECIDER is TRAINED_POLICY: bank.delete(DECIDER.stale(bank)) # DELETE 在动作空间里 def recall(question): # 动作③:召回 hits = [m for m in bank if relevant(m, question) and not superseded(m) and fresh(m)] return hits or ABSTAIN # 召回不完整 → 宁可弃答 # —— 治理底线 —— audit_log.record(every write / supersede / delete) # 可审计 git_like.version(bank) # 可回滚(删除可撤销) acl.check(writer) # 有权限 assert verify_signature(model_reply) # 信签名(Darktrace 的根治位)

必须与"分数"一起读的三句提醒:① 记忆基准的分数高度依赖评测脚手架与裁判选择,Memora 论文里六个记忆 agent 在自己的评测里也"仅带来边际提升"——把任何单一榜单数字当采购依据都不成立;② 六个学习化策略系统无一经过"记忆累积数月"的生产检验,RL 奖励仍是代理指标;③ Darktrace 的攻击效果按模型与 harness 而异(Opus 5 的护栏在 Claude Code 下守住了),但历史管理这一层结构缺陷是四家通用的。

4 · 应用场景

场景 1 · 跨月服务的个人助理:"该忘的没忘"是可扣分的病

背景:助理服务同一用户数月,偏好会漂移、决定会被推翻、地址会搬家;用户最怕的不是它忘了,而是它拿着三个月前作废的事实当现状,而且满怀自信。

如何应用:用 Memora 式的演化仿真构造评测集(周/月/季三档,内置偏好漂移与目标推进),用 FAMA(召回分减去陈旧依赖罚项)做验收指标;更新动作必须"取代"而非"并存",每条记忆带被谁取代的指针;DyadMem 式分段金标注定位坏在捕获还是更新。

结果:一套能把"什么时候该忘"量化成回归测试的记忆运维流程——改了记忆策略,跑一遍就知道陈旧依赖是升是降,而不是等用户投诉。

场景 2 · 企业编码 Agent:把会话历史库当安全敏感文件

背景:编码工具把会话历史存在客户端(常为明文 SQLite),不校验存储的"模型回复"是否真由模型产生;一次恶意包安装就能注入伪造历史,让 agent 相信自己"早已被授权渗透测试"。

如何应用:监控会话数据库的非 harness 进程写入(包安装脚本的 postinstall 碰它就是攻击信号);把"会话恢复/回滚编辑"当不可信输入对待;记录并固化模型选型(便宜模型默认值 = 未登记的安全决策);等厂商侧消息签名落地前,出站行为监控比工具审批更能发现被劫持的 agent——因为它做的事"看起来完全合法"。

结果:在"修复不由你部署"的窗口期内,把 78 条假对话式的攻击从"零成本"变成"至少要在监控里留痕";配合写入端溯源闸门,PMPA 式的诱导写入也难以升级为可信事实。

场景 3 · 长任务 Agent 的记忆运维:让"删"进入动作空间

背景:任务横跨数百次工具调用的 agent,窗口外记忆只增不减,top-k 里挤满过期与重复条目,信号被噪音淹没;人工调阈值跟不上任务域的变化。

如何应用:参考 Memory-R1 的双 agent 架构(一个管抽取/更新/删除/不动的四选一,一个管下游任务)加任务成功奖励的 RL;或 ATMem 的记忆成本感知奖励,在效率与召回间自动权衡;训练数据门槛远低于直觉(百量级 QA 对即可起步)。

结果:"何时压缩、何时删除"从每次人工调参变成随任务反馈持续改进的策略——但投产前必须补上生产环境的长周期检验与对抗输入测试,这一步 2026 年还没有人走过。

5 · 边界辨析

5.1 不是什么

  • 不是"更大的上下文窗口":窗口是容量,治理是结构与纪律。DyadMem 的证据是反向的——Gold-Memory(直接喂对的记忆)很强而 Full-Pipeline(自己管记忆)骤降,说明瓶颈不在"装不装得下",在"四个动作各自的质量"。
  • 不是上下文压缩(Compaction):压缩治理的是窗口内这一轮的历史怎么裁;本页治理的是窗口外跨会话的记忆库怎么写、怎么改、何时删。两者相邻(压缩丢的信息若重要,应当落进长期记忆而非蒸发)但对象不同。
  • 不是"带溯源记忆"那一页的重复:溯源(Provenance / CitationLock / Abstention)管的是入口与出口的纪律——写入要带来源、引用只引打开过的、无据弃答;本页管的是中间的全生命周期——更新、遗忘、决定权归属。入口干净不等于生命周期干净:PMPA 的注入恰恰是"带着合法来源"进来的良性文档里埋的雷。
  • 不是"记得越多越好"的反面装饰:遗忘不是失败,是能力。FAMA 把"复用已删除信息"列为扣分项;一个从不遗忘的系统在只测召回的老基准上是满分,在测治理的新基准上是重灾区。

5.2 常见误解

  • 「记忆是个性化功能,锦上添花」——在生产里它是可靠性子系统:写错一条,未来每一轮都跑在错的输入上;被投毒一条,攻击会在此后所有会话复发。
  • 「遗忘 = 数据丢失 = 事故」——恰恰相反,不安全的不遗忘才是事故(把已取消的偏好、已作废的授权继续当真);而"不安全的删除"(删掉仍被引用的事实)同样要测——DyadMem 把两端都量了。
  • 「学习化策略一举解决记忆问题」——六系统无一经过生产长周期检验,基准不含分布漂移与对抗输入,且写/取/变换三步尚无单一系统同时拥有;它们证明的是"方向可行",不是"方案可用"。
  • 「基准分数可以直接横向比」——记忆评测的分数依赖脚手架与裁判选择;连 Memora 论文自己测的六个记忆 agent 也"仅带来边际提升"。任何单一数字都只是起点假设。

5.3 适用与不适用

值得上"记忆治理"这一整套不必上这套复杂度
跨周/月/季持续服务同一用户的助理单会话、用完即弃的问答
事实会被反复更新、推翻、需要时间序一次写入、永不变化的静态资料
读取不可信外部内容(网页/工单/文档)并持久化输入可信且不写回长期存储
错误代价高,需要可审计、可证明"已遗忘"错误无所谓、随时清库重来
