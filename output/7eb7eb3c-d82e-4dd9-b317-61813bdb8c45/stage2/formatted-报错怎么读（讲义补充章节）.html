  本篇是《Python 基础语法讲义（第 1–4 课）》的补充章节，配合 §1.1 环境搭建、§1.2 变量与数据类型使用。讲义第 3 课 §3.6 讲的是"怎么用 try / except 让程序不崩"，本篇讲的是在此之前的那件事——看到一串红色报错时，你到底该怎么读。

TL;DR

Python 的报错信息是结构化的，不是一坨乱码。只要掌握"先看最后一行，再看箭头指向的那一行"这一条，90% 的初学者报错都能自己定位。

为什么这一章要放在第 1 课

教学方案里有一条教学方式叫「错误驱动教学」——每次课刻意演示 2 到 3 个典型错误。原因很直接：

初学者卡住的时间，大头不在"写不出代码"，而在"读不懂报错"。

一个真实的学习曲线是这样的：

阶段学员遇到报错时的反应
第 1 周盯着满屏红字发懵，逐个字符对照讲义，怀疑自己敲错了
第 2 周能认出 NameError / TypeError，知道大概是什么方向的问题
第 4 周直接看最后一行，跳到最后那个行号，十秒定位

这张表里从第一行走到第三行，靠的不是"写得多了自然就会"，而是有人把结构讲清楚。本章就是这张表的第一步。

一、先建立三个认知

在动手读第一段报错之前，先纠正三个最常见的误解。这三条认知决定了你后面能不能把报错当工具用。

1. 报错是信息，不是失败

Python 的设计者花了很大力气让报错信息有用。它不是"你错了"的宣判，而是"我在第几行、因为什么、没法继续了"的说明。

2. 报错信息有固定结构

每一段报错都由四部分组成，位置和含义都是固定的。你看多了会发现，换个错误类型，只有最后一行会变。

3. 你要读的永远是最后一行

这是全章最重要的一句话。初学者最常犯的错误是从第一行开始读，被 Traceback (most recent call last) 和一堆文件路径吓住，然后在中间那段里找线索。

真正的答案在最后一行。

二、Traceback 的四段结构

下面用一段最短的报错，把四段结构一次讲完。看懂这一段，后面所有报错都是它的变形。

一个完整的例子

在 Notebook 里运行下面这行代码：

"20" + 5

你会看到：

---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
Cell In[1], line 1
----> 1 "20" + 5

TypeError: can only concatenate str (not "int") to str

逐段拆解

段落内容它告诉你什么本案例
第 1 段Traceback (most recent call last):固定抬头，没有信息量，可以直接跳过—
第 2 段Cell In[1], line 1出错位置：第 1 个单元格的第 1 行第 1 行
第 3 段----> 1 "20" + 5出错的那一行代码原文，箭头指向行号"20" + 5
第 4 段TypeError: can only concatenate str (not "int") to str错误类型 + 原因，这才是结论字符串只能和字符串相加

  ⚠️ 在 Notebook 和脚本里，第 2 段长得不一样。Notebook 显示 Cell In[1], line 1；如果代码存在 .py 脚本里，显示的是 File "scores.py", line 1。两者含义相同，都是"出错的行号"，其余部分完全一样。

关于"调用链"：为什么有时候中间有好几段

如果出错的那行代码是被另一个函数调用的，中间就会多出几层：

Traceback (most recent call last):
  File "scores.py", line 12, in <module>
    print(average(scores))
  File "scores.py", line 8, in average
    return total / count
ZeroDivisionError: division by zero

这里的读法是 从下往上：

顺序位置含义
最下scores.py, line 8, in average真正炸掉的地方——average 函数第 8 行
往上scores.py, line 12, in <module>是谁调用了它——第 12 行的 print(average(scores))

结论：先看最下面那片（File 行 + 代码行），那才是问题的源头；上面的是"谁把它叫起来的"，用于理解上下文。

第 1 课你写的代码都在单元格里，调用链通常只有一层。等到第 3 课开始写函数，这里会变成三层、四层——但那时的读法和现在完全一样。

三、五步排查法

拿到任何一段报错，按这五步走：

  1. 看最后一行 —— 拿到错误类型和一句话原因。这一步就能解决一半问题。
  2. 找 ----> 箭头 —— 它指向出错的那一行代码原文，不用自己去翻。
  3. 对行号回代码 —— 把那个行号对应的代码找出来，逐字看。
  4. 判断错误类型属于哪一类 —— 是"类型不对"？"名字不存在"？"值不对"？"找不到东西"？见下一节的分类。
  5. 只改一处，然后重跑 —— 一次改一个地方。改太多，你会不知道是哪一处起了作用。

  ⚠️ 最容易违反的是第 5 步。 初学者常犯的错是一口气改三个地方，结果报了一个新错误，完全不知道是自己哪个修改引入的。

四、五个必须认识的错误

以下五类错误，覆盖了初学者 80% 以上的报错场景。每一类都给出真实运行产生的报错原文（不是示意）。

4.1 TypeError —— 类型不对

什么场景会撞上：把不同类型的值做运算。第 1 课 §1.2 类型转换那一节的反例就是它。

触发代码

print("20" + 5)

报错原文

Traceback (most recent call last):
  File "scores.py", line 1, in <module>
    print("20" + 5)
TypeError: can only concatenate str (not "int") to str

逐行解读

部分内容含义
最后一行TypeError类型错误——值本身没问题，类型配不上
最后一行后半can only concatenate str (not "int") to str直译：只能把 str 拼接到 str 上（不能是 int）。也就是"字符串只能加字符串"
箭头行print("20" + 5)"20" 是字符串，5 是整数，加号两边类型不同

怎么修

第 1 课学过：先转换类型，再运算。

print(int("20") + 5)     # 输出 25

一句话记忆：TypeError = 东西是好东西，只是类型不搭。

4.2 NameError —— 名字不存在

什么场景会撞上：用了没定义过的变量；或者 Notebook 里跳过了定义变量的那个单元格（推荐对照第 1 课上半场的"执行顺序"小实验）。

触发代码

print(score)

（在此之前从未给 score 赋过值）

报错原文

Traceback (most recent call last):
  File "scores.py", line 1, in <module>
    print(score)
NameError: name 'score' is not defined

逐行解读

部分内容含义
最后一行NameError名字错误——Python 在找一个叫 score 的东西，没找到
最后一行后半name 'score' is not defined直译：名字 score 没有被定义

怎么修，按可能性从高到低排查：

排查顺序可能原因检查方法
1Notebook 里跳过了赋值单元格从第一格开始依次运行一遍
2真忘了赋值在 print(score) 之前加 score = 88
3拼写不一致scroe / Score / scores ——Python 区分大小写，Score 和 score 是两个名字
4引号问题写成了 print(张三)，Python 会以为"张三"是个变量名。应该是 print("张三")

  ⚠️ 第 4 条是第 1 课 §1.2 提过的坑：字符串忘了加引号，报的就是 NameError 而不是别的。这一点很多人想不通，记住就行。

4.3 ValueError —— 值不对

什么场景会撞上：类型是对的，但这个值没法变成你要的东西。最典型的场景是 input() 之后做转换（第 1 课 §1.5）。

触发代码

score = int("八十八")

报错原文

Traceback (most recent call last):
  File "scores.py", line 1, in <module>
    score = int("八十八")
ValueError: invalid literal for int() with base 10: '八十八'

逐行解读

部分内容含义
最后一行ValueError值错误——类型没问题（都是字符串），问题出在值本身
最后一行后半invalid literal for int() with base 10: '八十八'直译：对 int() 来说这是个无效的字面量。base 10 是"十进制"，'八十八' 就是那个转不了的值

怎么修

输入了非数字字符，改输入或加校验：

score = int("88")        # 输出 88

TypeError 和 ValueError 怎么区分？ 这是本章最值得记住的一对：

TypeErrorValueError
问题出在类型值
例子"20" + 5（str + int）int("八十八")（类型是 str，对；值是"八十八"，转不了）
直觉记法"东西不对""东西对，但内容不对"

4.4 KeyError —— 字典里没这个键

什么场景会撞上：从字典里取一个不存在的键。字典是第 2 课的内容，这里只介绍最小用法：字典用 {键: 值} 存放数据，用 字典[键] 取出值。

触发代码

d = {"姓名": "张三", "年龄": 20}
print(d["成绩"])

报错原文

Traceback (most recent call last):
  File "scores.py", line 2, in <module>
    print(d["成绩"])
KeyError: '成绩'

逐行解读

部分内容含义
最后一行KeyError键错误
最后一行后半'成绩'你找的那个键，Python 把它原样报出来

注意：KeyError 只告诉你"这个键不存在"，它不会告诉你字典里有哪些键。所以要自己回头看定义。

怎么修

方法写法适用
改对键名print(d["年龄"])确认是敲错了
用 get() 给默认值print(d.get("成绩", "暂无"))键可能不存在，且不想让程序崩
先查有哪些键print(d.keys())不确定字典里到底有什么

  ⚠️ KeyError 最喜欢藏在读数据文件的场景里：csv 的表头写的是"学生姓名"，你按列取值时写的是"姓名"，两个对不上，报的就是它。第 3 课、第 4 课会反复遇到。

4.5 FileNotFoundError —— 找不到这个文件

什么场景会撞上：open() 一个不存在的文件。文件读写是第 3 课内容，这里同样只介绍最小用法。

触发代码

f = open("scores.csv", "r")

报错原文

Traceback (most recent call last):
  File "scores.py", line 1, in <module>
    f = open("scores.csv", "r")
FileNotFoundError: [Errno 2] No such file or directory: 'scores.csv'

逐行解读

部分内容含义
最后一行FileNotFoundError: [Errno 2] No such file or directory找不到文件或目录。Errno 2 是操作系统的错误码，不用记
最后一行后半'scores.csv'Python 实际去找的那个路径，原样报出来

怎么修，按可能性从高到低：

排查顺序可能原因检查方法
1文件真的不在那个位置去文件夹里看一眼
2文件名写错了（含大小写、扩展名）scores.CSV ≠ scores.csv
3路径不对代码在当前目录找，文件却在别处。用绝对路径，或把文件放到和代码同一个目录
4路径里的反斜杠被吃掉了Windows 路径写成 "C:\data\scores.csv" 时，\d、\s 会被当成转义符。改成 r"C:\data\scores.csv"（加 r）或 "C:/data/scores.csv"

  ⚠️ 最重要的一点：报错里的 'scores.csv' 就是 Python 实际去找的路径。如果你以为文件在 D:\桌面\data\scores.csv，而报错里写的是 'scores.csv'，那说明代码根本没往那个目录找——问题出在路径，不是文件。

五、其他常见异常速查表

异常名一句话含义典型触发代码报错最后一行长什么样
SyntaxError语法就是错的，Python 读不懂这行if score = 60:SyntaxError: invalid syntax
IndentationError缩进不对if 下面的语句没缩进IndentationError: expected an indented block
IndexError下标超出范围[88, 92, 79][5]IndexError: list index out of range
ZeroDivisionError除以 0100 / 0ZeroDivisionError: division by zero
AttributeError这个对象没有这个属性/方法"abc".push("d")AttributeError: 'str' object has no attribute 'push'
ModuleNotFoundError没装这个库，或名字写错import pandas（没装）ModuleNotFoundError: No module named 'pandas'

补充两点：

  1. SyntaxError 和 IndentationError 的性质和其他都不一样。 它们发生时，Python 一行代码都没执行——因为在"读代码"阶段就被拦下了。所以这类报错的行号有时会指向出错位置的下一行（Python 读到这里才发现上一行没写完）。
  2. IndexError 是 KeyError 的"位置版"：列表用下标 [] 取，字典用键 [] 取，取不到时一个报 IndexError、一个报 KeyError。

六、报错信息常用英文句式对照

报错的后半句是英文，但句式高度重复。认识这些短语就够了：

英文短语中文含义常见于
is not defined没有被定义NameError
can only concatenate str (not "int") to str只能把字符串拼接到字符串TypeError
unsupported operand type(s) for +: 'int' and 'str'+ 不支持这两种类型TypeError
invalid literal for int()给 int() 的值无效ValueError
could not convert string to float字符串转不了浮点数ValueError
not subscriptable这个对象不能用 [] 取值TypeError
object has no attribute 'xxx'这个对象没有叫 xxx 的属性AttributeError
out of range超出范围IndexError
No such file or directory没有这个文件或目录FileNotFoundError
No module named 'xxx'没有叫 xxx 的模块ModuleNotFoundError
unexpected indent缩进多了IndentationError
indent / expected an indented block该缩进的地方没缩进IndentationError

第 1 段

第 2 段

第 3 段

第 4 段

第 5 段

参考答案

题号错误类型错在哪怎么改
1NameError第 3 行用了 price，但前面没定义过在使用前加 price = 19.9

八、本章小结与自检清单
