上下文的两根轴：延续挂在什么上面 × 历史留多少

Two Carriers × Four Ways of Context —— 此前所有讨论都在同一根轴上选位置；2026-10 的两篇论文换的是另一根轴 · 草稿 2026-10-14 · 落 output/pending-review/

必须与结论一起读的证据等级（第一屏）：① CarryOn（arXiv:2610.18784）与 PoS（arXiv:2610.01415）本材料仅用到摘要级结论，PDF 未逐页打开；CarryOn 的 arXiv 页未列机构隶属；PoS「4 基准 × 3 基础模型 = 12 组全面领先」目前是经中文科技媒体转述读到的，未核对论文自身表格。② Fork-and-Flush：arXiv 页未列机构隶属、未挂代码仓库，数字经 The Decoder 等媒体转述；+66.0% 是归一化均分的相对提升，不是绝对分数；任务类型是优化 / 研究型（autoresearch），不是通用工具调用 agent。③ VISTA / Mem++：OrgMemBench 是合成组织，作者自陈不能证明真实组织同样成立；VISTA 作者自陈不能排除公开游戏进入模型训练数据，且性能仍高度依赖后端模型已有能力。④ DSV-Mem / EMBER-Bench 是基准论文——只证难度，不证方案。⑤ 本页是草稿，落在 output/pending-review/，未写入 learning-materials/（受 README 人工核查承诺约束）。

1 · 一句话定义

上下文治理有两根彼此正交的轴。轴 A = 历史留多少（四条路：① 物理上限 · ② 有损压缩 · ③ 无损外存 + 主动回看 · ④ 主动重置）；轴 B = 延续挂在什么上面（两种载体：一段被加工过的历史 vs 一个可复用的任务对象）。2026 年之前的讨论几乎全部在轴 A 上选位置；2026-10-13 的两篇论文，一篇换的是轴 B（CarryOn），一篇补的是轴 A 与轴 B 都没覆盖的一格——「推进了没有」（PoS）。

为什么要写成「×」而不是「+」：轴 B 的每一种载体，都可以挂在轴 A 的任一条路上（压缩后的历史是载体、重建出的进度叙述也是载体）。两根轴交叉后，原本看似互斥的「压缩 vs 无损外存」之争，暴露出它们共享同一个未被言明的载体前提——这正是 CarryOn 的落点。

2 · 个人解释：大家都在选位置，没人问挂在什么上面

把一次长任务想象成让一位助手做一份需要几百步的事。第二天开工时，他手上能有的东西大致四类：装不下的口袋（上下文窗口）、越抄越薄的笔记（压缩）、一整柜原始资料随时翻（无损外存 + 主动回看）、以及把笔记撕了重新开始（主动重置）。这四样就是轴 A 的四条路，行业过去两年几乎全部的工程讨论，都在这四样之间做取舍。

但有个更前面的问题一直没人问：他每天开工时，先看的是什么？是看那本笔记（一段被加工过的过去），还是看一张写着「还剩哪几件事、每件事的证据在哪」的清单（一个可复用的任务对象）？这是轴 B。它是个前提：不管你笔记抄得多薄或多全，只要你把「昨天做到哪」完全寄托在笔记上，你就同时继承了笔记的两个缺陷——抄得越薄越失真、存得越全越倾向已有路径（锚定效应）。

CarryOn 的价值就在这一句：它明确不以「压缩后的历史」也不以「重建出的进度叙述」为延续的主要依据，而把延续组织在可复用的任务对象（continuation carriers）上。它不是轴 A 的第五条路，而是路 ② 与路 ③ 共同的载体前提——这是它能同时对两条既有路构成边界主张的原因。

还有第三格，两根轴都没盖住：推进了没有。「还剩多少空间」可以靠 token 数回答，「延续挂在哪」可以靠载体回答，但「从昨天到今天，任务状态到底前进了没有、还差什么」——此前没有一种表示专门管它。PoS 补的就是这一格。

3 · 轴 A：上下文的四条路（每条标注「它解决哪条失效轴、解决不了哪条」）

路解决哪条失效轴解决不了哪条代表工作与关键数字现有落点
① 物理上限 「装不下」 「装得下也用不好」 [[ContextWindow]]。反证来自 VISTA：把上下文从 200K 拉到 780K，分数反而 99 → 93.9——只多烧 token，不涨分 concepts/ContextWindow.md
② 有损压缩 「装不下 + 除陈旧」 精度损失；且不解除想法盆地 [[Compaction]]。承重的否定式事实：Fork-and-Flush 明写——即使 agent 定期压缩对话历史，想法盆地依然存在 concepts/Compaction.md
③ 无损外存 + 主动回看 「信息永久保留、模型按需取回」 锚定效应——存得越多，回看越倾向已有路径 VISTA（arXiv:2610.02200，2026-10-01；Han / Hu / Qiu / Wu / He）：ARC-AGI-3 上 Claude Opus 5.0 的 RHAE 40.68 → 100.00，25 个公开游戏全通关，动作数比首次人类少 57.4%；消融：纯文本 13.33 → 换图 47.32 → 加简单外壳 65.82 → 加两份笔记 70.05 → 加无损视觉记忆与主动回看 94.10 → 加精确读像素 99.00；token 每局 71.9M（文本）→ 30.7M（图像）。Mem++（arXiv:2610.02002，2026-10-01）：「shifting from write-time distillation to read-time selection」，整篇存下文档 + 日期 + 作者，写入时不调用生成式模型，保留旧版本（OrgMemBench 超最强基线 8.0–13.1 分） 09-24「上下文卸载 / 文件系统即上下文层」是其文本版
④ 主动重置 「多样性锁死」 必须丢弃已积累的对话；目前只在优化 / 研究型任务上有证据 Fork-and-Flush（Microsoft Research，2026-10-12）：同一任务 8 次独立跑分落在 68.3 到 100.0，加大算力也不收敛；单次运行的解几乎总停留在一小块区域内 = idea basin（想法盆地）。方法 = 分叉成 K 个分支，每分支继承工作区（代码 / 文件 / 已存结果）但清空对话上下文。等算力下归一化均分 0.78 vs 单次 0.47（+66.0%）vs best-of-4 0.54（+44.4%）；归一化标准差 0.26 → 0.16；13 项中 12 项取得最高均分；只清空不分叉（11 项）0.45 → 0.55（约 +22%） 无 concepts/ContextReset.md（本总纲即其推进对象）

两条失效轴不是同一条，别混着记：[[ContextRot]] 写的是精度随长度下降；想法盆地写的是多样性随长度被锁死。压缩能治前者，治不了后者；重置能治后者，代价是丢掉对话。

4 · 轴 B：两种载体（这是 2026-10 才被命名的一根轴）

载体延续的依据代表工作它明确否定什么
载体甲 · 历史 一段被加工过的过去：压缩后的历史（对应路 ②）或重建出的进度叙述（对应路 ③） [[Compaction]] / VISTA / Mem++ ——（它是被否定的一方）
载体乙 · 任务对象 一个可复用的任务对象：CarryOn 的 continuation carriers。跨折叠维护 carrier 记录，只按绑定证据与环境检查就地修订受影响的记录，原样带走不受影响的记录 CarryOn（arXiv:2610.18784，2026-10-13）：OSWorld 2.0 +5.8% / BrowseComp-Plus +7.0%，总 token −51.9% / −22.9% 明写不以「压缩后的历史」也不以「重建出的进度叙述」为延续的主要依据 ⇒ 对路 ② 与路 ③ 同时构成边界主张

CarryOn 自己点出的核心难题值得单独记：周边历史被「退休」之后，这个可复用基础凭什么仍然有效？它的解法是——不重建叙述，而是就地修订：只改那些被证据与环境检查判定为受影响的记录。

5 · 两根轴之外的第三格：推进了没有（PoS）

PoS（《Beyond Memory: Harnessing Long-Horizon Agents with Explicit Belief States》，arXiv:2610.01415；南开大学 + 阿里云 + 清华大学；代码 github.com/luoyu100/PoS）做的是一件此前没人做的事：把智能体自己当前的理解变成一个被显式表示、并且带溯源的对象。

  • 表示什么：与任务相关的世界被组织成实体 / 状态 / 关系，而状态与关系各自携带来源、置信度与可用支持证据（杯子是否热、微波炉是否关闭、杯子在哪、由谁拿着）。
  • 还差什么，分两类：信息缺口 Epistemic Gap（还需弄清楚的事）与 达成缺口 Achievement Gap（还需靠行动改变的事）。这个二分是它能给出「下一步该做什么」的前提。
  • 闭环：从识别已经卡住（Belief Trapping）到决定怎样恢复进展，构成完整回路——而「识别卡住」本身，就是此前所有上下文治理都没有的能力。
  • 规模：4 个基准 × 3 个基础模型 = 12 组设置（⚠️ 该结果目前经中文科技媒体转述，未核对论文表格）。

对本知识网最硬的一条影响：[[Provenance]] 的对象第一次从「取进来的事实」扩到「智能体自己形成的理解」。此前所有溯源纪律管的都是「这句话有没有打开过来源」，PoS 问的是「你现在相信的这件事，它的证据与置信度在哪」——这是同一条纪律往内走了一层。

6 · 边界辨析（与既有概念的接缝）

对照对象它的主张本页的边界
[[Compaction]]把历史说得少一点压缩 = 说得少一点；重置 = 什么都不说；CarryOn = 根本不以历史为载体。三者不是同一维度的三个选项
[[ContextRot]]精度随长度下降还有第二条失效轴：多样性随长度被锁死。现有页只写了前者
[[ProgressiveDisclosure]]按需加载三个决定权方向：推给模型 / 模型拉取 / 全部丢掉——路 ④ 是第三种
[[MultiAgent]]并行提速并行还有第二个机理：共享长上下文会侵蚀方案多样性，Fork-and-Flush 让「独立性」的价值第一次有量化来源
09-23「持久化执行」状态能不能恢复再次印证 checkpoint ≠ memory：工作区继承 ≠ 对话继承
10-06「压缩时机是学出来的 / AutoCompact」压缩时机可学对象不同：可再生的环境观测 vs 不可再生的推理状态——引用时必须同句给出对象
[[LongTermMemory]]跨会话的语义事实carrier 记的是跨折叠的任务进度，不是语义事实
[[Provenance]]管取进来的事实的来源与置信PoS 管智能体自己形成的理解的来源与置信

7 · 可直接引用的判据句

  • 「工作区承载进度，对话承载偏见。」——Fork-and-Flush（这句话同时解释了为什么「继承工作区但清空对话」是有效的组合）
  • 「shifting from write-time distillation to read-time selection」——Mem++ 原文
  • 写入时蒸馏会在问题被提出之前就固定了可回答的内容——Mem++ 的判据句
  • 不以「压缩后的历史」也不以「重建出的进度叙述」为延续的主要依据——CarryOn（对路 ②③ 的共同边界主张）
  • 上下文 200K → 780K，分数 99 → 93.9——VISTA（「加大窗口」不是解法的最硬反证）

8 · 你会怎么用它

  1. 先定轴 B，再选轴 A。先回答「明天开工先看什么」——是看压缩后的历史，还是看一份可复用的任务对象清单；再回答「历史留多少」。顺序反了，就会在压缩率上反复调参而看不到真正的瓶颈。
  2. 别把「加大窗口」当解法。VISTA 的 200K → 780K 是最干净的对照证据：容量涨了 3.9 倍，分数反而掉了 5.1 分。
  3. 压缩不是重置。周期压缩不解除想法盆地；如果你的任务卡在「每次都在同一个局部最优附近」，需要的是路 ④（分叉并清空对话），而不是更激进的压缩。
  4. 把「还差什么」显式化，并分成两类。Epistemic Gap（要去查）与 Achievement Gap（要去做）分开之后，才有「识别已卡住」这回事——这是目前唯一能回答「推进了没有」的表示。
  5. 给溯源纪律补一层。不仅「这句话有没有来源」，还要问「我现在相信的这件事，证据与置信度在哪」。
