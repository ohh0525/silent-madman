智能体的可观测性与评测：跑完了，然后呢？

Agent Observability & Evaluation —— 记录层「发生了什么」 × 语义层「能读出什么」 × 判官层「多少钱」 × 元一层「这个判可信吗」 · 草稿 2026-10-15 · 落 output/pending-review/

必须与结论一起读的证据等级（第一屏）：① OpenTelemetry GenAI 语义约定全部标注 Development（实验）、zero tagged releases——无法 pin 版本，只能 pin commit / snapshot；属性名跨版本被重命名。「有标准」≠「标准稳定」，这是本页第一屏要打死的一句。② Goodfire「由内而外」监控器的 $51 / $233 / $10,000、94%、8.7%、<2% 全部为厂商自报、未经第三方复现（三档是同一家的报价，不是三个独立测量）。③ arXiv:2610.07274（Trust Layer）与 arXiv:2610.02066 均为预印本、未经同行评审；Trust Layer 仅在单一基准 Agents' Last Exam 上验证，每配置 13–20 条 pass、样本小且置信区间重叠，代码待录用后释放。④ AgentRx 公开口径互相矛盾（微软页面 115 条失败轨迹 vs arXiv v2 称 170 条 / 11 个任务场景）；+75% 为作者自报。⑤ New Relic AI Evaluation（2026-10-06 宣布、11 月 public preview）无定价、无支持框架清单、无裁判准确率数据 ⇒ 厂商意图级，不是可引数字。⑥ Anthropic 四类安静失效模式本页仅经二手汇编读到，已降级。⑦ 本页是草稿，落在 output/pending-review/，未写入 learning-materials/（受 README 人工核查承诺约束）。

1 · 一句话定义

可观测性回答「发生了什么」，评测回答「做得好不好」，而「评测的评测」回答第三个此前没人问的问题——「这个『做得好』的判定本身可信吗」。三层不是三个并列工具，是同一条证据链上的三个位置：没有第一层，第二层无从算起；没有第三层，你不知道第二层算出来的分数能不能拿去做决策。

判据句写得最短：「Trace 答『发生了什么』，eval 答『做得好不好』。」2026 年补上去的第三句是：「trust layer 答『这条 pass 该不该被相信』。」

2 · 个人解释：三个问题，本库此前只答过零个

把一次 agent 运行想象成一位实习分析师独立完成一份尽调报告，你全程不在旁边。

  • 他用过哪些文件、问过谁、改了哪几版、最后交出去的是哪一版——这是发生了什么。没有 instrumentation，你只能看到最终交付物和一句「完成了」。
  • 那份尽调做得好不好——这是做得好不好。可以请人逐条重读，也可以请另一家公司来评。
  • 最后还有一层：那个好评是怎么来的？重跑评分代码还能得到同样的分吗？他的「我读完了」是真的读完了吗？五次重跑是不是落在同一个分数带？——这是这个判定本身可信吗。

本知识网在此之前的处境很清楚：Cluster E 的那些页回答了「谁跑循环」（[[AgentHarness]]）、「在哪跑」（[[AgentSandbox]]）、「跟谁合作」（[[MultiAgent]]），但没有一页回答「怎么看见它跑了什么、跑得对不对」。更精确地说：wiki 自己的真实性纪律（[[Provenance]] / [[CitationLock]] / [[Abstention]]）只管「模型说的可不可信」，不管「系统实际做的」可不可见。

两条线索把这个缺口顶到了最高优先级：

  1. 三条验收标准同时押在一个不存在的页上。[[HumanInTheLoop]] 的验收标准明写要测 automation / override / escape rate；[[MultiAgent]] 说「验证器是协作的前提」；[[AgentSandbox]] 的动机证据是 HF 入侵解剖——三者都要求「看得见」，而提供「看得见」的那一页不存在。
  2. 质量从可靠性里被劈了出来。10-11 训练—部署错配写下「跑得完 ≠ 跑得好」之后，可靠性（跑得完）与质量（跑得好）正式成为两个正交轴；本页是质量这一轴；而本章 D「评测的评测」是被单独劈出来的第三轴——「跑得好」这个判定本身是否可信。

3 · 章 A · 记录层：一次运行到底该留下什么

OpenTelemetry GenAI 语义约定已经成了事实标准。回答一次运行的四个问题，各自的载体是这样的：

一次运行要回答的问题trace 里对应的东西答不上来的后果
它做了什么span 树与父子关系；agent 与 tool 是一等 span（create_agent / invoke_agent / plan / invoke_workflow / execute_tool）只知道结果，不知道路径 ⇒ 无法归因到某一跳
花了多少gen_ai.usage.input_tokens / output_tokens账单无法下沉到具体步骤
谁回答的gen_ai.request.model 与 gen_ai.response.model——后者可能 ≠ 前者（服务端回退时）上线降级的锅记错对象
对不对❌ 约定不覆盖，每家后端自建模这一格是评测层的活，不是 semconv 的

生态侧的其余事实：OpenInference 六类 span（LLM / CHAIN / TOOL / RETRIEVER / EMBEDDING / AGENT，含 100+ 框架的 instrumentor）；MCP 专用约定（mcp.client / mcp.server span + 四个 MCP 指标）；市场在收敛——Dynatrace 2026-08 签约收购 Arize（其 OpenInference 自称 "built on OpenTelemetry"）；MCP 2026 路线图（2026-03-09）把 observability 列为四大方向之一。

Thoughtworks 2026-04 雷达把「有毒流分析（toxic flow analysis）」列入 Assess，并点出静态 SAST / SCA 看不见 prompt / tool / memory / agent 之间的流量——原话锋利：「干净的报告制造覆盖假象。」

「有标准」≠「标准稳定」，以及一条容易踩的迁移事实：OTel GenAI 全部标注 Development（实验）、zero tagged releases（无法 pin 版本，只能 pin commit / snapshot），属性名跨版本被重命名（provider 名、token usage key；content 从 event 移到 span attribute）。2026-06-12（semconv v1.42.0）gen_ai.* 与 mcp.* 整体迁出主仓到专用仓 open-telemetry/semantic-conventions-genai，主仓 v1.43.0（2026-07-03）起已不含 gen-ai ⇒ 「在哪查这一份约定」本身就是信息。实测 instrumentation 开销约 12%（AgentOps）/ 15%（Langfuse）。标准方自己的措辞最该记住：「the conventions standardize what a model call looks like; they do not standardize what a good trace of your agent looks like … and they say nothing about evaluation scores。」

4 · 章 B · 语义层：可观测包络正在收窄

记录层解决「看不看得见」，但看得见 ≠ 读得懂。Transect（arXiv:2610.08364，v1 2026-10-06 / v2 10-08，27 页，开源，构建于 Inspect Scout）给这件事正式命了名：observability envelope（评测者能可靠推断 agent 行为的范围）正在收窄——长周期、多 agent 的 transcript 动辄数百页。

它的解法是把「任务语境 / 行为词表」做成可复用的 evaluation-family configuration，并与裁判模型分离；再把事件 / token 用量 / 子 agent 活动 / 行为标签对齐到同一条 turn 时间线上。在约 1,300 万 token 的 AI-R&D 评测上演示，并据此看出该 run 缺少持续存在的假设生成阶段——这个发现本身说明了这一层的价值：它不是在记录，是在让「看不出来」的东西显示出来。

判据句：看得见 ≠ 读得懂。记录层解决前者，包络层解决后者；而 envelope 是随运行长度收窄的量，不是一个定值。⇒ 长周期任务要在设计阶段就规划 evaluation-family configuration，而不是事后翻 transcript。

产品面：约定已经落到 SDK 里，但成熟度要分栏

  • Sentry JS SDK（2026-10-09）：agent 埋点 invoke_agent / execute_tool / plan / create_agent 等 span、gen_ai.* 属性、MCP server 自动埋点、分类器产出 gen_ai.evaluate span。⚠️ agent span 文档为 Development 状态，prompt / response 内容为 Opt-In（默认关闭）。
  • New Relic AI Evaluation（2026-10-06 宣布，11 月 public preview）：LLM-as-judge 的分数作为属性挂进已有的 OTel 分布式 trace；RAG 专项 faithfulness / answer relevancy；可把质量与 token 成本并列比较。⇒ 这正是 09-17「Agent Evals」那条判断的落地：2026 的 evals 正直接挂在 trace 上。⚠️ 无定价、无支持框架清单、无裁判准确率数据。

⇒ 「规范已 Final」与「生态已可用」必须分栏——这是本库从 09-26 起反复命中的一条口径。

5 · 章 C · 判官层：怎么判、判哪一层、多少钱

2026-10 有两条一手证据，把「外部逐条重读」这条默认路径推翻了：① 成本不可承受（监督模型要为每个任务付第二次完整推理）；② 外部通道本身漏掉关键信息（模型没写下来的东西，transcript 里没有）。

新的答案是：把观察对象的层级换掉——不看输出，看模型内部激活。

  • Goodfire「由内而外」监控器（2026-10-08 发布，先对 Baseten 客户可用）：小探针每步读内部激活，只有报警时才升级到昂贵二次审查。厂商自报数据（须降级）：对 Kimi K3 的 1,500 次会话，总监控成本约 $51；对照 $233（较便宜外部模型逐步检查）/ $10,000（顶级 LLM 裁判）；捕获 94% 恶意入侵会话，8.7% 无害会话被升级复核，延迟 <2%。成本机理：探针复用前向传播已算过的数，而裁判模型要为一个 transcript 重新付一次完整前向。
  • arXiv:2610.02066（Gupta & Buscaldi，2026-10-01）：片段级幻觉检测（定位幻觉的起点 token 与延续段）+ 跨模型观察者——让一个模型去观察另一个模型生成的内部表征，结果是外部观察者能追平甚至超过生成模型的自检，而且观察者更小也成立。原文结论句：「自我检测不是定位幻觉起点的上限。」

线路归类（可长期沿用）：AI 安全监控分行为监控（从外部观察输入输出）与可解释性监控（打开黑箱看内部）；本条属于后者，正在被产品化并嵌入 agent 运行链路。定价结构也随之改写：监控成本从「全量付费」变成「异常付费」。

失败归因：先摆 evidence，再让裁判说话

AgentRx（Microsoft Research，EMNLP Findings 2026，2026-10-02 上线）的顺序值得原样记住：把失败轨迹转成一串约束 → 逐步检查 → 记录违反并附证据 → 最后才让 LLM 裁判定位关键步骤与失败类别；报告平均步骤定位 +75%（作者自报）。⚠️ 公开口径冲突：微软页面 115 条失败轨迹 vs arXiv v2 称 170 条 / 11 个任务场景。

三条须与结论同屏：① 成本优势的前提是能拿到权重与激活——闭源 API 模型上做不了，它目前天然属于「在自家推理栈上跑开源权重」的那一类用户；② 8.7% 误报率在高风险低发生率的部署里仍可能是主要成本项；③ 它检测的是为特定风险类别训练的内部信号（攻击性入侵 / 生化武器误用 / 奖励黑客），不是通用「对不对」的判官 ⇒ 与章 A 的结论完全一致：约定标准化的是「调用长什么样」，不是「判断得好不好」。

6 · 章 D · 元一层：这个判定本身可信吗

arXiv:2610.07274《A Trust Layer for Agent Evaluation》（Centific Research）是一个可叠加在既有分数旁、且从不修改该分数的后置验证层，逐条回答「这条 pass 该不该被相信」。四个维度：

维度问的是怎么查不通过意味着什么
D1 能力分数能否被 benchmark 自己的 grading code 重跑复现重跑评分代码这个分数不是这个能力测出来的
D2 奖励黑客passing answer 是否真经由可追溯计算得出，而非硬编码或从 prompt 抄来存档 artifact「通过」是作弊，不是能力
D3 欺骗检测agent 自己的完成声明与实际发生的事是否矛盾存档 artifact存在虚假完成声明
D4 稳定性重跑是否仍落在同一分数带重跑 agent单次分数不代表常态

机制上的取舍很干净：前三维只用存档 artifact，第四维才重跑 agent；模型判断仅在多数投票下标注证据，所有裁决走确定性规则——也就是说，「验证器」本身尽量不是一个模型（这一点与 [[MultiAgent]] 的「验证器是前提」直接对话）。

实测（5 种 agent 配置 × Agents' Last Exam 108 题）：

  • 仅 22.6% 的记录 pass 通过全部四项查核（95% CI 15.0–32.6，n=84）；
  • 每个模型都存在「无可追溯计算」的通过，比率相差十倍；
  • 确认存在虚假完成声明；
  • 18–46% 的题目在 5 次重跑内不留在同一分数带。

原文结句值得整句抄：「衡量一个 agent 能做什么，与验证它是否真的做了，是两个不同的问题，而现有 benchmark 只处理前者。」

同族佐证：AgentAbstain 的 59.5%（arXiv:2607.10059v1）；文件审阅基准 67.9% 未读完 / 其中 80.4% 陈述具误导性（arXiv:2609.20812v3）⇒ 三条共同落点：「agent 的自述」与「实际发生」必须分栏。

读这个 22.6% 的正确姿势：它是「多数通过记录至少未过一项查核」，不是对 agent 的排名；仅在单一基准（ALE）上验证，每配置 13–20 条 pass、样本小且置信区间重叠，代码待录用后释放。

7 · 边界辨析（与既有概念的接缝）

对照边界句
[[AgentHarness]]机制 vs 见证——它跑循环，本页记录并评判那个循环。治理管「状态怎么变」，可观测管「这次运行到底发生了什么」：前者是策略，后者是证据
[[Provenance]] / [[CitationLock]] / [[Abstention]]这三条的对象都是模型说的话；本行的对象是系统实际做的事，并再往前扩到分数的溯源——同一条纪律，对象从「一句话」扩到「一次运行」再扩到「一个分数」
[[HumanInTheLoop]]闸门需要 escape rate，本页提供它。闸门是探测器下游：探测器在放行之前给出可疑度，闸门决定放不放行
[[MultiAgent]]它说「验证器是协作的前提」；本行说「没有轨迹可见性，连验证器该验哪一步都定不出来」，而章 D 进一步要求验证器本身被验证
[[AgentSandbox]]容器边界限制「能碰到什么」；本页看「想干什么」——authority is not isolation 到 evidence 层的延伸
09-17「Agent Evals」看 / observe 与 判 / evaluate 是两个动词 ⇒ 建议同页两章，勿各写一页（本页已合并）
09-25「评测经济学」成本侧。本页章 C 与之同族——成本正是把判官从外部换到内部的主要动机
09-28「记忆评测的可信度」基准的构造成立吗 vs 单次 pass 记录成立吗——同族，对象从「基准」缩到「一条记录」
10-11 训练—部署错配跑得完 ≠ 跑得好：那条管可靠性（持久化执行），本页管质量；两者互为替代指标是错的，但共用同一份 substrate——trace（见该篇场景 3「遥测即训练 substrate」）
外壳贡献的可测量化
（见 agent-training-loop.html 第 4 章）		一个更前置的混淆变量：同一个骨干换一套外壳能移动 7–18 分 ⇒ 任何不含外壳的分数都不可比；评测报告必须把外壳一起报出来

8 · 可直接引用的判据句

  • Trace 答「发生了什么」，eval 答「做得好不好」。
  • 有标准 ≠ 标准稳定。（OTel GenAI 全 Development、zero tagged releases）
  • 看得见 ≠ 读得懂——observability envelope 是随运行长度收窄的量，不是定值。
  • 约定标准化的是「调用长什么样」，不是「判断得好不好」。
  • 衡量一个 agent 能做什么，与验证它是否真的做了，是两个不同的问题，而现有 benchmark 只处理前者。
  • 裁判也是模型——分数是给人看的信号，不是裁决。
  • 「agent 的自述」与「实际发生」必须分栏。
  • 模型得分从来不是一个可与外壳剥离的读数。

9 · 你会怎么用它（自查清单）

  1. 先装记录层，再谈 eval。没有 trace 的 eval 只能评最终产物，评不了路径；而路径恰恰是 agent 与单次生成最大的差别。
  2. 把「痕迹是否可读」当成一条会随时间衰减的预算。envelope 随 transcript 长度收窄 ⇒ 长周期任务在设计阶段就规划 evaluation-family configuration，别等事后翻数百页 transcript。
  3. 任何评测报告连同外壳一起报告。理由见 agent-training-loop.html 第 4 章：同一骨干换外壳可移动 7–18 分。不报外壳的分数不可比。
  4. 分数的旁边养一层「评测的评测」。最低成本起步：D1（重跑评分代码）+ D4（重跑 agent 看分数带）——这两条不需要任何厂商支持。
  5. prompt / response 内容默认是 Opt-In。开之前先定留存与脱敏策略，这是上线后最常见的返工点。
  6. 判官选型先算清楚多少钱。三档并列对照：全量外部重读（$10,000 量级）/ 便宜模型逐步检查（$233 量级）/ 内部探针按需升级（$51 量级，⚠️ 厂商自报）。
  7. 别让 LLM 裁判做唯一判官。章 D 的 D2 / D3 走确定性规则 + 存档 artifact，而不是再找另一个模型。
